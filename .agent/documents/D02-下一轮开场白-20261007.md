### 2. 🔴 优先做（几分钟）：修掉 `git push` 每次弹凭据选择框

**现象**：用户每次向 GitHub 推送新提交，都弹出一个"选择凭据 / 账户"的框。

**根因（已查明）**：本机有**两个 Git**：
- `D:\Git\cmd\git`（用户自己装的，v2.55.0.windows.5）
- `<WorkBuddy>/resources/vendor/PortableGit/mingw64/bin/git`（AI 沙箱自带，v2.55.0.windows.3）

git 的 `credential.helper` 是**多值累积**语义（**不是覆盖**）。用户自己的 Git 实际看到的链是：

```
file:D:/Git/etc/gitconfig     → manager                       ← 用户自己的 GCM，正常
file:~/.gitconfig             → !"<WorkBuddy>/.../PortableGit/mingw64/bin/git-credential-manager.exe"
```

**两条都会被调用**。两个独立的 GCM 副本各有各的凭据存储 ⇒ 第一个存了、第二个查不到 ⇒ **弹框**。

🔴 那条 global 里的 PortableGit 路径**是本 AI 会话的 Git 写进去的**（`~/.gitconfig` mtime 与 AI 跑 git 的时刻吻合）——沙箱 Git 的 GCM 首次运行把 `credential.helper` 写进了用户全局配置。**这是污染，必须清掉。**

**修法（三条命令）**：

```bash
git config --global --unset-all credential.helper
git config --global --unset credential.helperselector.selected
"C:/Program Files/GitHub CLI/gh.exe" auth setup-git
```

- 第 1 条：清掉外来 helper。
- 第 2 条：清掉 `helper-selector` 残留（global 里有 `[credential "helperselector"] selected = manager`，是历史弹框留下的）。
- 第 3 条：让 `gh`（**已登录，token 存 keyring**，账号 `maelshiyan02`）接管 `github.com` 凭据 —— **非交互、无 GUI**，且两个 Git 行为一致。

**动手前**：先向用户要**弹框截图**，确认弹的确实是 GCM / 凭据选择框（而非 IDE 或 GitHub Desktop 自带的框）。
**改后回归**：`git push --dry-run` 应返回 `Everything up-to-date` 且**全程无弹框**。
**回滚**：`git config --global credential.helper '!"<WorkBuddy>/resources/vendor/PortableGit/mingw64/bin/git-credential-manager.exe"'`。
**注意**：`gh auth git-credential` 要求 gh 已登录（✅ 已确认）。用户另有 Azure DevOps 用法（`D:/Git/etc/gitconfig` 有 `credential.https://dev.azure.com.usehttppath`），**不受影响**（那段没有 helper，仍走 `manager`）。
