## 5. 旧 AI 翻译管线：是「活功能」，不是遗留代码

> 这条必须写清，否则后续会误删。`S9.5` 的原意是「旧流程退出 + 阅读器合流」，**实际只完成了合流的一半**：新工作室上线了，旧的阅读器内整章翻译**没拆**，用户现在两条路都能走。

**仍然活跃的调用点**（证据）

| 文件 | 行 | 用途 |
|---|---|---|
| `pages/reader/reader.dart` | 339 / 427 / 428 | 订阅页面翻译事件、退出时清队列 |
| `pages/comic_details_page/comic_page.dart` | 1709 | `isEnabledForComic` 决定是否显示译文 |
| 同上 | 2932 / 3081 | `storedPageCount` 显示已译页数 |
| 同上 | 3122 / 3331 / 3371 / 3391 / 3448 | `isReadyForComic` + `retranslate` 整章/单块重译 |
| `utils/data.dart` | 15 | 共享配置/状态 |
| `foundation/image_translation/glossary_service_backend.dart` | 18 | 术语表复用模型 |
| `foundation/image_translation/pre_translation_tasks.dart` | 16 | 预翻译任务 |

**关键区分：不能整目录删**

- 🔴 **共享基础设施（工作室也在用，必须留）**：`translation_pipeline.dart`（被 `translation_project/studio_pipeline.dart:20` 引用）、`ort_ffi.dart`、`llm_translator.dart`、`local_nmt_translator.dart`、`public_translator.dart`、`script_translator.dart`、`inpaint.dart`、`page_renderer.dart`、`font_fit.dart`、`text_color.dart`、`balloon_clustering.dart`、`glossary_*`、`translation_store.dart`、`translation_models.dart`。
- 🟡 **旧编排层（若要下线才动）**：`translation_service.dart`、`translation_worker.dart`、`pre_translation_tasks.dart`，以及上表 9 处 UI 引用。
- 结论：**这是一次功能级下线，不是删文件**。必须先决定「阅读器是否保留一键整章翻译」，再谈拆。

**若将来下线，建议顺序（每步单独构建 + 反向验证）**

1. 先做能力决策：阅读器保留 / 指向工作室 / 彻底移除。三者工作量差一个量级。
2. 保留入口时：把 `retranslate` 改为调用 `studio_pipeline`，UI 不变 —— 风险最低。
3. 移除入口时：先删 `comic_page.dart` 的 5 处调用与按钮，再删 `reader.dart` 的 3 处监听。
4. 最后才动 `translation_service/worker/pre_translation_tasks`，且必须先确认 `glossary_service_backend`、`utils/data.dart` 的依赖已迁移。
5. 🔴 全程不得碰 `translation_pipeline.dart` 与 `ort_ffi.dart`，否则工作室会一起挂。
