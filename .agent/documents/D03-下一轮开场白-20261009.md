我在做 **Mangrove**（前身 VeneraX）——一条**漫画 AI 汉化流水线**：下载 → 文字检测 → OCR →

### 0. 这个项目怎么记东西（**先读这一节，它决定你后面所有动作**）

我们不用各 agent 各自的私有记忆，而是共用 `.agent/` 一个目录，**所有 agent 看到的是同一份文件**。

```
.agent/
  memory/
    MEMORY.md              ← 唯一被自动注入的记忆文件（框架 + 索引 + 三条底线，≤3K 字符）
    YYYY-MM-DD.md          ← 每日工作日志，只追加不覆盖
    appendices/A01…A09.md  ← 编号附录，正文都在这里，按需读
  documents/
    worklog/P*.md          ← 编号工作日志（W00 是索引）
    plans/                 ← 计划类文档
  kb/                      ← 跨 agent 知识库（可迁移的方法论，非本项目事实）
  skills/ specs/
```

`.workbuddy/` 与 `.trae/` 下的同名子目录、以及 `<根>/docs`，**全部是指向 `.agent` 的目录联接
（junction）**。所以**改任何一条路径都是改同一份文件**，不存在"拷回去"这一步。
体检：`python tools/agent_links_check.py`（`--fix` 重建）。
🔴 **一切引用用相对路径**（`Mangrove/…`、`.agent/…`），**绝不写 `D:\…` / `C:\…`** ——
项目根将来会改名，junction 存的是绝对路径，改名后 9 条联接会**全部静默失效**，必须跑一次 `--fix`。

#### 三条底线（不能违反）

1. 🔴 本会话**不能**直接跑 `flutter` / `dart`。构建只走
   `python tools/run_build_task.py`（看 `BUILD_OK`）；headless 只走
   `python tools/run_headless_task.py <命令…>`。
2. 🔴 本会话**没有渲染表面**：凡涉及**图像像素**（解码 / 渲染 / 出图）的操作**只能在用户 GUI 会话做**。
   典型症状：`No Impeller context is available` / `HRESULT 0x887A0022`。
3. 🔴 任何「已完成 ✅」都必须有**反向验证**（注入故障 → 该断言真的 FAIL）；**空结果判 FAIL**。

#### 门禁清单（改完必须跑，全绿才算完）

### 2. 本轮三件事

#### 任务一 · 删掉「保存并修图」按钮及其冗余代码

上一轮我把「重新生成全部产物」的位置换成了「保存并修图」。**这个按钮现在也不要。**
理由是用户自己给的：修图按钮和保存按钮都各自存在，它纯属多余；而且它继承了
**用完会退出翻译工作室**的老毛病。

要删的东西（都在 `Mangrove/lib/pages/translation_studio/studio_page.dart`）：

| 位置 | 内容 |
|---|---|
| `studio_page.dart:2256` 附近 | 工具栏 `IconButton`（`tooltip: 'Save and repair artwork'`） |
| `studio_page.dart:1777` `_saveAndRepair()` | 保存 + 只补脏页出图 |
| `studio_page.dart:1791` `_confirmRepairAll()` | 它的确认框 |
| `studio_page.dart:786` / `1738` / `1773` 附近 | 几处引用这两个方法的注释段落 |

**红线：不能影响现有的修图效果。** 要点：

- `_regenerateResults(...)`（`studio_page.dart:1891`，返回 `(int, int)`）**必须保留** ——
  它是第四段「修图」的实现（`studio_page.dart:788` 那段 `if (stages.repair)`），

  一并清理，**保留 CRLF 行尾**（该文件是 CRLF，弄坏会一次性污染 6300 行 diff）。
- 门禁里有一条断言 `wiring.save_does_not_spawn_artifact_generation`（在

#### 任务二 · 单个文字块的「修图」与「复原原图」

用户要的是**按需、单块**的粒度，不是整页。上一轮的整页修图把"框歪不歪"和
"抹字"绑在一起，而抹字**不可逆**（`inpainted/` 一写出原图的字已被算法抹掉，
重画要重新下载原图），而"框歪不歪"只有人能判断 ⇒ 必须拆开让人先核对块。

**两个按钮，加在点击文字块后出现的右侧面板里**
（`Mangrove/lib/pages/translation_studio/studio_block_panel.dart`，
类 `StudioBlockPanel`，已有 `onRecognise` / `onTranslate` 两个同类回调和
`_ActionButton` 组件可直接复用）：

| 按钮 | 语义 | 实现线索（都已存在，可直接接） |
|---|---|---|
| **对本块修图** | 只抹掉**这个块**覆盖区域的原字并在该框填译文 | `result_renderer.dart:155 renderInpaintedPage` / `:233 renderMaskPage`；`mask_producer.dart:46 buildMaskPage(image, regions)` 接受 **regions 列表**（已支持多个 region 用「或」累积） |
| **本块复原原图** | 把这个块**已经抹掉的像素**放回原图 | `mask_producer.dart:91 restoreErasedPage({original, inpainted, mask})` —— **纯 Dart、已有 headless 断言（`headless_p7_checks.dart` 358~454），但至今没有任何 app 侧调用点**，这是接线活 |

🔴 **复原时掩膜范围必须放大 ≥30%**。理由来自 BallonTranslator 的实操经验：
按字形级掩膜复原只能盖回**原来那几笔字**，而抹字算法（inpaint）的实际影响范围
**总是比字形本身大**（笔画被抹掉后周围像素被算法改写过）。用原尺寸掩膜复原 ⇒
**残留一圈糊边**。所以复原用的掩膜要在块矩形基础上**外扩至少 30%** 后重算，
宁可多盖一点（多盖的是原图，一模一样）也不能留糊边。

⚠️ 注意 `buildMaskPage` 的极性是 **`255 = 需要被抹/已抹的像素，0 = 保留`**，
且它对 region 窗口会 **clamp 到图像边界**（越界写入会静默截断 `Uint8List`）。
外扩后必须自己夹取，不能信任 `computeMask` 的窗口。

#### 任务三 · 跨页气泡截断拼接的**计划书**（只要分析，不要实现）

写一份**计划文档**，分析如何处理「一张图是跨页漫画（左右两页拼成一张）」
导致对话气泡被**截图边界截断**的情况。三个目标：

1. **为后续自动化识别打基础** —— 检测/OCR 阶段就能把跨页的气泡当成一个整体。
2. **截断型文本块的语言适配** —— 句子被切断后，倒装句 / 语序调整需要
   **把多个文本块编成一个小组**再翻译（"大框套小框"的场景也要解决）。
3. **考虑截断本身带来的噪声** —— 气泡被切开后，OCR 会读出半句话，
   而半句话喂给翻译引擎必然产出垃圾译文且**看不出是垃圾**。

现状核实（我已查过，别重复查）：
- **代码里目前没有任何跨页/拼接/stitch 概念**（`grep` 全文无命中）。
- `TextBlock`（`Mangrove/lib/foundation/translation_project/text_block.dart:583`）
  是**纯 `raw` map 包装**（FT 的 23 个块键），**没有 group / 跨块引用字段** ——
  计划书要明确这字段怎么加、并且**不破坏与 FT 工程的零字节 diff**契约（见 `A03`）。
- 「大框套小框」在 FT 那边是 `lines` 字段（4 个角点）能表达的能力，
  当前 `TextBlock.createDefault` 写的是**平面四边形**，不支持旋转/嵌套。
- `studio_page.dart:618` 有注释：术语表恒为空，"跨页/跨章人名一致性是个空承诺" ——
  计划书可以顺带给这一条出路。

**计划书要落在** `.agent/documents/plans/` 下（目录存在），写完登记进 `W00`。
要求：给出**分阶段**方案 + 每个阶段的**验收判据** + 明确指出哪些部分
**依赖 BallonTranslator 的现成做法**（本地参考代码库位置在历史对话里，
当前磁盘上**未找到**，需要的话请先问我）。
