## 五、详情页要大改：本地 / 网络模式权限升级（核心设计）

### 5.1 现状与痛点
原先创建一本漫画记录，主要是**依赖从网络漫画源去找漫画**——作者、来源、描述、章节列表等全部来自网络源；标签还能点击导向该网络源的相
关搜索。正因漫画对网络配置源的强依赖，**大部分漫画信息都是"焊死"不可修改的**（我们不可能去改同步下来的网络内容，这很正常）。

### 5.2 两种模式的设想
针对「本地创建」与「网络复制」这两种不同情况，做**本地模式 / 网络模式**的权限升级：
- **网络模式**：同一本漫画的信息、以及阅读器显示的内容，**全部来源于网站**（章节随源更新）。
- **本地模式**：切换后**只显示已下载的内容 + 我们自己自定义的漫画信息**（不依赖网络）。

### 5.3 更进一步：本地自定义模式覆盖在「网络信息壳」上
一般我们默认从网络漫画源"挖"一份漫画信息（章节还会随网络源头更新）。**本地自定义模式 = 在这层网络信息壳之上做覆盖**：网络信息作底，本地自定义信息盖在上面。
- **落地规则**：
  - **本地创建的漫画**：只有本地模式（无网络壳）。
  - **网络复制的漫画**：先构建网络模式相关信息，再在其上自定义本地模式信息。
- **冲突处理**：若某漫画的网络源不再更新 / 长时间不更新，我们要自己补章节，就必须切到**本地模式**，且**不能和网络模式冲突**——这就需要**多张记录表**来分隔两种模式的字段（网络同步字段 vs 本地覆盖字段）。

## 六、封面信息（同理延伸）
- **网络来源**：一般固定一张封面，或随更新一起把封面也更新。
- **本地自定义**：可**保留多个封面**（一本漫画因季度更新会有多张封面）。自定义模式需要一个**封面文件夹**，里面注明分别是第几季度封面 / 或贺图类；命名不能再只叫 `cover`，要转成 `[cover]season(1)` 这种带语义的命名。
- **自定义封面的来源不止季度 / 贺图**：还可以**选漫画任意章节里好看的一张**作为封面——它不一定是整本漫画的封面，也可以是某章节的缩略图展示图。这意味着**章节列表要新增另一种显示模式**（章节缩略图模式）。
