## 四、硬规矩（不容商量）

### 4.1 🔴 GUI 核验一律后台（本轮新增，用户明令）

> 原话：「本次操作前台频繁占用我的鼠标键盘，我需要你后台操作后台截图。这一点计入规则。」

- ✅ 截图：`PrintWindow(hwnd, dc, 2)`
- ✅ 交互：`PostMessage` 投递 `WM_MOUSEMOVE` → `WM_LBUTTONDOWN` → `WM_LBUTTONUP` / `WM_MOUSEWHEEL`
- ❌ 禁用：`SetCursorPos`、`mouse_event`、`SendInput`、`SetForegroundWindow`、`SetWindowPos(HWND_TOPMOST)`、任何键盘注入
- 工具：`builds\ui_bg.py`（已实测滚轮+点击均生效，光标不动、前台窗口不变）
- 用法：`python builds\ui_bg.py <pid> --click X,Y --shot a.bmp --shot2 b.bmp --wait 2.0`，看 `CHANGED / SAME`
- **拉 GUI 只能** `python tools\launch_gui_task.py`（`InteractiveToken` 计划任务）。S4U / `cmd start` 起的 exe 拿不到渲染表面，会十几秒自退。

### 4.2 构建与闸门

- 构建只能走 `python tools/run_build_task.py`（用 venv：`C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`）
- 无窗口验证只能走 `python tools/run_headless_task.py <cmd> --json out.json`
- `flutter test` 在沙盒里不可用（WebSocket 握手失败），只能靠 `flutter analyze` 验编译
- 🔴 **构建前先关掉正在运行的 App**，否则 INSTALL 步骤覆盖不了 exe，报 rc=1（假故障）

### 4.3 排序与命名（P51 定稿，绝不再犯）

- 目录名归源站，**永不写语言段**；语言/标签/话号一律进记录表
- 话号解析只用 `chapterNumberValueOf`（全库唯一入口），正则必须带 `(?![0-9A-Za-z])` 负向断言，否则 UUID 首段被读成话号
- 「至少一个能读出话号就排序」是错的，判据必须是**多数**（`numberedCount*2 >= length && numberedCount > 1`）

### 4.4 反虚报纪律

- 任何「已完成 ✅」必须有**故障注入断言真的 FAIL**；空结果判 FAIL
- 断言判据要量**用户关心的事**，不要量容易被无关误差主导的代理指标
- 假绿比没断言更糟：写着 `calls == N` 的断言必须与代码落点同 commit 核对

### 4.5 其它

- i18n：新增 `.tl` / `tlParams` 必须同步 `assets/translation.json` 的 zh_CN + zh_TW，审计 `TOTAL MISSING=0`；提交前把该文件 CRLF 还原（编辑工具会整体改 LF，产生 7000+ 行脏 diff）
- 版本号：每批施工/交付/修复 = 1 小版本，base-10 三段式，build 号单调 +1
- 改动只进本地 git，攒批统一 push
- 汇报一律**中文 + 结构化**，不接受英文，不接受大段流水账
