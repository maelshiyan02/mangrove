## 一、需求与结论

> 「由于原来的中文正版平台倒闭了，podo 漫画在 2024 年左右退出了中国市场，
> 这导致了这本漫画目前的中文版停在了 69 话…一方面我们需要下载拷贝漫画来源的
> 这个漫画的 69 章，另一方面，我们需要走 comix.to 渠道，补充从 70 话到现在的
> 最新话…另外你还要生成本地漫画，搜集漫画的相关信息补全，查找有几个季度的
> 封面，还有中文版和英文版各自建立文件夹和漫画，然后再通过合集组合在一起。

## 二、关键发现（都影响实现）

1. **拷贝漫画的章节 key 是 UUID**，且分组模式下 `chapterNumber` 也是 UUID ⇒
   话号只能从**标题**（`第01话`）里读。App 自带下载器的目录名因此是一串 UUID
   （`230c97f8-632e-11ee-9733-d3d228a76de6`）。本地漫画要好看，目录名必须自己
   定 ⇒ 中文版改用 Python 下载器落盘（`<N> [copymanga]`），App 的
   `chapterDisplayName` 会把它显示成「第N话」✓。
2. **拷贝漫画 App API 会风控**：软风控（200 但 `results` 为空）、硬风控（210
   「访问过于频繁」）。**web 通道**（`www.copyXXXX.com`）的响应体是
   AES-128-CBC 加密的，但密钥就写在网页里（`ccz` / `cct`）⇒ 抓得到、解得开。
   解密口径：密钥 = 16 字节 ASCII，IV = 密文**前 16 个字符**的 ASCII，密文
   余下按 hex 解码，PKCS#7 去填充（= `tools/copy_aes.js` 的 `decryptPayload`）。
3. **comix.to 的章节 API token 绑定完整 query**（改 `limit` 就 403），所以
   翻页 API 拿不到全量章节；但**主分组的章节 id 是连续序列**
   （127→…11560406、126→…11560405…），用基准话反推即可得到任意一章的 URL
   （已实测 70/100/120/127 都对得上）。
4. comix.to 的**番外（Side Story）与正文共用话号**（chapter-125 下同时有
   `Ch.125` 与 `Side Story 10`）⇒ 选章时只认标题以 `Ch.` 开头的那些。
5. **季度封面在 KakaoPage 上**：封面 URL 带随机 token（`kid=…`），换封面就换
   URL ⇒ Wayback 的 7 个快照能还原封面史。已滤掉站点**通用占位封面**
   （`/shared/ogImage.png`），实得 **3 张**（2023-05 / 2024-04 / 2026-06）。
6. Kakao 原始数据：**115 话 + 12 番外，完结**（2023-05-09 ~ 2026-05-07）；
   comix.to 编号到 **127**（含番外编号）；拷贝漫画停在 **69**。
   ⇒ 中英两版**话号体系不同**，合集里并排展示而不是接着排。

## 四、最终布局

```
ComicLibrary/downloads/
  那個大公的華麗婚姻騙局/                     ← 中文版（本地漫画 id=N）
      1 [copymanga]/ … 69 [copymanga]/       ← 章节目录 = 章节 key
      cover/
          [CN][cover].jpg                    ← 拷贝漫画当前封面
          [KR][cover]season(1..3).png|jpg    ← 韩文原版 3 个季度的封面
  那個大公的華麗婚姻騙局 · 英文版/              ← 英文版（本地漫画 id=N+1）
      70 [comix.to]/ … 127 [comix.to]/
      cover/
          [EN][cover].jpg
          [KR][cover]season(1..3)…
```

* 章节目录名 = 章节 key；`chapterDisplayName` 把它显示成「第N话」✓
  （源站标签 `copymanga` / `comix.to` 不当翻译组显示）。
* 封面池里 `[KR]season(1..3)` 是**这部作品**的季度封面，中英两版共用同一组；
  `[CN]` / `[EN]` 是各自平台的当前主视觉。

## 六、落地时踩到并修掉的四个坑

1. 🔴 **`LocalManager.findValidId` 会覆盖别人的记录**：它的 GLOB 条件
   `id GLOB '[0-9]*'` 把 `503jz//i-will-save-my-father` 这种"以数字开头但不是
   数字"的 id 也算进去 ⇒ `int.tryParse` 失败 ⇒ 返回 `'1'` ⇒ 而 `'1'` 已被
   《cos写真》占着 ⇒ `add()` 的 INSERT OR REPLACE **把 42 章的《cos写真》顶没了**。
   现在只认**纯数字** id，并跳过已占用的 id（`lib/foundation/local.dart`）。
   《cos写真》已从备份库恢复（id 改为 `6`，封面原样）。
2. 🔴 **被覆盖的行会污染章节矩阵**：章节矩阵"只许变多不许变少"，所以那次
   撞 id 之后，《那個大公的華麗婚姻騙局》的章节表里混进了《cos写真》的 47 个
   章节目录 ⇒ 重建记录（删行 + 重新登记）才干净。
3. 🔴 **headless 里的写盘是 fire-and-forget**：`appdata.saveData()` 与
   `writeImplicitData()` 都是 `void async`，headless 进程 `exit()` 得快 ⇒
   "命令报告成功、磁盘上什么都没有"（合集就是这么丢过一次）。已加
   `appdata.flushImplicitData()`，并在 `local-comic-make` 里显式 `await
   appdata.saveData()`。
4. 🔴 **合集封面走网络栈**：合集封面借自成员，而**本地成员**的封面是相对路径
   （`cover\[KR][cover]season(3).jpg`）⇒ Dio 把它当 URI 解析，报
   "No host specified in URI" ⇒ 合集卡片空白。现在本地成员改走
   `LocalComicImageProvider`（`lib/components/comic.dart`）。

另外两个操作上的坑（已记进日志）：

* **下载器别用 `urllib.urlopen` 下图**：每张图都新建 TCP+TLS，境外 CDN 单张
  实测 **5.6 秒** ⇒ 吞吐 0.15 张/秒，一本 69 话要 5 小时。换成
  `requests.Session`（keep-alive 连接池）后 **3 话/分钟**（提速约 20 倍）。
* **别让 GUI 和 headless 同时开同一个数据目录**：GUI 启动时读到的 appdata 是
  旧快照，退出时会把 headless 刚写进去的合集**覆盖掉**。写数据的时段不要开 GUI。

## 九、遗留

1. **两版话号体系不同**（中文 1–69 / 英文 70–127，含番外编号）—— 没有做跨版
   话号对齐（用户没要求，且两侧的"第 N 话"并非同一话）。
2. 拷贝漫画的 App API 仍在风控 ⇒ 后续**新增**中文版章节要走 web 通道工具。
3. 中文版当前只到 69 话（平台侧就到这里）；后续更新要等 comix.to 或其它源。
