# 2026-10-27 · 包子漫画源"最新章只有 App 能看"修复（P48 收尾 / 用户报障）

## 1. 报障现象

## 2. 根因（线上实锤，非猜测）

- **不是章页 404，是图片 404**：四个镜像（webmota/kukuc/twmanga/dinnerku）对 152 章的**章页本身全是 HTTP 200**，但整页只塞了 **1 张图**，且这张图引用的 slug 是 `meishaonianbangjiashijian-aojianyixi2`（**错的，是另一本漫画**），该资源在镜像 CDN(`s2.bzcdn.net`)上**根本不存在 → 404 NoSuchKey**。
- **完整正确的图只在官方 app 域**：`appcn.baozimh.com` 的 152 章有 **91 张图**，slug 正确 `miemenjiazudezhongshengzhe-yangpyungpainkillersaintnine`，图床为 `s2.baozicdn.com` / `s.baozicdn.com`（二者均实测 200）。
- **源站未升级防护**：四个镜像 + 官方域全 200，无新 Cloudflare 挑战（P39~P45 结论依然成立）。本质是**镜像同步滞后 + 资源主机不匹配**——等价于"最新章目前只有官方域能看"。
- **为什么老章正常、新章不行**：152 章（数据库 `created_at` 10-26 当天新更）镜像尚未同步好内容；老章早已同步完毕。

## 3. 三处修复（`comic_source/baozi.js` v1.2.4 → v1.2.5）

1. **图床候选补 `s2.baozicdn.com` / `s.baozicdn.com`**（官方域真实图床）到 `cdn_domains` 设置项 → 进入 `cdnCandidates` 供穷举。
2. **`onImageLoad` 改链式穷举所有图床**：抛弃旧的"只换一个备用 CDN"，改为每个候选自带下一个 `onLoadFailed` 的闭包链。引擎每轮重读 `configs.onLoadFailed`（`images.dart:294`），**每个链接都是独立闭包**（引擎会在调用后 `free()` 上一个，复用同一引用 = use-after-free 静默失效，必须避免）。`retryLimit` 设 `alts.length + 1` 保证遍历到底。
3. **`collectPages` 首图"串错书/残缺"识别**：首图数 `<5` **且** 所有首图都不含本书 slug(`comicId`，= 图片 URL 里的 `/scomic/<slug>/`) → 抛 `DomainBlock`，触发 `loadEp` 回落官方 app 域。两条件必须**同时**成立，否则会误伤正常章（正常章图多≥50 且 slug 正确，天然互斥）。

> 关键认知：**"最新章连不上"≠ 反爬/新防护**。先查"镜像章页 200 但内容残缺 / 引用错 slug"——这是镜像同步滞后，不是墙。

## 26. 下载通道：App 侧不可行，改 Python（关键结论）

**实测三步，排除了两条路：**

1. **headless（真实引擎）走 appcn → 必挂**。
   `download-check --chapter 151` 跑满 300s，日志三次
   `CloudflareException: appcn.../0_151.html` 后 `TIMEOUT`。
   原因：GUI 的 `cf_clearance` 存在 **WebView2 profile**（`data/cloudflare_webview/appcn.baozimh.com`），
   Dart 侧 `cookie.db` 里**一条 baozimh cookie 都没有**；且挑战判据是 TLS 指纹，
   连 `cloudflareVerifiedHosts=["appcn.baozimh.com"]` 已置位也只够加浏览器头。
2. **curl / requests + 浏览器 UA → 全 200**。
   实测 key 0/1/75/150/151 五话，图片节点数 173/138/144/87/91。
   ⇒ 下载改由 `tools/baozi_app_download.py` 承担。
3. **源文件不动**：仍 v1.2.7（镜像优先 + 残缺回落）。本次不改源，避免再引入回归。

**脚本必须与 App 的约定逐字节对齐**（否则"下完读不到"）：

- 章节目录：`<话号 key> [<siteTag>]`，包子 `siteTag = baozimh`
  （`chapter_directory.dart::_sourceSiteTags`）
- 页文件：`<序号>.<ext>` 从 0 起；`.dl`/`.tmp` 视为未完成；0 字节视为缺失
- 图片只收 `data-src` 且含 `/scomic/<comicId>/` 的（首话 174 个 URL 里有 6 个是
  推荐位/广告图，靠 slug 过滤掉 → 168 张真图）
- 按 magic bytes 定扩展名（本例全 `jpg`，690px 宽）

**提速**：单图 1.9s（TLS 握手为主）→ 改 `requests.Session` 线程级复用 +
`HTTPAdapter(pool_maxsize=8)` → 133 张 21s（≈6.2 图/秒，并发 10）。

## 32. 语种进入目录名：P49 四件套规则

### 26.1 用户口径

> "我们下载的漫画必须区分语言……在原来的**网站来源 + 翻译组 + 章节序号**的
> 基础上再补充一个**最前面的语言分类**。这是针对不同翻译版本必须做出的语种区分。"

### 26.2 为什么语言必须是第一维

复合漫画里，**同一话的简/繁/英/日版是四份不同内容，不是镜像**。只靠 `[站点]`
区分不够——comix.to / mangadex / comick 是**站内多语种**，站点标签相同、话号
相同，只按站分必然撞车。所以语言放最前：

```
[zh-Hans] 120 [baozimh]
[zh-Hans] 5 [Rokari Comics] [comix.to]
[en]      5 [Asura Scans] [comix.to]
```

简繁必须分开：`zh-Hans` / `zh-Hant`（BCP 47 子标签），不写含糊的 `zh`。

### 26.3 语种从哪来（优先级，绝不猜）

1. `ComicChapterVersion.language`（mangadex / comick 章节自带 `lang`）；
2. 源默认表 `_sourceDefaultLanguages`：`baozi`/`copy_manga`/`dm5`/`manhuaren`/
   `Komiic`/`mycomic`/`goda`/`zaimanhua`/`rumanhua` → `zh-Hans`；
3. 都没有 → **不写语言段**，退回三件套旧名。

⚠️ `comix_to` / `comick` / `manga_dex` 刻意**不登记**默认语种（站内多语种，
凭源名猜会把英文版标成中文版，比不标更糟）。

### 26.4 代码落点（三条腿，缺一不可）

| 层 | 文件 | 改动 |
|---|---|---|
| 命名真相 | `lib/foundation/chapter_directory.dart` | 新增 `normalizeChapterLanguage` / `chapterLanguageLabel` / `splitChapterLanguageTag` / `defaultChapterLanguageOf`；`chapterDirectoryName` 增 `languageTag`；`_baseChapterDirectoryName` 让版本自带 `lang` 优先 |
| 解析兼容 | 同文件 | `parseChapterDirectoryName` / `chapterDisplayName` / `chapterNumberLabel` **先剥语言段再认话号**；`ChapterDirectoryRef` 增 `language`；`chapterDirectoryMatchScore` 只在**两边都标且不同**时判不匹配 |
| 写入 | `lib/network/download.dart` | `_chapterDirectoryName` 传 `languageTag: defaultChapterLanguageOf(source.key)` |
| 显示 | `lib/pages/comic_details_page/chapters.dart` | 格子小字升级为 `简中 · Rokari Comics` |

> 🔴 解析侧若不剥语言段，`[zh-Hans] 120 …` 不以数字开头 → `chapterDisplayName`
> 会把它当番外整本显示原名。这是本轮最容易漏的一处。

用户在 GUI 里逐条验证，报出六个独立问题。逐条查根因，全部落在同一层：
**「网络 / 本地」这两种模式从来没有真正分叉过** —— 章节列表分了，信息区没分。

| # | 现象 | 根因 |
|---|---|---|
| 1 | 切模式右侧信息一点不变 | `data` 只在 loadData 建一次；`overlayLocalOverrides` 在 network 模式直接原样返回 |
| 2 | 详情页封面是破图感叹号 | `comicDetailCoverProvider` 只看 `comicType == local` 才读盘；下载型漫画的 `comicType` 是源 key，本地封面路径喂给了网络栈 |
| 3 | 每进一次详情页就联网更新 | `comicInfoAutoUpdate` 用户配置是 `true` |
| 4 | 主页历史卡片还是老封面 | `HistoryImageProvider` 只在 `history.type == local` 时才查本地库；源漫画的历史行是**快照** |
| 5 | 第 152 话是浅绿"待命"但点开有图 | `downloading_tasks.json` 里躺着一条 `chapters=["151"]`、`downloadedCount=0` 的幽灵任务 |
| 6 | 换封面后详情页不刷新 | `refreshLocalComic()` 写死 `LocalManager().find(comic.id, ComicType.local)` |

第 6 条是第 2 条的兄弟：下载型漫画的 `comicType` 是 `source.key.hashCode`，
写死 `local` 永远 `find` 不到 → `data` 不重建。

## 39. 信息区二选一（不是合并）

```dart
ComicDetails? _onlineDetails;   // 最近一次网络响应，原样留档

ComicDetails _composeDetails([ComicDetails? online]) {
  final local = _localComic;
  if (local == null) return online ?? _onlineDetails ?? data!;
  if (displayMode == ComicDisplayMode.local) return _localView(local, state);
  final source = _onlineDetails ?? online;
  if (source == null) return _localView(local, state);   // 离线降级
  return _networkView(source, local);
}
```

* **网络模式** = 站点原文。标题/封面/简介/标签全部来自源 —— 这一点很关键：
  标签能点开跳站点搜索，靠的就是它们和源站同一个命名空间。之前把本地
  `作者:`/`标签:` 那套塞进去，标签就成了死链。
* **本地模式** = 我们补全的版本（`LocalComic` + `comic_field_overrides`）。
* **章节永远取并集**，且**底必须是本地记录**：

```dart
final baseChapters = local.effectiveChapters ?? current.chapters;   // 不是 data
```

  ⚠️ 拿 `data` 当底是个隐蔽的丢章路径：网络模式下 `data` 就是 `online`，
  自己和自己合等于没合，从别的源补进来的话会被"合并"掉。

切换按钮从 `update()` 改成 `_applyDisplayMode()`（重建 `data`）：

```dart
ComicOverrideStore.instance.toggleDisplayMode(overrideComicId);
_applyDisplayMode();
```

### 顺手修掉一个会崩的坑

`overrideComicId` 原来读 `comic`（= `data!`），而 `displayMode` 在
`loadData()` 里就要用来判断「要不要自动刷新」——那时 `data` 还是 null，
一旦 `_autoRefreshComicInfoOnOpen` 掺进 `displayMode` 就是空断言崩溃。
改成直接用 `widget.sourceKey` / `widget.id`。

if (localComic != null && !_isRemoteImageRef(cover)) {

## 44. comix.to 补 153–157（跨源章节并集的第一步）

### 为什么必须真浏览器

* 章节 API `/api/v1/manga/{hid}/chapters?…&_=<token>` 的 `_=` 是 SPA 现算的；
* 更狠的是**响应是加密的**（body 只有 `{e: "…"}` 一个字段），拿到也用不了；
* 首屏 HTML 是空壳，章节 id 也不在 DOM 里。

### 打通的三个机关（`tools/comix_to_download.py`，新增）

1. **入口用"最新一话"的章节页**，然后点 `aria-label="Previous chapter"`
   倒着走 —— 只要一个已知 URL 就能补齐任意 N 话，不依赖章节列表。
2. **图片一次性点亮**：阅读器是虚拟列表，滚动只挂当前屏一两张；进度条上
   每一页都有 `aria-label="Go to page N"`，全套点一遍 + MutationObserver
   收 `src`。实测 **收到的张数 == 页按钮数**（145/119/180/127/133），一页不差。
3. **正文图 URL 没有扩展名**（`https://1xx.<随机域名>/hi/<token>`），
   靠 `.jpg|.webp` 判会一张都留不下 —— 用 `class*=rpage` 或 `alt="Page N"` 判。
   图床域名会轮换，但**直连可下**（不用代理）。

### 结果

5 话 / **704 张** / 0 失败 / 6 分钟。逐章比对：页数与页按钮数完全一致、
页号无空洞。

### key 坐标系

comix 第 153 话 → key **`152`**（话号 - 1），与包子对齐（包子 key `151` =
第 152 话）。两个源的 key 落在同一套 0-based 坐标系里，并进同一份
`chapters` 时既不撞也不错位。

`tools/merge_external_chapters.py`（新增）负责并入：校验目录有图 → 写
`chapters`（保持数值顺序）+ `downloadedChapters`，刷之前先备份 `local.db`。

最终：**157 章 / 157 条下载标记 / 0 缺号**；语种标注 `zh-Hans × 152 +
en × 5`。

## 48. 三个根因（全部有取证，不是推测）

### ① 目录名被加了语言段 → key 变了，全库崩

P49/P50 让 `chapterDirectoryName` 生成 `[zh-Hans] 120 [baozimh]`。后果是连锁的：

| 后果 | 机制 |
|---|---|
| 拷贝漫画章节集体报错 | 已下载章节的**目录名**与 `downloadedChapters` 的 key 对不上 |
| 章节顺序退化成字典序 | `double.tryParse("[zh-Hans] 120 [baozimh]")` == null ⇒ 排序退化为字符串比较 ⇒ `0, 1, 10, 100, 101, …` |
| 翻译工程断 | 工程目录按章节名建 |
| 源站认不出 | 目录名是**源站的契约**，我们只是租用 |

**结论（写进代码注释，永久）**：目录名归源站，写入侧永不生成语言段；
读取侧保留剥离能力，只为吃下历史数据和其他设备上的旧目录。

### ② 迁移脚本把 map 自身顺序也改成了字典序

`tools/migrate_chapter_languages.py` 用 `sorted(os.listdir())` 重建章节 map。
即使 key 修好了，map 的迭代顺序仍是 `0,1,10,100,…`。所以 DB 侧的 key 必须
**按前导数字重排**，不能只剥前缀。

### ③ 覆盖表从 P11 起就没生效过（最隐蔽）

```dart
// comic_override_store.dart（修复前，五处）
final db = DomainDatabase().db;   // 🔴 DomainDatabase 不是单例
```

`App.domain = DomainDatabase()` 是进程内唯一被 `init(dataPath)` 过的实例；
`DomainDatabase()` 每调一次都 new 一个从未初始化的对象，`.db` getter 必然抛
`StateError: DomainDatabase is not initialized`。而 `_loadFromDb` 的 catch 只写
一行日志然后 `return {}`，`_upsertRow` 的 catch 也只写日志 —— 于是：

- 读：永远返回"这本没有任何覆盖"（显示模式回落到全局默认、语言标注读不到）
- 写：永远静默失败（用户改了、重启就没了）

**影响面**：per-comic 显示模式、封面/标题/简介覆盖、`chapter_languages`、
`chapter_labels`、`chapter_numbers` —— 整条覆盖层能力。`logs.txt` 里刷屏的
`error ComicOverride … load remote:… failed: Bad state: DomainDatabase is not
initialized` 就是它，此前一直被当成"启动早期的正常噪声"。

### ④ 合集详情页一片空白（数据全对，界面不画）

headless 证明数据完全正确（见 §51），GUI 却只剩标题和封面。链路：

```
comic_page.loadData()
  → cached = ComicDetailsCache().find(...)   // 合集 isCacheable == false ⇒ 恒 null
  → if (_autoRefreshComicInfoOnOpen()) …     // 默认关
  → return _fallbackDetails(state)           // chapters == null
  ⇒ buildChapters() 走"还没加载"分支 ⇒ 空白
```

也就是说：**合集永远走不到 `loadComicInfo`**。这个开关的语义本来只是
"打开时顺手把**已有的**列表再刷一遍"，却被当成了"要不要加载"的闸门。

   无缓存的网络漫画都踩同一个坑。

   实际是"没有渲染表面"。从 Agent 沙盒直接 `cmd /c start mangrove.exe` 同样起不来。
   ⇒ **必须用 `InteractiveToken` 计划任务**：`tools/launch_gui_task.py`
   （挂到当前登录用户的会话上跑，窗口就出现在用户桌面）。

2. **`PrintWindow` 能截到被遮挡的窗口 ≠ 输入能到达**。这是最危险的一条：
   截图一切正常，滚轮却全部滚给了压在上面的 Chrome，Mangrove 一像素没动。
   shell 里 `WindowFromPoint(900,700)` 返回 `Chrome_RenderWidgetHostHWND` 才露馅。
   ⇒ 发输入前必须**确认命中**：置顶 → `WindowFromPoint` 落到目标窗口或其子窗口
   → 才发事件；否则直接报错退出，绝不发一个注定打空的事件。
   脚本：`builds/ui_probe.py`（`--wheel / --click / --shot`，全程 `SWP_NOACTIVATE`
   不抢焦点，操作完还原光标与 NOTOPMOST）。

3. **pywin32 的 `EnumWindows` 回调返回 `False` 会抛 `error(6,'EnumWindows','句柄无效')`**
   —— 明明找到了窗口却报"句柄无效"，调用方会以为窗口不存在。
   回调必须**始终返回 True**，只记录第一个命中的 hwnd。

4. **DPI**：不调 `SetProcessDpiAwarenessContext(-4)` 时客户区报 2048×1104、实际
   2560×1380，差 1.25 倍 ⇒ 点 A 命中 B。

另外：第一次真实点击常常只用来**激活窗口**，不触发控件，所以点击要连发两次。

## 53. P51 收尾：新任规则（GUI 一律后台）+ 新发现的疑似假绿

### 53.1 🔴 用户明令：GUI 操作与截图一律后台

> 原话：「本次操作前台频繁占用我的鼠标键盘，我需要你后台操作后台截图。这一点计入规则。」

上一轮用的 `builds/ui_probe.py`（`SetWindowPos(HWND_TOPMOST)` + `SetCursorPos` + `mouse_event`）
虽然事后还原了光标，过程中仍然抢用户鼠标、把窗口浮到最上层挡住别的程序。**已弃用。**

新工具 `builds/ui_bg.py`：**零光标、零焦点、零置顶**

| 动作 | 手段 |
|---|---|
| 截图 | `PrintWindow(hwnd, dc, 2)`（被遮挡也能画） |
| 滚轮 | `PostMessage(WM_MOUSEWHEEL, MAKEWPARAM(0,±120N), MAKELPARAM(x,y))` |
| 点击 | `PostMessage(WM_MOUSEMOVE)` → `WM_LBUTTONDOWN` → `WM_LBUTTONUP` |

实测（2.8.26+270 / Flutter Win32）：滚轮与点击**均生效**（截图 md5 变化），
光标位置不变、`GetForegroundWindow()` 不变；脚本源码内 `SetCursorPos` / `mouse_event` /
`SendInput` / `SetForegroundWindow` / `SetWindowPos` / `keybd_event` 出现次数 = **0**。

两个必须记住的实现细节：

1. **点击前必须先发 `WM_MOUSEMOVE`**。Flutter 的 pointer 状态机要先知道"鼠标进了窗口"，
   否则随后的 `WM_LBUTTONDOWN` 被当成窗口外事件丢弃（实测）。
2. **`wParam` 高 16 位是"有符号"滚轮增量**，必须按 16 位截断（`(delta & 0xFFFF) << 16`），
   否则向下滚会被解释成巨大的正数。
