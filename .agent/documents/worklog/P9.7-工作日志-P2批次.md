## 二、P2-6 登记的遗留缺口

### 2.1 离开路径：`PopScope` 只能拦 `maybePop`（🔴 本批头号教训）

**症状**：编辑了 30 页块，按 **Alt+F4** → 进程直接退出，未保存提示一次都没弹。

**根因链**（逐环节都要走一遍才看得见）：

```
canPop: false
  → PopEntry.canPopNotifier
    → 只被 ModalRoute.popDisposition 读
      → 只被 maybePop() 查
```

而：

| 离开路径 | 是否经过 `maybePop` | `PopScope` 能否拦住 |
|---|---|---|
| AppBar 返回按钮 / 系统返回键 | ✅ 走 `Navigator.maybePop` | ✅ |
| 侧栏切页、其它 `Navigator.pop()` / `popUntil()` | ❌ 走 `_RouteEntry.pop(imperativeRemoval: true)`，直接置 pop，**不查** `popDisposition` | ❌ |
| `exit(0)` | ❌ 与 Navigator 无关 | ❌ |
| 窗口关闭（Alt+F4 / 任务栏） | ❌ 原生 → `window_manager` → `onWindowClose` | ❌ |
| 托盘菜单「退出」 | ❌ 原生 | ❌ |

本应用的离开路径里，**`PopScope` 只覆盖「返回」这一类**——而这恰是用户在 Windows 上最不常用的那一类。

**修法**（三层，缺一层都漏）：

1. **`tray.dart` `init()`：把关闭拦截提前并**常开****
   ```dart
   _wire();
   // 🔴 顺序：先立好关闭拦截，再决定托盘。
   await windowManager.setPreventClose(true);
   await setEnabled(appdata.settings['minimizeToTray'] == true);
   ```
   原实现把 `setPreventClose` 和「是否最小化到托盘」绑在 `setEnabled` 里，
   于是**没开托盘的机器上 `setEnabled(false)` 早退，`setPreventClose` 一次都没被调到**
   ——关闭权留在原生手里，`onWindowClose` 根本不会触发。

2. **`setEnabled` 不再碰 `setPreventClose`**：关闭拦截（"别让未保存的东西静默消失"）
   与「关窗去哪」（"最小化到托盘"）是两件独立的事。把 `false` 分支改成
   `destroy tray + show window`。

3. **退出收敛到唯一出口**：
   ```dart
   Future<void> _quitThroughGuards() async {
     if (LeaveGuardRegistry.hasGuards &&
         !await LeaveGuardRegistry.requestLeave()) {
       return;                       // 守卫拒绝（用户选"留下"）：窗口还在
     }
     exit(0);
   }
   ```
   托盘「退出」与原生关闭**共用它**。各写一次 `exit(0)` 的话，改一处必漏另一处。
   `onWindowClose` 只有在**开了托盘**时才走 `hideToTray()`（进程活着、未保存编辑还在，
   P9.2 已说明为何豁免它）。

> 🔴 **元教训**：给编辑器加"返回保护"之前，**先把全部离开路径列一遍，逐条确认机制**。
> 只按"我以为的返回"实现，覆盖率会停在 2/5，而剩下 3 条里恰有用户在 Windows 上
> 最常用的那一条。

### 2.2 框选模式随翻页复位

**症状**：在长画布模式下开了"画框新建块"，滚动到下一页 → 框选模式**跟着滚过去**，
下一次拖拽在**没打算动的那一页**上造出一个块。而块一旦落地就进了 undo 栈与脏页集合。

**修法**：两条翻页入口都清 `_marqueeMode`：

| 入口 | 位置 |
|---|---|
| 单页模式切页 | `_selectPage` |
| 长画布滚动翻页 | `StudioScrollCanvas.onPageChanged` |

只改一条会留下"单页模式正常、长画布漏"的**假象**——而这正是长画布模式下唯一会被触发的路径。

### 2.3 吸附：`snapResize` / `snapMove` / `snapTargets`

**为什么需要**：手工对齐 FT 的块（同一格里两块上下对齐、跨页保持栏宽）靠眼睛在
900×1778 的页面上做，误差几十像素是常态；而 FT 的 `xyxy` 是**整数比较**——差 3px
就是一次假的"版面不一致"。

**两个刻意的设计约束**：

1. **吸附必须能被看见。** 每个函数都**回传命中的参考线坐标**，画布画成虚线。
   拖到一半突然跳走、松手后没有解释，就是本项目反复点名的"静默改动"。
2. **吸附不许把矩形吸成不合法。** 吸附发生在 `applyResize` 的 `minSize` 夹取**之后**，
   一次吸附最多移动 `tolerance`(4px)，正好可能把尺寸压到 16 之下（小块的角点很容易）。
   所以**每条边吸附后都要重新验证尺寸**，不合格就退回吸附前的值，且**不报 guide**
   ——报一条没生效的参考线比不报更误导。

**关键语义**：

| 函数 | 语义 | 容易写错的点 |
|---|---|---|
| `snapEdge` | 拉近到容差内**最近**的参考坐标 | 去掉容差闸门 → "拖到哪都跳"；取最后一个命中 → 远的那条也能赢 |
| `snapResize` | **只**吸附被 handle 移动的那条边 | 未移动的边本来没动，让它吸附等于让"正确的"那条边也跳一下 |
| `snapMove` | 两条边都是候选，取**调整量更小**的那条 | 只看左边 → "把右边缘对到隔壁块左边缘"永远对不上（而这是最常用的对齐） |
| `snapTargets` | 其它块的边 + **页面边界** | 🔴 `self` 必须排除：把自己当参考，每条边都吸回原位，块**再也拖不动**（症状像"卡住"） |

**落点**：`editable_text_block_canvas.dart` 在 pan start 捕获一次 `_snapXs/_snapYs`
（页像素），`_preview()` 同时返回 preview blocks 与 canvas 像素 guide；
`_finishDrag` 在复位前把 guide 拷到局部变量，**committed 命令走同一套 snap**
——预览与提交必须用同一次吸附结果，否则松手会跳。

### 2.4 P1-4 引入的回归：描边与填充用了两种字面

`page_renderer._strokeStyle` 的**无格式分支**漏了 `fontFamilyFallback`，而 `_fillStyle`
两个分支都有。后果：**同一个块的字被画两遍（填充 + 描边），一遍用回退链、一遍不用**
→ 字形边界处出现重影，且只在"无 fontformat 的老块"上出现。

修法：`_strokeStyle` 的无格式分支补上 `fontFamilyFallback: bundledFamilyFallbacks(null)`。

> 🔴 **教训**：两条**渲染路径**不共享代码是已知的（P9.4 §6），但同一个渲染器里
> **填充与描边**也是两份字面。改字体属性时要数**分支数**，不是"文件数"。

## 三、字体缺口补齐：韩文

P9.6 §六 #1 记的是：**Noto Sans SC 无韩文**（cmap 直读 `U+D55C → glyph 0`），
韩漫渲染会**逐字回退**到平台字体。

### 3.1 做了什么

| 项 | 内容 |
|---|---|
| 二进制 | `assets/fonts/NotoSansKR-Regular.otf`（4,744,692 B）/ `-Bold.otf`（4,909,668 B），sfnt 头实测 `OTTO`（CFF 轮廓）→ 扩展名必须 `.otf` 而非 `.ttf`（对照：SC 的两个文件是 8.48MB / 8.72MB，同样是 `OTTO`） |
| 许可证 | `LICENSE-NotoSansKR.txt`（6,596 B，OFL 1.1 全文 + provenance）；`LICENSE-NotoSansSC.txt` 末尾指向它 |
| 注册 | `pubspec.yaml` 的 `fonts:` 段新增**独立 family** `Noto Sans KR`（400/700） |
| 表 | `bundledFonts` 新增 **KR 2 条**（SC 的 2 条原已存在） |
| 别名 | `Malgun Gothic / 맑은 고딕 / NanumGothic / Nanum Gothic / 나눔고딕 / Noto Sans CJK KR / Apple SD Gothic Neo → 'Noto Sans KR'` |
| 回退链 | `bundledFamilyFallbacks(requested)`：返回**除自己以外**的全部打包 family |

### 3.2 🔴 三个必须写下来的判断

1. **`primaryBundledFamily` 不动**（仍是 `'Noto Sans SC'`）。
   它是"未知字族的回退终点"——把它挪到韩文会让**每一个历史工程的外观变化**，
   而那正是 P9.4 §六 警告过的那类静默改动。韩文作为**独立 family** 注册，
   不做终点。断言 `font.korean_registered` 同时检查"韩文注册了"与"终点没被搬走"。

2. **别名映射与"未知回退"是两件事**。`Malgun Gothic` 是 Windows 韩文系统的默认字族
   （`FontFormat.defaultFontFamily` 里雅黑那一条的韩文对应物）。不认它，韩文工程
   会落到**中文字面**上，每个谚文音节都掉到平台字体去。
   `font.korean_alias_mapped` 就是钉这条。

3. **为什么是"回退链"而不是"让 Flutter 自己 fallback"**：
   `resolveFamily` 回答"工程要的字族我们没有 → **用哪一个**代替"，答案必须是**单个**
   family（它要写进面板、也要进 `font_family`）。
   `bundledFamilyFallbacks` 回答另一个问题:"选中的这个字面是对的，但它是**子集**，
   缺的字能不能从别的**打包**字面借？"。
   分界是：**bundled→bundled 可以，requested→别的 不行。**
   链内只能含打包字体，否则验收标准 ③（"中文不依赖系统字体"）在一台
   什么 CJK 都没装的机器上就破了。

### 3.3 证据：直接读 cmap

`headless_p2_checks.dart` 里的 `_Cmap12` 直接解析 `format 12`：

| 字体 | covered 码位 | `U+D55C`(한) | `U+AE00`(글) | `U+D55C` 在 SC 里 |
|---|---|---|---|---|
| `NotoSansKR-Regular.otf` | > 10000 | 有字形 | 有字形 | — |
| `NotoSansSC-Regular.otf` | > 10000 | — | — | **null** |

🔴 **只用 format 12，不用 format 4**：format 4 有 `idRangeOffset` 指针数组，
P9.3 那次误诊的根因就是漏读它；format 12 是顺序分段表，写错的余地小得多。
代价是"某字体只有 format 4"会得 `covered == 0` —— 而调用方的 `covered > 10000`
把那种情况判 **FAIL**，不是"两个空表相等"式的假通过。

**非空判据**同理：`covered` 做下限而不是"两表相等"，否则解析器坏掉（两个 0）会假绿。

### 3.4 工具：`tools/inspect_font.py`

带 `--expect U+XXXX=>glyphId` **自带 known-answer 自检**的字体检查器。

🔴 它自己就有一个 bug 被抓到了：

```python
# 🔴 The cmap header is version(2) + numTables(2) = **4** bytes, so the
# encoding records start at off+4. The first version of this file used
# off+8 and every subtable offset came out 4 bytes late, which surfaced
# as "formats seen [0, 42, 59392, ...]"
sub = off + 4 + i * 8
```

症状是"一堆乱码 format"。**先验证解析器本身**（P9.6 §七 的同一条教训）。

## 四、管线能力补齐：断点续跑

P9.6 §六 #7 记的是：整章 97 页中途退出后，已完成的页在工程里（可重跑并去重），
但**没有"从第 N 页继续"**。

### 4.1 语义收敛到一个纯函数

```dart
List<String> resumePages(List<String> pages, String? from) {
  if (from == null) return const [];
  final index = pages.indexOf(from);
  if (index < 0) return const [];
  return pages.sublist(index);
}
```

做成纯函数有两个理由：

1. **能被 headless 直接测** —— 而 `sublist(index)` 这种散在 widget 里的写法测不到，
   只能靠眼睛，正是 P9.0 §五说的"视觉验收兜不住的那类改动"。
2. 🔴 它把一条**容易写反**的行为钉住：**断点页不在 `pages` 里时返回空列表，
   而不是整份 `pages`**。写反了，"继续"会静默变成"整章重跑"——一次 97 页的重跑，
   而用户点的是"继续"。

### 4.2 落地

| 位置 | 内容 |
|---|---|
| `studio_page.dart` | 新增会话内状态 `String? _pipelineResumeFrom`（**不落盘**：断点是会话概念，不是工程状态） |
| `_runPipeline` 主循环 | 四条中断路径（取消 / 缺图 / `PipelineCanceled` / `run.failed` / 页不在工程）都 `resumeFrom ??= pageKey`（`??=` 保证记的是**第一条**没跑完的页） |
| 收尾 | `_pipelineResumeFrom = (stopped || failures > 0) ? resumeFrom : null`（全成功就清断点） |
| `_load()` | 打开工程时清空断点 |
| AppBar | 仅当 `_pipelineResumeFrom != null && !_pipeline.running` 时出现「继续」按钮 |

按钮 tooltip 走 `'Resume from page @a'.tlParams({'a': …})`。

## 六、反向验证（P9.3 元教训的落实）

### 6.1 方法

`tools/_reverse_verify.py` 定义 **54 个故障**（每个对应一条断言：P1 35 + P2 19），
`tools/_rv_drive.py` 逐个执行「注入 → 重新构建 → 跑 `edit-check` → 还原」，

### 6.2 🔴 本批对工装本身做的四处修正（都是"测量工具先坏了"）

| # | 工装缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | **`headless.out` 陈旧输出竞态** | `run_headless_task.py` 依赖**批处理**的 `>` 去截断，而它在计划任务一注册就开始轮询；上一轮残留的 `=== HL_EXIT=` 让**第一次轮询就成功返回**，于是 0.6 秒"跑完"并报出**上一轮**的结果 → 伪造出一次 `Edit check FAIL`（27/07 17:31 那次污染调查的根因） | Python 侧**注册任务前**先 `open(OUT, "w").close()`。不用 `os.remove`：批量删 35 次会触发环境的批量删除保护（第 50 次之后全被拒） |
| 2 | **CRLF 锚点失配** | `apply` 以前用 `io.open(..., newline='')` 保留 CRLF，而锚点用 `\n` 写 → `balloon_clustering.dart`（CRLF）的多行锚点**恒匹配 0 次**，被记为 `anchor not unique`（与"真错位注入"不可区分）→ **5 条 cluster 断言此前从未真正被注入过**，而批次照样报出一张满表 | 改为 **universal-newline 读**（`\n` 归一化）。行尾是 checkout 的属性，不是被测代码的属性，工装不该关心 |
| 3 | **中途被杀留下 `.rvbak`** | 下一次 `apply` 把**已被注入的文件**当"干净备份"存起来，`revert` 于是恢复的是故障 → 故障逐轮累积，**全部结果偏移一位** | 备份**无条件覆盖**；并新增 `tree_is_clean()` 守卫：树不干净就**拒绝开工** |
| 4 | 🔴 **`revert` 把正确性押在一个会失效的副作用上**（本批最贵的一次） | `cmd_revert` 末尾是 `os.remove(backup)`。**但本环境把 Python 的 `os.remove` 也打了补丁**（`os.remove.__module__` → `function _safe_remove`），而"每轮 50 次删除"的配额会被**构建过程本身**吃掉。配额耗尽后 `os.remove` 开始抛异常 → `revert` **在 manifest 的第一个条目就中断**：第一个文件还原了，后面的没有。`korean_family_never_registered` 是 2 条目故障，于是 `bundled_fonts.dart` 干净、`pubspec.yaml` **丢掉了整块韩文字族** —— 而 `_rv_drive` 当时把 `revert` 的返回值丢在地上（`run(...)` 后直接往下走），**一个字都没报**。接下来 26 条测量全是在一棵没人发现已经坏掉的树上做的 | ① 备份移出源树（`builds/_rv_backup/<id>/`），**`apply`/`revert` 全流程零删除**，manifest 用"改写成 `[]`"来退休而不是删文件；② `revert` 逐条目 try/except + **报告**，且**永远**把 manifest 退休（否则下一次 `apply` 会把故障态当干净备份存下来）；③ `_rv_drive` **检查 `revert` 的返回码**并打印输出 —— 静默的还原失败比响亮的失败坏得多：它把一个 bug 变成了一串数字 |

**同批新增的两项工装能力**：

- `selftest`：**只体检锚点，不注入、不构建**。跑 54 个故障前先跑它，输出
  `total faults: 54 / broken anchors: 0`。理由：锚点腐烂会让批次**静默跳过**故障，
  报出一张更小但"看起来完整"的表。
- **文件级故障 + 预期连带声明**：
  - 文本替换打不到二进制。`font.korean_cmap_has_hangul` 直读字体**字节**，
    唯一的诚实故障是「这个槽位装的是错的字体」→ 新增 `FILE_FAULTS`
    的 `('copy', src, dst)` 操作（把 SC 盖到 KR 上）。**改断言里的路径**让它自己失败
    属于"被要求失败"，不算验证。
  - 新增 `EXPECTED_CASCADE`：**已知且已理解**的连带不算"结果不可信"——
    两条断言本来就锁同一行代码，一个故障同时打红两条是**事实**，不是测量失手。
    **未声明**的连带照样判失败（那说明测的树不是我们以为的那棵）。

### 6.3 `apply` 的两个"拒绝执行"保护（都真的救过命）

- **锚点必须唯一**：`text.count(old) != 1` → 拒绝。第一版 `pubspec.yaml` 的锚点 `  fonts:\n`
  出现两次（`fonts:` 与缩进的 `- fonts:`）就被它挡住了。错位注入会"验证"一条从未被破坏的断言。
- **先全部校验，再全部写入**（本批新加）：第一版边校验边写，于是"第二个锚点失效"会留下
  **第一个文件已被改、而 manifest 还没落盘** → `revert` 找不到它，树脏着，
  下一次测量测的是错的树。

### 6.4 🔴 夹具必须落在"正确值"与"故障值"之间（本批最有价值的发现）

第一轮 54 条里有 5 条报「未检出」（注入成功、构建通过、**被瞄准的断言照样 PASS**）。
逐条查下去，它们不是同一个毛病，而是**三类不同的"这条验证其实没验证"**：

| 类别 | 故障 | 为什么没检出 |
|---|---|---|
| **夹具不在判别区间** | `cluster_merge_too_eager` | 夹具是 200px 间距。桥接条件是 `2 × gap > 间距`，而 `gap` 被 `maxGap` 夹在 90，最多 180 —— **够不着**。夹具必须落在"正确值够不到（2×18=36 < 间距）"与"故障值够得到（2×90=180 > 间距）"之间，所以改成 **100px** |
| | `cluster_orientation_check_removed` | 夹具的竖排行高 260px、横排 30px，**先被尺寸闸门（2.2 倍）拦掉**，方向闸门一次也没被执行过。改成一横（300×40）一竖（40×80）：外扩框相交、字高比 2.0 在闸门内 → 只有方向闸门能拒它 |
| | `cluster_nondeterministic_order` | 列切分游标 `rightmost` 从**第一个组**起算，而旧夹具首项恰好是右列块 → 正序与逆序**恰好同解**。改成首项为左列块（并把 B/D 的 `left` 拉开，避免"按 left 排序"的连带）→ 正序 `[B,D,C,A]`、逆序 `[A,B,D,C]`，差异立刻出现 |
| **故障自身不成立** | `cluster_empty_fabricates` | 注入的 `Balloon(...)`/`IntRect(...)` **不是 const 构造器** → 直接编译失败。**"build failed"不是一次测量**，它连"断言是装饰品"都证明不了 |
| | `cluster_extension_point_removed` | 改类名会让**断言文件**（`const detector = PureGeometryBalloonDetector();`）编译不过；保留 `@override` 又触发 analyzer 警告，而 `flutter analyze` 默认 `--fatal-warnings` → 构建仍然失败。必须**同时**改实现关系与摘掉 `@override` |
| | `font_family_commented_out` | 只注释父键 `fonts:` → 底下的 `- family:` 变成**无主列表项**，pubspec YAML 解析失败 → 构建失败。改成"删掉两个 family 条目 + 父键换成 `[]`"：YAML 合法、构建通过、`fonts:` 不再是裸键 |
| | `font_files_missing` | 改 **pubspec** 的 `asset:` 声明了一个不存在的资产 —— Flutter 视为**硬错误**，构建失败。改 **dart 表**的 `file:` 则构建照常（该字段只被断言读），故障才真的落在断言的观测面上 |
| **断言过弱** | `font.legacy_yahei_mapped` | 断言只比 `(family, fallback)`。可雅黑映射到的**恰好就是** `primaryBundledFamily`，而"完全未知的名字 → 落到 primary"给出的是**同一个二元组** —— 于是把别名表整条删掉，断言照样绿。别名有没有被**认识**只能从 `reason` 读，而 `reason` 的注释本来就写着"面板与断言都靠它说话"。**加了 `reason.contains('mapped to')` 之后，同一个故障立刻把它打红** |

**沉淀成三条规矩**：

1. **故障必须编译得过。** 判据是"这条断言真的翻红了"，不是"构建炸了"。
   构建失败意味着**没有测量** —— 而且它比假绿更隐蔽：报出来是一句 `build failed`，
   很容易被当成"工装环境问题"划过去。
2. **夹具要留余量，不要靠边界相等。** `Rect.intersects` 在**相等**时返回 `false`，
   于是"间距恰好等于 2 × gap"的夹具会**靠一个像素的运气**通过 —— 这种断言在
   别人改了一个常量之后就会开始说谎。留 20% 以上的余量。
3. **断言要挑一个"能区分"的观测量。** 两个不同的内部状态映射到同一组输出时，
   断言就分不出对错 —— 这时要么换观测量（如 `reason`），要么换用例。

**连带从噪声变成事实**：`EXPECTED_CASCADE` 从 3 条扩到 10 条，每一条都写明
**为什么这两个断言锁同一行代码**（例如 `_isReadingColumn` 一行同时决定两条阅读
方向断言；`resolveFamily` 同时是"该用哪个字面"与"回退链补谁"的上游）。
**未声明**的连带仍然判失败 —— 那说明测的树不是我们以为的那棵。

## 九、走过的弯路 / 这一批否掉的东西

| 走过的弯路 | 教训 |
|---|---|
| 断言"工作室没有用旧引擎"，结果匹配到的是**注释里解释"为什么不用"的那句** | 🔴 扫源码的断言**必须先剥注释**。本批同型两处：`tray.dart` 注释里的 `setPreventClose(false)`、`run_headless_task.py` 注释里的 `os.remove(OUT)` —— 都报过假 FAIL。加了 `_codeOnly()` 只按**行首**剥（`//`、`///`、`#`）；块注释不剥，因为不值得为两条检查写词法器 |
| 断言 detail 打印 `Instance of 'Offset'` | `Offset` 没有能打印分量的 `toString()`。失败信息不可诊断 = 失败不可诊断。加 `_offsetText()` |
| `_Cmap12` 里 `covered` 与 `coveredCount` 重复声明 | 改成单个 `late final int covered = _count()` |
| 想用 `listEquals` 比 `List<double>` | 该文件没引 `foundation`。改本地 `static bool _sameDoubles(...)` |
| 用 `entity.uri.pathSegments.last` 取目录名（`page-reconcile` 里） | 目录 URI **必带结尾斜杠** → 最后一段恒为 `''`，接 `isEmpty → continue` 就会把目录全跳过（报告恒为空）；且段是百分号编码的。改用 `FileSystemEntityExt.name` |
| 用 `'x $v'.tl` 拼参数 | **先插值再查表 → 永远匹配不到**。必须 `'x @a'.tlParams({'a': v})` |
| `\.tl\b` 正则扫未登记字面量 | **不匹配 `tlParams`**（`l` 与 `P` 之间无词边界）→ 漏掉三处全英文 tooltip。改成 `\.tl(?:Params)?\b` |

## 十、🔴 需要人工验证的项（headless 测不到）

### 10.1 离开路径

1. **关掉"最小化到托盘"** → 编辑一个块（不保存）→ **Alt+F4** → 应弹未保存提示；
   选"留下" → 窗口还在；选"放弃" → 退出。
2. **打开"最小化到托盘"** → 编辑（不保存）→ Alt+F4 → **收进托盘，不弹提示**
   （这是刻意豁免）。从托盘「显示」恢复 → 编辑内容**还在**。
3. **打开"最小化到托盘"** → 编辑（不保存）→ 托盘右键「退出」→ 应弹未保存提示
   （⚠️ 见 §八 #8：注意窗口被藏时对话框是否可见）。
4. 保存后立刻 Alt+F4 → **不应**弹提示（守卫已清）。

### 10.2 吸附

5. 选中一个块 → 拖右边缘靠近另一个块的左边缘（差 < 4px）→ 应**吸住**并出现**竖直虚线**。
6. 拖到离任何边都 > 4px 的位置 → **不吸**，也没有虚线。
7. 拖一个小块（宽度接近 16px）的角点 → 即使附近有参考线，**不得**把宽度吸到 16 以下，
   也不得出现虚线。
8. 拖动整个块靠近页边 → 应吸到**页左/页右**（0 / 900）。
9. 松手后块的位置必须与拖动时预览的**一致**（不许"松手跳一下"）。

### 10.3 框选复位

10. 长画布模式 → 点"画框新建块" → **滚动到下一页** → 图标应回到**未激活**状态，
    下一次拖拽不得造块。
11. 单页模式切页同理。

### 10.4 韩文

12. 打开一个 `font_family` = `Malgun Gothic` 的工程（或手改 json）→ 面板应显示
    落到了 `Noto Sans KR`（fallback 说明）→ 画布与 `result/` 的**谚文必须出字**。
13. 混排（谚文 + 简体汉字）的一页：**汉字不得变成豆腐块**（靠 `fontFamilyFallback`
    从 SC 借字）。
14. 韩文粗体（700）应与常规有明显粗细差。

### 10.5 断点续跑

15. 整章跑到一半点**停止** → AppBar 应出现「继续」按钮，tooltip 是中文
    （`Resume from page N` 的译文）。
16. 点「继续」→ 应**从断点页**开始，不是从第 1 页。
17. 关掉工程再打开 → 「继续」按钮**消失**（断点是会话状态）。
18. 制造一页失败（改名原图）→ 跑完 → 断点应停在**第一条**失败页。
