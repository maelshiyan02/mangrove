# comix 换漫画下载复用验证工作日志

> 主题：验证 comix 采集/下载逻辑在"换一部漫画"时能否正确复用，而非只对某一部硬编码生效。
> 时间：2026-10 中旬（consolidated 于 2026-10-17）。

## 1. 目标与假设

- **目标**：确认同一套 comix 采集管线对**不同漫画**（不同 hid / slug / 组构成）都能跑通，
  避免"只在这一部上验证过"的虚假置信。
- **假设**：若管线是通用的（按 hid+slug 参数化、按 DOM 结构解析而非写死），则换漫画应自然复用。

## 2. 工具与方法（AI 分析路线）

1. 取**另一部漫画**（mnm90 系列）作为对照样本，重复章节列表采集流程。
2. 读其首页计数文案 `Showing 1 to 20 of 594 items` → 确认该漫画总条目 **594**，
   证明"大规模列表也能被采到"（与 503jz 的 371 形成量级对照）。
3. 检查采集代码是否**参数化**：`ComixClient().fetchChapters(hid, slug, url)` 由
   `comix_to.js` 桥接（`comix_fetch_chapters`）传入，无写死 hid。
4. 检查 `comix_to.js` 的 `_chaptersCache`（L35 / L494-526）是否按 comic 维度缓存 versioned 结果，
   而非全局单例 → 换漫画不应串数据。

## 3. 观察与数据

- mnm90 计数文案 `of 594 items` 实证：大规模列表可采，**采集逻辑与具体漫画解耦**。
- `comix_to.js` 章节缓存按 comic 维度存 versioned 结果，交给 Dart 桥；切换漫画时以 comic id 区分。
- DOM 解析依赖的是**结构类名**（`mchap-item` / `mchap-row__group` 等），不依赖具体漫画文本。

## 4. 结论

- ✅ 采集管线对"换漫画"是**通用复用**的：参数化 hid/slug + 结构解析 + 按 comic 缓存，三件套成立。
- ✅ 之前几轮在 503jz / mnm90 等不同漫画上的成功，共同支撑"管线通用"的结论，不是单点假象。

## 5. 反向验证（不虚报）

- 对照两部漫画（503jz=371 项 / mnm90=594 项）各自独立采到完整量级，且分组构成不同 →
  排除"写死某一部"的可能；若写死则换漫画会采到错误/相同的集合。

## 6. 遗留 / 未决

- 换漫画复用的**完整性**仍受 §2（翻页卡顿）影响：超大列表若中途 `page N not effective`，
  该漫画也会只采到部分页 → 与 503jz 同源问题，见 `mangrove-同组重复bug根因取证.md`。
