## §3 三个缺陷的根因与修法

### 3.1 #4 · `mask/` 只有 2 个文件（=最该先修的一条）

**磁盘实测**：`of 94 pages → mask=2, inpainted=80, result=80`；`inpainted 有 / mask 无` = **78 页**。

`mask/1 [Asura Scans]/1.png` mtime `15:45:31`（早先手工块），`mask/1 [Asura Scans]/62.png` mtime `22:15:42`（今天你手工建的块）。两条都属于"手工块 + 保存 → 该页变脏"。

**两个叠加原因**：

1. **历史**：`renderMaskPage()`（`result_renderer.dart:192`）与 `_regenerateResults()` 里的 mask 接线（`studio_page.dart:1366-1382`）**晚于**那 80 页产物的生成时间。
2. 🔴 **结构缺口（真正要修的）**：产物重生成只处理 **dirty pages**：
   ```
   _save()  →  dirtyPages = _history.dirtyPages  →  _regenerateResults(dirtyPages)
   ```
   于是**一个页只要不再被编辑，它缺的 `mask/`（或 `inpainted/`、`result/`）永远不会被补回来**。78 页正是这个状态。

**另有一条相关的空转**：`_runPipeline` 只在 `!stopped && failures == 0` 时才自动存（`studio_page.dart:641-645`）。本次 94 页全失败 → 不存 → 不生成产物。这条本身是合理的（失败先让人看状态栏），但它把"失败"和"没有产物"绑在了一起。

**修法（建议）**：

| 项 | 做法 |
|---|---|
| A. **全量产物重生成入口** | 工作室加一个「重新生成全部产物」动作，`_regenerateResults(dirtyPages: null)`（null 已表示"全部"，语义现成）。用途：补历史缺口 + 首次 adopt 的工程 |
| B. **产物对账表（你的 #3 第一半）** | 每次产物重生成后写一份 `imgtrans_<name>.artifacts.json`：逐页 `{page: {inpainted, mask, result, blocks, translated, skipped, reason}}`。`reason` 取 `no-blocks` / `no-translation` / `downscaled` / `ok` —— 这正是你说的"给目录核对数据时补充证据"，且可被 headless 断言 |
| C. **失败也要留痕** | 全失败时不自动存是合理的，但应把 `failures/失败原因` 写进对账表与 `logs.txt`（`Studio Pipeline` 行已有），避免"跑了但什么都没发生"看起来像成功 |

> 注意：`renderMaskPage`/`renderInpaintedPage` 对 **>12MP 或 >8000px** 的页**刻意不产出**（坐标契约，见 `result_renderer.dart:109-116`）。对账表的 `reason` 必须能把这一类与"缺块"分开，否则又会变成一种静默。

### 3.2 #9 · 画布字号过大 + 截断（"…"来自画布自己）

**两条链路各算各的**：

| | `result/` 产出（`page_renderer.dart`） | 工作室画布（`text_block_canvas.dart`） |
|---|---|---|
| 字号 | `_fitFontSize()`：上限 `min(42, lineHeight×0.9, fontformat.font_size)`，再 **shrink-to-fit 循环**缩小直到塞得下（`:615-639`） | `_paintText()`：`fontSize = max(6, block.fontSize × fit)` 直接画（`:511`） |
| 溢出 | 无 —— 已缩到塞得下 | `maxLines = floor(rect.height / (fontSize × lineHeight))` + `ellipsis: '…'`（`:554-555`） |

实测那条块：`_detected_font_size = 76`、`fontformat.font_size = 76`、`xyxy = [140,625,539,746]`（框高 121）。
→ `result/`：cap 被压到 **42**，再 shrink → 塞得下；
→ 画布：按 **76** 画，`maxLines = floor(121 / (76×1.15)) = 1` → **第 2 行起被换成 `…`**。截图里的"即使是…"即此。

**修法（建议）**：把画布的字号计算改为**与 `page_renderer` 同一套规则**（同一个 cap + 同一个 shrink-to-fit），去掉 `ellipsis`。
优点：预览与产出不再漂移（正是 `font.preview_matches_output` 的精神）。
风险：低 —— 该断言是**源码文本扫描**（`headless_p1_checks.dart:295-314`，只查 `resolveFamily(` 用法），不涉及运行时字号；但改完仍要重跑 `edit-check` 全绿。

### 3.3 顺带查出：per-line `eraseRects` 在工作室链路丢失（静默）

- 检测链路本来会给出**逐行**的紧密矩形：`balloonToOcrBlock()` 填 `eraseRects: [for (final l in balloon.lines) l.rect]`（`balloon_clustering.dart:507`），`ocrRegion()` 也带（`translation_pipeline.dart:147`）。
- 但 **`TextBlock.fromOcr()` 不写 `erase_rects`**，**`toTranslatedRegion()` 也不读**（`text_block.dart:689 / 875`）。
- 结果：`TranslatedRegion.eraseRects` 落到构造函数的兜底 `[rect]`（`translation_types.dart:169/209`）→ **抹字按整个块外框做**，而不是逐行。
- 影响：块框内的美术（气泡尖角、贴纸边）会被一起抹；也解释了 `renderMaskPage` 那套"字形级掩膜"设计意图没有真正发挥。
- 附带：工程 json 里 141 个块**全都没有 `erase_rects` 键**（实测 `with_erase_rects=0 / no_erase_key=141`）——这是长期的，非本轮引入。

**修法**：`fromOcr` 落 `erase_rects`（可选键，不破坏零字节 diff：新块才有），`toTranslatedRegion` 读它并传给 `TranslatedRegion`。

### 3.4 另两条事实确认

- **`_runPipeline` 只在全成功时自动存**（`studio_page.dart:641`）→ 失败/取消时不产产物。合理，但要留痕（§3.1-C）。
- **`skipExisting` 默认 `true`**（`studio_page.dart:336`）→ 重跑去重不会覆盖人工校对过的块（`overlapsExistingBlock` 只读）。这是对的，保留。

### 4.1 #3 · 分离「本地库」与「翻译库」+ 原图副本 + 对账表

**你的判断我完全同意，而且代码结构已经站在那里了**：

`ProjectWriter` 的注释（`project_writer.dart:135-141`）写着「Two roots, one implementation」：

```text
old project  root = ComicLibrary/downloads/<manga>/    workspace == directory   （FT 原地布局）
new project  root = ComicLibrary/projects/<manga>/     workspace != directory   （工作室布局）
```

也就是说**"两个 root"这件事 FT 自己就支持**（json 里 `directory` = 原图根，`workspace` = 产物根），我们缺的只是"把原图也复制进 projects/"这一步。

**建议方案（= 你说的"放弃省盘、换不损伤原图"）**：

| 项 | 做法 |
|---|---|
| 原图副本 | 建工程时把用到的原图**逐个复制**到 `projects/<name>/source/`（或复制整章目录），json 的 `directory` 指向副本 |
| 下载目录角色 | `downloads/` 只作**只读保底**；翻译链路不再直接写/擦它 |
| 为什么必须这样 | 抹字是**破坏性**的（`TextInpainter.erase` 就地改像素）。现在从 `downloads/` 取底图擦，一旦逻辑错就是**擦掉用户唯一一份原图**。副本化把这条风险从"数据丢失"降为"重跑一次" |
| 额外收益 | 本地库（`local.db`）与翻译库彻底解耦：删工程不动下载；本地库换目录不影响工程 |
| 体积代价 | 按你说的接受。可加一层"仅复制被翻译到的章"的粒度控制 |
| 对账表 | 见 §3.1-B，落 `imgtrans_<name>.artifacts.json` |

**待你拍板**：迁移范围（新工程 only / 含现有工程）—— 见 §5。

### 4.3 #6 · 检测 / 识别 / 翻译 三段拆分

**可行性核对**：

| 段 | 现成能力 | 缺什么 |
|---|---|---|
| 检测（画气泡框 → 建块） | worker 内有 `_detectBoxes`（`translation_worker.dart:757`），但**没有对外 API** | 需要给 worker 加一个「只检测、不识别」的入口（返回框 + 空文本的块） |
| 识别（框内文字 → 填块） | **已有**：`ocrRegion()`（`translation_pipeline.dart:112`）= 工作室现有【识别】按钮 | 无（只需按块批量调用） |
| 翻译（文本 → 译文） | **已有**：`TranslationDispatcher.translateBatch` | 无 |

**语义（按你的描述整理）**：

```text
三选（可多选）：
  [检测]  选中 → 对页码范围做气泡检测，为每页创建文字块（此时块内文本为空）
  [识别]  选中 → 对"已有文字块"逐块 OCR，填原文
  [翻译]  选中 → 对"已有原文的块"调翻译引擎，填译文

次序契约（先检测 → 再识别 → 后翻译）：
  - 只选[检测]            → 建空块（版面预检）
  - 选[检测]+[识别]        → 建块 + 填原文
  - 全选                   → 等价于今天的"自动管线"
  - 只选[识别]/[翻译]      → **要求工程已有块**；没有块则无输入
```

**你问的那点（是否依工程状态拒绝选择）——我的建议**：

> **不要静默接受，也不要硬拒；要"算出来并明确告知"。**

具体：弹窗里**实时统计**当前选择会做什么，例如
`检测 12 页 / 识别 34 个已有块 / 翻译 34 条（其中 0 条已译）`；
若组合无输入（如"只选识别但我一开始就没检测过、工程也没有块"），**禁用开始按钮 + 一行原因**，而不是跑一遍报 0。
这与项目硬规矩 3（"绝不让空结果看起来像成功"）同一条。

**与现有开关的关系**：`translate` 开关 → 被 `[翻译]` 取代；`skipExisting` 保留为独立开关（去重语义不同）。

### 4.5 #11 · 竖排气泡默认策略

采纳你的结论作为**默认**：**除日漫外，默认不做竖排**（`_prefersVertical` 的启发式只在 `style == null` 时生效，`page_renderer.dart:473`；新块都带 `fontStyle`，所以只要**不主动置 `vertical`** 就不会竖排）。

补充建议（低成本、高收益）：**拟声词/非标准文字**这一类——检测出 `ko`+`en` 双语、且文本很短（≤2 字符或非词典字符）时，**在块上打一个 `label: 'sfx'` 标记**并默认不译文、不改字，供人工筛选。这比"试图识别夸张画法"务实得多。
