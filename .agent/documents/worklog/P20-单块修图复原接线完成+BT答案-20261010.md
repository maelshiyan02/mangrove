## 1 · 单块修图的真实接线（P19 存根 → 完整实现）

### 1.1 像素流程（`_repairSelectedBlock`，studio_page.dart）

```
原图（全分辨率，拒绝降采样）
  ├─ buildMaskPage(原图副本, block.eraseRects)  → 本块字形掩膜（空则报错退出）
  ├─ TextInpainter.erase(原图副本, rects)       → "只擦这一块"的整页图
  ├─ mergeRepairedInpainted(...)                → 只在掩膜像素上并入现有 inpainted
  ├─ unionMasks(本块掩膜, 现有 mask)             → 保住其他块的抹字记录
  ├─ 写 mask/（GrayPng 纯 Dart）
  ├─ 写 inpainted/（renderTranslatedPage smart，空 regions）
  ├─ _rerenderResultPage → 写 result/（整页所有有译文的块重画，他块不丢）
  └─ ArtifactReconciliation.write + 刷新画布（保留块选择）
```

### 1.2 关键设计决定

1. **绝不在现有 inpainted 上再擦一遍**：对已抹底图重复 inpaint 会逐次变糊
   （`renderInpaintedPage` 文档的同一条理由）。新擦只在**原图副本**上做，
   再按字形掩膜把像素贴进现有底图。
2. **只在字形掩膜像素上替换，不按块矩形替换**：FT 块框经常交叠，矩形替换
   会把窗口内属于另一个块的已抹像素用原图盖回去。
3. **恰好覆盖**：`TextInpainter.erase` 的 `_fillNearest`/`_relax` 都以
   `mask[i]==0` 跳过 ⇒ 算法动过的像素集合 == 掩膜像素集合，逐像素替换一个
   不多一个不少。
4. **两阶段顺序契约沿用** `_regenerateResults`：mask+inpainted 落盘后才
   画 result（`_rerenderResultPage` 单独 await）。
5. result 渲染返回 null（本块是页内唯一译文且被判太小等）时**删旧 result**，
   不保留——保留会让阅读器拿旧成品图遮住刚做的修图。

### 1.3 单块复原（`_restoreOriginalSelectedBlock`）

```
原图 + inpainted + mask 三者必须齐全且同尺寸
  ├─ buildRestorationMask(原图, block.rect)     → 外扩 30% 窗口内的原字掩膜
  ├─ intersectMasks(外扩掩膜, 现有 mask)         → 只盖"真被抹过"的像素
  ├─ 全空 → "No erased pixels found for this block." 退出
  ├─ restoreErasedPage(...)                     → 底图复原
  ├─ subtractMasks → 剩余 mask；全 0 则删 mask 文件（不写全 0 图）
  ├─ 写 inpainted/（先）
  ├─ _editBlock: 清空本块 translation + 同步 rich_text（一个可撤销步骤）
  ├─ _rerenderResultPage（本块不再填字；无块可画则删 result）
  └─ ArtifactReconciliation.write + 刷新画布
```

- **为什么取交**：外扩窗口可能罩住交叠的另一个块；那个块没被抹过（不在
  现有 mask）时盖回是 no-op，但它若也抹过，直接盖回会**连带撤销别人的
  修图**。
- **为什么清空译文**：底图退回原字后若继续画译文 = 两层字叠一起。撤销
  只回滚文字、不回滚像素（像素的撤销 = 再按一次【修图】），注释里写明。
- **全 0 mask 不落盘**：FT 把已存在的 mask 当权威，全 0 图会把"什么都没
  抹"伪装成"抹过但没笔画"（renderMaskPage 的同一条理由）。

## 2 · 反向验证：本轮真的被打红过两次

按 M08 纪律，故障路径不是摆设 —— 本轮有两次**真实失败 → 修复**：

1. **`blockrepair.merge_first_repair_equals_erased_block` 首版故障路径是
   装饰品**：白原图与红哨兵的 **R 通道都是 255**，故障判据永远为真。改成
   比 G 通道（红=0 / 白=255）后判据才真有分辨力。教训：哨兵像素选通道要
   避开与底色同值。
2. **`wiring.result_still_renders_in_a_second_pass` 旧扫描器被新代码打破**：
   旧判据是"文件里第一个 inpainted 出现位置 < 第一个 result"，新增的
   `_rerenderResultPage` helper 文本位置在修图方法之前 ⇒ 绿路径被误判
   FAIL。**先确认扫描器对不对**（A02 老坑）：契约本身没被破坏，是扫描器
   粒度太粗。改写为：① `_regenerateResults` 方法体窗口内 inpainted 先于
   result；② 两处 `await _rerenderResultPage(...)` 各自与上一次调用之间
   必须夹着一次 inpainted 写入，且调用总数 == 2；③ 故障路径改喂合成反序
   片段。三处落点现在都在同一条判据下。
