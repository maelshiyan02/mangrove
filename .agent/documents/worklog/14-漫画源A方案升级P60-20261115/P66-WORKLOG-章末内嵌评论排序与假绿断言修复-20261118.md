## 1. 缺陷根因

### 1.1 需求与落点的落差

P65 需求原文：「无论是漫画总评论区还是章节内部的评论区……需要正常地让评论的顺序从旧到新显示」。P65 落地了三处里的两处：

| 评论区 | 文件 / 类 | P65 是否接线 |
|---|---|---|
| 作品评价区 | `comments_page.dart` → `_CommentsPageState` | ✅ |
| 独立章节评论页（侧栏 / 工具栏 / 右键入口） | `chapter_comments.dart` → `_ChapterCommentsPageState` | ✅ |
| **章末内嵌评论页**（gallery 模式翻到话末，`images.dart:402` 构造） | `chapter_comments.dart` → `_EmbeddedChapterCommentsPageState` | ❌ **遗漏** |

该页在设置 `showChapterComments=true` 且 `showChapterCommentsAtEnd=true`（均可在设置界面打开）时，对有 `chapterCommentsLoader` 的源（拷贝漫画）可达。修复前它仍是「取 page 1 → page+1 顺序追加 → 无排序条」，即默认最新在前，与用户的「章节内部评论区从旧到新」直接冲突。

### 1.2 断言为何没拦住（假绿机理）

`headless_p56_checks.dart` 的 `comments.both_pages_use_order_policy`：

```dart
bool commentPageWired(String src) => src.contains('CommentOrder') && ... ;
commentPageWired(detailSrc) && commentPageWired(chapterSrc)   // ← chapterSrc 是整份文件
```

`_ChapterCommentsPageState`（已接）与 `_EmbeddedChapterCommentsPageState`（没接）同在 `chapter_comments.dart`，整份文件 `contains` 只要有一处命中就为真 ⇒ 没接的那处被喂绿。这正是 A02 §7「集合被收窄先证明未收窄侧非空」与「量具比被测对象更可疑」的反例。

## 2. 修复内容

1. **`_EmbeddedChapterCommentsPageState`** 与独立页对齐：
   - 增 `CommentOrder _order = CommentOrder.oldestFirst`（带 `// P65-embedded` 唯一锚点，供注入）。
   - 抽 `_load(page)` 统一取数；`firstLoad()` 先读 page 1 拿 `maxPage`，`commentFirstPage()` 决定首屏页（旧→新取最后一页）再取一次。
   - `loadMore()` 走 `commentNextPage()`（旧→新回退页号），`maxPage` 未知且空页时按 order 收敛。
   - 两处 `orderComments()` 按 `_order` 排序；新增 `toggleCommentOrder()` + `buildOrderBar()` 并挂进 `build()`。
   - 列表尾部「是否还有下一页」改用 `commentNextPage(...) != null`，否则反向分页会提前停。
2. **`headless_p56_checks.dart`** 断言收紧：
   - 新增 `_topLevelClassBody(src, name)`：行首 `class Name` 起、下一个行首 `class ` 止，逐类取正文（剥注释后）。
   - `comments.both_pages_use_order_policy` 改为对 `_CommentsPageState` / `_ChapterCommentsPageState` / `_EmbeddedChapterCommentsPageState` **三个类体分别**跑 `commentPageWired`，任一没接即红；detail 里附三类体长度作为非空凭据。
   - `commentPageWired` 把 `buildOrderBar` 由「存在即可」收紧为 `allMatches >= 2`（定义 + build 调用），堵住「只定义不挂」的漏洞。

## 4. 本轮新坑（写给下一次）

1. **「同一文件多实现」的类，接线断言必须逐类取值**：整份文件 `contains` 是假绿高发区；同类页面（独立页/内嵌页/嵌入分栏）只要漏一个，`contains` 全糊过去。判据里把被测实体切成最小可辨认单元（这里是顶层类体）。
2. **`RegExp.firstMatch(s, start)` 在 Dart 不存在**（只收一个位置参数）——要给起始偏移就 `firstMatch(s.substring(start))`，再把 offset 加回去。否则 `extra_positional_arguments` 直接让 analyze rc=1、`BUILD_FAIL`。
3. **「方法存在」≠「方法被调用」**：`src.contains('buildOrderBar')` 连只定义不挂都能过；用出现次数 >= 2（定义 + 调用）才钉得住接线。同理适用于其它「定义了但没接进 build」的控件。
4. **改断言代码也要重建产物**：断言 body 编译进 `app.so`，只改 Dart 源码不重建 → 跑的还是旧断言。本轮两次改断言各重建一次，`app.so` mtime 是唯一新鲜度凭据。
