## 1. 取证链（先证据后方案）

1. 该话接口 `GET /api/v3/roasts?chapter_id=…&limit=20&offset=…` 返回 `total=40`。
2. 源脚本 `comic_source/copy_manga(5).js`：`maxPage: (total - (total % 20)) / 20 + 1` → `(40-0)/20+1 = 3`。
3. 第 3 页 `offset=40` 必然空列表（只有 40 条，索引 0–39）。
4. `commentFirstPage(order: oldestFirst)` 返回 `maxPage` 即 3 → 首屏拿空页。
5. `orderComments` 用 `toList(growable: false)`，第二页 `addAll` 抛定长异常；异常在 `setState` 内被吞，`_page` 不前进 → 无限重复请求同一页。

## 2. 修复

### 2.1 源脚本（根因之一，治「高估」）

`comic_source/copy_manga(5).js` 两处 20 条/页翻页口径：

```js
- maxPage: (total - (total % 20)) / 20 + 1
+ maxPage: Math.max(1, Math.ceil(total / 20))
```

同步到运行时目录 `data/comic_source/copy_manga(5).js`（`copy.runtime_copy_in_sync` 断言守着这条）。

### 2.2 策略层（`Mangrove/lib/foundation/comment_order_policy.dart`）

| 新增/改动 | 语义 |
|---|---|
| `orderComments` → `toList()` | 返回值**必须可增长**；注释写明 P65 定长列表导致的无限请求链条 |
| `kCommentPageFallbackLimit = 3` | 回退预算：够跨过「高估一页」，又不把首屏拖成几十个请求 |
| `commentFallbackPage({page, attempts})` | 空页时回退到上一页；到第 1 页或预算用尽返回 null |
| `commentPagingExhausted({page, order, rawCount})` | 旧→新：中途空页只说明高估，**退到第 1 页仍空**才判到头；新→旧：空页即到头 |
| `commentNextPage(..., exhausted)` | 为真直接返回 null，不再发请求 |

### 2.3 三处页面接线（全部同一套逻辑）

- `pages/comic_details_page/comments_page.dart`（作品整体评论区）
- `pages/reader/chapter_comments.dart`：`_ChapterCommentsPageState`（独立章节评论区）
- `pages/reader/chapter_comments.dart`：`_EmbeddedChapterCommentsPageState`（章末内嵌评论区）

每处都做三件事：

1. 首屏拿到 `maxPage` 后，若尾页空则 `while` 逐页回退（`commentFallbackPage`）；
2. `loadMore` 用 `commentNextPage(..., exhausted: _exhausted)`；
3. 追加改成整体替换 `_comments = [...?_comments, ...filtered]`，不再对排序产物 `addAll`。
