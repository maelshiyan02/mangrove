2. `data/local.db` 主文件里 id=`ngdgdhlhypj` 是**分组式** 69 UUID（仅 5 个已下载）；WAL 里被刷新/合并改成了 versioned 138 格（69 编号 + 69 UUID）、下载 74 条。

4. `chapter_download_status.dart`：`downloadedChapters.contains(chapterKey)` 精确字符串匹配，不做形态换算。
5. `local_comic_edit.dart:refreshLocalComicChapters` / `local.dart:reconcileDownloadedChapters`：两条路径都只按 `chapterDirectoryName` 字面反查，UUID ⇄ 编号目录必然失配。

## 2. 修复

### 2.1 统一话号入口 `chapterNumberKeyOf()`

`foundation/chapter_title_parser.dart` 新增：`parseChapterTitle` 与 `chapterNumberValueOf` 的并集，认 `第N话` / `Ch.N` / 纯数字 / `N [copymanga]`，UUID 仍判 null。同时新增 `normalizedChapterGroupKey()`（`默認/默认/default` → 无组）。

`ComicChapters._cellNumberKey()` 与 `_chapterMergeIdentity()` 全改走它 ⇒ P69 的跨形态合并不再把同一话算两格。

### 2.2 等价章节键反查 `chapterKeysForDirectoryName()`

`foundation/chapter_directory.dart` 新增纯函数：磁盘目录名 → **所有**等价 chapterKey。

- 字面同名（`1 [copymanga]`）→ 话号 + 归一翻译组 → 无组话号兜底；
- 翻译组不同绝不互认（`1 [Asura]` 不会认成 `1 [DivaScans]`）；
- 返回**全部**命中 key，而不是第一个：编号 key 与 UUID key 同时标记已下载，本地视图与网络视图才会一起变蓝。

### 2.3 两个消费端接线

- `LocalManager.reconcileDownloadedChapters()`：用共用映射取代本地三步反查；日志里的 unmapped 应归零，并自动把 UUID key 并回 `downloadedChapters`。
- `refreshLocalComicChapters()`：在原有目录名/话号闸门之后再问一次共用映射，命中即跳过，杜绝每点一次刷新多一格。

> 没有直接改 `local.db`：用户 GUI 当时开着，按硬规矩不擅杀进程。修复靠**应用打开详情页时的磁盘自愈**完成，无需用户手动删历史或重导。

## 4. 踩坑

1. `chapterNumberValueOf` 的 UUID 防护必须保留：松成 `^(\d+)` 会把 `0fbab379-…` 读成话号 0，模拟时亲测把 69 话错配成 47 个 UUID。Dart 侧 `chapterNumberKeyOf` 已先挡 UUID 再走归一。
2. 故障注入锚点不能只用裸 `return keys.toList();`：文件里还有一个 `if (disk == null) return keys.toList();`，`replace_nth(..., 2)` 找不到独立行；改成带 `diskGroup` 上下文的唯一锚点。
3. `headless.dart` 是 CRLF 文件，`git diff --check` 会把它当 trailing whitespace；用 `git -c core.whitespace=cr-at-eol diff --check` 复核为 0。
4. 注入工装第一次跑 `INJECT_MISS` 会把该组写进台账为 FAIL；单组重跑会按 case 合并回台账，最终三组均 PASS。
