## 0. 三个定调（先对齐，避免返工）

### 0.1 补救机制改为「缺失页记录表」
不使用"整章作废"，也不"一图失败整任务失败"。改为：

- 每个**漫画根目录**维护一张表 `missing_pages.json`（一张表看全部缺失，入口统一）：
  ```json
  {
    "source": "comix_to",
    "comicId": "9lmnj-error-the-echo",
    "updatedAt": "2026-10-05T15:40:00",
    "entries": [
      {
        "chapterId": "11429606-chapter-6",   // 章节目录名（VeneraX 的 cid）
        "chapterTitle": "Chapter 6",
        "index": 69,                          // 页序号（文件名即 {index}.{ext}）
        "url": "https://lov.joshuanotes.site/...",   // 补救时直接取这张
        "error": "timeout",                   // 失败原因
        "attempts": 3,                        // 已尝试次数
        "firstFailedAt": "...", "lastFailedAt": "..."
      }
    ]
  }
  ```
- 成功补上某页 → 从表里**移除该条**；表空 → 删除文件（"无缺失"不留下噪音）。
- 保留 FT 工程的 `failed_pages` 语义（page/url/error），因此未来可与 FT 工程的清单互通。
  > 备选（如你更想要）：A 表放漫画根目录（推荐，全局可见）／B 每章各放一份（与 BT 完全一致，但入口分散）／C 全局总表放 App 数据目录（跨漫画汇总最方便，但与目录不同步）。**默认走 A**，你在阶段 2 前说要改就改。

### 0.2 补救排在靠后阶段
按你的要求：补救下载（阶段 4）放在**记录表 + 不完整标识（阶段 2、3）之后**。
因为只要表在、标识在，即使补救功能还没做，**缺失信息已不再丢失**——可以先靠人工去源站补，后面再自动化。

### 0.3 术语定调（2026-10-05 用户更正）
- **汉化工作室 → 翻译工作室（Translation Studio）**：主要内容是把其他语言翻译成中文，但也可能存在中文转英文或其他语言的需求，命名与设计都不假设翻译方向。
- **group = 翻译组**（scanlation group）：章节上的 `[Asura Scans]` 等署名一律称"翻译组"。
- **BT 工程 → FT 工程**：BallonsTranslator 工程后续统一改称 **FT 工程（Fan Translation）**。本文档中涉及该工程代码参考处均写作"FT 工程"（代码目录 `Ballonstranslator_win_minium` 暂不变，仅称呼变更）。

### 0.4 每阶段可独立回退
每阶段改动都集中在少数文件，出问题可单独回退该文件：`download.dart` / `local.dart` / 两个页面文件 / 新增 `missing_pages.dart`。

### S1 · 下载进度可视化（最小改动、立刻可见）
**问题**：本地 → 下载中 标签只渲染静态卡片，看不到进度；进度只在"任务"页。
**做法**：`downloading_page.dart` 里已经写好了"进度条 + 速度 + ETA + 暂停/取消"的卡片组件。
在本地页"下载中"标签复用同一套渲染（监听 `DownloadTask` 的 ChangeNotifier），
并给卡片加暂停/取消按钮。可选：点卡片跳转任务页。

**改动文件**：`lib/pages/local_comics_page.dart`（主要）、可能微调 `downloading_page.dart`（抽取组件）
**验收清单**：
- [ ] 本地 → 下载中 的卡片显示百分比进度条
- [ ] 显示速度/剩余时间（或至少显示"12/119"这类计数）
- [ ] 暂停后卡片变灰、可恢复；取消后卡片消失
- [ ] 多任务并行时每个卡片各自独立滚动

### S2 · 缺失页记录表 + 跳过失败页（本次的核心）
**问题**：一张图失败 → 整任务失败、整章已下的文件也标失败；且失败位置完全不留痕。
**做法**：
1. 新增 `lib/foundation/missing_pages.dart`：表的读/写/增删条目/扫描（含文件锁与损坏兜底）。
2. `download.dart`：`_ImageDownloadWrapper` 失败不再置 `error` 终止任务，
   改为把 `{chapterId, index, url, error, attempts}` 记进任务内存表；
   章末统一 `missing_pages.json` 写盘。
3. 任务新增"部分完成"语义：`isError=false` 但 `missingCount>0`，
   下载页状态行显示 `"119 页，缺 3 页"`。
4. 与现有续传兼容：恢复下载时按文件是否存在跳过已下载页；表内条目在重试成功后销账。

**改动文件**：新增 `lib/foundation/missing_pages.dart`；改 `lib/network/download.dart`
**验收清单**：
- [ ] 故意断网/超时下载一章 → **任务不失败**，显示"部分完成 N 页缺失"
- [ ] 章节目录里出现已下载的页文件（保留可用部分）
- [ ] 漫画根目录 `missing_pages.json` 有对应条目（章/页号/URL/错误原因）
- [ ] 重启后表还在（持久化正确）
- [ ] 全部成功时**不生成**表文件

### S3 · 不完整标识 + 章节标签四态配色（让状态"看得见"）

#### S3-a 章节标签四态配色（2026-10-05 用户需求，详见可行性分析文档 §6）
详情页章节网格的每个章节标签按下载状态着色（配色优先级：**红 > 黄 > 蓝 > 选中态 > 白**）：

| 状态 | 颜色 | 数据源 | 就绪度 |
| --- | --- | --- | --- |
| 基础（未下载） | 白（surface） | 现状默认 | ✅ 已有 |
| 下载中 | 黄 | 需要新增**按章**的下载中集合（现 `isDownloading` 只有漫画级布尔）；从 DownloadQueue 活动任务的 chapterId 聚合 | 需新增 ~30 行 |
| 已下载 | 蓝 | `LocalComic.downloadedChapters`（章节 id 列表）已有；chips 的 key 恰好就是章节 id，映射零成本 | ✅ 数据现成 |
| 缺页/下载失败 | 红 | 依赖 S2 的 `missing_pages.json`；S2 之前可先用会话内失败任务的记录临时显示 | 依赖 S2 |

渲染点唯一：`chapters.dart:447` 的 `Material.color`（现在只有 `isSelected → primaryContainer : surfaceContainerLow` 两态），加一个 `_chipColor(state)` 即可。
**已确认的冲突处理**：选择模式（多选下载）的高亮与状态色并存时，状态色作底、选中态用描边（border）表达，避免互相覆盖；"已读"的灰字逻辑不变。
**翻译组 chips 行**（Asura Scans 等过滤 chips）不着色，维持现状。

### S4 · 补救下载（按表逐页·排在你要求的靠后位置）
**做法**：新增 `RepairDownloadTask`（DownloadTask 子类，复用队列/暂停/恢复/重试框架）：
- 三种触发：单条（在缺失列表里点某页）／整章（详情页"修复本章"）／整部（"修复全部缺失"）
- 逐个条目走与主下载完全相同的取图通道（90s×3，WebView Lane）
- 成功 → 写文件 + 从表删除该条；仍失败 → 更新 error/attempts 保留
- 结束汇报"补齐 N 页，仍缺 M 页"
- **只补表里登记的页**，不重下整章（你要的"针对失败页面单独补救"）

**改动文件**：新增 `lib/network/repair_download.dart`（或并入 download.dart）；接通详情页/本地页入口
**验收清单**：
- [ ] 只重下缺失的那几页，不重下整章（看日志/网络）
- [ ] 成功后对应条目从表消失、页面文件出现在正确位置且命名正确
- [ ] 补齐后角标/提示消失，表文件被清理
- [ ] 仍失败的条目保留并可再次补救（attempts 递增）

### S5 · 下载稳定性增强（降低缺失率，前置条件 S2）
- Lane 级节流：连续取图 N 张后歇 1.5s（借鉴 FT 工程的 5 张组间歇，参数在 WebView 通道上重标定）

- 可疑小文件（<100KB）加一次真解码校验（当前只有魔数校验）
**验收清单**：批量下载一章的缺失页数量明显下降；中断后不留坏文件。

### S6 · 翻译工作室配套（前置条件 S3）
> 术语（0.3 节）：翻译工作室不假设翻译方向——中译外与外译中都是一等公民。
- 章节**翻译组**署名（`[Group]`）写入记录表，选源时明确要哪一组
- 目录布局与 FT 工程的 Venera 布局对齐（`{comic}/{chapter}/{index}.{ext}`），双向可消费
- **翻译前完整性闸门**：创建翻译工程/进入翻译流程前强制校验（缺页会导致页序错位）
**验收清单**：FT 工程（原 BT）能直接打开 VeneraX 下载的目录；缺页漫画进入翻译前被拦下并提示先补救。
