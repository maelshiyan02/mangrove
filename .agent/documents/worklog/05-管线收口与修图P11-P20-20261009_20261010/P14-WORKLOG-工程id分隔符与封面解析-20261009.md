## 1 · 根因一：`comicIdForJsonFile` 对路径分隔符敏感

**文件**：`lib/foundation/bt_project/bt_project_manager.dart`

```dart
static String comicIdForJsonFile(String jsonPath) {
  var hash = 0x811c9dc5;
  for (final unit in jsonPath.toLowerCase().codeUnits) { ... }   // ← 吃原始字符
}
```

同一个 json 的路径有**两个来源**，分隔符不同：

| 来源 | 路径形态 | 算出的 id |
|---|---|---|
| `scan()`（`Directory.list()`） | `D:\...\projects\<名>\imgtrans_<名>.json` | `bt_e2a58772` |
| `_create()`（`ProjectBootstrap` 的 `jsonPath`） | `D:/.../projects/<名>/imgtrans_<名>.json` | `bt_25ae63a1` |

⇒ `_projects` 里登记的是 `bt_e2a58772`，创建向导却拿 `bt_25ae63a1` 去 `projectFor()` ⇒
返回 null ⇒ `listed=false` ⇒ 弹「不在工程根下」、跳转按钮不亮。

**这也解释了上一轮那个「跳进工作室空白、退出重进就好」**：跳转用的是向导算的
`/` 变体 id，`ensureProject` 查不到。上一轮给 `ensureProject` 加的「miss 时补扫」
**治不了**它 —— 补扫产出的仍是 `\` 变体。**同一个 bug 的两个面。**

**实证**：`local.db` 里 `bt_e2a58772`（`\`），而对话框显示的是 `/` 形态的路径。

## 2 · 根因二：封面解析只查 `directory`，漏了工程根

**文件**：`lib/foundation/image_provider/local_comic_image.dart`

工程 json 的 `directory` 指 `<工程根>/source/`（原图副本），而 `cover.<ext>` 落在
**工程根**（与 json 同级）。`LocalComicImageProvider.load` 用
`comic.coverFile` = `source/cover.jpg`（不存在）⇒ `file = null` ⇒ 回落「扫
`comic.baseDir`（= `source/`）里的第一张图」⇒ 卡片显示章节第一页（实测是
AsuraScans 版权页）。

⚠️ 注意断点位置：`BtProjectManager.coverKeyFor`（P13 已改，两处都查）**已经**能查到
工程根封面（实测 DB `cover` = `'cover.jpg'`）—— 断的是**卡片那条路径**
（`LocalComicImageProvider` 自己拼路径，绕开了 owner）。

## 3 · 修法

| 文件 | 改动 |
|---|---|
| `bt_project_manager.dart` | `comicIdForJsonFile` 哈希前 `replaceAll('\\','/').toLowerCase()` ⇒ 写侧与查侧对齐 |
| `bt_project_manager.dart` | 抽出纯函数 `resolveCoverFile({directory, jsonPath, key})`（查 `directory` → 查 json 父目录 → null），`coverPathFor` 复用它 |
| `local_comic_image.dart` | `load` 开头：`isBtComic(comic.id)` ⇒ 直接 `BtProjectManager().loadCover(id)`，**复用封面规则唯一 owner**，不再自己拼 `directory/cover` |

**为什么抽 `resolveCoverFile`**：`BtProject` 是私有构造，规则内联在 `coverPathFor` 里就无法
被 headless 单独喂料 ⇒ 抽成只吃三个字符串的纯函数才能打红。

**为什么在图片 provider 里对 `bt_` 卡特判**：`coverFile` 的其它消费者
（`translated_export` / `cbz` / `epub` / `mangrove_comics` / `comic_page` /
`add_to_collection`）都作用于**素材漫画**，不作用于 `bt_` 工程 ⇒ 只需修卡片这一条路径。

**自愈**：id 变了之后，下次 `scan()` 登记 `bt_25ae63a1`，旧行 `bt_e2a58772` 按 stale 逻辑回收。

新增两条断言（均 绿路径=true / 故障路径=变红）：

* `projectEntry.the_project_id_is_separator_insensitive` —— 行为判据：`/` 与 `\` 同 id；
  故障路径 = 去掉归一化那一步的 FNV 副本。
* `projectEntry.cover.in_the_project_folder_is_found` —— 行为判据：用**真临时目录**造出
  「只有工程根有封面 / 只有 `source/` 有封面 / 两处都无」三种情形，要求前两者命中、第三者
  null；故障路径 = 只查 `directory` 的那一版。
