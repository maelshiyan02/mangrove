## 一、问题

P0-1 补上了 `TextBlock → TranslatedRegion` 的**正向**桥（渲染方向）。但反向没有：

- OCR 管线产出 `OcrBlock`（`rect` / `text` / `language` / 两个颜色 / `lineHeight`）
- 工作室与 FT 需要的是**完整 23 键的 `TextBlock`**

没有这个适配器，S9 自动管线跑出来的结果**无处落地** —— 工作室拿不到可编辑的块，用户只能手工一个一个重建。这是 P0-1 说的"核心接缝"。

## 二、`TextBlock.fromOcr`

### 🔴 关键约束：必须在 `createDefault` 之上 mutate，不能自建 map

P9.3 落地 `TextBlock.createDefault` 时，文档里已经把这个约束写下了（"这是**唯一**定义新块形状的地方，两个调用方不得分歧"）。本项严格执行：

```dart
final result = TextBlock.createDefault(rect: rect);
// 只改 OCR 知道得更好的字段
```

**为什么不自建**：`Error the Echo` / `S9Fixture` 这类项目一旦出现"同一页里既有检测块、又有手工块"，两套键集不一致就会**立刻破坏零字节 diff 承诺**（MEMORY 里那条"改一个字段可能动到另一处顺序"的教训同源）。

### 字段映射表

| 来自 `OcrBlock` | 写入 |
|---|---|
| `rect` | `xyxy` / `lines` / `_bounding_rect` |
| `text` | `text`（**按 `\n` 切成 FT 的列表形式**） |
| `language` | `language` |
| `textColor` / `backgroundColor` | `fontformat.frgb` / `srgb`（ARGB → FT 的 `[r,g,b]`） |
| `lineHeight` | 🔴 **`_detected_font_size` 与 `fontformat.font_size` 两个都写** |
| `rect`高/宽比> 1.3 | `src_is_vertical` + `fontformat.vertical` |

### 三条刻意的决定

**① `lineHeight` 必须写两个键。** 渲染器（P0-1）读 `_detected_font_size` 作上限，而属性面板与 `font_size` 联动 —— 只写一个会导致"面板显示 27px、渲染按 24px 画"。实测 OCR 的 `lineHeight` 是**中位数行高**，比 FT 默认的 24 可靠得多。

**② `translation` 留空。** 空译文块**不会被 letter**（`toTranslatedRegion()` 返回 null）；管线随后才填。若把源文写进 `translation`，会在已擦除的日文上再叠一层未翻译的日文。

**③ `det_model` 保持空串**（`createDefault` 写的）。填检测器名字会让**下一轮 re-detect 把这个块当成自己的输出** —— P1-3 的聚块逻辑会因此重写用户已经校对过的块。

| `fromOcr.roundtrips_through_json` | 写入→读出→再写入，字节稳定 |

### 🔴 一次"测试写错"被断言抓到

第一次写`fromOcr.marks_vertical` 时，我用的框是 `IntRect(120, 240, 480, 520)` = **360×280（横向）**，却断言它应标竖排。断言 FAIL 暴露了**我自己的测试写错了**（代码是对的）。

修正：拆成两条 —— 用**真横框**断言"不标竖排"，另加一个 160×600 的**竖框**断言"标竖排"。两个方向都锁住，比原来一条更严。

> **这正是断言的价值**：它不只防代码回归，也**防我自己把测试写成想要的结论**。

## 四、🔴 边界：适配器本身不解决"落地"

本项交付的是**接缝**，不是闭环。`OcrBlock → TextBlock` 现在有了，但：

- 管线仍走老路`_region(block, text)` 直接产`TranslatedRegion`（不经过工程）
- P9.0 §三 P1-5 的要求**产物须写工程而非阅读器 OCR 缓存** —— 那是触发入口那一批的事

两者共用`fromOcr` 的前提是：管线把 `block.translation` 填好后调`TextBlock.fromOcr(...)` 再 `project.addBlock(...)`。本项已把这条路铺好，**接线在 P1-5**。
