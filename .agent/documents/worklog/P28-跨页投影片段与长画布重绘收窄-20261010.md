## 1 · 诉求②：跨页块"只能存在上页"——根因是**下页根本没画**

### 1.1 取证

| 环节 | 事实（代码位置） |
|---|---|
| 落盘真相 | 跨页块**只落在顶页**：`_onSpanMarquee` 取 `parts.first`（虚拟坐标里最上那段）为 `head`，`_createBlockOn(head.page, head.rect, decorate: writeSpan)` ⇒ 块存进**顶页**的 `blocks`，`xyxy` = 顶段子矩形；`_span.parts` 记全部段（`cross_page_block.dart` §不变式） |
| 传输 | [`StudioScrollCanvas`](d:\Mangrove_Windows\Mangrove\lib\components\studio_scroll_canvas.dart) 逐页调用 `blocksFor(page.key)` |
| 🔴 缺口 | `studio_page._blocksFor(pageKey)` **只返回"存这一页的块"**（`project.pages[pageKey].blocks`）⇒ 下页的列表里**没有这个块** ⇒ 下页**什么都不画** |

⇒ 用户看到的"被下页遮挡"**不是 z-order 问题，是下页压根没有可画的图元**。P27 的修复
（`shouldRepaint` 值比较）与此无关，所以复测"没效果"是必然的。

### 1.2 修复：`_blocksFor` 增加**投影片段**

- [`cross_page_block.dart`](../../../Mangrove/lib/foundation/translation_project/cross_page_block.dart) 不动（`_span.parts` 仍是唯一真相，per-page 子矩形仍是落盘形态，D8）。
- [`CanvasTextBlock`](d:\Mangrove_Windows\Mangrove\lib\components\text_block_canvas.dart) 新增可选字段
  **`ownerPageKey`**（非 null = 这是"真身在别页"的**投影片段**）；参与 `==`/`hashCode`。
- `studio_page._blocksFor(pageKey)` = **本页自己的块** ∪ **`_span.parts` 落在本页、真身在别页的片段**
  （片段 `rect` = 该 `part` 的页内矩形，其余字段（译文/字体/角度…）抄真身；`index` = 真身在该页的下标）。
- 真身页**不重复投影**（`part.page == ownerKey` 跳过）：它由自己的 `xyxy` 覆盖。

### 1.3 片段是"投影视图"⇒ 只能点选，不能拖

片段的 `rect` 是派生视图；拖动它既改不了 `_span.parts`（落盘真相），又会让拖拽增量被施加到
真身的 `xyxy` 上 ⇒ **上下两页随即错位**。所以：

| 动作 | 处理 |
|---|---|
| 点选 / 双击 | 走 `hitTestCanvasBlocks`（含片段）⇒ 选中**真身** |
| 拖动 / 缩放 | 走**新增**的 `hitTestMovableCanvasBlocks`（**跳过片段**） |
| 吸附参考 | `_captureSnapTargets` 排除片段（否则会吸附到一个本页并不存在的边界） |

🔴 选中"回指真身"的映射只在 [`_StripItem._reportTap`](d:\Mangrove_Windows\Mangrove\lib\components\studio_scroll_canvas.dart)
一处完成：列表下标 → `(block.ownerPageKey ?? 本页, block.index)`。这是**必须**的：片段画在下页，
若照旧回报"本页 + 列表下标"，会选中下页同下标的**另一个块**。

## 2 · 诉求①：卡顿 + 频闪——三条独立根因，逐条消除

### 2.1 卡顿：`ListView` 滚动时整视口重绘 ⇒ 每页 `_paintText` 跟着跑

`_StripItem` 之前没有 `RepaintBoundary`：滚动要把视口重绘一遍时，**每个可见页的
`_paintText`（每块数次 `TextPainter.layout`）都会重跑** —— 这正是"连续滚很卡"的直接来源。

修复：`_StripItem.build` 的返回值整体包 **`RepaintBoundary`**（页码浮标/分隔线一起包进去，
它们本就是页的一部分）。

### 2.2 频闪（一）：`_pageAspect` 被**每一次解码**无条件改写 ⇒ 未解码页估高反复跳

`_loadAround` 的解码回调里原本对**每一次**成功解码都执行
`_pageAspect = decoded.h / decoded.w`。而 `_pageHeight` 对**未解码页**用的正是这个估计值
⇒ 只要工程里有两页长宽比不同（扉页 / 跨页大图 / 广告页），每解码一页就会改掉**所有未解码页**
的高度 ⇒ `ListView` 重新布局 ⇒ 视觉上"频闪"。

修复：**只在仍是默认估计（`_defaultPageAspect`）时**赋值 —— 取第一页的比例当估计值已经足够。

### 2.3 频闪（二）/ 重建风暴：keep-alive 窗口太窄

`_loadAround` 在"页离开窗口"的那一帧 `setState` 重建整条 `ListView`（连带可见页走 layout）。
`_keepAlive = 7`（窗口 `中心 ±3`）⇒ 连续滚时几乎每滚一页就重建一次。
修复：**7 → 10**（窗口 `中心 ±4.5`），淘汰与重建频率降到约 1/3；内存按 2400px 长边估算仍在
单页 10~20MB × 10 的量级。

## 3 · 诉求④：块投影 memo + 与撤销栈联动

- `studio_page` 新增 **`_BlockProjectionCache`（`_revision` → 页 key → 块列表）** 与
  **跨页片段索引 `_spanFragmentCache`**。二者**整体随 `_revision` 失效**。
- `_revision` 是"模型变了"的既有唯一信号：编辑、`undo`/`redo`、批量运行都在 ++ 它
  ⇒ 「与撤销栈联动」天然成立（撤销后 `_revision++` ⇒ 下一帧重建投影）。
- 🔴 **顺手补了一个缺口**：批量管线**逐页落地**时的 `setState`（`_pipeline.done++/…`）
  **漏了 `_revision++`**。没有投影 memo 时它无害（每次都重投影），有了 memo 就会让"这一页刚
  检出的块"**等到整章跑完才出现**。已在此处补上 `_revision++`（`_revision` 的契约本就是
  "每次模型变更都 ++"）。
- 没有这条 memo 时，每个已构建页每帧都要重新投影，且跨页片段要**扫全工程**找 `_span`；
  有 memo 后，滚动期间整段零成本。

## 4 · 诉求③：非选中框改**黑框 + 白晕**

[`PageCanvasPainter.paint`](d:\Mangrove_Windows\Mangrove\lib\components\text_block_canvas.dart)：
原来非选中框是一条 `outline.withValues(alpha: 0.55)`、`strokeWidth 0.8` 的细线（浅色主题下几乎透明）。
现在**先描 3.0px 白线（白晕）再叠 1.2px 黑线**：白线在框两侧各露出约 1px ⇒ 黑框在深色墨块与
浅色气泡上都稳定可见。选中框仍是 2px `primary`（未改）。
