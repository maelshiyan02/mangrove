| 字段 | result | canvas | 判定 |
|---|---|---|---|

| `strokeWidth` | 绝对 px（不随字号） | `strokeWidth * fit`（随 zoom） | ✅ 设计如此 |

### 🔴 字距在**出图上形同虚设**

FT 的 `letter_spacing` 是**倍率**（1.15 = 自然字距 +15%），而 Flutter 的
`TextStyle.letterSpacing` 单位是**逻辑像素** ⇒ 正确换算必须乘字号。成品侧停在
`(v - 1.0)`，对默认值 1.15 就是 **0.15 个逻辑像素** —— 在 40px 的字上完全看不
出来。于是「把字距滑块拖到底，导出图毫无变化」是个真 bug，而画布上是正常的
（画布乘了 `size`）。这正是 A05 §1「两条渲染路径不共享代码」的老账，P32 已把
文字定位收敛成共用纯函数，本轮照做。

## ③ 系统字体探测

### 新文件 `foundation/system_fonts.dart`

- **纯字节解析**（零 Flutter 依赖）：sfnt 表目录 → `name` 表（nameID 16/17 优先、
  1/2 回落；平台优先级 Windows(3,1,0x409) → Unicode(0) → Mac(1,0,0)）→
  `OS/2.usWeightClass` → `cmap`（format 12 优先、4 回落）覆盖判定。
- **文种覆盖**：按 5 类（Latin / 假名 / 谚文 / CJK / 中日标点）等距采样求覆盖率，
  ≥0.9 才算"支持"。采样而非全量是为了扫几百个文件时保持可用（format 4 是线性扫段）。
- **`.ttc` 集合**取第一个成员（Windows 的 `msgothic.ttc` 是常见日文字体，整个
  跳过太可惜）。
- **只读文件头**（512 KB）：表目录 + name + cmap 通常都在前几百 KB，避免把
  10~20 MB 的中日韩字体整个读进来。
- **不抛异常**：系统字体目录里什么都可能躺着（`.fon`、零字节、快捷方式），
  一次抛异常会让整次扫描半途而废，而"字体列表少了一半"是不报错的。

### `bundled_fonts.dart`：二档 → 三档

```
打包字体 → 机器里装着的字体 → 打包字体（回退终点）
```

🔴 **只有能显示中文的系统字体才被放行**（`SystemFontIndex.hasCjk`）。理由就是
A05 §3 那条底线"中文一定出字"：机器上装着 Arial，而 FT 工程里完全可能写着
`font_family: "Arial"` —— 若"装了"就等于"能用"，译文会变成一片豆腐块且**不报错**。
加了 CJK 门槛后，Arial 落回打包字体（和今天一样），雅黑/宋体这类真的能出中文
的才被放行。

**系统字体压过历史别名**：别名表（雅黑→思源黑）的存在前提是"雅黑没被打进包里"，
探测上线后这个前提不成立。机器上真有雅黑却仍换成思源黑，等于静默替换用户意图
—— 本文件开头反对的正是这类事。回退终点（第 5 条）没动。
