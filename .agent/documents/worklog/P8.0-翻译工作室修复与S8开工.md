## 一、🔴 工程失效根因：原图被删 → 封面解析失败 → 工程被静默丢弃

### 1.1 现象

- 用户发现 `Error the Echo` 本地 FT 工程打不开，**VeneraX 主页的"翻译工作室"入口消失**（列表为空）。
- 用户推测：**"在给下载补翻译组信息时，把原本没有记录信息的原英文版删掉了，导致连带问题。"** —— 推测正确。

### 1.2 根因链（已逐环实锤）

```
用户删除 downloads/Error the Echo（原英文版素材）
        ↓
BtProjectManager.scan → coverKeyFor(project)
   （旧实现只在 project.directory 里找 cover.* 或页图）
        ↓
返回 null（原图根已空）
        ↓
bt_project_manager.dart:304
   if (coverKeyFor(project) == null) continue;   ← 🔴 静默 continue
        ↓
工程不注册 → bt_ 卡不入位 → 工作室列表空白
   + 打开时 "Local comic not found"
```

🔴 **深层教训**：工程与原图已分家（`projects/` ↔ `downloads/`），原图本质是"随时可弃的一次性素材"，但工程模型却把它当**存在前提**。用户删除无翻译组信息的原英文版，恰好踩中这个隐含耦合。

### 1.3 修复

| 改动 | 文件 | 说明 |
|---|---|---|
| `coverKeyFor` 加 artifact 兜底 | `lib/foundation/bt_project/bt_project_manager.dart` | 封面解析从"只认 original"改为 `original → inpainted → mask`，只要工程目录里还有去字图/遮罩就能定出封面 |
| 新增 `displayPath` 回退链 | `lib/foundation/bt_project/bt_project.dart` | `displayPath(pageKey)`（original→inpainted→mask）、`hasDisplayImage(pageKey)`；`getImages` / `pageKeysForChapter` 全部改用它 |
| 静默 `continue` → 显式告警 | `bt_project_manager.dart:312-319` | `Log.warning('Skipped …: no cover and no page image found (looked in <directory> and <workspace>/inpainted\|mask).')`；同类告警还给 legacy parser 兜底 |
| `project.dart` 语义对齐 | `lib/foundation/translation_project/project.dart` | 新增 `resultPath`；`pageKeysForChapter` 改用 `hasDisplayImage` 语义 |

## 二、工作室长画布连续浏览

**问题**：原工作室只能单页查看，无法像阅读器那样连续翻页（用户原话："无法实现长画布的浏览，大概是需要修改对应的矢量位置之类的？"）。

**方案**：新增 `lib/components/studio_scroll_canvas.dart`（≈11.6 KB）

- `StudioScrollCanvas`：`ListView` 纵向串联所有页，每页懒解码（滚到才解码），复用既有 `TextBlockCanvas` 绘制层与块叠加。
- `StudioScrollCanvasState`：对外公开，通过 `GlobalKey<StudioScrollCanvasState>` 驱动 —— `scrollToPage(index)` 按页键跳转；页轨点击与它联动。
- `studio_page.dart`：
  - 新增 `_stripMode = true`（默认条带模式）；`_stripKey = GlobalKey<StudioScrollCanvasState>()`，仅条带模式挂载。
  - 新增 `_resolvePageFile(pageKey)`：统一解析（inpainted 优先 → mask 兜底 → original），单页/条带/页轨/属性面板共用同一解析。
  - 顶部按钮在两种模式间切换（`Icons.crop_portrait` ⇄ `Icons.view_agenda_outlined`）。
  - 状态栏、`_loadBase` 预载按模式判断（条带模式下不再预载单页 base）。

## 四、`studio-scan` —— 防止"工程再次悄悄消失"

### 4.1 为什么需要

`BtProjectManager.scan` 此前对"解析不出图"的工程**静默 `continue`**，无任何日志。原图被删后工作室列表直接空掉，与"tab 坏了"无法区分。这类静默丢弃今后必须在自检里被抓住，而不是靠用户报告。

### 4.2 用法

```bash
venera.exe --headless studio-scan [--json out.json]
```

### 4.3 输出（`builds/studio_scan.json`）

```json
{
  "command": "studio-scan",
  "roots": ["D:\\Ballonstranslator_Windows\\ComicLibrary\\projects"],
  "registeredCount": 1,
  "projects": [{
    "id": "bt_5be94984",
    "title": "Error the Echo",
    "pages": 97, "blocks": 85,
    "pagesFromOriginal": 0, "pagesFromArtifact": 97,
    "artifactSample": "…/Error the Echo/inpainted/0/1.png"
  }]
}
```

字段含义：`pagesFromOriginal` / `pagesFromArtifact` 直接告诉你**该工程有多少页是靠去字图/遮罩兜底的**。若某工程本应出现却不在 `projects` 里，对照 `%APPDATA%/io.github.kyosee/venera/logs.txt` 里的 `Skipped <json>: no cover and no page image found …` 即可定位。

### 5.2 🔴 五项必须先处理

**1. `rich_text` 会静默覆盖 `translation` — 决定性阻断**

FT 的 TextBlock 存 23 键，其中 `rich_text` 是一份 Qt `qrichtext` 完整 HTML 文档。**S8 若只改 `translation` 而不同步 `rich_text`，FT 打开时仍渲染旧内容**，用户会认为"保存没生效"。而 `text_block.dart` 对 `rich_text` **零建模**（全 `lib/` 无任何引用），必须先定同步策略（写 `translation` 时是否重生成 `rich_text`）。

**2. 字体属性在渲染链路全部丢失 — 三方不一致**

`TranslatedRegion` 只有 `rect / eraseRect / eraseRects / text / backgroundColor / textColor / lineHeight`（`translation_types.dart:80-109`），**没有 fontFamily / fontWeight / alignment / stroke / rotation**。`page_renderer.dart:248-264` 的字体写死 `FontWeight.w500`、`height: 1.2`，全文件无 `fontFamily`。

后果：S8 在 json 里改了字族/对齐/描边 → **FT 打开正确，VeneraX 阅读器与成品 `result/` 是错的**。阅读器走同一渲染器（`bt_project_manager.dart:221-266`）。

附带：`vertical` 键可写（`text_block.dart:287`），但画布按"旋转 90°"近似（`text_block_canvas.dart:329-338` 注释自认是 S8 的活），渲染器却用**启发式** `_prefersVertical(region.text, rect)`（`page_renderer.dart:186`、`:283`）而非该键——改 `vertical` 三方行为都不一致。

**3. `angle`（旋转）零建模 + 22/32 字体键只读**

实测真实工程 `Error the Echo` 的键数分布正是 **block 23 键 / fontformat 32 键**。但：

- `angle` 此前在本仓**不存在任何建模**，尽管每块都有 → ⚠️ **本轮已补建模**（`text_block.dart:554-563`、`CanvasTextBlock.angle`），但**渲染器仍不应用**（painter 从 S8 的编辑工作起才应用）。
- FontFormat 32 键：可写 10 个（family/size/weight/alignment/vertical/line_spacing/frgb + setOpacity/setStrokeWidth/setStrokeColor 复合），**只读 22 个**（含最可能被用户想改的 `letter_spacing` / `italic` / `underline` / `line_spacing_type`）。

UI 若渲染完整字体面板，22 项得显示为禁用——这是要提前定的产品决策。

**4. `result/` 产物写入完全无原子性**

> ✅ **本轮已闭合**：`project_writer.dart` 的 `result/` 写入改为批量原子写（`writeBytesAtomically`，tmp 名带 pid）；`.tmp` 固定名冲突与 `keepBackup` 默认值一并解决（见 §三）。

**5. Undo 栈架构决策（非编码细节）**

全仓**不存在**任何 undo 栈——只有 5 处"撤销 toast"一次性模式（`local_favorites_page.dart:1513-1537`、`read_later_page.dart:111`）。

唯一的可复用件是深拷贝：`project.dart:337-340` + `_deepCopy`/`_deepCopyMap`（`:384-398`）；本轮 `save()` 已能产出 `previousRaw` 快照。

🔴 但 `TranslationProject` 是**整份 json 的深拷贝**，实测样本 `imgtrans_Manhwa.json` 有 831 页键——**每步全量快照在 831 页工程上不可接受**。必须先定"命令式逆操作 vs 差量 patch"。**这是 §三 第 2 项之外，S8 本体最重的架构决策。**
