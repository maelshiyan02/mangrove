## 1 · 判定：一半是刻意设计，一半是迁移期实现问题

### 1.1 「缩到放进框」= 刻意设计（正确，保留）

两条渲染路径都有 shrink-to-fit：把文字缩到能放进框为止。用户自己也认可
（「缩小有限制很正常」），FT 同样有。**不是**问题。

### 1.2 「用户设置不可达」= 迁移期过度保护（bug，已修）

**文件 A**：`lib/foundation/image_translation/page_renderer.dart`（成品 `result/`）
**文件 B**：`lib/components/text_block_canvas.dart`（画布所见）

两处**手工镜像**的 `_fitFontSize` 里都是同一段：

```dart
var cap = 42.0;
if (lineHeight > 0) cap = math.min(cap, math.max(10.0, lineHeight * 0.9));
if (maxFontSize != null && maxFontSize > 0) cap = math.min(cap, maxFontSize);
var upper = math.max(10.0, math.min(cap, maxHeight * 0.8));
```

**三个 `min` 连乘**。关键在于：检测块的 `font_size` **恰好等于** `_detected_font_size`
—— `text_block.dart:744-752` 把两者一起赋成同一个检测值（`font_size` 给滑块/渲染器，
`_detected_font_size` 给 `lineHeight`）。于是：

```
cap = min(42, detected*0.9, requested)     // 而 requested == detected
    = min(42, detected*0.9)               // ← requested 分支被完全吞掉
    = detected*0.9  (或 42 更小)
```

⇒ **用户把 24 拖到 120，`cap` 依然是 `detected*0.9`**，屏幕上纹丝不动。P0-1 声称
「把 `font_size` 交给渲染器」，实际效果被这两层 `min` 完全抵消。

**这不是 FT 的语义**。FT 原版（`Ballonstranslator_win_minium/ballontranslator`）：

| 位置 | 事实 |
|---|---|
| `utils/textblock.py:150-155` | `font_size` 直接读写 `self.fontformat.font_size` —— 它就是**用户设的值** |
| `utils/textblock.py:397-400` | `detected_font_size` 只在 `_detected_font_size > 0` 时**替代** font_size，是个**取初始值**的机制，不是上限 |
| `ui/mainwindow.py:1986-1987` | `elif blk._detected_font_size > 0 and not enable_detect: blk.font_size = blk._detected_font_size` —— 检测值只**写入** font_size 一次 |

⇒ **FT 从不拿检测值反压用户的显式设置。** `42` 与 `lineHeight*0.9` 的「压制」是
Mangrove 自加的保守兜底。`42` 无出处（git 历史仅 3 提交、首推 squash，无法追溯）、
无 headless 断言、无文档 ⇒ 属迁移期「先别炸」的兜底，不是深思熟虑的产品设计。

**结论**：`font_fit` 的 auto-fit 保留；`42` / `lineHeight*0.9` 对**用户请求**的压制是 bug。

## 2 · 修法

### 2.1 新增纯逻辑层（两路径共用，消除手工镜像）

`lib/foundation/image_translation/font_fit.dart`：

```dart
double fitFontSizeCap({
  required double? requested,
  required double measured,
  double fallback = 42.0,
  double tolerance = 0.6,
}) {
  if (requested != null && requested > 0) {
    final userAsked = measured <= 0 || (requested - measured).abs() > tolerance;
    if (userAsked) return requested;          // ← 用户改过：它就是上限
  }
  if (measured > 0) return math.max(10.0, measured * 0.9);  // ← 源字号补偿
  return fallback;                                          // ← 兜底
}
```

- 仍是**上限**（不是替换值）：调用方的收缩循环可以**低于**它，20px 的框里请求 120px
  照样不溢出气泡。
- `tolerance=0.6`：吃掉成品路径 `region.lineHeight` 的 `.round()` 误差（≤0.5），又小于
  滑块步进（1）⇒ 拖动一格即算「用户改过」。
- 判据「`requested` ≠ `measured` ⇒ 用户改过」之所以成立：Mangrove 写入时两者同源，
  而用户拖动滑块**只**改 `font_size`。

### 2.2 两处渲染路径改为共用它

| 文件 | 改动 |
|---|---|
| `page_renderer.dart` | `_fitFontSize` 里三个 `min` → `fitFontSizeCap(...)`；加 import |
| `text_block_canvas.dart` | 同上；加 import；注释改为「共享代码，不是手工镜像」 |

### 2.3 确认缩放不破坏判据

`result_renderer.dart` 对 `lineHeight`（行 55-56）与 `fontStyle.fontSize`（行 288
`_scaledFontStyle`）用**同一个 `scale`** 缩放 ⇒ 降采样时两者仍同尺度，
`|requested - measured|` 的判据不失真。

### 2.4 「未动过的块行为不变」

`requested == measured`（新建块 24/24、检测块 detected/detected）⇒ 依旧 `*0.9`，
渲染与改动前**逐像素一致**。符合 A05 §2「没传时行为不变」的纪律。

新增 2 条断言（`headless_p9_checks.dart`，均 绿路径=true / 故障路径=变红）：

- `font.the_user_size_wins_over_the_measured_lettering`
  行为：`fitFontSizeCap(120, 49) == 120`、`(10, 49) == 10`。
  故障路径 = 旧的三连 `min` 副本 `_capByEverything`：120 被压回 44.1 ⇒ 变红。
- `font.untouched_block_keeps_the_measured_cap`
  行为：`(49, 49) ≈ 44.1`、`(null, 49) ≈ 44.1`、`(null, 0) == 42`。
  故障路径 = 去掉 0.9 补偿的副本 `_noSourceScaleCompensation`：返回 49 ⇒ 变红。
