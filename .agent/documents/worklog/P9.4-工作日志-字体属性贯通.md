## 一、问题

用户在工作室里设置字体族、字号、字重、斜体、下划线、描边、阴影、渐变、对齐、字距、旋转 —— **UI 全部确认成功**，`FontFormat` 的 32 个键也都在 JSON 里 —— 但导出的成品页**一个都不生效**。

断链有两处，**都是静默的**（不报错、不警告，只是样式被丢弃）：

| # | 位置 | 丢了什么 |
|---|---|---|
| 1 | `TextBlock.toTranslatedRegion()` | 只填 rect/text/bg/fg/lineHeight **5 个字段**，`FontFormat` 整包丢弃 |
| 2 | `result_renderer.renderProjectResultPage()` | 为缩放 boxes **重建** `TranslatedRegion`，只抄 5 个字段 |
| 3 | `page_renderer._fillStyle/_strokeStyle` | 字重写死 `w500`、行高写死 `1.2`、字体族根本没传 |

第2 处最关键：工作室保存后走的正是 `result_renderer`，即使修好第 1 处，**导出仍是默认字体**。

## 二、方案：新增 `RegionFontStyle`（可选载荷）

### 为什么不是直接传 `FontFormat`

`FontFormat` 住在 `translation_project/`，那里import 了 `ProjectPage`、撤销命令等**编辑模型**。直接递给渲染器会把**渲染路径耦合到编辑模型**，而 `translation_types.dart` 存在的全部意义就是**没有这个依赖**（它必须能被 headless 工具 import）。

于是新增 `RegionFontStyle`（`translation_types.dart` 内，纯标量、isolate 安全）：

| 设计点 | 理由 |
|---|---|
| **可选字段** `TranslatedRegion.fontStyle` | 6 处现有构造点（OCR 管线、阅读器 legacy 解析器、结果缓存）**一行不改** |
| **每个字段的默认值＝渲染器原有的硬编码值** | 无字体的 region 渲染结果与改动前**逐像素一致** |
| 不在 `translation_types` 里定义 `ui.TextStyle` | 该文件零 Flutter 依赖；翻译成 `TextStyle` 是渲染器的职责 |

### 映射了哪些键

**已贯通**：字体族・字号・字重・斜体・下划线・行距・字距・对齐・整体透明度・描边色/宽・阴影色/半径/强度/偏移・渐变开关/起止色/角度・块旋转 `angle`・字形斜切 `glyph_slantAngle`・`vertical`

**故意丢弃**：FT 的 `ligature_*` / `oldstyle_nums` / `text_transform` —— Flutter `TextStyle` 无法表达，**宁可丢弃也不伪造**。

## 三、渲染端的四条决策

### 3.1 🔴 `font_size` 是**上限**，不是替换值

`_fitFontSize` 原本就有"shrink-to-fit"搜索。FT 的 `font_size` 作为 `maxFontSize` **参与取 min**，而不是直接采用：

```dart
if (maxFontSize != null && maxFontSize > 0) cap = math.min(cap, maxFontSize);
```

理由：用户在 20px 高的框里要 40px 字号，**必须**得到可读的 20px 文字；强行采用 40px 会直接溢出气泡。

### 3.2 🔴 `letter_spacing` 是**倍率**，必须转成 `(v - 1) em`

FT 的 `letter_spacing: 1.15` 意思是"在字体自然间距上放大 15%"。直接把 `1.15` 当像素值传给 Flutter，**每个 CJK 字都会明显挤在一起** —— 这是本项最容易犯且最显眼的一个错。

### 3.3 🔴 `stroke_width` 是**绝对值**，不再随字号缩放

legacy 路径用 `_strokeWidth(fontSize) = max(1.5, fontSize * 0.14)`（描边随字放大）。FT 的 `stroke_width` 是绝对 px，按字面实现才能让"6px 描边在 20px 和 80px 字号下都像 6px"。

### 3.4 🔴 FT 的 `vertical` **压过**启发式

`_prefersVertical` 原本是纯启发式（"框高> 宽 1.6 倍且 CJK 占比 ≥70% 就竖排"）。现在：
- `format.vertical == true` → 竖排
- **有 `fontformat` 但 `vertical == false` → 尊重用户，绝不二次猜测**

修复了一个真实的错误行为：横向译文若恰好又高又全是 CJK，会被**静默转成竖排** —— 用户要横排却拿到竖列。

### 3.5 附带：RTL 与旋转/斜切

- **RTL**：按 Unicode 区段检测（希伯来/阿拉伯/叙利亚语/塔安纳/NKo/萨马里），并在 `rune < 0x0590` 时跳过 —— 否则一个杂散字符就能把整句英文判成 RTL。**对拉丁文静默、对阿拉伯文是灾难**，而翻译管线迟早会产出 RTL。
- **旋转/斜切**：`canvas.translate → rotate → transform(斜切 4x4) → translate回中心`，**在 layout 之前**做，让 shrink-to-fit 测量的是**旋转后的footprint**。

## 四、`result_renderer` 的缩放（第二处断点）

`_scaledFontStyle(style, scale)`：**像素类**字段（字号/描边宽/阴影半径/阴影偏移）乘以 `scale`；**无量纲**字段（字重/对齐/透明度/角度/字距倍率）原样透传。

不缩放的后果很具体：boxes 被缩到 0.4 倍，字号没缩 → 文字相对框**大 2.5 倍**，直接溢出。

## 六、🔴 这次最该记住的：静默失败必须用断言锁

本项的特征是**全程无报错**：改对了没提示，改错了也没提示。所以：

> **任何"把数据从 A 传到 B"的改动，若A→B 曾经是断的，就必须有一条断言直接检查 B 收到了值。**
> 靠"UI 上看起来对"验收这类改动是不成立的 —— 工作室用的正是 `PageCanvasPainter`（读模型），成品用的是 `page_renderer`（读 `RegionFontStyle`），**两条渲染路径本就不共享代码**。

`font.absent_format_stays_null` 同样是关键的一半：新增可选字段时，**"没传时行为不变"也是必须被锁住的契约**，否则一次"顺手给个默认值"就会改掉全部历史产物的外观。

## 七、已知限制 / 遗留

- 🔴 **字体资产仍未进工程**（P1-4）：`font_family` 现在会传到渲染器，但 `pubspec.yaml` 的 `fonts:` 仍被注释、`assets/fonts/` 不存在 → 设了字族会**回退到系统字体**。**本项与 P1-4 必须一起验收，否则"改字体族没反应"会被误判为 P0-1 未完成。** P9.0 已就此登记过"拆开会假绿"。
- **渐变填充**：`gradientEnabled` 已贯通到 `RegionFontStyle`（`hasDecoration` 会为true），但 `page_renderer` 目前只画纯色填充，渐变**未真正绘制**。选择"先贯通数据、后实现绘制"是为了让 P0-1 的边界清晰；绘制属S9 渲染器工作。
- **竖排**：`vertical` 已改由 FT 标志决定，但仍是"旋转绘制"的可读性辅助，不是 FT 的逐字竖排 + `line_spacing_type` 语义。
- **旋转块的可交互性**：见 P9.3 §9.8 —— 旋转后控制点仍按未旋转矩形摆放。
