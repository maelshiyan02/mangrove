## 一、comix.to 站点特点

### 1.1 内容特征

| 维度 | 说明 |
|------|------|
| 主要语言 | 英文（Fan Translation 场景）、韩文、日文 |
| 翻译组生态 | **同章节号常有 5-10+ 个翻译组版本**（如 Luna Toons、MistScene、Vortex Scans 等） |
| 章节标题格式 | `Ch.5 - Luna Toons 2024-09-28`（章节号 + 翻译组 + 日期） |
| 封面 | 每页详情页内嵌 cover 字段，直接 HTTP GET 可下载 |

### 1.2 技术难点（已解决，待移植）

BT v1.5.16-1.5.17 期间我们开发了完整的 comix.to 抓取管线，关键技术：

| 难点 | BT 侧解法 | Flutter 侧对应方案 |
|------|----------|-------------------|
| API 混淆 token 签名 | QWebEngineView 渲染，让站点 JS 完成签名，从 DOM/JSON 钩子截获 | **复用同一思路**：Flutter 的 `webview_windows` 或 `InAppWebView` |
| 响应加密 | 同上，浏览器原生 JSON.parse 解密 | 同上 |
| CDN 防盗链 | `Referer: https://comix.to/` 请求头 | Dio 的 `headers` 参数 |
| 魔数推断格式 | PIL 真解码 + 文件头字节判断 | Flutter `image` 库或自实现 `detectFileType` |
| 软封禁检测 | 多通道切换（App 接口→网页端通道） | 同一套逻辑移植 |
| 章节列表采集 | 逐页翻 DOM（分页器） | 同一套逻辑移植 |
| 翻译组提取 | `result.group.name` 字段 | VeneraX `ComicChapterVersion.scanlationGroup` |

### 1.3 comix_client.py 三级架构

```
层级 1: 元数据（普通 HTTP）
  parse_initial_data(html) → 从 <script id="initial-data"> 提取 JSON
  parse_comic_from_initial_data(data) → ComicInfo(title, url)

层级 2: 章节列表 + 每页图片 URL（需要浏览器）
  build_chapters_from_dom(rows) → [ChapterInfo(title, url, group, number)]
  parse_group_from_capture(json) → 翻译组名
  fetch_chapter_image_urls(chapter) → [img_url1, img_url2, ...]

层级 3: 图片字节（普通 HTTP + Referer 头）
  download_image(url) → bytes（含重试、cache-bust、PIL 校验）
```

## 二、VeneraX ComicSource 注册机制

### 2.1 当前架构

VeneraX 用 JS 引擎注册漫画源，**不是 JSON 配置文件**：

```dart
// parser.dart:830
ComicSource.sources.$_key.comic.loadInfo(${jsonEncode(id)})
```

现有 source（comick、copy_manga 等）用 JS 实现，注册时指定 `sourceKey`、`loadComicInfo`、`loadComicChapters`、`loadComicPages`、`getCover` 等方法。

### 2.2 comix.to 适配方案

**方案 A：Flutter + WebView（推荐）**

| 层级 | Flutter 实现 | 依赖 |
|------|-------------|------|
| 元数据 | Dio + HTML 解析 | `html` 包（已在 pubspec） |
| 章节/图片 URL | `webview_windows`（Flutter WebView）或 `InAppWebView` | 需确认 pubspec 有 |
| 图片下载 | Dio（已在 pubspec） | 已有 |

**方案 B：Dart 版 ComixClient + 原生桥接**

把 Python comix_client.py 重写成纯 Dart（解析逻辑大部分可直接 translate），只在需要 JS token 签名时调用原生 WebView 桥接。

### 2.3 数据结构映射

comix.to ChapterInfo → VeneraX ComicChapters.versioned：

| comix.to 字段 | VeneraX 字段 | 示例 |
|---------------|-------------|------|
| `ChapterInfo.group` | `ComicChapterVersion.scanlationGroup` | "Luna Toons" |
| `ChapterInfo.number` | versioned 键 | "5" |
| `ChapterInfo.url` | `ComicChapterVersion.chapterKey` | comix.to 内部章节 id |
| `ChapterInfo.title` | `ComicChapterVersion.title` | "Ch.5 - Luna Toons" |

## 七、翻译组 UI 的通用设计（2026-09-29 追加）

### 7.1 问题：网站特定 vs 通用

**结论：通用，由数据源自动触发。**

| 方案 | 可行性 | 理由 |
|------|--------|------|
| 只给 comix.to 做 | ❌ | 代码耦合度高，其他有同章节多翻译组的网站（如 Mangadex、MangaPlus 部分作者页）无法受益 |
| 所有网站都显示 Tab | ❌ | 95% 的网站没有多翻译组，Tab 空着浪费 UI 空间 |
| **数据源自动触发** | ✅ | `ComicChapters.isVersioned` 已经是现成的检测机制 |

**检测机制已就位**：

```dart
// models.dart
bool get isVersioned => _versionedChapters != null;

// comic_state_repository.dart::_findDomainChapters
final hasMultipleGroups = versions.values.any(
  (v) => v.length > 1 && v.any((x) => x.scanlationGroup != null),
);
if (hasMultipleGroups) {
  return ComicChapters.versioned(versions);  // 触发 UI 显示翻译组 Tab
}
```

任何漫画源只要返回的章节列表中**同一章节号出现 ≥2 次且至少一个带翻译组名**，就自动进入 versioned 模式，UI 自动显示翻译组 Tab。不需要为每个网站写特殊判断。

### 7.2 comix.to 原始数据形态 vs VeneraX 期望

comix.to 实际页面（见截图）：
```
第49话  Nyx扫描     3天前
第49话  Vali扫描     1天前     ← 所有翻译组的章节堆在一起，
第49话  EZManga      3天前           同一章号重复 N 次，
第49话  Nyx扫描     10天前          没有"翻译组分栏"的概念
第48话  MagusManga   2周前
第48话  Nyx扫描     5天前
第48话  Vali扫描     3天前
```

VeneraX 期望形态：
```
┌─────────────────────────────────────────┐
│ [Vali扫描] [Nyx扫描] [EZManga] [MagusManga] │ ← 翻译组 Tab（按最近更新排序）
├─────────────────────────────────────────┤
│ 第49话  第48话  第47话  第46话 ...        │ ← 选中组的章节（最新在前）
└─────────────────────────────────────────┘
```

**comix_client.py 的 `build_chapters_from_dom` 已经按章节号聚合**：
```python
# comix_client.py:98
def build_chapters_from_dom(rows: List[Dict], ...) -> List[ChapterInfo]:
    # 同一章节号可能有多个翻译组版本，全部保留
    # 排序规则：章节号升序 → 组名 → 标题
```

**但排序方向错了！** 当前是章节号**升序**（1, 2, 3...），comix.to 实际数据也是升序排（第1话在最上）。用户期望**最新话在前**（第49话在最上）。

### 7.3 "最新优先"排序机制

#### 当前现状

| 层级 | 排序机制 | 行为 | 问题 |
|------|---------|------|------|
| **数据源** | comix.to JS engine 返回顺序 | 升序（第1话在最上） | ❌ 不是最新优先 |
| **comix_client.py** | `sorted(rows, key=lambda r: float(number))` | 升序 | ❌ 同上 |
| **ComicChapters.versioned** | Map 插入序 | 跟随数据源 | ❌ 同上 |
| **VeneraX UI** | `reverse` 手动切换 +/−箭头 | 用户手动点 | ❌ 默认不是最新优先 |

#### 修复方案

**需要改的**：

| # | 改动 | 位置 | 层级 |
|---|------|------|------|
| 1 | `ComicChapterVersion` 加 `uploadedAt` 字段 | models.dart | 数据模型 |
| 2 | `ComicChapters.versioned` 加**按章节号降序** + **同章节内按 uploadedAt 降序**排序 | models.dart | 数据模型 |
| 3 | comix.to source JS 从章节 DOM 提取"X天前"文本 → 转 timestamp | comix.to JS source | 漫画源配置 |
| 4 | `_findDomainChapters` 传递 uploadedAt 给 `ComicChapterVersion` | comic_state_repository.dart | 解析层 |
| 5 | UI 默认 `reverse=true`（最新在前） | chapters.dart | UI 层 |

#### uploadedAt 字段设计

```dart
class ComicChapterVersion {
  final String? scanlationGroup;
  final String? language;
  final String title;
  final String chapterKey;
  final DateTime? uploadedAt;  // ← 新增
  
  const ComicChapterVersion({
    this.scanlationGroup,
    this.language,
    required this.title,
    required this.chapterKey,
    this.uploadedAt,
  });
}
```

**为什么 `uploadedAt` 要 nullable**：
- 不是所有漫画源都提供上传时间
- 没有 uploadedAt 时回退到源顺序（现有行为）

#### 同章节内版本排序（选默认翻译组的基础）

```dart
// ComicChapters.versioned 构造时排序
final sortedVersions = versions.map((key, list) {
  list.sort((a, b) {
    // 有 uploadedAt 按时间降序
    if (a.uploadedAt != null && b.uploadedAt != null) {
      return b.uploadedAt!.compareTo(a.uploadedAt!);
    }
    // 否则按组名
    return (a.scanlationGroup ?? '').compareTo(b.scanlationGroup ?? '');
  });
  return MapEntry(key, list);
});
```

#### 翻译组 Tab 排序

```dart
Set<String> get scanlationGroups => ...;  // 当前无序

// 改进：按该组最新章节的 uploadedAt 降序
List<String> get scanlationGroupsSorted {
  if (_versionedChapters == null) return [];
  final groupLatest = <String, DateTime>{};
  for (final versions in _versionedChapters.values) {
    for (final v in versions) {
      if (v.scanlationGroup != null && v.uploadedAt != null) {
        final current = groupLatest[v.scanlationGroup!];
        if (current == null || v.uploadedAt!.isAfter(current)) {
          groupLatest[v.scanlationGroup!] = v.uploadedAt!;
        }
      }
    }
  }
  final groups = scanlationGroups.toList();
  groups.sort((a, b) {
    final ta = groupLatest[a];
    final tb = groupLatest[b];
    if (ta != null && tb != null) return tb.compareTo(ta);
    if (ta != null) return -1;
    if (tb != null) return 1;
    return a.compareTo(b);
  });
  return groups;
}
```

### 7.4 默认翻译组选择

当前 `preferredVersionKey(chapterNumber, preferredGroup)` 需要显式传组名。用户期望：**打开漫画自动选中最近更新的翻译组**。

| 方案 | 说明 | 实现 |
|------|------|------|
| **A: 全局"默认组"持久化** | 用户选过一次后记住，下次直接用 | `Settings.defaultScanlationGroup[comicId]` |
| **B: 自动选最新** | 每次打开都选 uploadedAt 最新的组 | 不需要持久化，但用户偏好无法保留 |
| **C: A + B 组合** | 有持久化偏好用偏好，没有就自动选最新 | ✅ 推荐 |

```dart
String? preferredVersionKey(String chapterNumber, String? preferredGroup) {
  final versions = versionsFor(chapterNumber);
  if (versions == null || versions.isEmpty) return null;
  
  // 1. 用户显式偏好
  if (preferredGroup != null) {
    for (final v in versions) {
      if (v.scanlationGroup == preferredGroup) return v.chapterKey;
    }
  }
  // 2. 自动选最新（uploadedAt 降序排好的，第一个就是最新）
  return versions.first.chapterKey;
}
```

| `ComicChapters.versioned` 排序 | **基础代码** models.dart | 通用排序逻辑 |
| `scanlationGroupsSorted` getter | **基础代码** models.dart | 通用 Tab 排序 |

### 12.1 现象

```diff
+ var startTag = 'id="initial-data">';
```

```
startIdx = html.indexOf('id="initial-data">');   // 1927

```

### 15.4 章节采集验证：DesktopWebview 弹出但章节空白

第一次测试（旧代码）：
- ✅ DesktopWebview 弹出 + 正常加载 comix.to/title/9l3kj
- ✅ onTitleChange 回调触发
- ❌ 章节列表空白

根因：**evaluateJavascript 返回值双重 JSON 序列化 + onTitleChange 触发太晚**。

WebView2 的 ExecuteScriptAsync 会对 JS 返回值再做一次 JSON.stringify：
```
JS:  return JSON.stringify({ready: true, rows: [...]})
     → WebView2 再 stringify:  '"{\\"ready\\":true,...}"'
     → Dart 拿到的是 String，里面包着 JSON-encoded string
```

修复：`_parseEvalResult` 改成**循环 jsonDecode**，每次判断开头是否是 `{` 还是 `"`：
```dart
while (depth < 5) {
  final trimmed = s.trim();
  if (trimmed.startsWith('{')) return jsonDecode(trimmed) as Map;
  if (trimmed.startsWith('"')) {
    s = jsonDecode(trimmed) as String;  // 再解一层
    depth++;
    continue;
  }
}
```

另外把触发点从 `onTitleChange` 改成 `onStarted` —— `onStarted` 在 Webview 进程启动后 200ms 就触发，此时 SPA 还没加载，但**我们自己会在 _evalWithRetry 里轮询等待**。而 `onTitleChange` 只有当 SPA 完成 navigation 时才触发，之前的代码等它触发后才开始轮询，已经晚了。

### 15.5 翻页机制：btn.click() 对 SPA 无效

翻页第一轮（旧代码，用 `btn.click()`）的日志：
```
Page 2 click result: {ok: true}     ← click() 返回 true！
Page 2: 20 rows, 20 new, cumulative=40
Page 3 click result: {ok: true}
Page 3: 20 rows, 20 new, cumulative=60
...
Page 10: cumulative=200
Page 11 click failed — no more pages?
Built versioned: 26 chapter numbers, total rows=200
```

看起来翻到了 10 页？不对！实际 comix.to 有 **315 章 / 16 页**。而 `click()` 返回 `{ok:true}` 是因为 JS 里 `btn.click()` 没抛异常，不代表 SPA 真响应了。

**根因**：`btn.click()` 在 headless/WebView2 环境下不触发 React 的 synthetic event 系统。SPA 框架（React/Vue）监听的是真正的 DOM MouseEvent，不是原生 `.click()`。

修复：改用 `dispatchEvent` + 翻页后验证 DOM 是否真的变了：
```javascript
btn.dispatchEvent(new MouseEvent('click', {
  bubbles: true, cancelable: true, view: window
}));
```

翻页后**验证**：检查 `firstHref` 和 `activeBtn` 是否变了：
```dart
final verify = await _parseEvalResult(await evaluateJavascript(_pageVerifyJs));
final newFirstHref = verify['firstHref'];  // 翻页后应该变化
final activeBtn = verify['activeBtn'];      // 翻页后应该是 "2", "3", ...
if (prevFirstHref != null && newFirstHref == prevFirstHref) {
  // 翻页没生效，停止
  break;
}
```

### 15.8 JS 侧缓存（解决"返回后章节消失"）

第一次进入漫画详情页 → DesktopWebview 完整翻 16 页 → 用户点章节再返回 → **又触发一次 loadInfo → 又重开 Webview**（还在第一次的 90s timeout 内）→ 可能冲突。

修复：在 comix_to.js 里加模块级缓存：
```javascript
var _chaptersCache = {};

comic.loadInfo = async function(id) {
  ...
  var cacheKey = hid + '|' + slug;
  if (_chaptersCache[cacheKey] && Object.keys(_chaptersCache[cacheKey]).length > 0) {
    chapters = _chaptersCache[cacheKey];  // 命中缓存，直接返回
  } else {
    chapters = await sendMessage({method: "comix_fetch_chapters", hid: hid, slug: slug});
    _chaptersCache[cacheKey] = chapters;   // 缓存成功结果
  }
  ...
};
```

### 15.12 新教训总结

| # | 教训 | 下次遇到 |
|---|------|---------|
| 1 | **WebView2 evaluateJavascript 会双重 JSON 序列化** — `JSON.stringify(JSON.stringify({...}))` | 循环 jsonDecode，直到拿到 `{` 开头的 Map |
| 2 | **SPA 翻页用原生 `.click()` 无效** — React 不响应 | 用 `btn.dispatchEvent(new MouseEvent('click', {bubbles: true}))` |
| 3 | **翻页必须验证 DOM 真的变了** — click 返回 true 不代表翻成功 | 每页翻完检查 activeBtn 和 firstHref |
| 4 | **DesktopWebview 触发点选 onStarted 不要 onTitleChange** — onStarted 早且一定触发 | 轮询等待自己实现，不要依赖 onTitleChange 的 timing |
| 5 | **JS source 里缓存章节列表** — 避免每次进详情页重开 Webview | 模块级 `_chaptersCache` dict |
| 6 | **cmake install 目标是 `../../builds/venera/` 不是 `runner/Release/`** | 不要直接跑 runner/Release/venera.exe，用 cmake install 组装 |
| 7 | **日志路径固定** — `%APPDATA%\io.github.kyosee\venera\logs.txt` | 验证 bug 时实时 tail 这个文件 |
