## 1. 翻译组 UI：为什么不做"版本化矩阵"

第一直觉是把本地漫画的 `chapters` 从扁平升成 `ComicChapters.versioned`（一话多组各占一版本），这样详情页自动走版本化分支、chips 自动出现。**放弃了**，原因：

1. `versioned` 的 `ids` / `allChapters` 在版本化模式下**只投影每话的首个版本**。龙女友第 6 话有 Asura / Diva 两版，转版本化后列表里只剩一张卡，Diva 那版要切 chips 才看得到——等于把用户已经认可的「两个卡片各自带组名小字」的现状弄丢。
2. 阅读进度 key 会从扁平下标（`"3"`）变成 `"组-章"`（`"2-5"`），已读标记与 `read(i+1)` 全部要重对。

最终方案：**保持扁平，组信息只在显示层派生**。

- `_localGroups`：扫一遍章节键，用 `parseChapterDirectoryName()` 取 `[组名]`（站点标签 `comix.to` / `baozimh` 不算组），按登场次数降序排列；缓存，`_computeVisible()` 时失效。
- 筛选**只过滤 `visible`（原始下标列表）**，绝不重建 `ComicChapters`；`read(i+1)`、历史 `epKey`、下载任务全部仍按原始下标寻址。
- chips：多组时 `全部` + 各组（补了「全部」，以前只能再点一次已选 chip 才能退出筛选）；单组时渲染**只读标签** `翻译组：Lua Comic`（以前整行不出现，单组那几本完全看不出谁翻的）。
- 格子小字：扁平链路**只要有组名就显示**，去掉了上一版「只有一话多组才显示」的判别集合。

## 2. 站点标签判定修正

`_siteTagPattern` 只认「带点的域名」，于是包子源的 `116 [baozimh]` 被当成翻译组，整本挂一行 `baozimh`。新增 `isSourceSiteTag()`：带点域名 **或** 已登记站名（`_sourceSiteTags` 的值）都算站点。`chapterDisplayName()` 与 `parseChapterDirectoryName()` 统一走它。

## 4. 「扔掉的渣男」转本地

- **local.db（真相层）**：`comic_type` 233488852 → 0；`chapters` 从网络 276 章改为**磁盘真实 133 章**；`downloadedChapters` 排序；标签去掉 `作者:`/`标签:`/`更新:` 前缀。
- **history.db**：`history.type` / `reading_statistics.type` 同步改 0（不改就读不到进度）。
- **域库（镜像层）**：4 个身份（主行 + 3 个 `repair:` 衍生行）合并成 `local:rengdiaode…`。
  - 顺序：**先 `UPDATE history_events SET comic_id=新` → 再改 comics 主键 → 最后删多余行**。`history_events.comic_id` 带 `ON DELETE CASCADE`，顺序反了就是 A21 那次 798 条历史消失的重演。
  - 断链：`chapter_sources` → `comic_sources` → 远程 `comics` 行依次删，最终该本 `comic_sources` = 0。
- 结果：`history_events` 6967 条不变、孤儿 0；`comics` 2524 → 2521（删了 3 个空壳身份）。

### 🔴 本轮踩的新坑：复合主键不能"删了再 UPDATE"

第一版脚本写的是

```python
DELETE FROM comics WHERE id=? AND comic_type<>0
UPDATE comics SET comic_type=0, ... WHERE id=?
```

`comics` 的主键是 `(id, comic_type)`。删掉旧行后 UPDATE 匹配不到任何行，**整本漫画从真相层消失**（10 本变 9 本）。靠 `data/local.db.bak_p17_*` 才捞回来。

正确写法：主键列可以直接改，没有冲突时一条 UPDATE 就够：

```python
UPDATE comics SET comic_type=0, ... WHERE id=?
```

已在脚本里留红字注释，避免下次重犯。
