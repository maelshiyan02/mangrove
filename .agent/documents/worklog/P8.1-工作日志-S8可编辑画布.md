## 三、关键设计决策与坑

### 3.1 🔴 Undo 粒度：单块快照，而非整份工程（S8 盘点第 5 项落地）

盘点结论是"`TranslationProject` 是整份 json 深拷贝（样本 831 页键），每步全量快照不可接受"。本轮拍板：**命令的最小单位 = 一个 block 的 raw map（23 键，约 1KB）**。

`BlockEditCommand` 存该块 before/after 两份深拷贝，`apply()`/`revert()` 用 `clear()+addAll(deepCopy)` **原地替换、保持 map 身份**（这样所有活着的 `TextBlock` 视图都跟着变）。好处：翻译 + `rich_text` + 多个 `fontformat` 键的**复合改动作为一个撤销步**回滚，无需逐键建模。删除块走 `BlockListEditCommand`（快照一页的块列表）。

`isDirty` 用 **saved index** 而非布尔：撤销回到保存点时重新变"干净"，符合"改了又改回来"的直觉。

### 3.2 🔴 `rich_text` 必须同步（S8 五项必做第 1 项落地）

真实块里 `rich_text` 是完整的 Qt `qrichtext` HTML（实测 `Error the Echo` 每块 1000~1700 字符），FT 画布渲染的是**它**而不是 `translation`。本轮的 `buildFtRichText()` 按实测样本复刻文档结构：`<p>` 逐行、`font-size` 用 **pt**（px×72/96）、`letter-spacing` 写成 `(letterSpacing-1.0)em` 并镜像 `data-btrans-letter-spacing`、颜色 `#rrggbb` 小写。

🔥 坑：`1.15 - 1.0 = 0.1499999999999999`，直接 `toString()` 会把浮点误差写进 HTML、与 FT 的 `0.15em` 不一致 → 用 `toStringAsFixed(4)` 再去尾零。

### 3.3 🟡 可编辑画布与只读画布"合并策略"（S8 六项建议第 2 项落地）

原风险：`TextBlockCanvas` 被 `studio_page` 与 `studio_preview` 两页共用，就地加手势会波及只读预览。本轮**拍板并落地**：把绘制层抽成公共 `PageCanvasPainter`，只读保持 `TextBlockCanvas`、可编辑新建 `EditableTextBlockCanvas`，两者共用同一 painter 与 `hitTestCanvasBlocks` —— **绘制规则单一来源，只读路径零改动**。

🔥 拖拽只在**拖拽结束**才写模型（拖动期间只改本地 `_dragOffset` 预览）→ 一次拖动 = **一个**撤销步，而不是每个 pointer 事件一步。

### 3.4 保存 = 统一保存契约（P6 §2.8）

`_save()`：`ProjectWriter.save(root: project.workspace, keepBackup: true)` 原子写 json（自动 `.bak`）→ `_history.markSaved()` → `LocalManager().notifyListeners()` 失效阅读器 `@bt:` 缓存 → `unawaited(_regenerateResults())` 后台重渲染 `result/`（`writeArtifacts(kinds:{result}, concurrency:2)`）。

- `mask/`、`inpainted/` 是本工程的**输入**，保存不改动它们（去字/检测属 S9）。
- `result/` 重渲染用 `renderProjectResultPage`（`inpainted` + 页面 regions → `renderTranslatedPage(mode: smart)`），解码预算与阅读器一致（≤12MP / ≤8000px）。

### 3.5 其它

- **角度不再被忽略**：painter 现按 `angle` 绕框心旋转；`opacity` / 描边 / 行距 / 字距一并生效（P8.0 已补 `angle` 建模，本轮让渲染真正用它）。
- **ctrl 快捷键**：`CallbackShortcuts` + `Focus(autofocus: true)`；聚焦到 `TextField` 时编辑键由输入框优先消费，不影响打字。
- **选择定位**：条带模式下同一 block 索引存在于每一页，故新增 `_selectedPageKey`，`onSelect` 携带 pageKey —— 否则在第 5 页选中的块会被当成当前页的块。
- **面板控件提交时机**：滑块 `onChangeEnd`、颜色整体三元组一次提交、译文 `onSubmitted`/Apply/失焦提交 → 每次提交恰为 **1** 个撤销步。

## 七、🔴 反馈①②：工作室 UI 全英文 + 右面板太挤

### 7.1 根因：字符串**从未登记**进 `translation.json`（不是"翻译漏了"）

`String.tl` 的查找表**以英文原文为 key**（`translations.dart:31-37` 直接 `Map<String,String>.from(json[e.key])`，
`_translate()` 找不到就 `return this`）。所以：

- 上一轮新增的 `StudioBlockPanel` / 工具栏 / 状态栏里的**每一个英文字面量**，只要没在
  `assets/translation.json` 里登记过，`.tl` 就**原样返回英文** —— 看上去就是"整个面板全是英文"。
  实测统计：本轮补登 **74 条 × 2 语言（`zh_CN` / `zh_TW`）**，词条总数 1470 → **1474**。
  覆盖 `Translation / Source / Box / Alignment / Font size (px) / Font weight / Vertical /
  Rotation (°) / Fill colour / Stroke width (px) / Stroke colour / Line spacing / Letter spacing /
  Opacity / Apply / one undo step / Delete block / Undo (Ctrl+Z) / Redo (Ctrl+Y) / Save (Ctrl+S) /
  Single page + zoom / Continuous strip / Save failed: @a / Saved @a (@b B) / rendering result… /
  unsaved / …`
- 🔥 **另一个隐性杀手：先插值再 `.tl`。** 状态栏原来写的是 `'base: $kind'.tl` ——
  插值后的字符串**永远不可能**匹配到任何词条（词条是 `base: @a`），所以
  **这条即使登记了也修不好**。必须用仓库既有的占位符协议：
  `'base: @a'.tlParams({'a': kind})`（`tlParams` 内部替换 `@a`，见 `translations.dart:21-27`）。
  **规则：`.tl` 只吃字面量，带变量的走 `.tlParams`。**

## 九、反馈④：相邻两页无缝衔接

`lib/components/studio_scroll_canvas.dart`：

- `pageGap` 默认 **12 → 0**（`StudioScrollCanvas` 与调用方都不再传间距）。
- 🔴 但**光把 gap 设 0 还不够**：原实现的页标签**独占一整行**，那一行本身就是一条白缝。
  本轮把 `_StripItem` 改成 `Stack`：
  - `body` 用**非定位**（决定尺寸）→ 图片之间真正零间距；
  - `if (!isFirst)` 顶部画 **1px 分隔线**（0 间距时上下页边界才看得出来，且不占高度）；

# 【问题反馈】第三轮（10-07 11:00–11:40）—「`6 [DivaScans]` 修复完了，界面却说没下载」

> 用户报告：`6 [DivaScans]` 点过"下载修复"之后，磁盘上文件夹里 177 张图**齐全**，
> 但 ① 翻译组 `DivaScans` 下的第 6 话 **卡片不变蓝**；② 打开"下载"页，`Ch.6` 的**勾选框是空的**（＝未下载）。

## 十二、🔴 根因：**两个账本，只有一条腿在写**

"这一话在本地"这件事在本工程里有两份互不相关的记录：

| 账本 | 载体 | 谁在写 | 谁在读 |
|---|---|---|---|
| **A. 登记表** `downloadedChapters` | `local.db` 一行 JSON（存的是 **chapterKey**） | **只有** `LocalManager.add()` ← `completeTask()` → `task.toLocalComic()` | 章节标签配色 `chapterChipColorFor`（`chapters.dart:1184`）、下载页勾选框（`actions.dart:598`）、阅读器章节列表、`LocalComic.effectiveChapters.preferDownloaded` |
| **B. 磁盘** `downloads/<漫画>/<章节目录>/` | 真实文件 | `ImagesDownloadTask` 每下完一页就写 | 缺页对账（§17）、阅读器取图 |

`RepairDownloadTask` **按设计不写账本 A** —— 它的 `toLocalComic()` 返回
`downloadedChapters: const []`，`_finalize()` 里还留着注释
*"Unlike completeTask() we do NOT re-add the comic to the library"*。

于是这次事故的形状是：

1. `6 [DivaScans]` 当初是**半截下载**（下载任务在整章跑完之前就结束，**没走 `completeTask`**）
   → 它的 chapterKey **从来没有进过账本 A**；
2. 后来点"修复"，只补**页**（账本 B）→ 32 个空洞全补齐，`missing_pages.json` 因条目清零而
   **被自动删除**（所以"红色缺页"也确实正确消失了）；
3. 账本 A 依旧不知道这一话存在 → 卡片不上蓝、下载页勾选框为空。

**实测证据（修复前）**

```
磁盘 : '6 [DivaScans]'  177 文件 / min 0 / max 176 / gaps=0   ← 齐全
       '6 [Asura Scans]' 128 文件 / min 0 / max 127 / gaps=0
缺页表: missing_pages.json 已不存在（补完后自动删表，符合预期）
local.db: chapters  = 8 话号 / 84 版本 / 11 组   ← 健康（上一轮 enrichComicChapters 自愈过）
          downloadedChapters = 7 条，**全部是 Asura Scans（话 1–7）**
          DivaScans 的 7 个 key —— **一个都没登记**
```

## 十三、🔴 附带挖出：`completeTask()` 里那个对账钩子**是空的**

上一轮（§17）在 `completeTask()` 里挂了
`unawaited(reconcileMissingPages(stored))`，但**挂错了位置**：

```dart
add(task.toLocalComic());
final stored = find(task.id, task.comicType);
if (stored != null) unawaited(reconcileMissingPages(stored));  // ← 此刻任务还在队列里
downloadingTasks.remove(task);
```

`reconcileMissingPages()` / `reconcileDownloadedChapters()` 开头都有
`if (isDownloading(id, type)) return 0;`，而 `isDownloading()` 就是查 `downloadingTasks`
——**任务还在队里 → 守卫命中 → 直接返回 0**。所以"下完立刻对账"从来没真正执行过，
表现就是"下载完成后不马上变红/不变蓝，要等下次打开详情页才恢复"。

**修法：把对账移到 `downloadingTasks.remove(task)` 之后。** 两处都要移（本轮 + 修复任务）。

## 十四、修法

### 14.1 新增两个 API（`lib/foundation/local.dart`）

| API | 作用 |
|---|---|
| `reconcileDownloadedChapters(comic) → Future<int>` | 扫**磁盘**章节目录；目录名用 `chapterDirectoryName(chapters, key)`（与下载/读取/删除侧**同一份规则**）反查 chapterKey；命中的 key **并入** `downloadedChapters`。返回新登记数 |
| `reconcileDiskState(comic) → Future<bool>` | 一次扫描同时做"补缺页表 + 补登记表"（两个都是"磁盘 > 数据库"的自愈），返回是否有改写（供 `setState` 用） |

细节：
- 取库里**最新一行**再写回（`_writeComic` 是整行 `INSERT OR REPLACE`，用调用方可能过时的对象会把别的列一起回退）；
- 反查不到的目录**只记 warning 日志**（`Chapter directory on disk with no matching chapter version (left unregistered)`），不猜、不删、不登记；
- 目录里**没有可解析的页文件**（例如只有 `cover.jpg`）不算一话 → 跳过；
- 守卫与 §17 一致：跳过 `ComicType.local`、跳过正在下载的漫画。

### 14.2 三个调用点

| 位置 | 改动 |
|---|---|
| `LocalManager.completeTask()` | 对账**移到 `downloadingTasks.remove(task)` 之后**，并改调 `reconcileDiskState()` —— 一次同时补两张表 |
| `RepairDownloadTask._finalize()` | `removeTask(this)` **之后**取最新 `LocalComic` 调 `reconcileDiskState()` → 修完立刻登记 |
| `ComicPage._reconcileLocalMissingPages()` → 更名 `_reconcileDiskState()` | 打开详情页时两边一起对账；有改写就 `setState` 并把 `_localComic` 刷成最新 |

### 14.3 判据取舍（**有意为之**，不是漏考虑）

登记门槛取 **"目录里有页文件"**，与 `LocalComicStatus.downloaded` 同口径：

- 好处：磁盘上有副本就能被管理 —— **阅读器能列出来、删除入口能删掉、`preferDownloaded` 能排到首位**；
  "完不完整"由缺页表表达（红 > 蓝），不在登记这一层二次猜测。
- 已知副作用：**下载中途取消**留下的半截目录也会被登记为"已下载"。此时红色缺页标记会同时出现；
  若坚持只登记"完整章"，又无法离线判定（缺口可判、**尾部截断不可判**，见 §17 教训 6）——
  两害相权取"磁盘上确实有文件"。

## 十五、验证

### 15.1 🆕 headless 输出通道：`tools/run_headless_task.py`（本轮最重要的工程收获）

排查过程中发现一个**一直在骗人**的现象：`builds/venera/venera.exe --headless … > out.txt`
**永远得到空文件 + exit 1**，看起来像崩溃，其实命令跑了、输出全丢。原因：

> `venera.exe` 是 **GUI 子系统**程序，`main.cpp` 无条件调用
> `::AttachConsole(ATTACH_PARENT_PROCESS)`。从**有控制台**的 shell（Git Bash / cmd / PowerShell）
> 启动时，这一步会把 stdout/stderr **重新绑回控制台**，调用方的 `>` 重定向被丢弃。

计划任务**没有父控制台** → `AttachConsole` 失败 → 重定向生效。因此新增：

```bash
python tools/run_headless_task.py page-reconcile "gm28k//my-dragon-girlfriend-has-returned" \
    --source comix_to --json builds/page_reconcile.json
# 输出落 builds/headless.out，同时回显
```

（顺带解释了 §17 里"headless 命令无声退出"的直觉为什么不可靠。）

## 十六、教训 / 遗留

1. **"本地有它"必须只有一个真相，或者必须有一个对账器。** 两个账本、只写一个 = 必然分裂。
2. **对账函数的守卫要和它的调用点一起设计。** `isDownloading` 守卫是对的，但把它放在了
   "任务还没出队"的时刻调用 → 钩子静默空转（`return 0`）。**静默 return 0 比抛异常更难发现。**
3. **GUI 子系统程序 + `AttachConsole` = 输出黑洞。** 任何"跑完没输出"的判断都要先确认
   输出通道本身是通的。
4. 遗留：反查不到版本的目录只记日志（源上下架的版本需要 `chapters` 保留历史，属 S13）；
   详情页的自动登记是 `scheduleMicrotask` 触发，**本次修复已在 `setState` 里刷新**，
   但如果你正好停在详情页，最稳的是退出再进一次。
