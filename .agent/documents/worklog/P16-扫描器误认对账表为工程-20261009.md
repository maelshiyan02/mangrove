## 2 · 根因

`BtProjectManager._collectJsonFiles`（`foundation/bt_project/bt_project_manager.dart`）的
名字判据是：

```dart
if (name.startsWith('imgtrans_') && name.endsWith('.json')) out.add(entity);
```

而**产物对账表**叫 `imgtrans_<名>.artifacts.json`（`ArtifactReconciliation.pathFor`）——
它与工程 json **同级**、**同样** `imgtrans_` 开头 `.json` 结尾 ⇒ **完全命中**。

于是每次保存：
1. 工作室 `_save()` → 写工程 json + **写对账表**（`imgtrans_<名>.artifacts.json`）；
2. 下一次 `scan()` 把对账表**当成第二个工程**登记 → id `bt_640abdde`；
3. 对账表里没有 `pages` ⇒ 解析成**零页工程** ⇒ 一张**空卡片**、无详情标签；
4. 它**删不掉**：它挂的是**同一本工程**所在的目录，磁盘上并不存在一个与之对应的
   「工程」—— 删真实工程也带不走它（要等下次扫描才回收，而下次保存又会长回来）。

> ⚠️ 为什么日志（`logs.txt`）里看不出：它只有 662 B，只记 WebView/图片抓取，
> **不记工程注册**。所以「查运行日志」这条线索不成立，改由**穷举文件系统哈希**定位。

## 3 · 修法

1. 新增静态判据 **`BtProjectManager.isProjectJsonFileName(name)`**（可 headless 断言）：

   ```dart
   static bool isProjectJsonFileName(String name) {
     if (!name.startsWith('imgtrans_')) return false;
     if (!name.endsWith('.json')) return false;
     return !name.endsWith(ArtifactReconciliation.fileSuffix); // '.artifacts.json'
   }
   ```

2. `_collectJsonFiles` 改用它；
3. 后缀用**共享常量** `ArtifactReconciliation.fileSuffix`，而不是再写一遍字面量 ——
   对账表换名时若这条漏改会**静默**地再长出幽灵卡片。

**无导入环**：`artifact_reconciliation` 只依赖 `{project, project_bootstrap, project_writer}`，
三者都不 `import bt_project_manager`（已核）。

新增断言 `scan.artifacts_sidecar_is_not_a_project`（**绿路径=true / 故障路径=变红**）：
- 绿路径：`BtProjectManager.isProjectJsonFileName`；
- 故障路径：修复前的「前缀 + 后缀」判据；
- 判据含**四支**：真工程 ⇒ true；`.artifacts.json` ⇒ false；`.json.backup` ⇒ false；
  无关文件 ⇒ false。**「真工程算」这一支不能省**：只断言 sidecar 被排除时，
  一个「恒返回 false」的实现也会通过 —— 而那会让**全部**工程从列表消失。

### 4.1 幽灵记录清理 + 自愈

- **顺手清了 DB**（app 未运行时执行）：`bt_640abdde` 已删，`bt_` 行 **3 → 2**，与磁盘一致；
- **自愈**：`init.dart:114` 启动即 `BtProjectManager().scan()`，`_scan()` 末尾的 stale
  逻辑会回收任何**不在 `seen` 里**的 `bt_` 行 ⇒ 即使漏清，下次启动也会自动消失。
