## 三、关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 预设数 | system + 11 种子 + custom = **13** | 沿用上游 §3.2.1。secondary/tertiary 一律 `null` 自动派生，`FlexTones.vividBackground` 不变 ⇒ 从旧 `color` 迁到同名色系时**观感不漂移** |
| 迁移触发 | **独立 flag `colorSchemePresetMigrated`**，不是「键缺失」 | 🔴 新键有合法默认值 `'system'`，旧机载入后键也在（默认值兜底），「键缺失」不可用作判据。用 flag 才能既「只跑一次」又「不覆盖用户后来的选择」 |
| 旧键 | `color` **保留写入** | 回退安全：若本构建要回滚，旧代码路径仍能读到用户原来的选择 |
| 迁移映射 | orange→**amber**（无同名预设）；yellow→amber；cyan→teal；其余同名；未知→blue | 旧 switch 里 `yellow`/`cyan` 存在但 UI 从未提供，按色系就近落位；未知落 `blue` 与旧 `translateColorSetting()` 的 `_ =>` 一致 |
| 自定义取色 | **自研 HSL 三滑条 + HEX**（约 150 行），不引 `flex_color_picker` | 只需一个种子色；加依赖会给构建链路新增风险点（本仓库插件 symlink 已翻车过一次）。拍板 ② |
| 滑条范围 | 饱和度 ≥ 0.05、明度 ∈ [0.15, 0.85] | 🔴 纯黑/纯白/纯灰种子**无法**被 M3 展开成 tonal palette，会把整个界面打成灰片 |
| 持久化时机 | 拖动只 `setState` 重绘预览，`onChangeEnd` 才 `saveData()` | 每帧保存会排队一次写盘 + 一次 WebDAV 上传 |
| 主题派生 | 抽出 `buildAppTheme()` 供预览复用 | 预览若另写一套派生，tones/字体一改就会与真实主题漂移 |
| 同步分类 | preset/customSeed 进 appearance（可同步）；migration flag 进 `_disableSync` | `test/sync_skip_test.dart` 对「未分类的新设置键」会 FAIL，两类都必须登记 |
