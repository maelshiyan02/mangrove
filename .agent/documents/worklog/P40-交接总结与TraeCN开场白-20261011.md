## 6. 根因分析与待排查假设（交给 Trae 的重点）

### 6.1 comix.to（P39 已证：代理出口 IP 被 CF 封）
- 硬证据：**本机 `curl` 直连 comix.to → 200**；**经系统代理 `127.0.0.1:7890` → 403 `Attention Required! | Cloudflare`**。
- 系统代理实况：`ProxyEnable=1`，`ProxyServer=127.0.0.1:7890`。
- **待验证假设 A（最可能）**：**WebView2 会过滤 `additionalBrowserArguments`**——它对命令行参数有白名单，
  `--proxy-server` / `--proxy-bypass-list` 可能被忽略。WebView2 的代理应走 `SetProxy` API
  （较新版 `ICoreWebView2Controller2`）或环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，而非这里的 settings 字段。
  → **排查**：确认 `flutter_inappwebview_windows` 是否把该参数真正透传给 WebView2；在日志里我们已有 `webview proxy: ...` 打印，可确认参数是否传了。
- **待验证假设 B**：用户开的可能是 Clash **TUN 模式（虚拟网卡）**，此时**任何应用层「直连」都会被 TUN 捕获走代理**，
  `DIRECT` 无效（`cf-ray: AMS` 佐证流量从节点出）。→ **排查**：看 Clash 是否 TUN/系统代理。
- **最稳的根治（不依赖 App 代码）**：在**代理侧**给 `comix.to` / `static.comix.to` / `*.joshuanotes.site` /
  `*.comixcdn.*` 加 **DIRECT 规则**；或**换一个未被封的节点**；或**临时关代理**（直连实测 200）。

### 6.2 包子漫画（P39 已证：运行时配置卡在死域名；已修正但仍未走镜像）
- `baozi.js::loadEp`（部署版第 684 行起）：**先**试网页镜像
  `https://<lang>.<镜像>/comic/chapter/<comicId>/0_<epId>.html`（第 708 行），**失败才**兜底
  `https://appcn.baozimh.com/baozimhapp/comic/chapter/<comicId>/0_<epId>.html`（第 726 行）。
- 本机实测：四个镜像 `webmota/kukuc/twmanga/dinnerku` **直连与走代理均 200、零 CF 挑战**，
  阅读页 200 且含真实 `data-src` 图片（`s2.bzcdn.net`）。
- **待排查 C**：App 是否**真的重新加载**了新 `baozi.js`（v1.2.2）？日志里 webmota 0 次尝试，可疑。
  → 确认重启 + 源热加载路径。
- **待排查 D**：若确实加载了新版，为何 `loadEp` 的镜像请求未出现在日志里（是静默失败，还是逻辑未走到）？
  → 在 `loadEp` 加日志或断点；确认 `loadSetting("domains")`/`good_web_domain` 的运行期取值。
- **待排查 E**：下载（「获取漫画信息」卡死）是否走的是**另一条**取图路径（非 `loadEp`），其中可能硬编码 `appcn`。
