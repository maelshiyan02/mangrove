## P1：性能与体验
1. **章节采集提速**：`_inPageFetchJson` 修好后，分页可直接页内 fetch，不再点分页按钮。
   观察一轮日志确认稳定后，降低 DOM 兜底的触发权重（现在是 API 空才走 DOM）。
2. **图片并发与预取**：当前 4 路并发；按条漫实测提升到 6~8 路，并加"当前页前后各 2 张"预取。
   注意并发上限要能被源覆盖（避免某些源被限流）。
3. **封面批量取**：搜索结果 28 张封面各走一次 WebView 是串行瓶颈。
   方案：封面走独立队列 + 去重 + 快速失败跳过；并实测"挑战 cookie 到手后 dio 是否也通"
   ——若通，封面可回落 dio，成本大幅下降。
4. **后台验证的可感知性**：验证期间显示"正在后台验证…"（带计时），完成后自动重试；
   而不是先弹错误页 + 按钮再默默验证。

## P2：健壮性
5. **验证状态持久化**：簇验证标记与 cookie 现在只在内存（重启失效）→ 写 `appdata.implicitData`，
   重启后免重新验证（注意票据过期时间，落盘时记时间）。
6. **站点簇跨品牌归一**：baozimh 会跨不同可注册域轮换（baozimh.com / webmota.com / cnbzmg.com），
   当前簇按 eTLD+1，跨品牌仍会各验一次。方案：加"同源站点别名表"，或验证成功后把
   challenge 的 return 域一并记入该簇。
7. **重定向链上的 cookie**：更彻底的做法是在 dio 层接管重定向（关掉 followRedirects、
   自己逐跳重发并注入 cookie），一次解决"跳到别的 host 就没 cookie"这一类问题。
   风险：会影响所有依赖自动重定向的源，需要开关控制 + 逐个源回归。
