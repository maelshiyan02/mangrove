> 日期：2026-09-28

## 一、需求背景

### 1.1 现状总结

在 P1 阶段，VeneraX 已能直接读取 BallonsTranslator（BT）翻译工程并渲染译文页面。真机验收中发现并修复了以下问题：

- BT 工程页键中混有已删除的 jpg 键（如 `0/001.jpg`），导致首页历史封面裂图（`relative URL without a base`）
- 从首页历史入口直达阅读器时，BT 工程索引（`_projects`）尚未扫描，导致阅读器白屏
- `HistoryImageProvider` 对 BT 相对封面路径不识别，直接丢给 HTTP 栈
- `LocalManager.add` 的 `downloadedChapters` 合并逻辑产生重复值 `["0","0"]`

以上均已修复（test 840 全过，builds/venera 成品冒烟通过）。

### 1.2 新需求触发点

验收通过后，用户在使用过程中发现以下三个关联问题：

1. **封面不理想**：BT 工程封面默认用第一张页图（`0/1.webp`），而非 comix.to 等网站展示的正式封面图
2. **章节层级错位**：Error the Echo 实际是第 6 章，但 BT 导入时将大文件夹识别为漫画名，自动创建了 `0/` 子目录，导致章节信息丢失
3. **章节名显示冗长**：下载时 source 返回的章节标题包含「章节号 + 翻译组 + 日期」，如 `Chapter 5 - Luna Toons 2024-09-28`，显示在 VeneraX 中太长且不美观

## 二、需求一：自定义封面

### 2.1 问题描述

大部分本地翻译工程的封面使用的是成品的第一张图片充当封面，实际上应该在从 comix.to 等网站下载漫画时就把网站展示的封面也下载好。

### 2.2 现有机制

#### 2.2.1 VeneraX 下载时的封面处理

文件：[download.dart:485-512](file:///D:/Ballonstranslator_Windows/VeneraX/lib/network/download.dart#L485-L512)

```dart
if (_cover == null) {
  _message = "Downloading cover...".tl;
  notifyListeners();
  var res = await _runWithRetry(() async {
    Uint8List? data;
    await for (var progress
        in ImageDownloader.loadThumbnail(comic!.cover, source.key)) {
      if (progress.imageBytes != null) {
        data = progress.imageBytes;
      }
    }
    if (data == null) {
      throw "Failed to download cover";
    }
    var fileType = detectFileType(data);
    var file = File(FilePath.join(path!, "cover${fileType.ext}"));
    file.writeAsBytesSync(data);
    return "file://${file.path}";
  });
```

- 下载开始时，若 `_cover == null`，会从 source 的 `comic.cover` URL 下载封面
- 封面保存为 `<下载根目录>/cover<ext>`（如 `cover.jpg`）
- 下载根目录 = 漫画在 `LocalManager` 中的 `directory` 字段

#### 2.2.2 BT 工程的封面解析

文件：[bt_project_manager.dart](file:///D:/Ballonstranslator_Windows/VeneraX/lib/foundation/bt_project/bt_project_manager.dart) — `coverKeyFor` / `loadCover`

```dart
static String? coverKeyFor(BtProject project) {
  final key = project.pageOrder.firstWhere(
    (key) =>
        BtProject.isImagePage(key) &&
        File(project.originalPath(key)).existsSync(),
    orElse: () => '',
  );
  return key.isEmpty ? null : key;
}
```

- 封面 = `pageOrder` 中第一个磁盘上存在的页图
- 对于 Error the Echo：`page_order` 为 `["0/001.jpg", "0/1.webp", ...]`，`0/001.jpg` 已删除，回退到 `0/1.webp`
- `loadCover` 读取该文件的原始字节并返回

#### 2.2.3 封面在 LocalComic 中的存储

BT 工程注册到 LocalManager 时，`LocalComic.cover` = `coverKeyFor` 返回的页键（如 `0/1.webp`），是相对于 `directory` 的路径。

### 2.3 问题根因

- VeneraX 下载的 `cover.jpg` 保存在**下载根目录**（如 `downloads/Error the Echo/cover.jpg`）
- BT 工程的 `directory` 可能指向同目录或子目录
- BT 工程封面解析只看 `pageOrder` 中的页图，不检查 `cover.*` 文件
- 如果用户先下载漫画、后用 BT 翻译，`cover.jpg` 可能被 BT 的页面扫描忽略（因为 BT 的 `imgtrans_*.json` 的 `pages` 只包含正文页图）

### 2.4 改造方案：A + B + C 三方案组合

三个方案不是互斥的，而是互补的覆盖全链路：

| 方案 | 时机 | 作用 | 状态 |
|------|------|------|------|
| **A. 读取时优先读 cover.\*** | 封面解析 | 确保 cover 文件能被正确识别 | 新增 |
| **B. 下载时自动同步** | 下载完成 | 确保 cover 文件出现在工程目录 | 新增 |
| **C. 手动设置** | 用户操作 | 补缺/覆盖任意时刻的封面 | 新增 |

#### 方案 A：BT 工程优先读取外部封面文件

修改 `coverKeyFor` / `loadCover` 的解析优先级：

1. 先查 `directory/cover.{jpg,jpeg,png,webp}` — 若存在，用作封面
2. 不存在则回退到 `pageOrder` 中第一个存在的页图（当前逻辑）

**影响文件**：[bt_project_manager.dart](file:///D:/Ballonstranslator_Windows/VeneraX/lib/foundation/bt_project/bt_project_manager.dart) — `coverKeyFor` / `loadCover`

#### 方案 B：下载完成后自动同步封面到 BT 工程目录

下载完成后，检测同目录下是否有 BT 工程结构（`imgtrans_*.json`），若有，把 `cover.jpg` 复制到 BT 工程的 `directory` 下。

**时序问题**：VeneraX 下载和 BT 翻译是两个独立流程，执行顺序不确定。BT 可能在下载后运行（此时 `imgtrans_*.json` 还不存在），或先于下载运行。

**解决**：方案 A 已覆盖两种时序——只要 `cover.*` 文件存在于工程目录，就会被读取。方案 B 作为补充，在下载完成时尝试同步一次，同步失败也无妨（方案 A 会兜底）。

**影响文件**：[download.dart](file:///D:/Ballonstranslator_Windows/VeneraX/lib/network/download.dart) — 下载完成回调

#### 方案 C：手动设置自定义封面

提供两个 UI 入口（见下方 2.5 节），用户选择一张图片后：

1. 写入到 `LocalComic.directory` 下作为 `cover.<ext>`
2. 同步更新 `LocalComic.cover` 字段并写入 local.db
3. BT 工程调用 `coverKeyFor` 重新解析（方案 A 会自动选中 `cover.*`）
4. 清除封面图片缓存（`ImageCache` / `PaintingBinding`），使 UI 立即刷新

**影响文件**：[bt_project_manager.dart](file:///D:/Ballonstranslator_Windows/VeneraX/lib/foundation/bt_project/bt_project_manager.dart) — 新增 `setCover(comicId, bytes)` API；[local.dart](file:///D:/Ballonstranslator_Windows/VeneraX/lib/foundation/local.dart) — `LocalComic.cover` 更新

### 2.6 封面查看页：两个独立功能按钮（非差异化）

#### 2.6.1 问题分析

当前 `_saveCover`（[cover_viewer.dart:113-139](file:///D:/Ballonstranslator_Windows/VeneraX/lib/pages/comic_details_page/cover_viewer.dart#L113-L139)）对所有漫画统一执行"下载封面"逻辑：解析 `ImageProvider` → 转 PNG → 调用 `saveFile` 保存到用户选择的路径。

问题在于，对本地漫画来说"下载封面"毫无意义——封面文件就在本地磁盘上，用户需要的是定位文件而非再次下载。最初软件制作者没有对封面查看页的按钮做不同类型漫画的区分。

#### 2.6.2 改造方案：两个独立按钮

**不是**同一个按钮按类型切换行为，而是**两个完全独立的按钮**，各自有独立的图标和功能语义，只是占据同一个位置（右上角）。根据漫画类型显示其中一个：

| 漫画类型 | 显示的按钮 | 图标 | 功能 |
|---------|-----------|------|------|
| 网络漫画（未本地缓存） | **下载封面** | `Icons.download_outlined` | 下载封面到用户指定路径（当前 `_saveCover` 逻辑） |
| 网络漫画（已下载）/ 本地漫画 / BT 工程 | **打开封面位置** | `Icons.folder_open_outlined` | 在资源管理器中定位封面文件 |

两个按钮的关系：
- **名称不同**：`Download Cover` vs `Open Cover Location`
- **图标不同**：`download_outlined` vs `folder_open_outlined`
- **功能不同**：一个保存到用户选择的新路径，一个在原位打开文件管理器
- **位置相同**：都在右上角，同一时间只显示其中一个

#### 2.6.3 实现要点

1. **判断显示哪个按钮**：
   - `comic.type == ComicType.local` → 显示"打开封面位置"
   - `comic.type == ComicType.online` 且 `LocalManager.find(comic.id) != null` → 显示"打开封面位置"
   - 其他 → 显示"下载封面"

2. **"打开封面位置"实现**（新增方法 `_openCoverLocation`）：
   - 本地漫画：`LocalComic.directory` + cover 文件名 → 拼接绝对路径
   - BT 工程：`BtProjectManager().projectFor(cid)` → `directory` + `coverKeyFor` 返回的页键
   - 调用 `Process.run('explorer.exe', ['/select,', filePath])` 在资源管理器中选中文件
   - 若文件不存在，显示提示 `Cover file not found`

3. **_CoverViewer 需要额外信息**：
   - 当前只接收 `imageProvider / title / heroTag`
   - 新增 `comicType`（`ComicType`）和 `localComic`（`LocalComic?`）参数
   - 或传入回调 `coverLocationPath: String?` 和 `isLocal: bool`

## 三、需求二：文件夹层级 / 章节识别问题

### 3.1 问题描述

Error the Echo 的漫画图片实际属于第 6 章节内容。但在导入 BallonsTranslator 时：

- BT 将大文件夹名识别为**漫画名**（`Error the Echo`）
- BT 自动创建了下一级目录 `0/`（即 chapter name = "0"）
- 所有图片保存在 `Error the Echo/0/` 中

这导致 BT 工程的 `imgtrans_*.json` 中：

```json
{
  "directory": "D:/.../downloads/Error the Echo",
  "chapters": [{"name": "0", "pages": ["0/1.webp", "0/2.webp", ...]}]
}
```

章节名为 `"0"` 而非 `"6"` 或 `"第6话"`。

### 3.2 根因分析

- 章节名 `"0"` 由 BT 的导入逻辑生成，不是 VeneraX 控制的
- VeneraX 的 `BtProject.parse()`（[bt_project.dart:96-115](file:///D:/Ballonstranslator_Windows/VeneraX/lib/foundation/bt_project/bt_project.dart#L96-L115)）忠实地读取 `chapters` 字段
- `BtProjectManager._registerLocal` 将章节名直接写入 `LocalComic.chapters` 和 `downloadedChapters`

### 3.3 可选方案

| 方案 | 说明 | 可行性 |
|------|------|--------|
| **A. 修正 BT 工程** | 在 BT 中重新设置章节名为 "6" 或 "第6话"，VeneraX 下次 scan 检测 mtime 变化自动刷新 | 最简单，但需用户在 BT 端操作 |
| **B. VeneraX 端章节名映射** | 在 `BtProject` 解析后增加可选的章节名映射表（如 `0→第6话`） | 表面修补，映射表需手动维护或从外部元数据获取 |
| **C. 下载时正确命名** | 改下载逻辑，章节目录名包含真实章节号（见需求三） | 从源头解决，但只影响新下载，不影响已存在的工程 |

### 3.4 建议

- 对已有工程：**方案 A**（在 BT 端修正章节名）
- 对新下载：**方案 C**（下载时目录名包含真实章节号，见下文）
- VeneraX 端不需要做特殊处理，保持忠实读取 BT 工程数据的策略

## 四、需求三：章节名显示拆分（章节号 + 翻译组）

### 4.1 问题描述

#### 4.1.1 下载文件名冗长

当前下载时的章节目录名由 source 返回的章节标题决定。

#### 4.1.2 VeneraX 章节显示不美观

文件：[comic_details_page/chapters.dart:389-424](file:///D:/Ballonstranslator_Windows/VeneraX/lib/pages/comic_details_page/chapters.dart#L389-L424)

章节列表直接显示 `ComicChapters` 的 value（即 source 返回的章节标题），无格式化。

#### 4.1.3 期望的显示效果

参照 comix.to 等网站的 UI 模式（图 3）：

```
章节网格：  第5话  第6话  第7话  第8话 ...
语言标签：  [英文]  [中文] ...
```

用户期望改为：

```
章节网格：  第5话  第6话  第7话 ...
翻译组标签：[Luna Toons]  [MistScene] ...
```

具体规则：
1. `Chapter 5 - Luna Toons 2024-09-28` → 章节号显示为 `第5话`
2. `Luna Toons` 作为翻译组单独显示在章节下方的分栏
3. 下载日期从文件名中去掉（看文件创建时间即可）
4. 语言和翻译组是不同维度，不能混为一谈

#### 4.2.3 BT 工程的章节显示

BT 工程的章节名来自 `imgtrans_*.json` 的 `chapters[].name`，如 `"0"`。这个值由 BT 设置，与 source 的章节标题无关。

### 4.3 改造方案

#### 4.3.1 章节标题解析器

新建工具函数，将 source 返回的章节标题解析为结构化数据：

```dart
class ParsedChapterTitle {
  final int? chapterNumber;     // 5
  final String? scanlationGroup; // "Luna Toons"
  final String? language;        // "English"
  final String rawTitle;         // "Ch.5 - Luna Toons 2024-09-28"
  String get displayTitle => chapterNumber != null ? '第$chapterNumber话' : rawTitle;
}
```

需要支持的 source 命名格式（不完整列表）：

| Source | 标题格式示例 | 解析结果 |
|--------|------------|---------|
| comix.to | `Ch.5 - Luna Toons` | ch=5, group=Luna Toons |

| 拷贝漫画 | `第5话` | ch=5, group=null |

### 4.4 难点与风险

1. **各 source 的章节标题格式不统一**：解析器需要覆盖多种格式，且需要持续维护以支持新 source
2. **同章节多翻译组**：comix.to 同一章节有多个翻译组版本（图 1 可见 8 个组），当前 `ComicChapters` 不支持
3. **向后兼容**：改了目录命名规则后，已下载的漫画目录名还是旧格式。读取时需要兼容
4. **ComicChapters 改动影响面大**：`ComicChapters` 被 reader、download、local、history 等多处使用，改动需要全链路测试
5. **BT 工程章节名与 source 章节名脱节**：BT 工程的章节名由 BT 设置，与 source 无关。无法自动映射

## 九、P2-C 多翻译组支持实施记录（2026-09-29）

### 9.1 目标

comix.to 同一章节（如 Ch.5）有 8 个翻译组版本，`ComicChapters` 原 flat/grouped 结构无法表达"同章节号多版本"。用户确认语言与翻译组是两个不同维度，选择**新建多版本结构**方案（不复用 groups 机制）。

### 9.2 已实施

| 步骤 | 内容 | 文件 |
|------|------|------|
| 1 | 新建 `ComicChapterVersion` 类（scanlationGroup / language / title / chapterKey，含 fromJson/toJson） | models.dart |
| 2 | `ComicChapters` 扩展：新增 `_versionedChapters` 字段 + `.versioned()` 构造；新增 `isVersioned` / `scanlationGroups` / `versionsFor` / `preferredVersionKey` / `scanlationGroupAt` / `versionCountAt` API | models.dart |
| 3 | `fromJson` 检测 `List` 值走 versioned 分支；`toJson` 输出 `{章节号: [{group,lang,title,key},...]}` | models.dart |

| 5 | `_findDomainChapters` 用 `parseChapterTitle` 解析标题，按章节号聚合多翻译组 | comic_state_repository.dart |

| 8 | 修复 models.dart 8 个 `unnecessary_non_null_assertion` warnings | models.dart |

### 9.3 关键设计决策

**聚合条件收紧（防回归）**：`_findDomainChapters` 的 versioned 触发条件从"同章节号出现 ≥2 次"收紧为"同章节号出现 ≥2 次**且至少一个版本带翻译组名**"。否则纯标题重复的章节（如两个"第5话"，即"隐藏重复章节"功能处理的场景）会被错误折叠成单版本导致章节丢失。

**versioned 模式下游零改动**：reader 的 `eid`（`ids.elementAtOrNull(chapter-1)`）、`chapterOrder`、`duplicateTitleIndices`，以及 download 的 `allChapters.keys` / `_images` 键，全部走第一版本兼容 API，无需逐处适配。

**下载目录名**：沿用 P2-A 的 `parseChapterTitle(chapterKey).chapterNumber` 逻辑，versioned 模式的 chapterKey 为源章节 id，行为不变。
