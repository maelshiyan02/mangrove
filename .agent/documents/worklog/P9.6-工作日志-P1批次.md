## 一、P1-4 · 字体资产进工程

### 1.1 现状与根因

`pubspec.yaml` 的 `fonts:` 整段被注释、`assets/fonts/` 不存在，而 P9.4 已经把 `FontFormat.font_family` 贯通到了渲染器。于是出现P9.0 §7.3 预登记的那个状态：**看起来通了，其实没通**。

根因不止"没打包字体"，还有两处：

1. **`FontFormat.defaultFontFamily` 是 `'Microsoft YaHei UI'`**（FT 的历史默认值），`S9Fixture` / `Error the Echo` 这类真实工程里到处是这个值。它是一个**系统字体**，本应用从未注册过。
2. **Flutter 对未注册的 `fontFamily` 会静默替换成平台默认**。于是"设了字体"与"没设字体"在产物上看起来一样，而用户无从判断。

第 2 点才是 P0-1 验收的真正阻塞：**只改 P0-1 会得到一个无法证伪的绿灯**。

### 1.2 字体从哪来（🔴 下载过程与验证）

`raw.githubusercontent.com` / `unpkg` 的 8MB 级下载在本机极慢（首次尝试 8 分钟 0 字节，被kill）。最终从 unpkg 上的 `@expo-google-fonts/noto-sans-sc@0.2.3` 取到 TTF，6.9s / 8.3s 成功。

**下载后逐项校验**（不自制解析器下结论，见 §七）：

| 查什么 | 怎么查 | 结果 |
|---|---|---|
| 是不是 TrueType | 读 sfnt 头 4 字节 | `OTTO` = **CFF 轮廓**，所以扩展名改成 `.otf`（诚实命名） |
| 是不是 Noto Sans SC | `name` 表 nameID 1/2 | `Noto Sans SC` / `Regular`·`Bold` |
| 字重对不对 | `OS/2.usWeightClass` | 400 / 700 ✅ |
| 有多少字 | `maxp.numGlyphs` | 30900 |
| **中文字形真的在吗** | 读 `cmap`，**按 format 12 分组查找**（不是 format 4） | 中文/日文假名/全角标点/拉丁全部命中 |
| 韩文在吗 | 同上 | 🔴 **U+D55C / U+AE00 → glyph 0，缺字** |

> 🔴 **韩文缺失是本项的已知限制**（§六）。这一条是**读 cmap 得来的**，不是看文件名猜的 —— P9.3 恰好因为漏读 `idRangeOffset` / `format 12` 子表而误诊过一次，所以这里刻意用 format 12（该字体 5 张cmap 子表里最全的那张）。

### 1.3 方案：新增 `bundled_fonts.dart` 作为**契约**，不是配置表

```
lib/foundation/bundled_fonts.dart   ← 打包字族表 + resolveFamily + 选择器候选
lib/foundation/image_translation/page_renderer.dart   ← 成品渲染走 resolveFamily
lib/components/text_block_canvas.dart                 ← 画布渲染走 resolveFamily
lib/pages/translation_studio/studio_block_panel.dart  ← 字族下拉
pubspec.yaml                                          ← fonts: 注册
assets/fonts/{NotoSansSC-Regular.otf, NotoSansSC-Bold.otf, LICENSE-NotoSansSC.txt}
```

`resolveFamily` 的三条规则：

| 请求 | 结果 | 为什么 |
|---|---|---|
| 空 / 缺 `font_family` | → 打包字体 | 老工程里"缺失"是常态，而"缺失"不等于"用系统默认" |
| 已打包 family | 原样返回 | 不许被"清洗" |
| **其它任何值** | → 打包字体，`fallback=true` | 这条是核心：不让未知字体静默落到平台字体 |

另有一张**别名表**（雅黑 / 思源黑体 / Noto Sans CJK SC → Noto Sans SC）。只映射**确实等价**的无衬线 CJK；**不**映射任何衬线/手写体 —— 悄悄替换等于伪造用户意图。

#### 🔴 一处刻意的行为变更

`_fillStyle(style == null)` 那条**无 FT 格式的旧路径**也从"不指定 family"改成了"用打包字体"。理由：这条路径服务的是旧 OCR 管线与历史产物，在没装中文字体的机器上它画的是豆腐块，而症状（有框没字）看起来像检测器坏了。不改的话，"中文字体不依赖系统字体"这条验收在**最需要它的那台机器上**恰好不成立。

代价：已渲染的历史产物**不变**（位图在磁盘上），只有**新渲染**的页面会用打包字体。

### 1.4 否掉的方案

| 否掉 | 原因 |
|---|---|
| 直接把 `Microsoft YaHei UI` 注册进 `fonts:` | 那是**微软的字体**，没有再分发权，不能打包 |
| 只在 `page_renderer` 改，画布不改 | P9.4 §六 已指出两条渲染路径**不共享代码**；只改一边的症状是"预览和导出不一致"，而这类不一致不报错 |
| 把 family 名写进 `FontFormat.defaultFontFamily` | 那是**写进 FT 工程 json 的值**。改它会让所有历史工程在 FT 里打开时字体对不上 |
| 在 `resolveFamily` 里枚举系统字体并"有就用" | 那样"不依赖系统字体"这条验收自动作废，且不同机器产物不同 —— 不可复现 |

### 1.5 面板字族选择器（S8 遗留⑤）

新增 `_FamilyField`：下拉列出**打包字族** + 当前块那个（若未打包，标红并注明"应用未打包"）。

**下拉里必须列出未打包的那一项**：不列的话，用户打开 FT 工程会看到面板显示打包字体、json 里却是另一个名字，"我明明有那个字体"就变成了一个像 bug 的现象 —— 而真相是那个字体根本没进这个应用。

## 二、P1-3 · 气泡聚块 + 阅读顺序（方案 A）

### 2.1 两层"聚类"的分工（这是本项最容易搞混的地方）

仓里已经有 `clusterOcrBoxes`（`translation_worker.dart`），也叫聚类。两者目标不同，**阈值也因此必须不同**：

| 层 | 位置 | 输入 | 目的 | 犯错的代价 |
|---|---|---|---|---|
| `clusterOcrBoxes` | worker 内，isolate 侧 | DBNet 文本**行**框 | 把同一气泡内的多行并成一个 OCR 输入，**为了识别准确率** | 合并错 → OCR识别崩坏 |
| **本项** | `balloon_clustering.dart`，主isolate | 已 OCR 的**行** | 聚成**气泡**（版面单元）+ **阅读顺序**，**为了工程块粒度与校对顺序** | 合并错 → 一个块太大，逐字校对变累 |

所以本层**允许**比 worker 层更激进的合并：气泡大一点只影响排版，不影响识别；反之 worker 层不敢激进。

### 2.2 算法（三步，全部纯几何）

```
1. 合并行   并查集：允许间隙内相交 ∧ 方向一致 ∧ 字高比 ≤ 2.2
2. 切列     x 投影上"覆盖率为 0"的纵向缝隙 ≥ 4% 页宽 → 切一刀
3. 排序     列沿阅读方向编号（右起 = 0 是最右列），列内按 top 从上往下
```

**用并查集而非按顺序贪心两两合并**：并查集对传递性是自然的（A~B、B~C ⇒ A~C），贪心在检测器不保证输出顺序时会漏合并。

**间隙阈值全页统一**（`medianHeight × 0.6`，夹到 `[6, 90]`），而不是逐对计算 —— 逐对会让阈值取决于"谁先被看到"，于是同一页两次跑可能给出不同的气泡数，而用户无法分辨那是模型抖动还是代码不确定。

#### 🔴 切列**明确不做**"横向重叠即同列"的传递闭包

这是本项最关键的一个决定。三个气泡排成阶梯时 A~B、B~C 立刻全并，整页被当成一列从上往下读 —— **恰好是本项要修的那个错**。改成"找零覆盖缝隙"之后，阶梯形排版得到三列。

有断言专门锁它：`cluster.staggered_not_merged_into_one_column`。

### 2.3 参数取值依据（不拍脑袋）

| 参数 | 值 | 依据 |
|---|---|---|
| `gapFactor` | 0.6 × 字高中位数 | 气泡内相邻行行距通常是字高的 0.2~0.5 倍；相邻气泡之间至少隔半个气泡短边（900×1778 页面上普遍 20~60px）。0.6 能桥接气泡内行距、跨不过气泡间空隙 |
| `maxGap` | 90px | **必需的上限**。不设时两个并排的大气泡会被横向桥接成横跨半页的巨块；90px 已接近一个气泡的短边 |
| `minGap` | 6px | 比6px 更小的"间隙"是检测抖动，不是排版 |
| `columnGapFactor` | 4% 页宽 | 分栏/多格版面的列间距通常在页宽 4%~10%；取下限以免把"同一格子里左右两小段"错判成两列 |
| 字高比上限 | 2.2× | 漫画里小字注释与大号旁白并排常见；强行合并会让 `medianLineHeight` 取折中值，两头不讨好 |
| `lineHeight` 聚合 | **中位数** | 它唯一的作用是给译文字号封顶；均值会被一个异常高的框拉走 |

### 2.4 否掉的方案

| 否掉 | 原因 |
|---|---|
| 「同一行内左右相距过远就不合并」 | 看起来合理，但**分栏版面里同一个气泡的两行本来就可能左右错开**（竖排），加上它会把竖排气泡拦腰截断。改由 `maxGap` 兜住跨气泡误合并 |
| 逐对计算间隙阈值 | 见§2.2，破坏确定性 |
| 把聚类写进 `translation_worker` | 那里是 isolate 侧，拿不到 `RgbaImage` 以外的东西，且**主isolate 侧的气泡框要直接进工程模型**，跨 isolate 传几何没有好处 |
| 让聚类顺便采样颜色 | 采样要 `RgbaImage`；聚类层刻意只依赖 `IntRect`，这样它能被 headless 直接测 |

### 2.5 方案 B 的扩展点（不做，但接缝固定）

```dart
abstract class BalloonDetector { Future<List<DetectedBalloon>> detect(DetectedPage page); }
class PureGeometryBalloonDetector implements BalloonDetector { ... }   // 方案 A
```

`DetectedPage` / `DetectedBalloon` **只带纯几何**，不 import 任何 OCR 类型 —— 外部检测器不该被本仓的 OCR 形状绑住。

`cluster.detector_extension_point_exists` 断言锁住这个接口不许消失：将来换模型实现，若接缝动 了，落地路径（最贵的部分）就要重写。

## 三、P1-5 · 工作室触发入口

### 3.1 根因：两条引擎，一个分叉

旧 AI 翻译引擎把产物写进**阅读器 OCR 缓存**（`pageTranslation@2@…`），工作室工程完全看不到它。本项把产物写成**工程的 `TextBlock`**，工作室立刻能编辑、能撤销、能存进 FT 的 json。

> 反过来也成立：工作室里的编辑不会流回阅读器缓存。**两条路各自完整，S9 之后也不合并** —— 合并要等 P10。

`pipeline.studio_does_not_use_legacy_engine` 断言锁住这个分叉。

### 3.2 进度/取消：**不复用** `PreTranslationTaskManager`

题面允许复用，但本项选择不复用，理由写在这里：

- 那套状态机绑在旧引擎的章节/分组模型上（`eid`、group committer、断点游标）；
- 拉过来就得连带把**旧缓存写入口**一起拉进来 —— 那正是本项要避免的；
- 失败模式是"跑完了，作品里一个字没变"，**完全静默**。

改为一个 `CancellationToken`（页边界检查）+ 一个计数器状态对象。

### 3.3 落地必须走脏页登记单一入口（硬规矩 3）

批量建块与 Create/Delete 块**共用同一条路径**：

```dart
captureBlockListEdit(page.rawBlocks, () => page.addBlocks(fresh),
                     pageKey: pageKey, label: 'Detect blocks')
  → _history.push(command)
```

`ProjectPage.addBlocks`（新增）而不是循环 `addBlock`：**一次批量运行 = 一个 undo 步**。一章 97 页 × 平均 8 块 = 776 步，而 `EditHistory.limit` 是 200 —— 逐块 push 会把用户最早的编辑挤出 undo 栈，"跑错了能一键回退"就不成立了。

### 3.4 失败 / 部分成功 / 兜底

| 结局 | 行为 |
|---|---|
| 全成功 | 自动 `_save()`（一批块可能是几十页的量，跑完不存等于还要按一次 Ctrl+S） |
| 有失败页 | **不自动存**；状态栏红字报 `@b/@c 页共 @a 个块，@d 页失败` |
| 用户停止 | **不自动存**；`Stopped after @a of @b pages` |
| 页面图不在盘 | 计为失败，**不静默跳过**（Error the Echo 就是原图已删的工程） |
| 漏检 | `skipped` 行数 + 面板上明确指向 Create 块 / 框选新建 |

三种结局必须能被一眼分开。混成一句"完成"就会让**漏掉的页被当成已处理**。

### 3.5 去重：只读，绝不改

`overlapsExistingBlock` 单独拎出来是因为它有一条硬约束：**只能读既有块**。整章重跑时用户已经校对过的块必须原样保留 —— 覆盖它们等于丢掉人工工作。

这与 P9.5 那条「`det_model` 必须留空，否则下一轮 re-detect 把它当自己的输出」是**同一条理由的两面**。

默认**开启**去重（`_pipelineSkipExisting = true`）：整章重跑是最容易点错的按钮，而人工校对过的块比新检测的块更值钱。关掉它等于允许批量运行覆盖人工工作，那必须是明确选择，不能是默认值。

### 3.6 会话内状态 vs 落盘

`_pipelineRightToLeft` / `_pipelineTranslate` / `_pipelineSkipExisting` 三项是**会话内**状态，不进 `appdata`、不写工程 json。理由：它们描述的是"这一次怎么跑"；写进工程会让**零字节 diff 立刻破掉**。

## 四、被断言抓到的问题（这一节是本批最有价值的部分）

### 4.1 🔴 列指派漏赋值 → 右起漫画被当成单列读

第一次跑，`cluster.reading_order_right_to_left` / `left_to_right` / `column_reads_top_to_bottom` / `staggered` **四条同时 FAIL**，detail 是 `[左@col0/#0, 右@col0/#1]` —— 所有气泡的 `column` 都是 0。

根因在 `_assignColumns`：

```dart
if (group.bounds.left - rightmost >= minGap) {
  column++;
  rightmost = group.bounds.right;
  continue;              // ← 这一行跳过了下面的 assignment[group] = column
}
assignment[group] = column;
```

于是**每一列的第一个组都保留了初值 0**。症状是"阅读顺序静默退化成从上到下" —— 而那正是本项要修的东西。若没有这四条断言，这个 bug 会带着一个全绿的报告进 P10。

### 4.2 🔴 断言自己抛异常，吞掉后面 9 条检查

修好 4.1 之前，`cluster.bridge_keeps_per_line_erase_rects` 里`oneBubble.first` 抛了 `Bad state: No element`；`edit-check` 的 catch 把它当成整批异常，于是**第 15 条与后面 9 条 `pipeline.*` 断言根本没跑**，而报告里根本没有它们。

这不是假绿，是**根本没执行**。所有 `.first` / `[0]` 都加了长度守卫，且失败时报告"必须不抛异常"而不是让异常吃掉整批。

### 4.3 🔴 我的断言自己写错了两次

| 断言 | 报的假 FAIL | 真因 |
|---|---|---|
| `font.registry_matches_pubspec` | `yaml=[Noto] table=[Noto Sans SC]` | 正则用 `family:\s*(\S+)`，把有空格的名字截成 `Noto` |
| `pipeline.studio_does_not_use_legacy_engine` | 报 studio_page 用了旧引擎 | 匹配到的是**解释"为什么不用"的那句注释** |

两条都是 P9.3 那条元教训的复现：**断言与代码冲突时先怀疑断言**。修法分别是"捕获到行尾"与"先剥注释再扫"。

### 4.4 一个 DTO 不诚实

`_fillStyle` 里的 family 一开始写成 `.ttf`，而下载下来的二进制是 `OTTO`（CFF）。断言 `sfnt==0x00010000` FAIL 之后才改成 `.otf`。**内容一样，扩展名要诚实。**

### 4.5 🔴 管线主循环里三个静默 bug（断言测不到，靠逐行读代码发现）

这三处都**不会**被 `edit-check` 抓到（它测的是聚块算法与落地接缝，不跑真实检测），但会让工作室里的按钮"看起来能跑"：

| # | bug | 症状 |
|---|---|---|
| 1 | 用**气泡外框**反查 `OcrBlock` 取颜色 | 气泡外框是**若干行的并集**，几乎不可能等于任何一行的矩形 → 整页产出 **0 块**，且**不报错**。改为**逐行**回查 |
| 2 | `ocr.ready` 是 `List<TranslatedRegion>`（zh→zh-TW 已转好），却用 `is OcrBlock` 过滤 | 整类区域被**静默丢弃**；一个"中文源 + zh-TW 目标"的工程跑管线产出 0 块 |
| 3 | 三条 `continue` 路径（缺图 / 检测失败 / 页不在工程）各自 `continue`，**都没走 `_pipeline.done++`** | 进度条在遇到第一个失败页时**永远停在 N-1/N** —— 而"进度条卡住"正是用户判断"是不是死了"的依据 |

第2 条的修法还牵出一个下标错位：`readyTranslations` 一开始按**气泡下标**记，而 `sources` 只在"该气泡有待翻译行"时才增长 —— 两者不是一回事，译文会写到错误的块上。**内容错位而不报错**，比崩溃更难发现。

> 这一节的教训与 §4.1 不同：§4.1 是**断言抓到了我**，这一节是**断言没抓到我**。断言只能覆盖它写下来的那些性质；主循环的错误路径属于"必须读一遍"的部分。

### 4.6 🔴 反向验证工具自己坏了三次（第三次最隐蔽）

三次都在**测量工具**而不是被测代码上，而每一次都产出了一批看起来很像结果的数字：

| # | 工具 bug | 后果 | 修法 |
|---|---|---|---|
| 1 | `revert` 把备份写成 `basename`，还原到 `VeneraX/<name>.dart` 而不是 `lib/foundation/...` | 故障文件留在原地 + 野副本 → 下次构建相对 import 失败 → **整批 35 项全丢** | 记相对 PKG 的路径 |
| 2 | 批量跑 35 次时每次 `os.remove(builds/headless.out)`，触发环境的批量删除保护 | 第 50 次之后每次都被 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 拒绝，7 项静默无结果 | 那次删除本就多余（bat 里的 `>` 已经截断），删掉 |
| 3 | `apply` 沿用已存在的 `.rvbak`；而上一轮被杀的任务留下了备份 | 备份的是**已经带故障的文件** → `revert` 还原成带故障的版本 → **故障逐轮累积**，每一项的结果都**偏移一位** | `apply` 总是覆盖备份；驱动脚本新增"树必须干净"的**前置检查**与"还原后必须干净"的**后置检查**，并把"打破的断言不是目标断言"判为 **OFF-TARGET BREAKAGE**（结果不可信） |

第3 次的识别线索是报告里的 `also broke` 列：如果每一次故障都额外打破**上一个**故障的断言，那就不是代码的问题，是**树被污染了**。

> **第 4 次**（`cmd_revert` 把"还原成功"押在 `os.remove(backup)` 这个副作用上，而本环境给 Python 的删除**也**上了"每轮 50 次"配额）是在**第 2 批**跑到一半时才暴露的 —— 它让 `pubspec.yaml` 丢掉整块韩文字族，而之后 26 条测量全在那棵已坏掉的树上做。**静默的还原失败比响亮的失败坏得多：它把一个 bug 变成一串数字。** 详见 P9.7 §6.2 第 4 行。

> 这条元教训值得单独记住：**一个批量实验工具的输出，必须能被独立检查出"实验条件确实成立"**。否则它给出的是一串数字，而不是 35 个结论。

| # | 限制 | 影响 | 后续 |

## 八、🔴 需要用户人工验证的项（headless 测不到）

### 8.1 字体（P1-4）

1. 打开任意 FT 工程 → 属性面板 → **Font family** 下拉：应列出 `Noto Sans SC`，并显示 `stored as "Microsoft YaHei UI", renders as Noto Sans SC`（若工程是默认字族）。
2. 切到 `Noto Sans SC` → 保存 → 看 `result/`：**中文必须出字，且字形要与打包字体一致**（不是雅黑）。
3. 面板里换成一个**不存在的字体名**（可手改 json）→ 渲染必须仍出中文（回退到打包字体），而不是变成方块或衬线字。
4. 画布预览与导出成品**必须字形一致**（这是 `font.preview_matches_output` 断言在保护的那件事，但只有眼睛能确认渲染结果）。
5. 粗体（Font weight 700）应与常规有明显粗细差。

### 8.2 聚块与阅读顺序（P1-3）

6. 对 `My Dragon Girlfriend Has Returned` 跑一页，**与 FT 的检测框数量对比**（漏检/误检可接受度是S9 验收第一条）。
7. 右起日漫：进度条推进时，块应当**从右往左、从上往下**出现。
8. 竖排气泡的译文**不得左右颠倒**。
9. 多格/分栏页面：同一格里的上下两段文字应聚成不同气泡，不该跨格合并。
10. 观察 `cluster.blank_lines_ignored` 的真实对应：若某页检测出大量空白行，页面上的块数会偏多 —— 那说明检测器噪声大，不是聚类问题。

### 8.3 触发入口（P1-5）

11. 单页运行 → 块应出现在画布上，状态栏显示 `N blocks on 1 pages`。
12. 整章运行 → 进度条走；**跑到一半点停止** → 已完成的页应保留，状态栏 `Stopped after N of M pages`，且**不自动保存**。
13. 失败注入：把某页的原图改名 → 该页应计入失败、状态栏红字报失败页数、**其他页照常完成**。
14. 同一页**跑两次** → 第二次应因去重而不新增块；关掉"跳过已有块"再跑 → 应新增块（这会覆盖，所以默认必须开）。
15. 批量跑完按一次 Ctrl+Z → **整页新块全部回退**（不是只退一个）。
16. 跑完**不按 Ctrl+S**，直接关窗 → 应弹未保存提示。
17. 漏检兜底：面板上出现"有 N 行文本被跳过"时，用 Create 块 / 框选新建补上。

### 8.4 交叉回归

18. 打开一个**已渲染过**的历史工程，只切别的字段保存 → `result/` 应**只重渲那一页**（脏页增量，P9.1），且新旧字形不同（因为现在用打包字体了，这是**预期内的视觉变化**）。
