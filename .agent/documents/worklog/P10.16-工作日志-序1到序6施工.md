### 序1 · #4 全量产物重生成 + 产物对账表（§3.1）

**为什么**：S9.5-a 的「78 页 `inpainted` 有 / `mask` 无」在磁盘上要一页一页 `ls` 才看得出，
而且"缺"有**六种**原因（本来没字 / 没有译文 / 超解码预算 / 原图不在 / 底图缺 / 成品缺）。
分不出就等于静默。

**改了什么**

- 新增 `foundation/translation_project/artifact_reconciliation.dart`（零 Flutter 依赖，可 headless 断言）：
  - `ArtifactReconciliation.reasons` = `ok / no-blocks / no-translation / downscaled / source-missing / base-missing / result-missing`；
  - `maxPixels = 12*1024*1024`、`maxDimension = 8000` —— **与 `result_renderer._decodeBounded` 同一组数**，
    否则对账表会把"刻意不产出"记成"缺产物"（一种新的静默）；
  - `pathFor / build / write / read / statusFor / isBeyondDecodeBudget`；文件名 `imgtrans_<名>.artifacts.json`。
- 🔴 `_reasonFor` 的**判序**是这一条链路的命门：`no-blocks` → `downscaled` → `no-translation` → `source-missing`
  → `base-missing` → `result-missing`。`no-translation` 必须排在 `base-missing` **前面**（底图只对有译文的页产出），
  写反会把"刚检测完、还没翻译"的整片页报成缺口。
- `read()` 显式归一：`if (decoded is! Map) return null; else {for (entry in decoded.entries) ...}`。
  **不能**写 `decoded is Map<String, Object?>` —— `jsonDecode` 交出 `Map<String, dynamic>`，
  那条判据不保证成立，一旦为 false，一份**真实存在**的对账表会被读成"没写过"。
- `studio_page.dart`：`ArtifactReconciliation? reconciliation` → `File? reconciliation`
  （`write()` 的返回类型是 `Future<File>`）。

**反向验证**：`bootstrap-check` 里 7 条 `reconcile.*`，每条绿/红双路径。
其中 `untranslated_page_is_not_a_gap` 的故障路径与它**只差一个判序**。

### 序2 · #9 画布字号与产出对齐（§3.2）

**根因**：两条链路各算各的字号 —— `result/` 走 `page_renderer._fitFontSize()`（cap `min(42, lineHeight×0.9, font_size)`
+ shrink-to-fit），而工作室画布按 `block.fontSize` 直接画并加 `maxLines + ellipsis`。
实测那条块 `_detected_font_size = 76`、框高 121 → 产出被压到 42 塞得下，画布按 76 画只剩 1 行，
**「…」是画布自己加的**，不是译文里的字符。

**改了什么**：`components/text_block_canvas.dart` 改为**镜像** `page_renderer._fitFontSize`（同一个 cap +
同一个 shrink-to-fit，`_fitFontSize` at `:672`），去掉 `ellipsis`；`studio_page.dart` 只把**原始**字体族交给画布，
由画布解析（`fontFamily: format?.fontFamily ?? FontFormat.defaultFontFamily`），避免双重解析。

**验证**：`edit-check` 的 `font.preview_matches_output`（源码扫描：画布必须解析、不得透传原始族名、
页面不得自己解析）+ `edit-check` 全绿。

### 序3 · per-line `eraseRects` 打通（§3.3）

**根因**：检测链路**本来**给出逐行紧密矩形（`balloonToOcrBlock` 填 `eraseRects: [for (l in balloon.lines) l.rect]`），
但 `TextBlock.fromOcr()` 不写 `erase_rects`、`toTranslatedRegion()` 也不读 ⇒
`TranslatedRegion.eraseRects` 落到构造函数兜底 `[rect]` ⇒ **抹字按整个块外框做**，
块框内的美术（气泡尖角、贴纸边）会被一起抹，而且不报错。

**改了什么**

- `fromOcr`：**只在 `eraseRects.length > 1`** 时才写 `erase_rects` 键 ——
  "块外框 == 唯一擦除矩形"的常见情形不落盘，旧块本来就没这个键，**零字节 diff 不受影响**。
- `toTranslatedRegion` → `_eraseRectsOrDefault(rect)`：优先读 `erase_rects`，缺失/损坏回落整块外框；
  只接受 **≥2×2 px** 的矩形（更小的擦不出笔画，却让 `TextInpainter` 多跑一轮搜索窗）。

**验证**：`edit-check` 的 `cluster.bridge_keeps_per_line_erase_rects`（3 行 → `eraseRects.length == 3`）。

### 序5 · #3 原图副本 + 双 root 分离（§4.1 · P1「全部迁移」）

**为什么（这条推翻了上一版的设计）**：上一版刻意"原图不复制、`directory` 直接指下载目录"。
那个决定是**错的** —— 抹字是**破坏性**的（`TextInpainter.erase` 就地改像素），
底图取 `downloads/` 里**唯一**那份原图，一次逻辑错就是**擦掉用户的原图**。
副本化把风险从"数据丢失"降为"重跑一次"，代价是磁盘。

**改了什么**（`foundation/translation_project/project_bootstrap.dart`）

- `sourceDirectoryName = 'source'`；`ProjectBootstrap.copySources({root, plan, fromDirectory})`
  按**页键**逐个复制（不是整目录复制 —— 那会把 `notes.txt` / `.DS_Store` / 子目录一起搬进工程根）。
  🔴 **副本根一定会被建出来**（即使一页都没复制成功）：`TranslationProject.directory` 在目录**不存在**时
  会静默回落到 json 所在目录，于是"json 指着 `source/` 而 `source/` 还没建"这个中间态在界面上完全正常，
  读的却是错的目录。建出来就把这种静默堵死。
- `create(copySources: true)`（产品路径）：**先复制、后写 json**。顺序反过来会留下上面那个中间态。
  `directory` → `<工程根>/source`，且**仍不写 `workspace` 键**（FT 自己也不写，写了就是编造）。
  由此 `directory`（原图根）与 `workspace`（产物根）是两个**真实存在**的不同目录 ——
  `ProjectWriter` 那套 "Two roots, one implementation" 才真正成立。
- `migrateSources({jsonFile})`：既有工程（`MDGH-ch1`）的"复制原图 + 改 `directory`"迁移。
  - **幂等**：已经迁过（`directory` 已指向存在的 `source/` 且页图齐全）直接返回 `alreadyMigrated: true`，**一个字节都不写**；
  - **顺序**：全部复制成功之后才改 json；中途缺页时**不改 json**（半迁移状态会触发静默回落，读的是错目录）；
  - 新增 `ProjectBootstrapCopy` / `ProjectBootstrapMigration` 两个结果类型。
- `bt_project_manager.dart` 的 `createFromDownload` 文档同步（约束 1 从"不复制"改为"复制进 `source/`"）。
- `tools/_make_chapter_carrier.py` 文档同步：标明产品路径已反过来，该脚本只用于造一次性夹具。

**新增 headless 命令**：`migrate-sources <project.json> [--json out] [--verify-only]`
（`headless.dart::runMigrateSources`，**在 `init()` 之前**跑 —— 它必须在"没有 `downloads/`"时也能跑）。
`ok` 的四个条件缺一不可：有页、没有解析不到的页、`directory` 存在、**且 `directory` 不在 `downloads/` 之下**
（最后一条是迁移前/迁移后唯一的分界）。

**真实验收（序5 的可反验证判据）**

```text
① 迁移：  previousDirectory = ComicLibrary/downloads/My Dragon Girlfriend Has Returned
          directory         = ComicLibrary/projects/MDGH-ch1/source
          copied=94  missing=0  wroteJson=true  dualRootSeparated=true
② 移走 downloads/（改名 <dir>.__hidden）
③ 验证：  migrate-sources --verify-only
          → Migrate sources OK: pages=94 missing=0 ownCopy=true   ← 工程不再需要 downloads
④ 恢复 downloads/（1021 个文件原样回来）
```

**断言**：`bootstrap-check` 新增 6 条 —— `copy.sources_land_under_own_source_dir`（逐字节比对，
不只查存在性）、`copy.skips_non_page_files`、`copy.directory_points_at_the_copy_not_downloads`、
`migrate.copies_then_rewrites_directory`、`migrate.is_idempotent`、`migrate.downloads_still_untouched`。
上一版那条语义已反过来的 `sources_not_copied` 被**删除**。

### 序6 · #11 sfx 标记（§4.5）（数据层）

**改了什么**

- `text_block.dart`：新增 `label` getter/setter（FT 的 `label` 键本就在 `createDefault` 里写成 `null`，
  所以"没标记"和"标记过又清掉"在 json 里是**同一个形状**，零字节 diff 不受影响）。
- `studio_block_ops.dart`：新增 `StudioSfxOps`（纯函数）。
  - `looksLikeSfx(text, {required language})` 三条**同时**成立才判 SFX：
    源语言是 `en`/`ko`（[languages]）；去空白后 ≤ 5 字符；不含中日文字，且
    韩文**只有 1 个音节**、或拉丁**全大写**且 ≥ 3 个字母。
  - 🔴 判据刻意收得很窄：**误标的代价是"一句真对白默认不译"**（要人点一下才回来），
    漏标的代价只是"多问一次模型"。两者不对称，所以宁可漏。
  - 🔴 韩文只收**单音节**：「두근」（拟声词）与「안녕」（台词）**字数完全一样**，
    靠字数判必然误标 —— 这一条只有词典能解决，现在没有。
  - 已知误标（可接受）：全大写短问候语，如 `HELLO` / `OK!`。
- `studio_pipeline.dart`：在翻译**之前**算一次 `sfxIndexes` 下标集合，同一条判据驱动两件事
  —— ① 不进翻译批次（`_translate(..., skip: sfxIndexes)`）；② 建块时 `block.label = StudioSfxOps.label`。
  算一次传下去，两处就不可能判出不同结果。
  - 标记写在 `fromOcr` **之后**而不是塞进 `fromOcr`：`fromOcr` 是纯映射（OCR 载荷 → FT 块），
    "哪些块算拟声词"是**策略**；混进去会让"检测到的块"与"手工建的块"在形状上分不出差别 ——
    而那正是零字节 diff 与 `fromOcr` 那批断言赖以成立的前提。
  - "不改字"是**自动**成立的：`translation` 为空 ⇒ `toTranslatedRegion()` 返回 null ⇒ 不 letter、
    也不产生 `region` ⇒ 抹字区域里没有它 ⇒ **原字原样留在图上**。
- `studio_page.dart` 的 `_runBlockStages`（只识别/只翻译那条路）：批量翻译前 `if (StudioSfxOps.isMarkedSfx(block)) continue;`。
  刻意**不**在该段给旧块补标记 —— 那一段的语言来自"用户这一轮选的语向"，
  而标记必须依据块**自己**的检测语言，否则同一页会因为用户换了语向而得到不同标记。
  **标记只有一个产生点**：`StudioPagePipeline.runPage`。
- 人工兜底：块面板上的【翻译】是**单块**动作、**不看**这个标记 ⇒ 误标一次点击就能回来，不是死路。

**断言**：`block-ops-check` 新增 7 条（`sfx.*` + `wiring.*`），含
`sfx.never_marks_a_cjk_source`（忽略源语言时会变红）与
`wiring.pipeline_marks_sfx_and_excludes_them_from_the_batch`（只打标记不跳过 ⇒ 变红）。

**本序未做（有意）**：sfx 的 **UI 筛选**（列表/面板上的筛选项）与 i18n 文案。
本轮只落数据层（`label` 在 json 里可筛、可被后续 UI 直接消费）。
