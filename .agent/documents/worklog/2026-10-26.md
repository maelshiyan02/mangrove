### B. 新文件 `context_repair.dart`（纯 Dart，可 headless 断言）
三层能力，全部作用在**源像素**域：

1. **物体级掩膜** `buildWatermarkMask`
   - 双层窗口：检测区 `ctx`（块框外扩 max(30%, 24px)）+ 背景取样区 `outer`（再外扩一圈）。
     🔴 **预测必须从 outer 取**：块框贴着水印时，ctx 边界还在水印自己身上，
     从那里预测会把水印底色预测出来，残差≈0，检测直接失败。
   - 残差种子 → `k=3` 颜色聚类 → 连通生长（限 ctx 内）→ 闭运算 → 去小块 → **填洞** → 膨胀 2px。
   - 种子不足时**退回整块块框**：水印必须消失，"没检出来"不能变成"留着"。
2. **结构填充** `repairRegionInPlace(quality: structural)`
   - 四方向射线插值（权重 1/(d²+1)）+ Jacobi 松弛，替代原 `TextInpainter.erase` 的
     最近邻 chamfer（长条洞会填成放射性条纹）。
3. **纹理填充** `repairRegionInPlace(quality: texture)`（面板的【AI 修复填充】）
   - 块级 Criminisi 式 patch 合成：按距已知像素远近排序 → 在 outer 环带里找最相似块
     （已知像素权重 10、已填像素 3）→ 70% 覆盖，避免块边界硬缝。
4. `buildResidualTextMask`：普通文字块的**补漏**掩膜（残差 + 去小块 + 膨胀 2），
   与字形掩膜取并集，治"擦完还留着半个字"。
5. `mosaicWithBackgroundInPlace`：马赛克向**上下文预测底色**融合（默认 0.75），
   黑底读作近黑、裙子读作裙子色；`backgroundBlend: 0` 即经典保留原色马赛克。

### C. 接线（`studio_page.dart` / `studio_block_panel.dart`）

# P48 第五轮人工验收整改 · ONNX LaMa 接入（2.8.21+265）

## A. 写入范围 = 选区（唯一真相）

- 新增 `selectionMaskOf(width,height,rect,polygon)`（`polygon_mask.dart`）：先栅格化
  多边形，**再与块矩形取交集**。
- 🔴 为什么还要取交集 —— 真实数据里两条诉求会打架：`003.webp` 的手绘 lasso 有 196 个
  顶点，包围盒 (372,415,224,108) 比水印块框 (389.5,437.1,585,487.4) 高出 22px、向下
  多出 36px，下缘压到蓝色头发上。纯按多边形涂黑后 `ViewImage` 实测**头发被一起刷黑**，
  正是用户说的"又多了一圈"。取交集后 `selectionPixels` 9750(矩形) → 18646(纯多边形)
  → **9394**(交集)，黑块只落在黑带上、头发完好。
- 例外：交集为空（画笔整个画在块框外）时退回纯多边形，避免"点了没反应"。
- `repairRegionInPlace` 窗口 pad 分档：纹理档 `max(24, min(bw,bh)*0.35)`。此前 pad=3，
  写入区域=整片选区时窗口里放不下一个干净的 8×8 patch ⇒ `sources` 为空 ⇒ 直接 return
  ⇒ 纹理档与结构档输出**逐字节相同**（静默空操作）。

## B. 纯色底直填

- `detectFlatBackground(image, rect)`：取样**选区外环带**（ring = max(8,min(48,min(bw,bh)*0.45))），
  量化到 16 级/通道统计主色桶；命中条件 = 主色占比 ≥0.62 **或** 四条边里 ≥3 条各自
  "压倒性"（≥0.65）同色，且主色平均偏差 ≤10。命中则整片选区刷该色，不插值。
- 🔴 取样框只认**块矩形**，不认多边形外接框（`detectFlatBackground` 已移除 `polygon` 参数）。
- 🔴 弱多数陷阱：第 10 页水印右/上贴白页边，左/下是渐变闪粉 —— 三条边"多数色"都是白但
  两条只有 0.30~0.50。按"计数≥3 就平色"会整块刷白（用户截图里那块白方块）。
  已加 `edgeBest/edgeTotal >= 0.65` 门槛。

## C. ONNX LaMa 接入 —— 以及那个骗了我们两轮的 bug

- 模型：`Carve/LaMa-ONNX` 的 `lama_fp32.onnx`（208,044,816 B，Apache-2.0），走已有
  `OrtFfiSession`（FFI，绕开 platform channel），推理放 `Isolate.run`。
- 契约（`onnxruntime` 实测）：`image [1,3,512,512] float`、`mask [1,1,512,512] float`，
  **1 = 要修**；输出 `[1,3,512,512] float`，量程 **0..255**（max 实测 247）。
- 🔴🔴 **本轮最贵的根因**：Dart 侧按 **HWC** 填/读张量（`(y*size+x)*3+c`），而模型声明的是
  **NCHW**，ORT 严格按声明顺序消费那块扁平内存 ⇒ 三个通道整体错位。不报错、不崩，
  症状是"水印原样保留 + 整片噪声块"。肉眼极易误判成"模型质量差/模型不对"。
  数值复现：正确布局 `mean|out-clean| = 0.91`，HWC 布局 `= 7.91`，且合成图上的故障
  结果与用户截图**形态完全一致**（水印还在 + 一块块噪声）。
- 修复：抽出 `inpaintImageIndex(c,y,x,size) => (c*size+y)*size+x` 作为单一真相，填与读
  都走它；断言 `inpaint.tensor_layout_is_channel_planar` 直接锁这条公式并用 HWC 公式
  做故障注入。
- 几何：选区外接框 ×1.3 后**补成正方形**再缩 512（保住长宽比，长条水印不被压扁），
  推理后双线性缩回，`_compositeBack` **只写 regionMask 内**。路径必须在主 isolate 求值
  再捕获（`App.dataPath` 在新 isolate 未初始化）。
- 面板文案按 `isInstalled` 分流：`AI fill (LaMa model)` / `AI fill (local texture)`；
  设置页新增 "Image inpainting (erase & reconstruct)" 分组，`isOcr()` 追加
  `&& !TranslationModels.inpainting.contains(c)`（否则修复模型被归进"文字识别"）。

3. **语言导向按钮缺失** —— 用户"没有找到在文字块切面的识别和翻译的地方有调整识别

外加一项工程卫生要求：测试产生的文件已经把 `builds/` 堆成垃圾场（用户截图可见），
"你做测试的素材和记录都放在统一的测试材料文件夹里面"。

## 1 · 加速：耗时的 60% 花在"重读权重"上

`InpaintModel.inpaintRegion` 旧实现每轮 `Isolate.run(...)`，而 isolate 里第一件事是
`OrtFfiSession.open(modelPath)` —— **每轮重新读一遍 200 MB 的 LaMa 权重**，再 `close`。
推理只用一百多毫秒，重读要好几秒，比例完全倒挂。

改法（`inpaint_model.dart`）：

- 常驻 worker：`_lamaWorkerMain(SendPort)` 是一个活着的 isolate，`inbox.listen` 处理
  `warm` / `run` 两种消息，`OrtFfiSession` 只在第一次 `open`，之后**复用**。
  预处理（RGBA→CHW float / letterbox）与后处理也搬进 worker，主 isolate 只收发缓冲。
- `_WorkerClient`：握手 30s 超时、`_pending` map 按 request id 回话、`_serial` 串行链
  （模型不可并发跑同一 session）、单轮 `_runTimeout = 3min`，超时就 `_resetWorker()`
  重建，避免一次异常把 worker 永久挂死。
- MB 级缓冲用 `TransferableTypedData` 传递，免拷贝。
- `InpaintModel.warmUp()`：工作室 `initState` 后 **延迟 3 秒**静默预热（避开首帧抢帧），
  用户第一次点 AI 修复时 session 已经在手。
- `InpaintModel.dispose()`：退出工作室回收（session 常驻 ≈200 MB，不能永远占着）。

另外补了一个**整页解码缓存** `_decodePageCached`（最多 4 条，键 = `path|mtime|size`，
返回副本防调用方就地改缓存）。修复路径原先同一页会被解码 3–5 次（每轮修复、每块修复），
现在只在第一次付解码成本。

实测（`inpaint.second_pass_is_far_cheaper_than_the_first`，真机跑 LaMa）：

| 轮次 | 耗时 | 说明 |
|---|---|---|
| 冷轮 | **6764 ms** | 含 open + 首轮推理 |
| 热轮 | **1226 ms** | 只有推理 |

`opens == 1` 由 `inpaint.worker_reuses_one_model_session` 单独断言。
**画质未变** —— 复用 session 是唯一可以"不牺牲效果"的加速点，这也是选它而不是
降采样/降轮数/换小模型的原因。

## 2 · 语言导向：控件压在它作用的那只框上方

用户的原话是"在原文框上方加一个显示识别到的源文字是什么类型，并且可以主动选择
语言导向；同样译文框上方也要有针对翻译方向的语言导向按钮"。这句话其实规定了两件事：
**放哪里**（框上方）和**放什么**（不只是显示，还要能改）。

块上新增三个字段（`text_block.dart`，全部空值删键 ⇒ 旧工程零字节 diff）：

| 键 | 含义 |
|---|---|
| `source_lang` | 本块识别/翻译的**源语言覆盖** |
| `recognised_lang` | 上次识别**实际采用**的语言（多数票，只写不读作覆盖） |
| `target_lang` | 本块**目标语言覆盖** |

`studio_block_panel.dart` 的布局改成：

```
【Source】  识别为 韩语（整页投票）        [源语言·跟随工程 ▾]   ← 压在源框上方
   [识别到的原文]
【Translation】 韩语 → 简体中文（跟随工程设置） [目标语言 ▾]   ← 压在译框上方
   [译文]
```

为什么 `recognised_lang` 要单独存：多块一页时识别语言由整页投票决定，单块显示"识别为
X"必须显示**实际用的**那个，而不是面板里那个可能被手工改过的下拉值。`_recogniseSelectedBlock`
识别后统计 `langVotes`（跳过空与 `unknown`），多数票写回，日志 `lang=请求->实际`。

`_translateSelectedBlock` 用 `block.targetLangOverride.isEmpty ? _currentTargetLang() : …`，
日志 `applied 源->目标`，这样"跟随工程"与"钉死本块"在日志里一眼能分开。

## 3 · 第三种形状：椭圆（对话气泡）

三条**互相独立**的轴（用户在第六轮之后又逼出一条，所以必须写清楚）：

| 轴 | 决定什么 | 能否缩放 |
|---|---|---|
| `polygon` | 顶点表就是最终形状 | 不能（拖动顶点改形） |
| `shape` | `rect` / `ellipse`，靠 `xyxy` 外接框定形状 | 能（8 手柄） |
| `kind` | 语义种类，只管管线与配色 | — |

优先级：`polygon` > `shape` > `rect`。

- 掩膜：`polygon_mask.dart` 新增 `rasterizeEllipse`，判据 `dx²/rx² + dy²/ry² ≤ 1`
  按**像素中心**取样；`selectionMaskOf(..., ellipse: true)`。**绝不退化回外接矩形** ——
  框内四角属于邻居，退回去就是把别人的画面一起擦掉。断言
  `polygon.ellipse_selection_is_curved_not_a_box` 同时验"中心写 / 四角不写 / 矩形版四角写"。
- 文字内接：椭圆内接矩形系数 `1/√2 ≈ 0.7071`，否则长句会顶到椭圆外。
  `_paintText` 加了 `boxScale` 参数，源像素侧与画布侧同乘，否则字号仍按外接框量。
- 外接框：**只在选中时画虚线**（白 3.0 + 类型色 1.2 双层）。理由：一页十几个气泡都挂
  虚线框会变成噪声，而虚线的语义是"这里可以拖大小"——8 个手柄就摆在这条虚线上。
  与矩形块的实线外框形成区分（用户明确要求"虚线表示，这些可以更好区分"）。

## 6 · 本轮踩的坑（已写进 A23 规则 17–23）

1. **`referenced_before_declaration`**：把 `eraseBefore` / `eraseAfter` 声明写在 probe
   **之后**。Dart 局部变量不提升，哪怕闭包是延迟执行也照样编译错。声明必须在使用点之前。
2. **假绿**：`runBlockOpsCheck` 在 `init()` 前 return ⇒ `App.dataPath` 还是常量
   `/mangrove/data` ⇒ `InpaintModel.isInstalled` 恒 false ⇒ 模型断言走"跳过"分支却显示
   绿色，detail 还写"冷轮 0ms / 热轮 0ms"。修法是在 `runBlockOpsCheck` 开头补
   `App.init()`；**detail 必须明确写"⚠️ 跳过实测"，不能让人当成已验证**。
3. **判据本身失真**：擦除断言原先用"与干净原图的逐像素均差"降到 1/3 以下。夹具是
   高频正弦条纹（周期 ≈ 38 px），重建相位差半周期均差就会大幅上升 —— 实测
   before=126.3 → after=55.0 而水印**其实已擦干净**。改量**掩膜内近白像素占比**
   （条纹 G 通道永远 ≤110，与水印纯白不混淆）：100.0% → 0.0%。教训：判据要量
   "用户关心的事"（水印还在不在），不要量一个方便算的代理指标。
4. **夹具尺度**：96×96 送进 512 模型等于放大 8×，条纹被拉成粗波纹，量到的是夹具失真。
   改 256×256（约 2.7×，与真实页裁剪倍率同量级）。
5. **沙盒跑不了 `inpaint-apply`**：`dart:ui` 要渲染表面，沙盒里报
   `No Impeller context is available` 并卡死，残留进程还会锁住 `builds/headless.out`
   （后续 headless 报 `PermissionError: [Errno 13]`）。像素级效果只能在用户 GUI 会话验。
