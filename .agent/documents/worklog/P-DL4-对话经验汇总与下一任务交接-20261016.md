## 二、经验教训（可复用，按重要性排序）

### E1 任务 id 唯一性原则（本轮最大坑）

- 现象：多选章节修复只出一个「浓缩任务」，队列/下载中弹窗按 id 索引互相
  覆盖，渲染一片空白占位。
- 根因：`RepairDownloadTask.id` 旧为 `repair:$comicId`，整本共用。
- 教训：**队列任务的拆分维度（章/页）必须进 id**。同类多任务并存的场景，
  id = `类型:实体:子维度`；持久化兼容用「新字段缺省回退旧格式」。

### E2 自动模式的防循环 + 去重双守卫

- 触发点选择：下载完成钩子用 `completeTask`；修复任务收尾走 `removeTask`
  （不回到 completeTask）→ 修复完成不会再次触发自动修复，无循环。
- 去重：`enqueue` 入队前检查 `downloadingTasks` 里是否已有同 id 任务，
  有则跳过——否则自动模式撞手动任务会造出同 id 双任务（E1 问题复辟）。
- 模式：先 reconcile 对账再读缺页表，保证磁盘空洞也纳入；失败只记日志
  不影响主流程。

### E3 Appbar/透明背景环境的文字色陷阱

- 现象：模式下拉放在 ContentDialog 的 Appbar 标题行，「手动」白字落在
  白底上看不见。
- 根因：`ts.sXX` 是 `const TextStyle()`（color=null）→ 继承 Appbar 的
  白色 DefaultTextStyle；P47 全局多配色（13 预设 + 自研取色）下继承色与
  背景撞色无法穷尽防御。
- 解法（用户拍板的「双重保障」）：**浅色主题黑字白框、深色主题白字黑框**
  ——Stack 双层 Text（描边层反差色 `Paint()..stroke` + 填充层显式明暗
  色），另加显式 `iconEnabledColor`。已封装为 `_ContrastText`
  （download_manager_dialogs.dart），后续任何「放在 Appbar 里/透明背景上/
  用户自定义配色区域」的控件都可复用此模式。
- 推论：**放在 Appbar 标题行的控件不要依赖 DefaultTextStyle 继承色。**

### E4 ExpansionTile trailing 被占用 = 默认箭头消失

- 把 `trailing` 换成 Checkbox 后，Flutter 默认的右侧旋转箭头被挤掉，
  只剩无提示的整行点击，用户找不到收起展开入口。
- 解法：自定义 `leading` 箭头（`_ExpandHintIcon`）+ StatefulWidget
  （`_expanded` + `onExpansionChanged` 同步）；多个弹窗要统一风格时
  （统计/修复）同步改造，并去掉另一处的默认箭头保持一致。

### E5 i18n 纪律补强（老问题新形式）

- `Past/Problems/Standby` 三个 `.tl` 键从未登记 translation.json → 静默
  回落英文（用户截图才发现）。
- 🔴 **`tools/tl_key_audit.py` 只扫 translation_studio + glossary_editor
  两个目录，覆盖不到阅读器/主页/下载管理/设置**——各轮「TOTAL MISSING=0」
   historically 靠更广的全 lib 扫描兜底。新批次交付前必须跑全 lib 扫描
  （正则扫 `['"]key['"]\s*\.tl(Params)?\b` 对 zh_CN/zh_TW 取差集）。

### E6 translation.json 跨提交拆分零风险手法

备份 → 删批 A 键（同步修尾逗号）→ 全 lib 扫描验证「恰好缺批 A 键」→
提交 A → 还原备份 → 提交 B。每步都有JSON 合法性 + 差集断言，避免一个
文件两个功能互相捆绑。

### E7 GUI 验收驱动的快迭代节奏

- 用户每轮反馈 1-2 个小点（ tab 英文 / 浓缩任务 / 缺箭头 / 白字），
  响应要快、修得准、根因要写进日志。
- 方向类细节（如箭头朝向）用户可能中途纠正——**按常规 UI 惯例默认**
  （收起▽/展开△）比标新立异稳。

### E8 设置结构扩展的四件套

设置页类别列表扩展要同步四处：`_settingsCategories`（名称）+
`_settingsCategoryIcons`（图标）+ `_buildSettingsContent`（页面 switch）+
`settings_search.dart`（搜索索引，**带类别下标数字**）。
🔴 插入新类别会挪动其后所有类别的下标，search 索引数字要跟着改。
组内扩展（如 Data & Sync 内加「下载管理」组）只动一个 part 文件，
成本低——用户本次先选了组内拆分，下一任务选新类别（见下）。

  不要中途 push。
