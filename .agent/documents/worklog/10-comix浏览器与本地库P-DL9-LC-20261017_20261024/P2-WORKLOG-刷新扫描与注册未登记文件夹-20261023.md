# P2 · 本地库刷新按钮 + 扫描注册未登记文件夹

> 日期：2026-10-23 ｜ 关联：用户反馈「Mangrove 不会把文件夹识别成漫画，不管空还是有图」
> 阶段：本地漫画手动管理（续）→ 刷新扫描
> 前序：P1-WORKLOG-空本地漫画链路修复-20261023.md

## 一、问题

用户在 `ComicLibrary/` 三个子目录下手动丢进文件夹（素材/工程/成品），Mangrove 视而不见：
- `downloads/` 下新建的空文件夹 → 不进本地库，也因为 P1 之前的 `status==notDownloaded` 开不了详情页；
- 即便有图的文件夹，只要不是经"下载/导入"流程写的记录，库里也没有它。

根因：本地漫画记录的**唯一入口**是 `LocalManager.add`，而它只被下载完成、导入向导、`createLocalComic`（新建）调用。磁盘上"野生"文件夹没有任何时机被登记。

## 二、方案

本地库页右上角工具栏加「刷新」按钮，触发一次磁盘扫描登记：

1. **`downloads/`（素材）**：遍历子目录，对未登记的调用 [registerUnlistedDownloadFolders]
   （新增于 `lib/utils/local_comic_edit.dart`）：
   - 已登记（同目录 basename）或标题已被导入 → 跳过；
   - 有图能扫出封面 → `scanLocalComicDirectory(dir, id, useRelativePath:true)` 取章节矩阵 + 封面后 `add`；
   - **空文件夹 / 无封面** → 登记为**可填充空漫画**（`chapters=null, cover=''`，见 P1 链路修复），
     这样刷新后空素材也能进库、也能开详情页加章节。
2. **`projects/`（工程）**：直接 `BtProjectManager().scan()`（已有能力，读 `imgtrans_*.json` 注册 `bt_*` 卡；
   带 `_scanFuture` 缓存，重复调用安全）。
3. **`translated/`（成品）**：**本批不处理**，留待 Phase 6 统一适配 `ft_` 前缀与成品详情（避免半成品登记出
   非 `ft_` 前缀的"伪成品"卡，污染 `comicCardKindOf` 分类）。

## 三、改动清单

- `lib/utils/local_comic_edit.dart`
  - 新增 `registerUnlistedDownloadFolders()`：扫描 `LocalManager().path`（`= ComicLibrary/downloads`）下
    未登记子目录并补登记；空文件夹走空漫画分支。
  - 新增 `import 'package:mangrove/utils/local_comic_scanner.dart';`（`scanLocalComicDirectory`）。
- `lib/pages/local_comics_page.dart`
  - 工具栏 `normalActions` 新增「刷新」`IconButton`（Icons.refresh），点按：loading →
    `registerUnlistedDownloadFolders()` + `BtProjectManager().scan()` → 提示扫描到的新文件夹数 → `update()`。
  - 补 `import 'package:mangrove/utils/local_comic_edit.dart';`（此前只引了 `local_comic_edit_dialogs.dart`，
    漏了数据层，导致首次 analyze 报 `undefined_method` —— 见坑 P2-1）。

## 四、校验

- `flutter analyze lib/utils/local_comic_edit.dart lib/pages/local_comics_page.dart`：**0 error**
  （仅剩 3 处 pre-existing `unnecessary_cast` warning）。
- ⚠️ 沙盒无 GUI，无法实机点刷新验证扫描结果；逻辑上 `scanLocalComicDirectory` 对空文件夹返回 null、
  走空漫画分支，与 P1 路由一致。实机回归需用户在 GUI 会话确认。

## 五、遇到的坑（命名归档）

- **坑 P2-1「数据层函数未 import 导致 undefined_method」**：`local_comics_page.dart` 一直只 `import`
  `local_comic_edit_dialogs.dart`，从没引数据层 `local_comic_edit.dart`，于是新增的顶层函数被当成
  `this.` 成员报错。修法：补 import。今后页面调用数据层函数，先确认 import 到位。
- **坑 P2-2「scanLocalComicDirectory 强制要封面，空文件夹返回 null」**：这是 P1 空漫画不可见的同一根。
  刷新路径必须给空文件夹单独建空漫画记录，不能只依赖 scanner。
- **坑 P2-3「ft_ 成品不能随手 scanLocalComicDirectory + add」**：scanner 产出的 `comicType=local`、
  id 非 `ft_` 前缀，直接 add 会生成分类错乱的伪成品卡。成品登记沿用 `FinishedExport.publish` 的
  `ft_` 前缀流程，放 Phase 6。

## 七、回归修复：刷新导致漫画成倍重复（P2-回归）

> 日期：2026-10-23 ｜ 触发：用户在 GUI 会话人工验收，点刷新后截图显示多本漫画各出现 2 次（素材段）。

### 现象（反馈）
用户手动验收发现：点刷新按钮后，本地库里**已有的漫画被又识别了一遍、整列翻倍**。截图中
`第一次告白`、`天门家族的重生者`、`扔掉渣男，绝不饶恕！`、`My Dragon Girlfriend Has Returned`、
`The Runaway Extra and the O…` 各出现 2 条，其余只出现 1 条。全部为"素材"标签。

### 根因（定位）
`registerUnlistedDownloadFolders` 构建排除集合 `known` 时用了
`where((c) => c.comicType == ComicType.local)`，**只收集了本地类型记录**。但网络来源下载的漫画
`comicType` 是源平台类型（非 `ComicType.local`），它们的磁盘文件夹被漏出 `known`，于是刷新时
被当成"未登记"重新 `add` 成一条 `ComicType.local` 副本 → 同文件夹两条记录、列表翻倍。
> 关键判别点：若 bug 是"所有本地漫画都没被排除"，应**全部**翻倍；实际只翻了一部分，说明
> 被漏的是"非 local 类型"的记录（即网络下载漫画），与根因吻合。

### 修复
- `registerUnlistedDownloadFolders`：排除键改为**所有漫画记录**的目录 basename（小写），不再按
  `comicType` 过滤（`bt_*`/`ft_*` 的目录名是 `bt_xxx`/`ft_xxx`，不会与素材文件夹名冲突，纳入安全）。
- 新增 `dedupeDownloadFolderRecords()`（`local_comic_edit.dart`）：按目录 basename 分组，清理
  "同一文件夹被多条记录引用"的重复记录。**只删 DB 记录、绝不删磁盘目录**（`batchDeleteComics(..., false, false)`），
  因为副本与原记录共用同一文件夹，误删目录会连原记录的图一起干掉。判定：
  - 组内存在非本地记录 → 删掉组内所有 `ComicType.local` 副本（文件夹由网络记录继续持有）；
  - 组内全是本地记录（理论上不会发生，因文件夹名磁盘唯一）→ 保最"重"一条、删其余。
- 刷新入口（`local_comics_page.dart`）改为 `dedupe → register → BtProjectManager().scan()`，
  并反馈「清理重复 N 本，新增 M 本」，使重复可自愈。

### 验收（人工 + 静态）
- `flutter analyze lib/utils/local_comic_edit.dart lib/pages/local_comics_page.dart`：**0 error**
  （仅 3 处 pre-existing `unnecessary_cast`，非本次引入）。
- 逻辑验收：排除集合已覆盖网络下载漫画的文件夹 → 刷新不再重复登记；已存在的重复记录会被
  `dedupeDownloadFolderRecords` 在刷新时清掉（只删记录、目录保留）。
- ⚠️ 沙盒无 GUI，需用户在 GUI 会话实机点一次刷新确认：原重复的 5 本应回落为 1 本，
  且图/章节不丢。

### 命名坑点（永久归档）
- **坑 P2-4「刷新排除集合必须覆盖所有 comicType，不能只认 ComicType.local」**：网络下载漫画的
  `comicType` 不是 `ComicType.local`，仅按本地类型去重的扫描登记会把它们当新文件夹重复建卡。
  **凡做"按磁盘文件夹登记/去重"的逻辑，均以「目录 basename」为键、覆盖全部 comicType**，
  此规则写进 MEMORY.md「本地漫画」段，作为跨页面判据。
- **坑 P2-5「同文件夹多记录去重只能删记录、不能删目录」**：副本与原记录指向同一磁盘文件夹，
  任何去重/清理都必须 `removeFileOnDisk=false`，否则会误删原记录的数据。
