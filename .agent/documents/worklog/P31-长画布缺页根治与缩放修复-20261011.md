## 问题 A（最严重）：长画布约 15 页后必现缺页/卡死

用户实测推翻 P30 核心假设：**把横版首页隐藏后问题依旧**——不是估高污染。
读码 + 日志定性后，本轮落在四处真因/隐患：

### A1 尺寸探测根本没读到 WEBP（真因之一）

- P30 的 `probePageSize()` 只认 PNG/JPEG，龙女友工程 **94 张全是 webp**
  （0.webp=VP8 1532×1024、1.webp=900×1778…）⇒ 逐页探测对该工程**全部返回 null**，
  长画布只能靠全局 aspect 估高，P30「探测真值」在该工程上形同虚设。
- `page_size_probe.dart` 新增 `_probeWebp()`：RIFF chunk 漫游，支持
  VP8（data+3..+5 签名 `9d 01 2a`，宽高 data+6/+8 uint16 LE 掩 `0x3fff`）、
  VP8L（data 首字节 `0x2f`，data+1 uint32：宽 `(n&0x3fff)+1`、
  高 `((n>>14)&0x3fff)+1`）、VP8X（data+4/+7 起 24 位 LE 的宽-1/高-1，
  **只有扩展容器、位流被截断也给画布尺寸**）。
  chunk 声明长度可≫已读字节（真实文件头探测就是读不全的），尺寸字节够即给结论；
  只有漫游下一 chunk 才要求 end 可达；坏签名/坏标记/截断一律安全 null。
- `probePageSizeFromFile()` 先读 32 字节（WEBP/PNG 魔数直定），否则 64KB 块漫游，
  消除 94 页×约 1MB 的同步 IO。

### A2 解码调度：失败计数出窗永不清零（实锤根因）+ 名额账抽纯逻辑

- **实锤根因**：页滚出窗口被 dispose 时，旧逻辑只对「有位图」的页清 failures，
  **null（失败/在飞）页的 failures 永不清零**。深滚时页被反复回收重建，
  偶发取消/失败累计到 3 即永久闩锁，占位符成片、回顶重建才"复活"——
  与「固定页数后永久缺页、回顶又活」症状精确吻合。
- 新纯逻辑件 `strip_decode_planner.dart`（无 Flutter 依赖，可 headless）：
  `StripDecodePlan{wanted,startInOrder,evictDecoded,cancelLoading,resetFailures}`
  + `windowRange`（half=keepAlive~/2，全 clamp）+ `plan`（候选按距中心排序、
  同位距位置小者优先，取 freeSlots 个；出窗分三路 evict/cancel/reset）
  + `DecodeBudget(capacity)`（acquire/release，多还夹 0）。
- `studio_scroll_canvas.dart` 接线：`StudioStripPage.cancelInFlight()`
  （token++、loading=false）、`_decodeBudget` 替换裸 `_inFlight`、
  `_loadAround()` 委托 planner；**五条解码终结路径**（成功/位图 null/
  token 失效/取消迟到/异常）共同先 release，名额永不泄漏。

### A3 解码生命周期日志留痕

`text_block_canvas.dart` 的 `decodePageFile()`：readAsBytes catch 打
`Log.warning('StripDecode','read failed...')`；空文件打日志；
codec catch 从 `catch (_)` 改 `catch (e)` 打 `codec failed: ...$e`。
下轮若仍有缺页，logs.txt 可直接区分 IO 缺失、codec 拒绝、还是调度饿死。

### A4 正反断言（12 条，全部「故障路径=变红」）

`headless_p15_checks.dart` 并入 `block-ops-check`，基线 92 → **104**：

- WEBP×4：VP8 有损尺寸+坏签名拒读、VP8L 打包位+坏标记拒读、
  VP8X-only 截断容器给画布尺寸、宽高字节缺失安全 null
  （故障实现=缺字节用末尾字节回填，胡报尺寸）。
- 调度×6：窗口夹取（故障=hi 不夹）、距中心优先开解（故障=窗口升序占坑）、
  隐藏页用工程下标（故障=把可见位置当下标）、失败闩锁（注入式命题，
  故障=闩锁页每轮重试吃光名额）、出窗失败清零（故障=只 evict 不 reset，
  即本轮实锤根因）、出窗在飞取消（故障=不取消，旧 token 迟到写错页）。
- 名额账×1：占满拒入、取消终结也必须归还、多还夹 0
 （故障=没有 release 的漏还账，busy 永久钉满）。
- 组缩放×1：见 B2。

## 问题 B：缩放手柄回归 + nest 组外框直接缩放

### B1 手柄被长按/pan 竞技场吃掉（回归修复）

- P30 加长按拖动用的是 `GestureDetector`，框架内部给 pan 挂了普通 slop 仲裁：
  手柄命中盒只有 ±6px，触摸 slop 36px、垂直拖拽又被 ListView 抢赢 ⇒ 8 手柄全失灵。
- 改 `RawGestureDetector` + 自定义 `_EagerPanGestureRecognizer`
  （`dragStartBehavior.down`）：pointer-down 当下用按下点判定 `_eagerClaimAt`
  （框选模式 **或** 命中选中块 resize 手柄 **或** 命中组外框手柄），
  命中即 `resolve(accepted)` 抢先独占，并覆写
  `hasSufficientGlobalDistanceToAccept` 对被抢指针直接放行（第一个 move 就缩放，
  不用白走 36px）。未命中时行为与普通 pan 完全一致（垂直拖拽仍让位滚动）。
- ⚠️ 本仓 Flutter 版本 API 与新文档不同：team 类叫 `GestureArenaTeam`，
  且此版 `DoubleTapGestureRecognizer` **直接继承 GestureRecognizer、没有 team
   setter**（框架自己的 GestureDetector 也不用 team）⇒ tap/doubleTap 不组队，
  靠竞技场时序裁决，与旧 GestureDetector 行为一致。

### B2 nest 组外框手柄 + 整体等比缩放（新功能，用户拍板语义）

语义（用户已确认）：拖组外框手柄 = **并集框整体等比变换**，成员块位置与尺寸
按同因子映射；拖外框体平移即整体平移；一次 Ctrl+Z 回退整组。

- 纯函数 `block_group.dart :: scaleRectsToBounds({oldBounds,newBounds,rects})`：
  `sx=newBounds.w/oldBounds.w`，`x' = newBounds.left + (x-oldBounds.left)*sx`
  （四边独立 round，y 同理）；退化旧框（宽或高≤0）原样拷贝返回。
- `text_block_canvas.dart`：新类型 `CanvasGroupFrame{groupId,bounds,memberIndices}`
  （bounds=页像素并集，不含外扩）；`PageCanvasPainter` 新增 `activeGroupFrame`，
  在块层之上画外扩 8px 的 8 手柄；shouldRepaint 比较 groupId/bounds。
- `editable_text_block_canvas.dart`：新 `_DragKind.groupResize`；
  组框手柄判定先于成员块；preview/finishDrag 双路都用
  `applyResize(...,minSize:32)` 算 live/new bounds，成员经
  `scaleRectsToBounds` 映射；0.5px 四值 no-op 门槛。
- `studio_page.dart`：`_activeGroupFrameFor(pageKey)`——选中块属于本页 nest 组、
  成员全在本页（跨页组/孤儿引用不出手柄）、非 link 模式；
  `_resizeGroup()` 在**当前模型**重算并集（不盲信画布旧框），整数 target 与
  union 比 1px 门槛，`captureBlockListEdit(label:'Resize group')` 一次快照
  ⇒ **一次撤销步**。
- 🔴 顺带修复：strip 调用点此前给 EditableTextBlockCanvas 的 `selectedIndex`
  恒为默认 -1（长画布里选中块从不画手柄，缩放本就无从开始）；本轮补
  `selectedPageKey/groupFrameFor/onResizeGroup` 三个参数接通单页与长画布两路。

## 问题 C：Ctrl+滚轮只产生横滚、内容不缩放（真等比缩放）

- 根因：P30 只改 `effectiveWidth`，item 高度（`_pageHeight`）/pageGap/块坐标
  没随 zoom 缩放，视觉上只是裁切宽度变化。
- `_effectiveGap = pageGap * _stripZoom`；`_pageHeight()` 去掉
  `math.min(1.0,…)` 钳制改 `h*(w/原图宽)`；scrollToPage /
  _currentVisiblePosition / _spanGeometry 的 gap/padding 全部乘 zoom。
- 新增横向 `ScrollController`（dispose 释放）；缩放以**视口中心为锚**：
  setState 后 post-frame 两轴 jumpTo（`ratio*old+(ratio-1)*半宽`，clamp 新 extent）
  再 _loadAround。
- P27 教训保持：树结构恒常（外层 SizedBox 永远 `max(视口,有效宽)`，
  <100% Align 居中、>100% 横滚），不重挂 ListView；`_StripItem` body 统一包
  固定高 SizedBox，item 高度钉死不随内容跳动。
