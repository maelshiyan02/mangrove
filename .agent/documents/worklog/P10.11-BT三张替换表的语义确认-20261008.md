### 2.3 替换引擎（三表**共用同一个函数**）

`utils/text_processing.py:30-67`：

```python
for index, substitution in enumerate(substitutions):
    keyword = substitution['keyword']
    if keyword == '':
        continue
    pattern = keyword
    flags = re.DOTALL
    if not substitution['case_sens']:
        flags |= re.IGNORECASE
    if not substitution['use_reg']:
        pattern = re.escape(pattern)
    try:
        text = re.sub(pattern, substitution['sub'], text, flags=flags)
    except Exception:
        LOGGER.error(f'Invalid regex expression {pattern} at {index + 1}:')
        LOGGER.error(traceback.format_exc())
return text
```

**行为要点（宿主实现必须对齐的 10 条）**：

1. 按列表插入顺序**串行**执行，`text = re.sub(...)` 回写 ⇒ **前者输出进入后者输入**（链式）。
2. `use_reg == false` → `re.escape` 做**字面量**匹配。
3. `use_reg == true` → 直接当正则。
4. `case_sens == false` → 加 `re.IGNORECASE`。
5. 🔴 **恒带 `re.DOTALL`** —— `.` 跨行。宿主若漏这条，行为与 BT 不一致（跨行文本里的 `.` 语义变了）。
6. `keyword == ''` → **跳过该条**（`:50-51`）。空 pattern 会匹配每个位置，**必须挡**。
7. **替换所有出现**（`re.sub` 而非 `str.replace(..., 1)`）。
8. **无词边界**。需要边界得用户在 `use_reg` 里自己写 `\b`。
9. 单条规则正则非法 → 记 error 并**继续下一条**，不抛出、不中断（`:62-66`）。
10. 🔴 缺键会抛 `KeyError`（`:49` 是裸下标 `substitution['keyword']`，无 `.get`）—— **这是 BT 的缺陷，宿主实现必须更稳**。

## 三、与 BT `glossary` 的关系：**叠加，不互斥**

| | `glossary` | 三张 sublist |
|---|---|---|
| 层次 | **语义层**约束（"这个专名必须译成 X"） | **字符串层**机械替换 |
| 生效引擎 | **只对 LLM 引擎**（`llm_glossary_path` 仅在 `trans_llm.py:365-366, 1110-1117` 被消费） | 对所有引擎 |
| 形式 | prompt 文本注入（`prompt + "\n\nGLOSSARY:\n" + rendered_glossary`） | 字符串改写 |
| 可靠性 | **软约束**（模型可能不听） | **硬约束**（确定性替换） |
| 模式 | matching / all 两种（`modules/context/glossary.py:12-14`） | 无 |

两者可同时生效，代码里无互斥判断。

## 四、🔴 `GlossaryBridge` vs `pre_mt` + `mt`：**不等价**

宿主 `glossary_bridge.dart` 全文核对后，差异是**结构性**的，不是边角：

| 维度 | BT pre_mt + mt | `GlossaryBridge` | 判定 |
|---|---|---|---|
| 规则来源 | 用户自建**两张独立表**，互不相关 | **单一术语表**派生（`:45-48`），译前译后由同一 map 生成 | ❌ |
| 译前行为 | 任意替换，可把 `A`→`B` **彻底改写**送给引擎 | 只把术语换成哨兵 `XQZ0ZQX`，**不改写语义**（`:33, :71-78`） | ❌ |
| 译后行为 | 对**引擎返回的任意字符串**做替换 | 只认自己插的哨兵（`:35, :38`），其他一律不动 | ❌ |
| 正则 / 大小写 | 支持 `use_reg` / `case_sens` | **不支持**。只有字面量 + `RegExp.escape`（`:57-59`，已核实） | ❌ |
| 生效引擎 | 对**所有引擎** | **只有 2/3 路径**：`translation_dispatcher.dart:38-45` 真 LLM 走 prompt **不桥接**；只有公共免 Key LLM（`:46-55`）与本地 NMT（`:56-63`）走桥接 | ❌ |
| 失败处理 | 静默跳过非法正则 | 统计 `lost`/`residue` 并 `Log.warning`（`:80-89`） | ✅ **宿主更强** |

**结论**：`GlossaryBridge` 解决的是"**术语表对无 prompt 通道的引擎静默失效**"，
它是术语一致性的**旁路**，不是通用的译前/译后替换表。

宿主 prompt 注入**已实现**（`llm_translator.dart:486-487` 把 `'glossary': glossary`
塞进 JSON payload），但那是**软约束**；`mt_sublist` 是**硬约束**。
**二者不重叠，是互补关系**，宿主目前没有任何译后强制替换。

## 五、宿主实现 `ocr_sublist` 的最小落点（规格）

### 5.1 唯一咽喉点

| 位置 | 说明 |
|---|---|
| **`lib/foundation/image_translation/translation_worker.dart:623-625`** | `text = text.trim();` → `if (text.isEmpty) continue;` → 之后、`sourceLang == 'auto'` 语言投票之前 |

🔴 **为什么落在 worker 而不是 pipeline**：`ocrRegion`（`translation_pipeline.dart:112`，
S-N1 新增）与整页路径（`:197`）**都**经由 `TranslationWorker.instance.ocrPage`，
`worker:623` 是两条路径唯一的交汇点。改 pipeline 会漏掉单区域路径。

### 5.2 建议的独立文件

`lib/foundation/image_translation/ocr_substitutions.dart` —— **纯 Dart、不依赖 isolate**，
便于 headless 全测（对齐 `studio_block_ops.dart` / `mask_producer.dart` 的做法）。

### 5.3 函数规格

```
List<OcrSubRule> applyOcrSubstitutions(List<OcrSubRule> rules, String text)
```

| 规则字段 | 对应 BT | 类型 |
|---|---|---|
| `keyword` | `keyword` | `String` |
| `sub` | `sub` | `String` |
| `useReg` | `use_reg` | `bool` |
| `caseSensitive` | `case_sens`（**取反**） | `bool` |

行为严格按 §2.3 的 10 条。补充三点宿主专属决定：

- 🔴 **必须加 `dotAll: true`**（对齐 `re.DOTALL`）。
- **反则替换串**：BT 直接把 `sub` 当 `re.sub` 的 replacement（支持 `\1` 反向引用）。
  Dart `replaceAllMapped` 按**字面量**用返回值 ⇒ **第一版不支持反向引用**，需在 UI 标注。
  （要用就得自己实现 `\$1` 解析。）
- **空 `keyword`** 跳过（对齐 `:50-51`）。
- **空 `text`** 直接返回 `''`，不抛。

### 5.4 配置与 UI 落点

| 项 | 落点 |
|---|---|
| 配置 | `TranslationConfig`（`translation_config.dart`），字段名 `ocrSublist`，默认 `const []` |
| UI | 第一版对齐 BT：4 列表格 + New/Delete。**不做**导入导出（BT 也没有） |
| 可选 | BT 另有一处 `sub_text()` 对单 block 手动应用（`mainwindow.py:2408`）—— 可择一实现 |

### 5.5 已知局限（如实告知）

- **不保证幂等**：规则 A→B、B→A 会语义翻转（BT 同样如此，因为串行链式）。UI 应提示。
- 替换会改变文本长度 → 但 `_medianLineHeight` 用的是识别框高度而非文本长度，**不影响渲染字号**。
