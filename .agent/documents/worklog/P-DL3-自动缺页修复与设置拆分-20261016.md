  Auto Repair Missing Pages，分类 3）。

## 2. 自动缺页修复机制（默认关）

- 新设置键 `autoRepairMissingPages`（默认 false，登记在 appdata
  默认表）。
- `download_manager_store.dart` 加纯数据层访问器
  `autoRepairMissingPages` getter / `setAutoRepairMissingPages`。
- `local.dart` `completeTask` 挂钩：下载任务完成后，若开关打开，
  走 `_autoRepairAfterDownload`——先 `reconcileDiskState`（把半截章节 /
  磁盘空洞补进缺页表）再 `MissingPages.peek`，有缺页则调
  `RepairDownloadTask.enqueue(silent: true)` 按章生成修复任务入队，
  弹汇总 toast「已自动创建 @a 个缺页修复任务」。开关关闭时走原
  普通对账路径，行为不变。失败只记日志，不影响下载主流程。
- 防循环：RepairDownloadTask 收尾走 `removeTask` 而非 `completeTask`，
  修复完成不会再次触发自动修复。
- **去重守卫**（本轮顺带修的隐患）：`enqueue` 入队前检查
  `LocalManager().downloadingTasks` 里是否已有同 id
  （`repair:<comicId>:<chapterId>`）的修复任务，有则跳过并记日志——
  否则自动模式撞上手动建的任务会造出第二个同 id 任务，重新引入
  P-DL2.1 修掉的「同 id 互相覆盖」问题。

## 3. 按钮统一命名「缺页修复」

- 详细页 tooltip、本地漫画页长按菜单、下载管理页头部 tooltip、
  主页分区按钮，全部改用同一键 `Missing Page Repair`（缺页修复）；
  本地页带计数的用 `Missing Page Repair (@a)`。
- 范围区别不变：详细页/本地页 = 当前漫画；下载管理 = 全库 + 分区。

## 4. 模式切换「抽屉」（自动/手动）

- 新增共用组件 `RepairModeDropdown`（`download_manager_dialogs.dart`）：
  细边框圆角小盒 + 当前值 + 下拉箭头，选项 自动/手动；样式参考设置里
  已有的「实时/省流/仅手动」下拉。
- 两处入口共用同一开关：① 缺页修复二级弹窗**标题右侧**
  （`ContentDialog` 新增 `titleTrailing` 槽，dense 模式）；
  ② 系统设置「下载管理」分组 ListTile trailing。
- `ContentDialog.titleTrailing`：`components/message.dart` 标题行
  Appbar 的 title 改 Row（Flexible 标题 + 后缀），不影响其它调用方。
