# BT v1.5.17 更新提炼 + G 键废弃 + 术语统一

> 日期：2026-09-29
> 触发：BT v1.5.17 更新后，结合用户决策提炼可利用的新功能，同时清理废弃的设计决策

---

## 一、BT v1.5.17 值得提炼的新功能

### 1.1 韩语识别/翻译改进 ✅

BT 1.5.17 更新项明确提到：
> "更新新中文和韩语翻译、Photoshop Bridge 韩语、西里尔文字处理"

**影响**：
- comix.to 有大量韩漫，韩语翻译组（如 Luna Toons、MistScene 等常同时出现在英文和韩文漫画中）
- BT 内置翻译器（Papago、Google、DeepL、M2M100 等）的韩语映射已经完善
- **对我们有益**：后续翻译工作室接入 BT 管线时，韩语漫画翻译质量直接受益

**无需移植**：这是 BT 翻译模块内部改进，VeneraX 调 BT 管线时自动获得。

### 1.2 西里尔文字处理 ✅

BT 1.5.17 改进了西里尔（俄文、保加利亚文等）的渲染和文字识别。comix.to 上俄文漫画量不大，但有就比没有强。同上，管线自动获得。

### 1.3 TextItemMoveSession（G 键移动文本框）✅

BT 1.5.17 新增 `text_engine/editing/move_session.py`，将 G 键功能从"区域翻译模式"改为"移动选中的文本框"。

**对我们的价值**：
- 原来我们的 G 键区域翻译信号（`region_translate_rect`）被 BT 删除了
- BT 用更完善的 TextItemMoveSession 替代——支持 Shift 约束方向、Ctrl 精确移动等
- **我们直接受益**，不需要再维护自己的 G 键逻辑

### 1.4 TTY（中横）渲染修复 ✅

BT 1.5.17 对竖排中横（tate-chu-yoko）渲染做了 80 行改。这是日文漫画的常见排版。我们依赖 BT 文本渲染时自动受益。

### 1.5 字体搜索改进 ✅

BT 1.5.17 字体搜索支持名称任意位置关键词匹配。翻译工作室里选字体时更方便。

### 1.6 shape fill（矩形/椭圆填充擦除）⚠️ 可选

BT 1.5.17 新增矩形/椭圆填充和擦除工具，可调颜色和不透明度。

**评估**：
- 这是修图/绘图功能，不是翻译核心
- 翻译工作室主要做 OCR + 翻译 + inpaint，绘图工具可以留给纯修图用户
- **暂不移植**，等翻译工作室核心管线跑通后再评估

### 1.7 Codex API / 图像生成 ❌ 不适合

BT 1.5.17 新增 Codex（ChatGPT 账户登录）用于图像修复、文字识别、图像生成。

**不适合融合的原因**：
| 维度 | 问题 |
|------|------|
| 成本 | 闭源商业 API，按 token 计费 |
| 隐私 | 漫画图片上传到第三方服务器 |
| 依赖 | 需要用户有 ChatGPT 账户 |
| 定位 | 翻译工作室应该用本地 OCR/翻译模型，不依赖外部 API |

**决策**：不融入翻译工作室，留给有需要的用户自己在 BT 侧使用。

## 二、G 键废弃

### 2.1 废弃原因

用户在对话中明确：
> "一开始用 G 键是因为没有找到怎么画文本框，后来发现在右下角就有这个功能之后，就其实可以把 G 键去掉了"

> "后续在连续阅读本章的功能页面中那个右上角的 G 键框选实际上也是画蛇添足"

### 2.2 废弃范围

| 位置 | 旧功能 | 决策 | 原因 |
|------|--------|------|------|
| BT mainwindow.py | G = 区域翻译模式 | **保留 BT 新功能** | BT 改成了 G = 移动文本框，更合理 |
| BT continuous_canvas.py | G = 框选气泡合并 | **废弃** | 长画布本身未实现；BT 原生 G 移动更实用 |
| BT canvas.py | region_translate_rect 信号 | **不再用** | BT 已删除，我们不再维护区域翻译模式 |
| BT drawingpanel.py | 区域翻译工具按钮 | **继续用** | 右下角按钮本身没问题，只是 G 键不再触发 |

### 2.3 BT 1.5.17 新 G 键功能

| 快捷键 | 功能 | 价值 |
|--------|------|------|
| **G** | 移动选中的文本框 | 替代了我们的区域翻译，用更精确的移动代替粗框选 |
| Shift + 单击 | 画直线 | 绘图辅助 |
| Ctrl+Shift+单击 | 画水平/垂直直线 | 精确绘图 |
| X/Y 轴约束 | 移动/绘制时按 X/Y 锁定方向 | 精确操作 |

### 2.4 结论

**G 键不再冲突**——BT 1.5.17 把 G 键改成了"移动文本框"，我们的长画布 G 键本来就没实现，现在直接用 BT 原生功能即可。不需要任何互斥逻辑。

## 三、术语统一

### 3.1 汉化组 → 翻译组

| 旧术语 | 新术语 | 适用范围 |
|--------|--------|---------|
| 汉化组 | **翻译组** | 所有外文漫画的翻译群体（英文、韩文、日文、俄文等） |
| scanlation group | 翻译组 | 同上 |
| 汉化组标签 | 翻译组标签 | UI 显示 |
| 汉化组版本 | 翻译组版本 | 版本化章节 |

**原因**：comix.to 是英文漫画平台，翻译组翻译的是英文、韩文、日文等，不限于中文"汉化"。统一用"翻译组"更准确、更通用。

**例外**：内部变量名可保留 `scanlationGroup`（已在 models.dart），因为它是技术标识符，不影响用户。

### 3.2 BT → FT

| 位置 | 当前 | 目标 |
|------|------|------|
| 工程类型名 | BT 工程 | **FT 工程** |
| 设置键前缀 | `bt` | `ft` |
| 类名前缀 | `Bt` | `Ft` |
| 文档引用 | BT | FT（新文档）/ BT（旧文档保留） |

## 四、项目记忆更新

本次更新涉及的持久化知识：

### 4.1 BT 更新模式

- BT 更新器做**干净安装**：删除所有 untracked 文件后装新版本
- BT 重写**核心文件**（mainwindow.py、proj_imgtrans.py、canvas.py）
- **对策**：不要在 BT 侧加 untracked 新文件；尽量不碰核心文件；重要改动先 git commit

### 4.2 BT 1.5.17 输出契约变化

- `proj_imgtrans.py` **不再输出** `page_order` / `chapters` / `workspace`
- VeneraX Dart 侧需自行从 `pages` dict 重建
- 已有降级实现，但需持续验证

### 4.3 术语决策

- 翻译组（不是汉化组）— 通用
- FT（不是 BT）— 正式项目名
- 翻译工作室 — 融合后功能定位

### 4.4 功能取舍

- **放弃**：长画布、区域翻译模式（G 键框选）、BT 侧 comix.to 集成、proj_imgtrans.py 结构化输出
- **保留并融入**：BT 工程直读、BT 渲染链、翻译管线（OCR/翻译/inpaint）
- **待开发**：comix.to Flutter 侧下载、翻译工作室 UI、多翻译组切换
