## 2. 各项实现要点

### 2.1 章节胶囊（R4-1）

`‹ Ch.12 / 48 ›` 连体胶囊：高 34、圆角 4、`surfaceContainerHighest @ .92`；左右箭头切章、点中央开章节抽屉；完整书名与话名退到 tooltip。

- **可用性判据用 `visibleChapterFrom(chapter, ±1) != null`，不用 `isFirst/LastChapterOfGroup`** —— 后者只看分组边界，在"目标话在另一个分组"时会把一个能跳的按钮误置灰（与 R3 章尾导航卡同一个坑，第二次踩）。
- **窄窗（`width < 560`）退回双行标题**。这不是妥协而是必要：顶栏右侧还有翻译控件、更多菜单、设置三个按钮组，把它们挤掉换一颗胶囊是净损失。阈值提为常量 `kChapterCapsuleMinWidth`，避免魔法数字散落。

### 2.2 一键灰度（R4-2）

BT.709 亮度权重矩阵，`ColorFilter.matrix`。

**落点选在 scaffold 的图片区整层，而不是逐张图片**。原因：

- gallery 的单图走 `PhotoViewGalleryPageOptions(imageProvider:)` 路径，PhotoView 内部自己建 `Image`，**没有可以插入的 child 包装点**；
- 勉强改成 `customChild` 就必须自己给 `childSize`，而这会牵动 `initialScale`（contained / covered 的基准从"图片尺寸"变成"给的 childSize"）与 `maxScale`（`covered * 10` 的基准同步变），等于为了一个开关去动缩放语义 —— 不划算；
- 挂整层则 gallery / continuous 两种模式、所有页一视同仁，一行 `if` 收工。

**已知取舍（写进代码注释了）**：章尾导航卡与章末评论页同属这一层，开启灰度时也会一并去色。文字仍可读，只是饱和度归零；导航卡会偏"禁用态"观感。要精确排除得把这两个页面从 gallery 里挪出去另起一层，不在本轮范围。

> 🔴 **上游计划里"与自定义滤镜互斥"这一条，代码里没有对应物**。实测 `lib/` 全量检索：阅读器侧**不存在**任何自定义滤镜/色彩滤镜设置（只有 `FilterQuality` 这种采样质量参数）。所以互斥逻辑无从实现，本轮**跳过**，并在此登记：若将来真的引入自定义滤镜，需要在 `reader_filters.dart` 补一条优先级判定，并在设置项上做禁用态。

### 2.3 压暗（R4-3）

`ColoredBox(Colors.black.toOpacity(dim))` 独立遮罩层，与夜间遮罩并列（可叠加）。

- **与夜间遮罩刻意拉开量级**：夜间 `readerNightModeIntensity` 上限 0.85（换色相：暖/黑/暗红），压暗上限 0.4（只降亮度不换色）。压暗再高就等于蒙一层黑，没必要两套设置并存。
- UI 上两者归到同一分组（紧跟"Night mode intensity"之后），是为了让"护眼"相关档位挨在一起 —— 但语义是两套，注释里写明了。

### 2.4 显隐触发策略（R4-4）

三个取值各自"谁负责切换显隐、谁负责翻页"：

| 取值 | 单击切显隐 | 单击翻页 | 双击切显隐 |
|---|:---:|:---:|:---:|
| `tapCenter`（默认，= 现状） | ✅ 中心区 | ✅ | — |
| `singleTapAnywhere` | ✅ 任意位置 | ❌ | — |
| `doubleTap` | ❌ | ✅ | ✅ |

实现上的两处关键：

1. **`doubleTap` 模式下必须强制打开双击检测**。原代码 `onTapUp` 里是 `if (!_enableDoubleTapToZoom) { onTap(location); return; }` —— 用户关掉"双击缩放"时双击根本不会被识别。所以引入 `_detectDoubleTap = _enableDoubleTapToZoom || trigger == doubleTap`，否则这个模式永远收不到它的触发手势。
2. **双击与缩放只能二选一**。`doubleTap` 模式下 `onDoubleTap` 直接 `openOrClose()` 并 `return`，不再调 `handleDoubleTap`。这是硬冲突，没有两全方案；设置项 `help` 里写明了"单击任意位置 / 双击会取代双击缩放"。

三条纯函数（`readerSingleTapTogglesChrome` / `readerSingleTapTurnsPage` / `readerDoubleTapTogglesChrome`）都打了断言，外加一条"每种策略至少要留一条能把工具栏叫回来的路"的不变式。

### 2.5 匀速自动滚动（R4-5）

- `Timer.periodic(100ms)`，每 tick 推进 `speed * 0.1` px，走 `_scrollController.jumpTo`。
- **用 `jumpTo` 而不是 `animateTo`/`smoothTo`**：自动滚动本身就是高频小增量，再套动画会在每次 tick 上叠加新动画、互相打断，实际速度反而不可控；`smoothTo` 还带 `readerScrollSpeed` 倍率和 Shift 抑制，那是给手动滚轮用的。
- **gallery 静默退回按页计时**，而不是给死按钮：判据用新增的接口成员 `supportsPixelScrolling`（gallery `false` / continuous `true`），比在外面判 `mode.isContinuous` 更可靠 —— 控制器自己才知道能不能按像素推进。
- 到底时尝试 `toNextChapter()`；失败或控制器随换章重建则停表并 `update()` 让按钮回到未播放态，**不跨章续播**（刻意的保守行为，避免和"滑到边缘才加载下一话"的无缝逻辑抢方向）。
- 底栏按钮从直接调 `autoPageTurning()` 改为统一入口 `toggleAutoPlay()`；图标判据从 `autoPageTurningTimer != null` 改为 `isAutoPlaying`（两个计时器取并）。`dispose()` 同步补了 `autoScrollTimer?.cancel()`。

## 3. 本轮挖出来的坑 / 决策

1. 🔴 **`_ReaderLocation` 里没有 `mode` getter**。原打算在 `toggleAutoPlay()` 里判 `mode.isContinuous`，analyze 直接报 `undefined_getter`（`_ReaderLocation` 是 mixin class，`mode` 是另一个 mixin 的抽象成员）。改为让控制器自报 `supportsPixelScrolling`，反而更可靠。
2. 🔴 **`ColorFilter` 不对外暴露 matrix 字段**（`_matrix` 是私有的）。为了让灰度矩阵可断言，把矩阵数组拎成常量 `kReaderGreyscaleMatrix`，`kReaderGreyscaleFilter` 由它构造 —— 断言打在源数组上。
3. 🔴 **plan 里的"自定义滤镜互斥"无对象**：见 §2.2，全库检索无此物，已登记为遗留。
4. **`readerAutoPlayMode` 是 plan 之外的第 6 个键**。plan 只列了 `autoScrollSpeed`，但"UI 上两者二选一"需要一个显式的模式开关；不给就只能靠阅读模式隐式推断（continuous→滚动、gallery→计时），用户在 continuous 下就失去了选择权。默认 `'page'` 保证既有行为不变。
