## 2 · 数据模型（计划 §4.0.3）

- **块级 `_uid`（惰性）**：块本来没有稳定 id，全项目按页内下标寻址；组若用下标引用成员，
  「删一个块」就会让整组指错块。解法 = 块**加入组时才写**可选键 `_uid`；
  **从不建组的工程块里不出现这个键** ⇒ 与 FT 的零字节 diff 契约不受影响（D9）。
- **工程级 `_groups`**：`{groupId: {mode, members(有序), source?, translation?, assignment?, seam?}}`。
  - `mode ∈ {nest, link}` 只影响可视化，**同一数据结构**（D17）；
  - `members` = 有序 `{page, uid}` 列表；`assignment` 键 = `"<page>#<uid>"`；
  - `seam` = `"<上页>|<下页>"`（非跨页组为 null）。
- **组边界框不落盘**：成员矩形并集是**派生值**（`groupBounds`），`nest`/`link` 切换只改 `mode`。
- **两条不变式**：① 未知键原样保留（只碰 `_uid` / `_groups` 两个键）；② **不存在即 nil**
  （没有组时 `_groups` 根本不出现，空表写回 = **删除该键**）。

## 3 · 🔴 关键取舍：成员排序采用「阅读序 · y 升序」（用户 2026-10-10 拍板）

计划书 §4-B3 字面写的是「同页按 y **降序** / 从高到低」，但页漫阅读序是**自上而下**
（与 `balloon_clustering._orderedLines` 的自上而下约定一致）——两者方向相反。
本轮以 `AskUserQuestion` 请用户确认，用户选定 **阅读序：y 升序（页顶块在前）**。

⇒ `sortMembersReadingOrder` 的顺序为：**页号（阅读序下标）升序 → 同页 y 升序 → x 升序 →
uid → 原始下标**（`List.sort` 不保证稳定，用原始下标兜底，保证结果与输入顺序无关）。
组合出的原句顺序全靠它，方向反了句子就反了；文件头与断言 detail 均已注明此事。

## 5 · 实现取舍（写成注释留在代码里）

1. **`GroupMemberRef.parse` 在最后一个 `#` 处切分**：`_uid` 由本模块铸造、不含 `#`，
   而页键理论上可以含 `#` —— 从尾部切才能把页键原样留住。
2. **`concatMemberSources` 默认分隔符是换行**：截断处常有 OCR 断字/重复/缺字，换行让
   「这里原本是分段」可见、便于人工校对；CJK 断字场景可传 `''`。
3. **切分只是「建议」**：`suggestSegments` 只产片段、**绝不自动采纳**，也不按字符比例自动切。
4. **`translateGroupOnce` 入参是长度 1 的列表**：一组只调一次，而不是每成员各调一次
   —— 否则会把一句被截断的话拆成互不知情的碎片，正是本功能要消灭的错。
5. **`applyGroupAssignment` 逐成员 `captureBlockEdit`**：未分配/译文相同/孤儿成员跳过，
   命令逐个 `pageKey` 齐备 ⇒ 脏页跟踪仍有效、可整体 undo。
