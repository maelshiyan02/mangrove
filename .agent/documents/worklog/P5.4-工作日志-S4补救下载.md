## 1. 目标
只针对 `missing_pages.json` 里登记的缺页做补救下载，不重下整章/整部；成功后销账，
仍失败保留并累加 attempts。三种触发：单页 / 整章 / 整部。

## 2. 改动文件

### 2.1 新增 `lib/network/repair_download.dart`（核心引擎）
- `RepairDownloadTask extends DownloadTask with _RepairSpeedMixin`
  - **复用同一取图通道**：`ImageDownloader.loadComicImageUnwrapped(url, source.key, comicId, chapterId, forDownload:true)`
    —— 即 comix.to 的 WebView Lane，下载策略（90s×3）自动生效，无需为 repair 另写通道。
  - 成功 → `MissingPages.removeEntry(dir, chapterId, index)`（销账）；
    失败 → `MissingPages.putEntry(dir, updatedEntry)`（error 更新、attempts+1 保留）。
  - 并发池：`downloadThreads`（1–8）取图；`_done/_started/_repaired/_failed` 计数；
    `progress = _done/_total`；状态行 `Repaired @a/@b · @c failed`。
  - **暂停/恢复正确性**（关键）：`pause()` 取消在飞 wrapper 并 `clear()`，但**保留 `_started`**；
    `resume()` 先 `_started = _done` 再续跑——被取消的在飞页会重建而不是被跳过。
    取消的 wrapper 在 `then` 里 `if (w.isCancelled) return;` 不更新计数，避免恢复时漏页或重复。
  - **不重写本地库**：完成走 `LocalManager().removeTask(this)`（不调 `completeTask`，
    后者会 `add` 漫画记录导致重复）。修复只填缺页，漫画本就在库里。
  - `toJson/fromJson` 持久化 `targets`（缺页条目）+ `path` + `wasRunning`；
    重启经 `DownloadTask.fromJson` 恢复并自动续跑（队列 `_autoResumeDownloads`）。
  - 静态入口：`enqueue` / `repairComic` / `repairChapter` / `repairEntry`，
    从 `LocalComic` 反查 `source`（`comicType.comicSource`）、`path`（`baseDir`）、封面。
- `_RepairImageWrapper`：逐页取图 + 魔数/体积校验，与 `download.dart` 的 `_ImageDownloadWrapper` 一致。
- `_RepairSpeedMixin`：极简吞吐记录（speed 字段供下载列表显示）。

### 2.2 `DownloadTask.fromJson` 注册机制（避免循环依赖）
- `repair_download.dart` **不能**被 `download.dart` 直接 import（否则 `RepairDownloadTask extends DownloadTask`
  在 import 循环里解析不到基类）。改用在 `download.dart` 加 `registerDownloadTaskType(type, fn)` 注册表，
  `repair_download.dart` 在 library 顶层用 IIFE 变量 `_repairTaskRegistered` 注册自身。
  加载顺序：UI 页 → repair_download → download（已完整加载）→ `extends DownloadTask` 解析通过。

## 5. 已知边界
- repair 与同漫画整章下载**并发**写同一 `missing_pages.json` 时，靠 `MissingPages` 串行写锁 + 单例缓存表
  保证文件不损坏；逻辑上以最后写者为准（用户通常不会同时跑两者）。
- `eid` 传给取图通道用「目录名」而非源章节 id；comix.to 实际按 URL 取图，不受影响。
- 详情页 AppBar 的「修复缺失」按钮在 repair 完成后不会自动消失（需页面重建）；本地卡片与对话框靠
  `LocalManager`/`MissingPages` 实时刷新。下阶段（如需要）可监听刷新。
