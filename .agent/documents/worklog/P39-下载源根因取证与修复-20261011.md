# P39 · 下载源根因取证与修复（comix.to 代理封禁 / 包子死域名）

> 日期：2026-10-11（18:30 会话）
> 触发：用户实测「comix.to 抓不到章节、搜索栏转圈；包子仍要 CF 验证、下载卡死在获取漫画信息」，
> 上轮 P38 只做了「空结果重建 worker」的加固，**未解决**。
> 本轮改用**站点侧 + 客户端出站链路**的真实取证（curl 直连/代理对照、运行日志、持久化设置），
> 定位到两个与代码改动无关、但可在代码/配置层修复的**确定性根因**。

---

## 0. 一句话结论

| 站点 | 真实根因 | 性质 | 本轮修复 |
|---|---|---|---|
| **comix.to** | 应用全部请求走**系统代理** `127.0.0.1:7890`，而该**代理节点出口 IP 被 comix.to 的 Cloudflare WAF 判 403**（同机**直连 200**）。dio 与离屏 WebView 都吃系统代理 ⇒ 搜索/章节/图片一起 403。 | 客户端出站链路 | comix 全域**强制直连**（dio `findProxy=DIRECT` + WebView2 `--proxy-bypass-list`）；并把 CF **封禁页**纳入 `looksLikeChallengePage` |
| **包子漫画** | 用户持久化设置 `domains="baozimhcn.com"`（**已死域名**，302→`www.baozimh.com/__gatekeeper_challenge`）。App 把死域名排在候选首位 ⇒ 每章先进官方 gatekeeper 挑战 → 兜底 `appcn.baozimh.com` 又 CF ⇒ 「卡死在获取漫画信息」。**可用镜像 webmota/kukuc/twmanga/dinnerku 全程未被请求。** | 源配置 + 死域名 | 部署源删除 3 个死域名 + 1 个坏图床；运行时 `baozi.data` 的 `domains` 改回 `webmota.com` |

> ⚠️ 与 P38 的差异：P38 判断「站点端升级、非我代码」只对了一半——**comix 确实是外因（代理节点），但包子是纯粹的本地配置/源数据问题**，且 P35 的源修复**从未同步到运行时**。

## 1. 取证方法与原始证据

### 1.1 comix.to：直连 vs 代理 对照（决定性）

```text
curl -A <Chrome126>  https://comix.to/                       -> HTTP=200 SIZE=416493   （真 SPA 外壳）
curl -A <Chrome126> -x http://127.0.0.1:7890 https://comix.to/ -> HTTP=403 SIZE=5481
        <title>Attention Required! | Cloudflare</title>      （CF 硬封禁页）
```

运行日志同刻吻合（`%APPDATA%\io.github.maelshiyan02\mangrove\logs.txt`）：

```text
info JS Console  comix_to: status=403 len=5848                       ← 与代理封禁页同构
info ComixClient fetchPageHtml: 4675 chars from https://comix.to/title/9lmnj-error-the-echo
error Network    Error: no initial-data in page  at loadInfo (ComixTo:285:41)
warning ComixClient browse: no usable manga-list payload for https://comix.to/browse?q=...&page=1&limit=28
info JS Console  comix_to: search got 0 comics, maxPage=0
warning ImageLane1 fetch status=403 error=http 403                    ← 图片 CDN static.comix.to 亦 403
```

**判定**：`fetchPageHtml` 拿到的是 **403 封禁页（4675 字符）**，但旧 `looksLikeChallengePage`
只认「挑战中」关键字（`just a moment`/`cf-chl`/`gatekeeper`），**不认 CF 硬封禁页**
（`Attention Required`/`cf-error-details`/`blocked_why_headline`）⇒ 把封禁页当正常 HTML 返回，
上层报出误导性的 `no initial-data in page`。

**系统代理确认**（`HKCU\...\Internet Settings`）：`ProxyEnable=1`、`ProxyServer=127.0.0.1:7890`。

**为什么应用会走代理**：
- dio：`app_dio_io.dart::createIOHttpClient` 的 `findProxy = (uri) => 'PROXY $proxy'` —— 对**所有 host** 生效；
- WebView：`applyProxySetting()` 在 Windows 上是**空操作**（`WebViewFeature.PROXY_OVERRIDE` 不受支持，
  且 `flutter_inappwebview_windows` 无 proxy 实现），离屏 WebView 走 **WebView2 默认 = 系统代理**。

### 1.2 包子漫画：可用镜像 vs 死域名

```text
curl -A <Chrome126> https://cn.webmota.com/    -> 200 194046   （无挑战）
curl -A <Chrome126> https://cn.kukuc.co/       -> 200 194723   （无挑战）
curl -A <Chrome126> https://cn.twmanga.com/    -> 200 194705   （无挑战）
curl -A <Chrome126> https://cn.dinnerku.com/   -> 200 194703   （无挑战）
curl -A <Chrome126> https://cn.cnbzmg.com/     -> 403
curl -A <Chrome126> https://cn.bzmgcn.com/     -> 403
curl -A <Chrome126> https://cn.baozimhcn.com/  -> 403
curl -A <Chrome126> https://www.baozimh.com/   -> 302 -> https://cn.bzmgcn.com/
```

网页阅读路径实跑通过（镜像）：

```text
GET https://cn.webmota.com/comic/<cid>                        -> 200 260412   （chapter-items/chapters_other_list 齐全）
GET https://cn.webmota.com/comic/chapter/<cid>/0_1.html        -> 200  67441   （comic-contain__item data-src × N，无挑战）
GET https://s2.bzcdn.net/scomic/<cid>/0/1-hfsr/1.jpg           -> 200 53508   image/jpeg
```

运行时持久化数据（`comic_source/baozi.data`，修复前）：

```json
{"settings":{"image_quality":"/w640","domains":"baozimhcn.com"},
 "good_web_domain":"webmota.com",
 "challenged_domains":{"baozimhcn.com":...,"cnbzmg.com":...,"bzmgcn.com":...}}
```

运行日志（**决定性**）—— 整个会话里包子**只请求了官方域，从未请求任何可用镜像**：

```text
info Cloudflare  Gatekeeper challenge detected:
     https://www.baozimh.com/__gatekeeper_challenge/start?return=%2Fcomic%2Fchapter%2F<cid>%2F0_0.html
error Network    CloudflareException: https://appcn.baozimh.com/baozimhapp/comic/chapter/<cid>/0_0.html
error Download   step failed after 3 attempt(s): CloudflareException: .../0_0.html
```

域名出现频次统计：`www.baozimh.com`×N、`appcn.baozimh.com`×N、**`webmota|kukuc|twmanga|dinnerku` = 0**。

**判定**：`domains` 停在死域名 ⇒ 候选首位是 `cn.baozimhcn.com` ⇒ 302 到官方 gatekeeper ⇒
每章吃一次 CF 挑战 ⇒ 兜底 appcn 又 CF。**P35 的源修复（删死域名）从未同步到 `%APPDATA%`**
（运行时 `baozi.js` 时间戳停留在 10-05 14:02）。

## 2. 本轮修复清单

### 2.1 comix.to —— 强制直连（代码）

| 文件 | 改动 |
|---|---|
| `Mangrove/lib/network/proxy.dart` | 新增 `kDirectProxyHostSuffixes`（`comix.to`、`joshuanotes.site`）、`isDirectProxyHost(host)`、`buildProxyBypassList()` |
| `Mangrove/lib/network/app_dio_io.dart` | `createIOHttpClient.findProxy`：命中直连白名单 → `DIRECT`，否则 `PROXY $proxy` |
| `Mangrove/lib/network/comix_client.dart` | ① `_getSharedWebViewEnvironment()` 传 `additionalBrowserArguments`：`--proxy-server=<解析出的代理> --proxy-bypass-list=<comix 全域>;<local>`（代理解析不到则不加，维持原行为）；② 补 `import .../network/proxy.dart` |
| `Mangrove/lib/network/comix_client.dart` | `looksLikeChallengePage` 增补 CF **封禁页**特征（`attention required`/`cf-error-details`/`blocked_why_headline`/`you have been blocked`/`error 1020`），避免把 403 封禁页当正常内容 |

> 设计原则：comix 域**本机直连可达、代理有害**，故只对这组域旁路；其余站点仍走用户代理（不影响需要代理的源）。
> WebView 旁路依赖 WebView2 的 `--proxy-bypass-list`；若某版本不生效，行为退化为「与现状一致」（仍走代理），无回归。

### 2.2 包子漫画 —— 删死域名 + 修设置（源 + 配置）

| 目标 | 改动 |
|---|---|
| `venera-configs-main/baozi.js`（工作副本） | 以**部署版为基**（保留上游 PoW `_challengedDomains` 逻辑），删 `bzmgcn.com`/`baozimhcn.com`/`cnbzmg.com` 与坏图床 `asgb-a3.bzcdn.net`；版本 `1.2.0 → 1.2.2` |
| `%APPDATA%\...\comic_source\baozi.js`（运行时） | 同步上述文件（`node --check` 通过；已备份 `baozi.js.bak_20261011_P39`） |
| `%APPDATA%\...\comic_source\baozi.data`（运行时） | `settings.domains: "baozimhcn.com" → "webmota.com"`；清空 `challenged_domains`；`good_web_domain="webmota.com"`（已备份 `baozi.data.bak_20261011_P39`） |

## 3. 用户 GUI 复测步骤（无需命令行）

> 🔴 **包子生效前提：必须先让 App 重新加载源/重启 App**（源从 `%APPDATA%\...\comic_source` 读取）。

1. **完全退出并重开 Mangrove**（让新 `baozi.js` / `baozi.data` 生效）。
2. **包子漫画**：进漫画源设置，确认「主域名」显示为 `webmota.com`（若仍写着 `baozimhcn.com` 请手动选回 `webmota.com`）。
   - 打开任一包子漫画 → 应能秒出**章节列表**（不再进 gatekeeper 验证）；
   - 点一章阅读 → 应直接出图（`s2.bzcdn.net`）；
   - 下载一章 → 观察是否还在「获取漫画信息」卡死。
3. **comix.to**：
   - 搜索一本（如 `One Husband Is Enough`）→ 看是否还转圈；
   - 进详情看**章节列表**是否出现；
   - 进一章看图片是否能出。
4. 把**界面现象**（成功/失败、红字报错原文）回报即可，无需敲命令。

### 若 comix 仍 403（WebView 旁路未生效时的兜底）
最直接的根治在**代理侧**（任选其一）：
- Clash 里给 `comix.to` / `static.comix.to` / `*.joshuanotes.site` 加一条 **DIRECT 规则**；或
- 切换到一个**未被 comix.to 封禁**的节点；或
- 临时关闭系统代理（`ProxyEnable=0`）验证——直连实测 200。
