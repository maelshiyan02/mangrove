## 0.5 · 本轮整合了什么（用户 4 条拍板 + 可行性裁定）

| # | 用户拍板 | 可行性裁定 | 落点 |
|---|---|---|---|
| 1 | 缩略图栏要**区分单页+缩放模式 / 长画布模式**；**长画布模式默认禁用**（长画布自己能翻页）；**横版页（如龙女友回归首页）故意隐藏**，让后续图片有充足宽度 | ✅ **可行**。门控条件是现成量：`_stripMode` / `_runDirection` / 页数。⚠️ 唯一新增工作量 = **判断某页是不是横图**，需要页宽高；可用 PNG/JPEG 头解析拿尺寸（便宜），不必整图解码 | §A-1.2 门控、§A-1.4 横图页 |

| 4 | **翻译完成的文字块与文字块组，也可能被截图截断**，这很正常，必须支持 | ✅ **可行**。跨页块/组的坐标是"源像素"层面，与块是否已有译文无关；代价是要对**涉及的每一页**都重画 result | §4-B5 |

### ⚠️ 第 3 条的 4 处硬约束（本计划的可行性要点）

1. **稳定块 id 缺失（最要紧）**。
   已核实：`TextBlock`（`Mangrove/lib/foundation/translation_project/text_block.dart`）**没有 `id` 字段**，
   全项目按**页内下标**寻址（`_editBlock(pageKey, index, …)`）。
   ⇒ 小组若要引用成员，用下标就会"删一个块 → 整组指错块"。
   **建议**：块加入组时**惰性**写一个可选键 `_uid`（不用组的工程完全零字节 diff）。
2. **"真相"必须落在源像素坐标系，不能落在画布坐标**。
   长画布的坐标随缩放/页序变化；跨页块的落盘形式必须是**每页各自的子矩形**（§4.0.2）。
3. **临时拼接必须封顶**。用户担心的"无限的相似问题 / 最终一张超长大图"正是全幅拼接的后果。
   ⇒ 只拼**缝附近窗口**（默认上页底 35% + 下页顶 35%），且**绝不落盘**。
4. **两页宽度必须一致**才能建跨页块。封面横图、异宽页会破坏同宽假设 ⇒ 异宽直接拒绝并给出理由（D12）。

## 1 · 方向：手动优先，但为自动化留结构

用户 2026-10-10 前后两次表态，合起来才是完整需求：

- 第一次：**截断气泡主要不是 AI 识别，而是人工复查的补充功能；不涉及自动翻译流程，因为很容易出错，倾向手动完成与修正。**
- 第二次：**"我其实想要在之后再慢慢把自动检测跨页 → 自动判截断 → 自动建组喂引擎 → 自动分配译文全部实现"**；
  且指出**"如果不能实现文本块跨页创建，就无法处理跨页的识别和翻译，乃至后续的存放"**。

⇒ 结论：

1. **当下**：判定来源全部是**人**（没有任何自动判定参与生产）。
2. **结构上**：把"**决定从哪来**"抽成可替换的一层（§4.0.4 的 L2）——
   今天接"人工点击"，将来换"自动算法"时，**数据模型 / 几何 / 渲染 / 持久化全都不动**。
3. 这正是本计划与旧 v2 的本质差别：旧 v2 是**一套自动算法**；本计划是**一套数据结构 + 可替换判定层**。

### 2.2 BT 的翻译管线阶段 + 可汲取的优点

阶段顺序（`ui/run_pipeline_dialog.py:580-711`，`stage_specs`）：

```
Detection(检测) → OCR → Translation(翻译) → Inpainting(抹字)
```

| 阶段 | BT 落点 | 一句话 |
|---|---|---|
| 检测 | `modules/textdetector/base.py:17-53` | 出 mask + `TextBlock` |
| OCR | `modules/ocr/base.py:49-109` | 逐块 OCR + 后处理 + 字体检测 |
| 翻译 | `modules/translators/base.py:140-255` | 上下文拼接 + `_translate()` + 校验返回条数 |
| 抹字 | `modules/inpaint/base.py:86-185` | OOM 重试、Alpha 保留、按块裁剪 |
| 合并 | `utils/merger.py:259-414` | **并查集**合并相邻 shape + 阅读方向 + 内容拼接 + 旋转框 |
| 块组织 | `utils/textblock.py:968-1051` | 过滤 / 拆分 / 合并 scattered lines / grid 排序 |

**可汲取的优点（工程层面，不是抄代码）**：

1. **并查集合并 + 阅读方向当一等参数**（`merger.py`）——
   在**将来**的自动建组里，这就是"这 n 个块其实是一组"的现成思路；
   当下只用于 §4-B3 的**高亮建议**（不自动建组）。
2. **阶段可插拔**（`stage_specs`）—— 与 §4.0.4 的 L2「可替换判定层」是同一个思想。
3. **统一模块错误包装**（`ModuleRunError`）+ **OOM 重试** —— 长章节与跨页大图批跑的稳定性。
4. **缩略图落盘缓存**（JPEG）—— 避免重解码。
5. **页面范围 + 进度**（`page_range_progress.py`）—— 长章节分批。

**明确不汲取**：自由画笔 / 图层 / 文字特效（BT 强项，但非本项目目标，见 P12 §三）。

## 3 · 模块 A · 翻译工作室 UI 优化

### A-1 左侧缩略图栏（核心）

#### A-1.1 需求逐条 → 设计含义

| # | 需求（要点） | 设计含义 |
|---|---|---|
| 1 | 参考 BT 左侧可滚动缩略图，但**代码自写**（适配性） | 只借范式，不移植 `QListWidget` 那套 |
| 2 | 左栏已有收起机制（宿主左侧栏自动收起，工作室变宽），**有必要效仿吗** | 结论：**做**，做成"左栏的第二种模式"，不是新增第三条栏 |
| 3 | 为利用空间**精简**：缩略图**放大** | 单张更大，同屏更少 |
| 4 | **不堆叠页码与文件名**，改为**图片中心**一个小序号标签 | 去角标文字，序号居中 |
| 5 | 目的：判断**上下相邻页连接处有没有气泡被页边界（截图线）分割** ⇒ **标签不能遮挡** | 上下边缘**必须干净**：序号居中，状态不用角上覆盖点 |
| 6 | 不需要显示很多张（一章可能 >100 张） | 放大后同屏自然少 |
| 7 | **只针对上下滑动阅读的页漫/条漫**；日漫（右→左）不存在截断问题 | **日漫：按钮保留但置灰**（见 A-1.5） |
| 8 | 启用按钮**默认关**，放**右上角按钮排**，点开再点关，有**选中效果**，悬浮**中文**提示 | 复用现有 toggle 范式（marquee / strip 那套） |
| 9 | **（本轮新增）** 缩略图主要服务**单页+缩放模式**；**长画布模式默认禁用** | 见 A-1.2 门控 |
| 10 | **（本轮新增）** 横版页（如封面）**故意隐藏**，让后续图片有充足宽度 | 见 A-1.4 |

#### A-1.2 门控（本轮新增，最重要）

缩略图栏的可用性 = 三个条件的合取：

```
可用 ⇔  !_stripMode                       // ① 单页+缩放模式（长画布模式禁用）
      &&  _runDirection == topToBottom     // ② 上→下阅读（日漫/欧美页漫禁用）
      &&  pageCount > 1                    // ③ 至少有两页才存在"缝"
```

四种"不可用"各有**自己的 tooltip 文案**（不共用一句，用户要知道**为什么**不能开）：

| 不可用原因 | Tooltip（`.tl`，中文） |
|---|---|
| 长画布模式 | `长画布模式可以自己翻页，无需缩略图栏` |
| 日漫/左右阅读 | `仅适用于上下翻页的页漫或条漫`（日漫按钮置灰，D1 结案） |
| 只有一页 | `至少需要两页才能检查页间截断` |
| 无工程 | 按钮禁用，无 tooltip 或"未打开工程" |

⇒ **按钮常驻在右上角那一排**（用户明确要求），**不可用时置灰失效**，与日漫的处理方式一致（统一一种"失效"观感，不混用"隐藏/置灰"）。

#### A-1.3 左栏两种模式

现状：`_buildPageRail()`（`Mangrove/lib/pages/translation_studio/studio_page.dart:2883-2917`）+ `_PageTile`（`:3256-3345`）。

- **紧凑模式（现状，保持）**：宽 156px；小缩略图（`cacheWidth: 96`）；页码角标在**左下**、完成状态点 8×8 在**右上**。
- **缩略图模式（新增，默认关）**：宽约 220~260px（D6）；单张明显放大（建议 `cacheWidth ≈ 320`）；
  **序号标签置中**；**完成状态改用边框色**，不再用角上覆盖点。

原因（A-1.1 第 5 条）：现状的**左下页码**与**右上状态点**恰压在上下边缘 —— 正是要看"缝"的位置。

#### A-1.4 横版页处理（本轮新增）

- 判定：`width ≥ height`（阈值 D11）即视为**横版页**（封面/跨页大图/宣传页）。
- 行为：**该页在缩略图栏中整体隐藏**（不占位、不出图），列表其余页仍保持**真实页号**标注。
- 依据（用户原话）：横图缩进缩略图栏没有意义，隐藏后"后续的图片就有充足的宽度来显示"。
- **副作用要写明**：横版页两侧的**缝不可检视**（该缝在 §4-B1 里标为 `n/a`，而不是 `todo`，避免永远还不了债）。
- 取尺寸的便宜做法：读 PNG `IHDR` / JPEG `SOF` 头（不整图解码）；
  若工程里已缓存尺寸则直接用缓存（B-1 的缝视图也要用尺寸，**共用一份**）。

#### A-1.5 交互与状态

- 新增状态：`bool _thumbRail = false;`（默认关）。
- 开关按钮放在 AppBar `actions`（`studio_page.dart:2399-2597`），与「连续条漫 / 单页」开关（`:2526-2553`）相邻
  —— 两者都是"怎么看这一章"的**视图模式**。
- 按钮范式照抄 marquee/strip：
  `Tooltip` + `IconButton(isSelected: active, style: 选中时底色+前景色, icon: 选中/未选中两个 const 图标)`；
  不可用时按现有**禁用态**渲染（灰）。
  - 图标建议：`Icons.view_list_outlined` ↔ `Icons.view_list`。
  - Tooltip：见 A-1.2 表格。
- **与「连续条漫 / 单页」开关联动**：切到长画布模式时，若缩略图栏是开着的 → **自动关闭**（而不是保留一个可用的灰色按钮），
  避免"开着但看不见"的状态残留（**决策点 D14**）。

#### A-1.6 落点

| 文件 | 改动 |
|---|---|
| `Mangrove/lib/pages/translation_studio/studio_page.dart` | ① `_thumbRail` 状态；② AppBar 开关按钮 + 门控 + 联动关闭；③ `_buildPageRail` 支持两种宽度 + 缩略图模式分支；④ `_PageTile` 增加 `large` 变体（序号居中 + 边框色表状态）；⑤ 横版页过滤 |

| `Mangrove/assets/translation.json` | 新增 4~5 条文案（zh_CN + zh_TW，保持 CRLF） |

#### A-1.7 验收

- **可 headless 测**（纯逻辑）：
  1. `thumbrail.default_is_off` —— 默认 `_thumbRail == false`
  2. `thumbrail.gate_truth_table` —— `(!strip) × 方向三值 × 页数(0/1/2+)` 的完整真值表（含**不可用原因码**，不只布尔）
  3. `thumbrail.landscape_pages_are_hidden` —— 给定页尺寸集合，横版页被剔除且**页号不错位**
  4. `thumbrail.tile_hides_edge_overlays` —— 缩略图模式下**不存在**贴边覆盖层（源码切片构成性判据）
  5. `pageheader.reads_png_and_jpeg_size` —— 头解析在两种格式上都取到正确宽高（用**构造的小文件**做夹具，故障路径：截断文件 → 返回 null）
  每条都要有**故障路径**能把判据打红（M08）。
- **只能 GUI 验收**（无渲染表面）：放大后的可读性、序号置中是否真不挡缝、>100 页滚动流畅度、"隐藏横图后是否真的更宽"。

#### A-1.8 不做什么

- 不做"每页强制落盘缩略图文件"（先用 `Image.file(cacheWidth: …)` 惰性解码；>100 页卡顿**再**评估 BT 式 JPEG 缓存）。
- 不做文件名 / 页数文字（用户明确不要）。
- 不做"自动检测这页有截断并高亮"（那是 AI 识别，用户排除）。
- 不在长画布模式下提供缩略图栏（用户明确禁用）。

### A-2 其余空间精简（P12 方向 A 的吸收，次要）

- 右栏 `StudioBlockPanel`（宽 340，≥1600 时 400，`:2613`）可折叠为图标条，或悬浮覆盖而非挤占画布。
- 窄屏（<1180）时右栏压成 320 高横条（`:2625`）—— 可改为按需展开。

## 4 · 模块 B · 跨页气泡截断拼接（人工优先，5 阶段）

### 4.0 核心设计与数据模型

#### 4.0.1 三条铁律

1. **不落盘任何合成图**。物理拼接只存在于内存、只在识别那一瞬间、用完即弃。
   → 用户的"无法导向自动化"的物理修复路线（拼图 + 手调分割线）**不采用**。
2. **"真相"在源像素坐标**。跨页块的落盘形式是**每页各自的子矩形**；"跨两页的大矩形"是**派生视图**，随时可算。
3. **人工优先，判定层可替换**。所有判定来自人；判定层单独一层（§4.0.4），将来换自动算法不动其他层。

#### 4.0.2 跨页坐标怎么表达

```
页 A（key="p003", 尺寸 1600×2400）   虚拟 y ∈ [0, 2400)
页 B（key="p004", 尺寸 1600×2400）   虚拟 y ∈ [2400, 4800)
虚拟坐标 = 两页纵向零间隙拼接后的坐标（x 沿用页内 x）
```

- **不存**虚拟整矩形（它依赖"当前是哪两页、当前顺序"，是**派生值**）。
- 存的是 `_span.parts = [{page:"p003", rect:[…]}, {page:"p004", rect:[…]}]`。
- 好处：单页重导、页序变化、异宽页……每个子矩形在**自己那页上永远有效**；虚拟矩形由 `parts` 现算。
- 这正是用户说的"从一张图片的坐标位置范围，变成两张图片组合出新的坐标系之后的相对坐标范围"，
  只是把它**再往回拆一层**：**最终真身仍是每页自己的坐标**，中间那层虚拟坐标是工作视图。
- 两种写法的逐项对比与结案推导见 **§8.3**（结论：per-page = 真身 / 虚拟 = 派生）。

#### 4.0.3 数据模型（全部可选键，零字节 diff）

**块级**（`TextBlock.raw`，落点 `translation_project/text_block.dart:785`）：

| 键 | 类型 | 含义 |
|---|---|---|
| `_uid` | `String?` | **惰性**分配的稳定块 id（仅在块加入组/跨页块时写）—— 解决 §0.5-① |
| `_span` | `Object?` | 跨页标记：`{"parts":[{"page":k,"rect":[x,y,w,h]}, …]}`；单页块无此键 |

**工程级**（`TranslationProject.raw`，落点 `translation_project/project.dart:89-97`）：

| 键 | 类型 | 含义 |
|---|---|---|
| `_groups` | `Map<String,Object?>?` | 组定义（下） |
| `_seam_reviews` | `Map<String,Object?>?` | 缝检视状态：`"<pageA>|<pageB>" → "todo"｜"clean"｜"split"｜"n/a"` |

**组定义**（`_groups[groupId]`）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `mode` | `"nest"｜"link"` | 大框套小框 / 多块连线。**只影响可视化**，不影响数据（D17） |
| `members` | `List<{page,uid}>` | **有序**成员引用（顺序 = 组合原文的顺序；可人工拖动重排，见 B-4 倒装） |
| `source` | `String?` | 组合后的**完整原文**（人工校对） |
| `translation` | `String?` | 完整译文（一次调用得到） |
| `assignment` | `Map<String,String>?` | 每个成员的译文片段（键 = `"<page>#<uid>"`） |
| `seam` | `String?` | 所属缝（`"p003|p004"`）；非跨页组为 null |

> ⚠️ 工程级写回**第一件要验证的事**：未知顶层键必须原样保留（否则一保存就把 `_groups` / `_seam_reviews` 抹了）。
> 落点 `project.dart:373`（`buildFrom`）+ `project_io.dart`。

#### 4.0.4 分层：为未来自动驾驶预留的接口分层

| 层 | 内容 | 今天 | 将来 |
|---|---|---|---|
| **L1 几何层**（纯函数，可 headless） | 虚拟坐标 ↔ 每页子矩形互转；缝窗口范围计算；成员排序（页号 → y 降序）；组边界框 = 成员并集 | 现在就写完 | **不变** |
| **L2 判定层**（可替换的"决定来源"） | `SeamMarker`（缝是否截断）/ `SpanFramer`（给定缝窗口 → 候选跨页矩形）/ `GroupSuggester`（给定块集 → 建议组） | **人工实现**（点选） | 换成**自动实现**（复用 `TranslationWorker` + `merger.py` 的并查集思路），**上层不动** |
| **L3 执行层**（复用现有） | `TranslationDispatcher`（一次翻译）、`result_renderer` / `page_renderer`（渲染）、`_rerenderResultPage`（逐页） | 只调用 | **不变** |
| **L4 持久化层** | 可选键 + 两个不变式（未知键保留 / 不存在即 null） | 现在就定死 | **不变** |

⇒ 用户说的"之后再慢慢全部自动化"，在本计划里**只是替换 L2 的三个实现**，不推翻任何数据。

#### 4.0.5 五阶段一览

```
B-1 缝发现与标记（单页模式·缩略图栏）
        ↓
B-2 跨页文本块创建（长画布·临时拼接→识别→分割）   ← 用户指出的"前提"
        ↓
B-3 文字块小组（大框套小框 / 多块连线）
        ↓
B-4 组合原文 → 翻译一次 → 断句分配（含倒装处理）
        ↓
B-5 渲染与复原（涉及几页就重画几页）
```

每个阶段都能中途退出，状态留在工程里；每步只在上一步**人工确认后**才解锁。

### B-1 · 缝发现与标记（单页模式）

**目标**：人眼在**单页模式**下借助缩略图栏，逐条缝判断"有没有气泡被页边界截断"，记录 `todo / clean / split / n/a`。

**用户操作流程（步骤级）**

1. 进**单页+缩放**模式，开缩略图栏（A-1）。缩略图栏里**上下相邻两张**就是一个"缝"。
2. 人眼扫两图的**上下边缘**（这正是 A-1 把标签移到中心、不用角上覆盖层的原因）。
3. 点【标记为干净】/【标记有截断】→ 写入 `_seam_reviews`。
4. 缩略图栏在对应缝上显示状态（有截断 = **居中**小标记，仍不挡缝）；支持"下一条未检视的缝"跳转（D7）。
5. 横版页被隐藏（A-1.4）⇒ 其两侧缝自动标 `n/a`。
6. 标记为 `split` 的缝，提供【到长画布处理】按钮 → 切到长画布模式并滚到该缝（衔接 B-2）。

**手动 vs 自动边界**
- 自动**只做**：把相邻两页摆成上下两张、统计已检视/未检视、跳转。
- 自动**不做**：任何"这里像截断"的判定 —— **不预勾选、不给置信度、不自动标红**。

**落点**
- 新文件 `Mangrove/lib/foundation/translation_project/seam_review.dart`（缝 id 规则、状态读写、计数；纯逻辑）。
- 工程级键写入：`project.dart` / `project_io.dart`。

**验收**
- headless：① `seam.id_is_order_stable`（`"A|B"` ≠ `"B|A"`，只认阅读序）；
  ② `seam.reviews_round_trip`（写→读→还原，**含未知键保留**）；
  ③ `seam.counts_exclude_na`（`n/a` 不计入"待检视"，否则永远还不完）；
  ④ `seam.landscape_neighbours_are_na`。
- GUI：缩略图栏里"缝"是否看得清。

**不做什么**：不做跨页图（spread）检测；不做自动评分；不在长画布模式下做缝检视。

### B-2 · 跨页文本块创建（长画布 · 临时拼接 → 识别 → 分割）

**目标**：把被缝截断的一个气泡，建成**一个几何上完整的跨页块**（坐标跨两页），供后续识别/翻译/渲染。

**用户操作流程（步骤级）**

1. 切到**长画布模式**（`_stripMode`），滚到目标缝（或由 B-1 的【到长画布处理】进入）。
2. 两种创建方式（**都要有**，因为云朵状/畸形气泡自动识别会误判）：
   - **a. 纯人工框选**：在长画布上拖一个大框**跨过缝线**、盖住整个气泡；
     系统按缝把框**切成每页子矩形**（`_span.parts`）。
   - **b. 识别辅助**：点【识别这一块】→ 系统在内存里**临时拼出缝窗口**
     （页 A 底 35% + 页 B 顶 35%，零间隙，**封顶**）→ 在该窗口跑现有检测/OCR
     → 把候选框**映射回虚拟坐标** → **人工确认 / 微调** → 落盘。
3. 落盘为跨页块：写 `_span.parts` + 惰性 `_uid`。
4. **立刻分割**：临时拼接图**当场丢弃**，不进任何产物目录。

**手动 vs 自动边界**
- 自动**只做**：拼缝窗口、在窗口上跑检测/OCR 拿**候选**、把候选映射回虚拟坐标、按缝切分成子矩形。
- 自动**不做**：**不自动采纳**候选框（必须人确认）；**不落盘合成图**；**不做全幅拼接**。

**落点**
- `Mangrove/lib/foundation/translation_project/cross_page_block.dart`（新）：
  虚拟坐标 ↔ 子矩形互转、缝切分、`parts` 校验（同宽、边界不越页、不重叠）——**纯函数、可 headless**。
- `Mangrove/lib/foundation/translation_project/seam_window.dart`（新）：
  缝窗口构造（在 `RgbaImage` 层拼两页的条带，纯 Dart，无 `dart:ui`）——**可 headless**。
- 长画布建块交互：`studio_page.dart` + `components/studio_scroll_canvas.dart`（跨缝拖框、缝线吸附/高亮）。
- ⚠️ **要放宽"页面之间文本块互不侵犯"规则**：现状长画布不允许块跨页；需改成"**仅跨页块例外**"。
  这条规则的具体落点要在实现前先定位（**决策点 D16**）。

**验收**
- headless：① `span.split_maps_back_to_source_pixels`（虚拟矩形 → 子矩形 → 还原虚拟矩形，**往返无损**，坐标是整数像素）；
  ② `span.window_is_bounded`（窗口高度 ≤ 封顶值；故障路径：故意传全幅 → 返回拒绝）；
  ③ `span.never_writes_merged_image`（跑完整条流程，产物目录**字节不变**）；
  ④ `span.rejects_mismatched_width`（两页宽不同 → 拒绝 + 给理由码）；
  ⑤ `span.parts_do_not_cross_page_bounds`。
- GUI：跨缝拖框的手感、缝线吸附、识别候选框的位置是否正确。

**不做什么**：不持久化合成图；不做全幅超长拼接；不自动采纳识别结果。

### B-3 · 文字块小组（大框套小框 / 多块连线）

**目标**：把"一句话被分成几个气泡"的若干块（**可含跨页块**）组织成**一个组**，作为**翻译单位**。

**两种形态 —— 同一数据结构，只是可视化不同（D17）**

| 形态 | 适用 | 可视化 | 说明 |
|---|---|---|---|
| `nest` **大框套小框** | 气泡**贴合/云朵状**（距离近，截图方便） | 画一个**组边界框**（大框），成员块（小框）在框内 | 大框对**畸形/非矩形**（云朵轮廓）**不必精确**，避免对怪形状误判；也**省修图成本** |
| `link` **多块连线** | 成员**间隔较远** | **不画大框**，成员之间画连线 | 距离远时大框会圈进无关画面 |

**用户操作流程**

1. 选中若干块（`nest`：拖一个大框圈住；`link`：依次点选成员）→ 【建组】。
2. 系统按规则**自动排序**成员：**先按来源页号升序；同页按 y 从高到低**。
3. 人工可**拖动重排**（为 B-4 的倒装句准备）。
4. 组边界框 = 成员矩形**并集**（派生，不存）。

**手动 vs 自动边界**
- 自动**只做**：排序、算并集、画框/连线、给"这些块按聚类参数本会被合并"的**高亮建议**。
- 自动**不做**：不自动建组 —— **没有人的点选/框选，就没有组**。

**落点**
- `Mangrove/lib/foundation/translation_project/block_group.dart`（新）：组模型、成员排序、并集、增删成员、解组（纯逻辑）。
- UI：长画布上的建组交互 + 组可视化；右栏 `StudioBlockPanel` 的**组模式**（见 B-4）。
- 建议复用：`balloon_clustering.dart` 的 `ClusterParams`（只做高亮）。

**验收**
- headless：① `group.members_sort_by_page_then_y`（跨页成员：页号优先；同页 y 降序；**用例要含跨页与同页混排**）；
  ② `group.mode_does_not_change_data`（把 `nest` 改成 `link`，除 `mode` 外**数据完全一致**）；
  ③ `group.bbox_is_union_of_members`；
  ④ `group.member_ref_is_stable_after_unrelated_delete`（用 `_uid`：删掉别的块，组仍指向原块）；
  ⑤ `group.uid_is_lazy`（**从未建过组的工程**，块里不出现 `_uid` ⇒ 零字节 diff）。
- GUI：大框/连线的观感、拖动重排的手感。

**不做什么**：不自动建组；不做"块同时属于两个组"。

### B-4 · 组合原文 → 翻译一次 → 断句分配（含倒装处理）

**目标**：把组内多个成员的原文**组合成完整句** → 翻译**一次** → **断句** → **分配**回各成员；
并**处理倒装句**（成员顺序与译文顺序可能错位）。

**用户操作流程（步骤级）**

1. **右栏以"小组"形态同时显示多个成员**（用户明确要求）：
   按 B-3 的顺序列出每个成员的原文，**跨页成员标注来源页**，同页内按 y 降序。
2. 【组合】→ 依成员顺序拼成**完整句** → **人工校对**（截断处常有 OCR 断字/重复/缺字）。
3. 【翻译一次】→ 调 `TranslationDispatcher.translateBatch([组完整原文])`（**一组一次调用**，与单页管线同引擎/同设置）。
4. 【断句分配】：
   - 系统可给"按标点/句读切分"的**建议片段**（**仅建议，可关**）；
   - **人工**把片段指派给成员（拖拽或下拉）；
   - **倒装处理**：映射**允许非顺序**（第 1 段可以指派给第 2 个成员），面板把**映射关系**显式画出来，
     让人一眼看出"哪段译文去哪了"（这正是用户说的"识别出的原文很可能和正式填写的译文的意思不匹配"）；
5. 确认 → 走 `_editBlock` **逐个**写回成员译文（可撤销）。
6. 每个成员可单独标记【本块不再出译文】（例如整句都塞给 head 块时，tail 块留空）。

**手动 vs 自动边界**
- 自动**只做**：组合、一次翻译调用、切分**建议**、映射校验。
- 自动**不做**：**不自动采纳**切分；**不按字符比例自动切**（旧 v2 的做法**已删除**）；不自动纠错。

**落点**
- `Mangrove/lib/foundation/translation_project/group_translate.dart`（新）：组合、切分建议、映射校验（纯逻辑，可 headless）。
- `.../image_translation/translation_dispatcher.dart`：**只调用，不改语义**。
- `StudioBlockPanel`：新增**组模式**（多成员并排 + 组合/翻译/分配三区）。
- 附带小功能：**与相邻块交换译文**（BT 那个实验）——交换两个块的 `translation` + `rich_text`，
  一个 undo step；与倒装处理天然配套，**独立排期，不阻塞本阶段**。

**验收**
- headless：① `groupconcat.order_is_member_order`；② `groupconcat.never_mutates_member_source`（跑完成员 `source` 字节不变）；
  ③ `distribute.allows_non_monotonic_mapping`（倒装：映射可乱序，且被接受）；
  ④ `distribute.rejects_unmapped_members`（有成员没分配 → **不写**，返回未完成）；
  ⑤ `distribute.one_dispatcher_call_per_group`（用注入的假 dispatcher 断言**调用次数 == 1**，不是成员数）；
  ⑥ `distribute.never_runs_when_source_missing`（无组原文 → 调用次数 == 0）；
  ⑦ `distribute.is_undoable`。
- GUI：中 / 日 / 英三语的组合 → 翻译 → 分配全流程观感；倒装映射是否看得懂。

**不做什么**：不做自动比例切分；不调用 AI 纠错；不把组塞进批处理管线（§5）。

### B-5 · 渲染与复原（涉及几页就重画几页）

**目标**：把分配结果**画回图**；跨页块/组涉及**两页**时两边都要重画；并能**解组 / 解跨页 / 复原**。
（对应第 4 条拍板：**已翻译的块和组也可能被截断**，同样要能处理。）

**用户操作流程（步骤级）**

1. 【出图】→ 对**涉及的每一页**走 `_rerenderResultPage`（P20 已接线），
   **逐页**满足两阶段顺序契约（mask → inpainted → result，**不能把两页混在一批**）。
2. **跨页块的抹字**：抹字范围 = 该块**在各页的子矩形**（`_span.parts`）——
   复用 P20 的 `eraseRects` 思路 + `block_artifacts.dart` 的掩膜合并（**逐页**做）。
3. 【解组】：清 `_groups[id]` + 可选清成员译文（走 undo）；组内若有跨页块，**跨页块本身保留**。
4. 【解跨页】：把跨页块**拆回两个单页块**（各自保留原文/译文）或直接删除；
   若要退回原字，走 P20 的**复原**路径（`buildRestorationMask` + `restoreErasedPage`），**逐页**做。
5. 状态回收：解组后 `_seam_reviews` 对应缝状态回到 `todo`（若原本是 `split`）。

**手动 vs 自动边界**
- 自动**只做**：调用现有渲染、按 `parts` 逐页抹字、逐页满足顺序契约。
- 自动**不做**：不自动判断"要不要抹 tail 块的字"；不自动决定拆不拆。

**落点**
- `studio_page.dart`：`_stitchRenderPage()`（**多页版**，复用 `_rerenderResultPage` / `_writeArtifactBytes`）。
- `translation_project/block_artifacts.dart` / `result_renderer.dart`：**不改语义**，只调用；
  需确认"跳过某块"与"只抹某块的某些子矩形"能用现有入参表达（**决策点 D5**）。

**验收**
- headless：① `stitchrender.per_page_two_phase_order`（**每一页**都 mask/inpainted 先于 result）；
  ② `stitchrender.erase_covers_all_span_parts`（两页的抹字区域合起来 == 跨页块全形）；
  ③ `stitchrender.split_restores_two_single_blocks`（解跨页后恢复成两个单页块，`_span` 键消失）；
  ④ `stitchrender.no_merged_artifact_written`（产物目录里**没有**合成图）。
- GUI：出图后缝两侧是否接得上、tail 块是否干净。

**不做什么**：不新写渲染器；不动 `mask/inpainted/result` 契约；不落盘合成图。

### 8.3 D8 附注：per-page 子矩形 vs 虚拟整矩形（为什么前者是真身）

**设定**（下文全部用它举例）：`p003`、`p004` 均 1600×2400；同一个跨缝气泡
在 `p003` 上占 `(600, 2200, 400, 200)`，在 `p004` 上占 `(600, 0, 400, 300)`。

```
虚拟坐标系（两页零间隙纵向拼接）
  y = 0 ───────────── p003 (0 … 2399)
  y = 2400 ────────── 缝（截图线）
  y = 2400 … 4799 ─── p004
  ⇒ 气泡虚拟整矩形 = (600, 2200, 400, 500)   // 高 = 200 + 300
每页坐标系（各自 0 起点）
  p003: 气泡占 (600, 2200, 400, 200)
  p004: 气泡占 (600,    0, 400, 300)
```

**两种写法**

```json
// 写法一 · 虚拟整矩形
{"x":600, "y":2200, "w":400, "h":500, "pages":["p003","p004"]}

// 写法二 · per-page 子矩形（结案）
{"parts":[
  {"page":"p003", "rect":[600, 2200, 400, 200]},
  {"page":"p004", "rect":[600,    0, 400, 300]}
]}
```

**分岔场景逐项对比**

| 场景 | 写法一（虚拟整矩形） | 写法二（per-page 子矩形） |
|---|---|---|
| 章节插页 / 删页 / 重新下载 | y 起点依赖"当前是哪两页、什么顺序" ⇒ **整体错位** | 每段挂在**自己页**上 ⇒ 不受影响 |
| 某页重新导入成不同分辨率 | 整条矩形失效（x/w 也一起变） | 只有**那一页**的那一段要重算 |
| 两页宽度不一致 | **无法表达**（只有一个 x/w） | 天然能表达（每段各写各的 x/w）⇐ 但仍在 D12 拒绝建块 |
| 真实执行（抹字 / 渲染） | `mask` / `inpainted` / `result` 都是**逐页**产物 ⇒ 每次用前**必须先拆** | 直接就是逐页输入，**零转换** |
| 校验 | 只能整条校验，坏一段看不出来 | 每段可**独立校验**边界 / 不越页 / 不重叠 |
| 隐含假设 | 依赖"两页一定相邻且同宽" | 无隐含相邻性假设 |

**结论（三段）**

1. **不是二选一，而是"谁是真身、谁是派生"**：
   **per-page 子矩形是落盘真身**（`_span.parts`），**虚拟整矩形是运行时派生视图**
   （由 `parts` 现算，用于画布上画一个整框、算成员并集、算缝窗口）。
2. **`parts.length > 1` 本身就等于"这是跨页块"** ⇒ 不需要额外的 `_isCrossPage` 标志位
   （少一个会和 `parts` 漂移的冗余字段）。
3. **将来做自动化时，虚拟坐标是中间态、per-page 是终点**：
   检测器给的是**窗口**坐标 → 映射回**虚拟**坐标（人工微调在这一层最直观）
   → 落盘前**切成 per-page**。
   代价 = 一组"虚拟 ↔ per-page"互转**纯函数**（纯 Dart、可 headless、可反向验证
   `span.split_maps_back_to_source_pixels`，见 §4-B2 验收）。
