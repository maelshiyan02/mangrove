## 0 · 问题定义与现状

### 0.1 我们要解决什么

漫画里的一张图是**左右两页拼成一张**（典型宽幅跨页，如战斗跨页、封面拉页），导致对话气泡被**截图边界截断**。后果有三层：

1. **检测/OCR** 层：一个完整的气泡被切成两个块，OCR 读出**半句话**
2. **翻译** 层：半句话喂给翻译引擎 = **垃圾译文**（倒装句、语序调整、指代消解全失效），而且看不出是垃圾——它会自信地翻出一段看起来合理的文字
3. **渲染** 层：两个块各画各的译文，之间缺桥接关系，读者看到的是两个"独立的"气泡

MDGH-ch1 载体里**已经有一张真实的跨页图**（1532×1024 横向），不是假设场景。

## 1 · 核心设计：「组」模型

### 1.1 为什么需要「组」

跨页截断不是简单的"合并块"，而是**语义层面**的组：

```
页 A ┌─────────────┐     页 B ┌─────────────┐
     │  "我刚从...  │─────────│  "...医院出来" │
     │   那所医院"  │  ←截断→ │  （同一气泡）  │
     └─────────────┘     └─────────────┘
     Block A                    Block B
```

翻译引擎需要看到**完整句子** "我刚从那所医院出来"，而不是两半。翻完后，译文 "I just came out from that hospital" 需要**分配回两个块** —— 左边块放前半截或整句（取决于气泡大小和文本长度），右边块可能放后半截或留空（译者决定）。

「组」**不是**把两个块物理合并成一个：
- 块位置（`xyxy`）仍然各自独立 —— 渲染、OCR、编辑都按块操作
- 组是**翻译管线和术语表**的概念 —— 告诉引擎"这几个块一起喂，翻完再分开"

### 1.2 不破坏零字节 diff 的方案

FT 工程互读契约：**FT 会忽略它不认识的 JSON 键**（JSON 标准行为）。所以 TextBlock 加**可选新键**不会破坏 round-trip —— 只是 BT 侧看不到这个组引用而已（功能退化到逐块翻译，和我们现状一样）。

**拟新增的可选键**（按 FT 风格用下划线前缀 `_` 表示"宿主扩展"）：

| 键 | 类型 | 含义 | 谁写谁读 |
|---|---|---|---|
| `_group_id` | `String?` | 组唯一标识（如 `"group_001"`） | 检测阶段写；翻译引擎读 |
| `_group_role` | `"primary"\|"continuation"\|null` | 主块/续块（决定译文默认放哪） | 检测阶段写；渲染阶段读 |
| `_group_cross_page` | `bool?` | 组是否跨页（决定跨页术语表作用域） | 检测阶段写；术语表读 |
| `_group_total_blocks` | `int?` | 组内块数（冗余，校验用） | 检测阶段写；翻译前校验 |

**为什么用可选键**：
- 不破坏已有工程（没有这些键的块 `_group_id` 为 null = 不是组的成员，逐块翻译走原有路径）
- FT 忽略未知键 = 我们的组信息不会让 BT 崩
- 零字节 diff 保证仍然成立（**已有键的值不变**，只是多了几个可选键）
- 新字段加在 `raw` 里 = `TextBlock` 这个 Dart 模型**零改动**（它就是 `this.raw` 的包装）

**为什么不用顶层的 `page_order` / `chapters` 那种自加字段**：因为 TextBlock 是**每个块一条**的粒度，组引用也应该在块级别。

### 1.3 组与术语表的关系

当前术语表作用域 = `comicId`（整本漫画）。加入组之后：
- `_group_cross_page: true` 的组 → 术语表自动**跨页**作用域（但仍是 `comicId` 级别，不升级到跨漫画）
- 非跨页组 → 不变

这给 `studio_page.dart:618` 那条"空承诺"一条自然的出路。

## 2 · 分阶段方案

### 阶段 S10-A · 跨页图检测（检测层前置）

**目标**：在检测/OCR 阶段标记出"这张图是跨页拼接图"。

**检测策略**（不依赖 BT）：

| 策略 | 原理 | 可能误判 |
|---|---|---|
| **宽高比阈值** | 漫画单页通常 3:4 ~ 4:3；跨页拼接近 2:1 或更扁 | 横版漫画/全景图（MDGH-ch1 那张 1532×1024 就是 ~3:2，刚好在边界上） |
| **相邻页边界匹配** | 下载层通常连续存两张相邻页，检测它们的右边界/左边界像素是否连续 | 两张独立页面的边界恰好匹配（罕见） |
| **人工标注** | 工作室工具栏加一个按钮："标这页为跨页"，存进工程 json | 依赖用户操作（最可靠也最费人） |

**拟组合**：宽高比阈值（自动，判为候选）→ 相邻页边界匹配（二次确认）→ 两者都不确定时留候选标记但不自动分组。

**落点**：
- `project.dart` 的 Page 模型加可选 `_isCrossPage` 字段（同 TextBlock 的 `_` 前缀风格）
- `image_translation/pre_translation_tasks.dart` 的检测阶段（已是开关 `legacyPipelineEnabled=false`，当前主路径走 `StudioPipeline`）

**验收判据**：
1. MDGH-ch1 那张 1532×1024 图被正确标记
2. 同漫画里所有非跨页图**不误判**（可在 GUI 会话里人工核对）
3. 零字节 diff：有检测标记的工程 → BT 能正常打开（忽略未知键）

**BT 依赖**：无（v2 已确认）。开工前在 `Ballonstranslator_win_minium/`
做一次证伪式 grep（stitch/spread/double page）即可。

### 阶段 S10-B · 截断气泡识别（块级）

**目标**：在检测到的跨页图上，标记"被页边界截断的文字块"。

**判据**：块的四个角点（`lines` 字段）中，有至少两个角点在**页边界 ±N 像素**范围内（N 取典型气泡 padding，经验值 ~20px）。

```
页边界在 x=1532
块的 xyxy = [1512, 200, 1552, 240]
→ 右边界 1552 超出页边界 1532 → 截断！
→ lines 角点 [1552, 200] 和 [1552, 240] 在页边界 ±20px 内
```

**边界情况**：
- 块整体在页边界**之前**但贴近（如 [1490, 200, 1530, 240]）→ 不是截断，是"刚到边界"
- 块整体在**两页交界处**（跨页图里一页写到底一页写头）→ 更复杂的场景，可能需要 `distance` 字段辅助
- 旋转块（`angle != 0`）→ `lines` 是真实角点，直接用 `right`/`left` 不够精确，但先从轴对齐开始

**落点**：
- `text_block.dart` 的 `fromOcrBlock` 适配器里加截断判据（检测阶段后）
- 加可选键 `_truncated: bool?`（与 `_group_id` 同源）

**验收判据**：
1. MDGH-ch1 跨页图上的截断块被正确标记
2. 非截断块**不误判**
3. 零字节 diff 保证不破坏

**BT 依赖**：无（v2 已确认），判据全部自研。

### 阶段 S10-C · 跨块分组（核心）

**目标**：把截断块编成一个组，让翻译引擎看到完整上下文。

**分组规则**：
1. 同一页的截断块 → 按 `y` 坐标排序、相邻距离阈值（气泡间距经验值 ~30px）、同文本方向（横排/竖排）匹配候选
2. 不同页的截断块 → 只在**已标记跨页**的图上才考虑；按"前一页最右截断块 ↔ 后一页最左截断块"做配对
3. 组内必须**至少有一个 primary 块**（默认：`lines` 角点不在页边界上的那个 —— 说明它包含完整的起点/终点语义）

**翻译管线的接入方式**：
- `translation_dispatcher.dart` 里，遇到 `_group_id` 的块 → 把同组所有块的 `sourceText` 拼成一段，**共享一次翻译调用**
- 翻译引擎收到的是完整句子 → 译完后，需要分配译文回各块（S10-D）

**为什么不做"跨组一次翻译"**：
- 组内块的**译文文本长度**可能差很大（一句长 50 字一句短 5 字），合成一段给引擎可能让它输出过长或过短
- 更安全的做法：**合成原文 → 一次翻译 → 分配译文**（而不是"一次合成+翻译出一段，不管长度"）

**落点**：
- `translation_project/text_block.dart`（`_group_id` 等可选键）
- `image_translation/translation_dispatcher.dart`（接组的翻译调用逻辑）
- `foundation/bt_project/bt_project.dart`（加载时把同组块关联起来的查询）

**验收判据**：
1. 已知截断样本翻译质量提升（**需 GUI 人工验收**，本会话无渲染表面）
2. 不截断的块翻译**无回归**（`block-ops-check` 现有断言全部仍绿）
3. 降级路径：组内有块原文为空/译文冲突 → 逐块独立翻译（当前行为），不崩
4. 零字节 diff

**BT 依赖**：无（v2 已确认 —— BT 没有分组/多块合并给翻译的概念），
S10-C 是本项目原创能力。

### 阶段 S10-D · 译文分配（S10-C 的收尾）

**目标**：翻译引擎产出的一段完整译文，分配回组内各块。

**三种分配模式**（从简单到复杂，递进实现）：

| 模式 | 描述 | 适用场景 |
|---|---|---|
| **A. 整句放 primary** | 完整译文只放在 primary 块上，续块留空（或用 `_group_role` 显示"译文见主块"提示） | 译文不长、气泡主要在一页的情况 |
| **B. 比例切分** | 按原文各块字符数比例切分译文 | 译文较长、需要填满两个气泡 |
| **C. 智能分配** | 翻译引擎在 prompt 里要求"按 [块 1: 原文片段 1, 块 2: 原文片段 2] 分别输出译文"，一次调用返回多段 | 最理想，但需要引擎（LLM）支持 |

**建议先做模式 A**（最简单、最安全），在 UI 上加一个"译文分配"设置让用户选择模式 B/C。模式 C 需要 LLM 上下文记忆（A08 §1.1.5 里提到的"LLM 上下文记忆三层"）—— 这是另一项能力的延伸。

**落点**：
- `image_translation/llm_translator.dart`（如果做模式 C 的 prompt 工程）
- `translation_project/studio_block_ops.dart`（译文分配的纯逻辑层）

**验收判据**：
1. 模式 A：译文只出现在 primary 块，续块状态合理（不是空到让人以为没翻）
2. 模式 B：切分后各块译文长度与原文长度比大致匹配
3. 零字节 diff

**BT 依赖**：无自动分配。BT 侧唯一相关的是用户做过的**两块互换译文**
实验（v2 确认）——已归类为译者手动操作，见 §0.3 末尾，不进本阶段。

## 3 · 不做什么（明确排除）

| 不做 | 理由 |
|---|---|
| **不把跨页图物理合并成一张** | 下载层就是逐页 `.webp`，改目录结构 = 重下整本 + 扫描器红线（A03 §1：章节目录内出现子目录 → 整本被拒） |
| **不重写检测/OCR 管线** | 复用现有管线，只在**后处理**加组识别。检测管线已跑通（edit-check 196 基线） |
| **不把 TextBlock 结构改成复杂类** | 保持 `raw: Map` 包装（零 Dart 模型代码改动），组用可选键实现 |
| **不破坏零字节 diff** | 任何新字段都是**可选的**（不存在 = null），不影响已有工程的 round-trip |
| **不要求 LLM 引擎** | S10-C 先用本地 NMT（现有引擎），S10-D 模式 C 才需要 LLM 的上下文记忆 |
