## 1. 背景与目标

Mangrove 翻译工程室已具备：文字块模型（`TextBlock`）、分组（`block_group`）、跨页缝
（`cross_page_block`）、组级拼句翻译（`group_translate`）、纯 Dart 抹字/修复
（`TextInpainter`）、分层产物（`mask/ → inpainted/ → result/`，且 `result` 强制从原图算）。

本轮目标（用户明确）分两件，且**有明确先后**：

1. **去水印前置**：把"去除翻译组水印"作为翻译管线的**第 0 步**——先净化再去翻译。
2. **文字块分类重构**：扩展块分类，支持「对话 / 拟声词 / 物件文字 / 水印」三类语义，
   并配套「规整 / 不规则（艺术字）」字形轴与「特殊字体」识别难度标记，为后续
   全局理解式识别/翻译留口子。

**设计原则（用户拍板）**：走 Mangrove 真实管线扩展，不单独建环境；只扩展不新建
核心架构；UI 显示一律中文；英文命名按本计划第 4 节锁定。

### 2.2 水印特征（视觉逐页核验 + 自动扫描，已验证）

素材为恋爱漫（画稿自身大量粉色），水印为 **`ROKARICOMICS.COM` logo**：

| 实测结论 | 证据 |
|---|---|
| **logo 水印间歇性、位置不固定** | p3 右中黑边、p11/p83 等；p50 右下**压在画稿上**（约 x72% y95%） |

| **抽样结构**（23/86 页） | logo 约 17%、装饰/声明横幅约 22%、干净约 61%（视觉可能漏检极小透明 logo，真实比例或略高） |
| **纯色区 vs 压画稿两类** | p3 黑边（纯色，易擦）；p50 右下（压画稿/文字，需 AI 修复） |

**结论**：水印识别必须靠「站点标专用检测」（模板匹配 / OCR 命中 `ROKARICOMICS.COM`
/ 小目标检测），且逐页门控——先判「本页有没有、在哪」，再只对那块做处理。

## 3. 用户补充的四条硬约束（必须落进计划）

### 3.1 去水印 = 管线第 0 步，净化严格先于翻译

- 水印是**无规则的"贴纸"**，会破坏漫画原有信息；贴在哪**全看翻译组心情**：
  - 有时贴在可直接擦除的**纯色区域**（易）；
  - 有时贴在**对话框附近 / 画稿上**（难）。
- **明确的先后关系**：进行翻译的前提是**先对漫画图片做纯净化（去水印）**。
  自动化管线开展时**必须牢记**此顺序：净化 → 再翻译。
- **两种擦除难度**：
  - 简单：填充附近底色即可（纯色底）；
  - 难点：水印下方有**图片或文字** → 必须 **AI inpaint** 把擦除处补全。
- **第一步**：先实装功能——用填充式擦除跑通全流程；AI inpaint 作为算法热插拔升级
  （数据模型已预留 `region_inpaint_dict` 键，见 5.2）。

### 3.2 文字块形状：配套 UI 切换 + 自由选区（画笔闭合多边形）

- 非矩形框需要**自由选区**能力。
- 必须做**配套的 UI 切换功能**：在「矩形框选」与「自由选区」之间切换。
- **技术难点（明确告知难度高）**：实现**画笔工具**——用笔触连接成**闭合图形**
  作为「选取结束」的信号，再用该闭合区生成掩膜。这是异形（艺术字/拟声词/手绘信）
  落地的唯一实质新增 UI。

### 3.3 字体形状识别内置 + 拟声词翻译难

- **识别字体形状需要作为内置能力**（不依赖外部、随 App 走）。
- **拟声词等生成/翻译本身困难**，可能需要**借鉴别人的成功经验**
  （如 BallonTranslator 的既定方案），属研究/长期项，本轮先"留口子"不硬上。

### 3.4 命名与 UI 语言

- 英文命名**按第 4 节推荐锁定**。
- **UI 显示一律用中文**（下拉/标签/提示不得出现英文枚举值）。

## 4. 文字块分类重构方案

### 4.1 三件套模型（而非一个平铺 enum）

| 轴 | 取值（英文，落键） | 含义 |
|---|---|---|
| **kind（语义：是什么）** | `dialogue` / `onomatopoeia` / `objectText` / `watermark` | 决定管线如何处理该块 |
| **shape（字形规整度）** | `regular` / `irregular` | 决定是否需要异形选区 |
| **flag（识别难度）** | `specialFont`(bool) | 异体/特殊字体，常规 OCR 可能失灵 |

**约定**：
- `onomatopoeia` 默认 `irregular`（艺术字/异形）；
- `objectText` 显式标注 `regular`（书名）/ `irregular`（手绘信）；
- `dialogue` 默认 `regular`；
- `watermark` 走自己的擦除区域，不归 shape 轴。

> 「作者画的小字」不再单列类：手绘拟声词 → `onomatopoeia+irregular`；
> 手绘信件小字 → `objectText+irregular`。两者靠 shape 轴区分。

### 4.2 英文命名锁定表 + 中文 UI 显示名（已确认）

| 概念 | 英文（落键） | 中文 UI 显示 | 管线行为 |
|---|---|---|---|
| 对话（气泡/旁白/独白） | `dialogue` | 对话 | 识别+翻译+嵌字 |
| 拟声词/语气词 | `onomatopoeia` | 拟声词/语气词 | 默认不译、保留原字（可单块翻） |
| 物件文字 | `objectText` | 物件文字 | 翻译；规整/异形见 shape |
| 翻译组水印 | `watermark` | 水印 | 擦除、不翻译、不嵌字 |
| 字形·规整 | `regular` | 规整 | 矩形框足够 |
| 字形·不规则（艺术字） | `irregular` | 不规则/艺术字 | 需自由选区 → `region_mask` |
| 标记·特殊字体 | `special_font` | 特殊字体（异体） | 常规 OCR 可能失败，需手动/特殊识别 |

备选（未采用，记录备查）：`objectText` 备选 `sceneText`/`propText`；
`specialFont` 备选 `nonStandardFont`/`lowOcrConfidence`。用户已选推荐项。

### 4.3 与旧 `sfx` 的关系（迁移）

- 旧 `StudioSfxOps.label = 'sfx'`（`studio_block_ops.dart:148`）→ 迁移为 `kind: 'onomatopoeia'`。
- 保守启发式 `looksLikeSfx`（`studio_block_ops.dart:174`）保留，仅改写 `kind` 而非 `label`。
- 兼容 getter：旧块 `label:'sfx'` 仍当 `onomatopoeia` 读取，避免旧工程行为突变。

## 5. 可行性分析（逐点对齐真实代码）

### 5.1 数据模型 —— 可行，零字节 diff 安全 ✓

- `TextBlock` 是 FT JSON 透传模型（`text_block.dart:583`），getter 只读、setter 走 `raw`。
- 新增 `kind` / `shape` / `special_font` 三键，写法沿用现有 `_color_auto` 先例
  （`text_block.dart:876`）：**仅当非默认才落盘**，缺键 getter 返回默认
  （`dialogue`/`regular`/`false`）。
- 旧块缺这些键 → 默认行为 → **FT 往返零字节 diff 不受影响**。

### 5.2 异形"口子" —— 数据已预留，UI 是真正缺口 ⚠️

- `region_mask` / `region_inpaint_dict` 已在 `createDefault` 预留
  （`text_block.dart:651-652`），但**全工程从不被读取**（grep 仅 2 处命中，都在该工厂内）。
- 全库**无 polygon / lasso / freeform 选区**（grep 0 命中）→ 当前**只能画矩形**。
- 异形真正可用 = 新增**自由选区模式**写入 `region_mask`（位图掩膜）。这是唯一实质新增 UI。

### 5.3 翻译路由 —— 改动极小 ✓

- 跳过点在 `studio_page.dart:1307`：`if (StudioSfxOps.isMarkedSfx(block)) continue;`
  （跳过 sfx 进翻译批次）。
- 改为按 kind 跳过：`if (block.kind != dialogue && block.kind != objectText) continue;`
  → `onomatopoeia`/`watermark` 不进自动翻译批次。
- `onomatopoeia` 靠空译文自然「不嵌字也不被抹、原字保留」，与现 sfx 行为一致。

### 5.4 擦除路由 —— 必须补洞（水印当前不被擦除）✓ 但需改

- 现状：`result_renderer.dart:161` 与 `:239` 都 `final regions = page.regions;`，
  再从各 `region.eraseRects` 收集擦除区（`result_renderer.dart:178-193, 257-269`）。
- `page.regions` 由 `project.dart:45` 的 `block.toTranslatedRegion()` 生成，而
  `toTranslatedRegion()` 在译文为空时返回 `null`（`text_block.dart:942-943`）。
  → **水印块无译文 → 不在 `page.regions` → 当前根本不被擦除**。
- 方案：在 `result_renderer` 两处收集 + 一个 gather 辅助里，**并入 `kind==watermark`
  块的擦除区域**；用 `TextInpainter.eraseWithMask`（`inpaint.dart:38`，预设整块掩膜）
  而非 `computeMask` 字形级（`mask_producer.dart:54`），否则月标会被漏掉。改动可控。

### 5.5 全局理解（翻译侧已大半存在；识别侧是留口子）

- **翻译侧已存在**：`translateBatch` 一次带整页所有块 + 术语表
  （`studio_page.dart:1288` 注释）；`group_translate` 做「拼句→翻译一次→断句→分配」，
  支持跨页组。用户讲的「分句串联翻译」**已实现**，不用重做。
- **识别侧**：仍是逐块 OCR（`StudioBlockOps.cropWindow`，`studio_block_ops.dart:34`）。
  用户明确「大量测试训练，不展开」。本轮**留口子**——把 `kind/shape/region_mask/
  分组/阅读序` 做成一等公民，将来整页识别器直接消费，**管线不用改**。

## 7. 风险与开放问题

1. **压画稿/文字的水印**：纯填充会留缝 → 必须 AI inpaint。算法升级路径明确
   （`region_inpaint_dict` 已预留），但属阶段 0 之后的增强。
2. **自由选区 UI 复杂度高**：画笔→闭合多边形→位图掩膜，是最大工作量与不确定性点。
3. **拟声词翻译质量**：依赖外部经验，短期不承诺自动质量。
4. **第 0 步检测准确率**：漏检/误检水印会污染后续翻译 → 需人工复核位 + 可单独
   重跑净化步。
5. **环境**：构建/无头 venv 缺 numpy（离线装不上）；但抹字/修复是纯 Dart，无需
   外部 numpy/OpenCV，去水印功能可完全进 App——这是 3.1 / 5.4 可行的前提。
