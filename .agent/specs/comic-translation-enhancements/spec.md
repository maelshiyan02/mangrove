# 漫画翻译精细化三项功能 - 产品需求文档

## Overview
- **Summary**: 在 BallonsTranslator 现有"全图自动流水线（检测→OCR→翻译→抹图→排版）"之外，新增三项精细化能力：① 框选区域识别翻译；② 多断句文本框合并翻译并回填；③ 滑动页漫截图拼接与页面自定义排序。
- **Purpose**: 软件将演进为面向一整套漫画的翻译工具。实际使用中存在三类现有流程覆盖不到的场景：自动检测漏框、截图内/跨截图的对白被分割导致逐框识别歧义与误译、滑动截图把同一对话框切成两半。
- **Target Users**: 在桌面端对漫画截图进行精修翻译的译者（本项目所有者）。

## Goals
- **G1 框选翻译**: 自动流程结束后，用户可在画布上拖一个矩形，只对该区域执行 OCR+翻译，生成一个与自动检测完全等价的普通文本框。
- **G2 合并翻译**: 选中 2 个及以上文本框，将其原文按顺序拼为完整句子，整体翻译一次；译文经"自动切分预填 + 对话框人工校正（含顺序调整）"后回填到原文本框，文本框本身保持独立、不做几何合并。
- **G3 页面拼接与排序**: 页面列表支持拖拽自定义顺序并持久化；可将两张截图纵向拼接为一张新图片、作为新页面加入工程，对其执行正常流水线；原页面与原图片不受影响。
- **分期交付**: 按 G1 → G2 → G3 顺序实施，每完成一期由用户真机验证后再进入下一期。

## Non-Goals
- 不做拼接截图重叠区域（重复带）的自动/手动去除（本期为直接首尾拼接；如真机反馈需要再迭代）。
- 不把拼接页的翻译结果自动映射回两张原始截图。
- 不做横向（传统左右翻页漫画）拼接，仅支持纵向（滑动页漫）。
- 不改写现有全图 RUN 流水线；不新增强制依赖；不改变既有工程 JSON 字段语义。
- 不引入云端服务；全部沿用用户已配置的本地/在线 OCR 与翻译器。

## Background & Context
- 全图流水线：`RunPipelineDialog` → `MainWindow.on_run_imgtrans` → `ImgtransThread._imgtrans_pipeline`。
- 单框管线已存在：`ModuleManager.runBlktransPipeline(blk_list, mode, blk_ids)`，mode：-1 仅翻译、0 仅 OCR、1 OCR+翻译、2 OCR+翻译+抹图、3 仅抹图；完成经 `RunBlkTransCommand` 支持撤销。
- 手动建框已存在：文本框模式右键拖框 → `Canvas.end_create_textblock(QRectF)` → `SceneTextManager.onEndCreateTextBlock` 仅创建**空** TextBlock（不识别、不翻译）。
- 现有"合并工具"（merge_dialog.py + utils/merger.py）是把检测框做**几何永久合并**（xyxy/lines/text 合一），与本需求"逻辑合并翻译、框仍独立"不同，不改动它。
- 工程模型：`ProjImgTrans.pages: Dict[str, List[TextBlock]]` + `_pagename2idx/_idx2pagename` 顺序映射；页面顺序来自 `find_all_imgs(sort=True)` 的文件名排序；`new_pages` 机制支持工程目录中新增图片。
- UI：页面列表 `PageListView(QListWidget)`（mainwindow.py L92），"页面列表和上下文"开关在 mainwindowbars.py；底部绘制工具 `DrawingPanel`（hand/inpaint/pen/rect 四种模式）。
- 工程 JSON 必须向后兼容：新增字段须有默认值，旧工程正常加载。
- 用户已确认：分期交付；译文回填采用"自动切分预填+人工可改"；拼接产物为工程内新图片页面；本期加入页面拖拽排序。

## Functional Requirements

### G1 框选区域识别翻译
- **FR-1** 底部工具栏新增"框选翻译"工具（与现有四种工具同形态：图标按钮 + tooltip + 可切回）。
- **FR-2** 进入该工具后，在画布上按下拖出矩形、松开即：按矩形创建 TextBlock → 对该块执行 OCR → 翻译（mode=1 链路）；过程在后台线程，UI 显示现有进度反馈。
- **FR-3** 一次截取完成后保持在该工具模式，可连续框选下一个区域；Esc 或切换其他工具退出。
- **FR-4** 产生的文本框是普通文本框：可在右侧面板编辑原文/译文、可用"重译"按钮、可删除、可抹图排版，且创建+翻译整体可 Ctrl+Z 撤销。
- **FR-5** 矩形过小（小于 OCR 最小有效尺寸）时不创建请求并给出轻量提示。

### G2 多断句合并翻译与回填
- **FR-6** 选中 ≥2 个文本框时，可通过画布右键菜单/文本面板入口打开"合并翻译"对话框；不足 2 个时入口不可用。
- **FR-7** 对话框按当前阅读顺序列出各源片段，可调整片段先后顺序（上移/下移）、可编辑拼合后的完整原文，并提供连接符处理（默认按横排空格/竖排直接相接，用户可改）。
- **FR-8** 在对话框内触发翻译，使用当前选定翻译器在后台线程翻译整句，失败时显示现有错误对话框且不修改任何文本框。
- **FR-9** 译文回来后，按"目标语言标点优先、按源片段长度/框面积比例兜底"的规则自动切分为 N 段，预填到 N 个目标行；目标行可逐行编辑，且可上移/下移调整目标框顺序（应对译文倒装）。
- **FR-10** 确认后把目标行按顺序写入各文本框的 translation，触发重新排版渲染；整个写入是一个撤销命令，一次 Ctrl+Z 恢复全部原译文。
- **FR-11** 取消则不产生任何修改；几何信息（xyxy、lines、角度等）全程不变；不产生永久合并框。

### G3 页面纵向拼接与自定义排序
- **FR-12** 页面列表支持拖拽重排，立即生效（RUN 顺序、左右切换顺序跟随），顺序持久化到工程 JSON 的新增可选字段；无该字段的旧工程按文件名字典序，与现状一致。
- **FR-13** 提供"拼接页面"入口：在页面列表中指定上、下两张图（默认当前页与下一页），纵向拼接生成新图片文件存入工程目录，作为新页面插入到下页之后并自动跳转过去。
- **FR-14** 新页面是普通页面：可执行检测/OCR/翻译/抹图全流程，结果随工程保存；原两张页面与其文本块、原图片文件均不被修改。
- **FR-15** 宽度不一致时以最大宽度为准、窄图侧边补白后拼接，不崩溃；重复拼接同一组合时提示覆盖或改名；新文件命名可辨识（含两个源页名）。
- **FR-16** 拼接页可按现有"移除页面"方式从工程移除（文件可保留或一并删除，遵循现有机制）。

## Non-Functional Requirements
- **NFR-1** 所有 OCR/翻译/拼接耗时操作不得阻塞 Qt 主线程；复用现有 worker 线程与进度/停止机制。
- **NFR-2** 所有对工程数据的修改可撤销或可恢复，并纳入现有保存时机（切页/完成时自动保存）。
- **NFR-3** 不新增必需的第三方依赖；拼接使用 numpy/Pillow（已在内置环境）。
- **NFR-4** 新 UI 文案全部走 `self.tr()`，并更新 zh_CN/zh_TW 的 .ts/.qm；样式遵循 stylesheet 主题与对象名作用域规则。
- **NFR-5** 兼容 headless 模式：新 UI 动作在 headless 下安全 no-op 或仅不弹窗。
- **NFR-6** 符合 AGENTS.md：模块键不重命名、模型懒加载行为不变、工程 JSON 容错加载。

## Constraints
- **Technical**: Python 3.12 + PyQt6/qtpy（内置环境）；numpy、PIL、cv2 可用；无 lrelease（沿用上期临时 PySide6 lrelease 方案编译 .qm）。
- **Business**: 不得破坏用户工程数据与 Ballonstranslator_store 现有项目；旧版本工程文件必须可打开。
- **Dependencies**: OCR/翻译质量依赖用户已配置模块；功能本身不绑定特定模块。

## Assumptions
- 拼接的两张截图宽度通常相同或相近；本期不处理重叠去重。
- 合并翻译面向同一语言、同一方向（横/竖）的文本框；横竖混选时按实际文本拼接并允许用户在对话框修正。
- 自动切分是辅助预填，最终回填内容以用户在对话框的确认为准。

## Acceptance Criteria

### AC-1: 框选翻译端到端可用
- **Type**: `rule`
- **Given**: 已打开含图片的工程，OCR 与翻译模块可用
- **When**: 选择"框选翻译"工具，在画布拖出一个覆盖对白的矩形并松开
- **Then**: 生成新文本框，其原文为该区域 OCR 结果、译文为翻译结果，右侧面板与画布均可见
- **Pass Condition**: 面板出现新行且 e_source/e_trans 非空，新块出现在 imgtrans_proj 当前页 blocks 中
- **Evidence**: 真机操作截图/记录；offscreen 测试验证矩形→建块→mode=1 管线被调用

### AC-2: 连续框选、退出与撤销
- **Type**: `rule`
- **Given**: 处于框选翻译工具
- **When**: 连续拖两个矩形，再按 Esc，然后 Ctrl+Z 两次
- **Then**: 连续生成两个块；Esc 后退出工具；两次撤销分别移除两个块及其译文
- **Pass Condition**: 块数量变化与撤销栈行为符合描述
- **Evidence**: 真机验证记录 + 撤销命令单元测试

### AC-3: 框选工具入口可发现性
- **Type**: `rubric`
- **Dimension**: 工具栏入口与现有工具的视觉/交互一致性
- **Scale**: 1-5
- **Anchors**: 1 = 找不到入口或风格突兀；3 = 能用但需要说明；5 = 与现有工具按钮完全同构、tooltip/图标清晰
- **Pass Threshold**: >= 4
- **Evidence**: 真机界面检查

### AC-4: 合并翻译对话框内容与编辑能力
- **Type**: `rule`
- **Given**: 选中 2 个以上有原文的文本框
- **When**: 打开"合并翻译"对话框
- **Then**: 源片段按顺序列出，可上移/下移、可编辑拼合原文；未选中 ≥2 块时入口禁用
- **Pass Condition**: 片段顺序变化与原文编辑均反映在待翻译文本中
- **Evidence**: offscreen 对话框测试

### AC-5: 合并翻译走当前翻译器且失败安全
- **Type**: `rule`
- **Given**: 对话框中拼合原文完成
- **When**: 点击翻译，翻译成功/失败两种情形
- **Then**: 成功则译文区显示整句译文；失败弹错误对话框，所有文本框译文保持操作前状态
- **Pass Condition**: 成功路径译文非空；模拟异常后 blocks 的 translation 集合不变
- **Evidence**: 代码路径核查 + 失败路径测试

### AC-6: 自动预填、人工校正与顺序调整
- **Type**: `rule`
- **Given**: 整句译文已返回，源块数 N
- **When**: 对话框生成 N 个目标行
- **Then**: N 行文本拼接（去分隔差异后）等于整句译文；行可编辑、可上下移动；确认后按行顺序写入各块 translation
- **Pass Condition**: 预分行覆盖全文、无丢失；确认后各块译文与目标行一致；顺序调整改变写入映射
- **Evidence**: 切分算法单元测试（标点/比例用例）+ offscreen 写入映射测试

### AC-7: 回填可撤销且不改变几何
- **Type**: `rule`
- **Given**: 已确认合并翻译回填
- **When**: 检查各块 xyxy/lines，并执行一次 Ctrl+Z
- **Then**: 几何字段与操作前逐字段一致；撤销后全部块恢复原译文（含原本为空的块）
- **Pass Condition**: 几何比对一致；撤销后 translation 快照完全恢复
- **Evidence**: 单元测试 + 真机验证

### AC-8: 自动切分质量
- **Type**: `rubric`
- **Dimension**: 中日韩/拉丁文标点下切分位置的合理度
- **Scale**: 1-5
- **Anchors**: 1 = 大量切断词/句中；3 = 大段均匀但部分不自然；5 = 基本落在标点边界且长度均衡
- **Pass Threshold**: >= 4
- **Evidence**: 至少 6 组代表性例句的切分测试结果

### AC-9: 页面拖拽排序与持久化兼容
- **Type**: `rule`
- **Given**: 含多页的工程
- **When**: 拖动页面调整顺序，触发保存后重启软件重新打开；另用一个无新字段的旧 JSON 打开
- **Then**: 重开后顺序为自定义顺序；旧工程顺序为文件名排序且无加载错误
- **Pass Condition**: 顺序映射、RUN 页面顺序一致；旧 JSON 正常加载并有默认值
- **Evidence**: 排序/序列化往返测试 + 旧 JSON 兼容测试

### AC-10: 拼接页端到端
- **Type**: `rule`
- **Given**: 工程含两张纵向连续截图 A、B
- **When**: 以 A 在上、B 在下执行拼接
- **Then**: 工程目录出现新图片文件，页面列表在 B 后出现新页面并自动跳转；A、B 页面内容与原图片文件未改变；新页面可跑流水线
- **Pass Condition**: 新文件存在且像素为 A/B 纵向拼接；pages 含新键；原两页 blocks 与文件哈希不变
- **Evidence**: 拼接函数单元测试（像素比对）+ 真机记录

### AC-11: 拼接边界情况
- **Type**: `rule`
- **Given**: 宽度不同的两图，或同一组合已拼接过时
- **When**: 执行拼接
- **Then**: 窄图补白后等高拼接不崩溃；重复时提示覆盖/改名且不产生静默重复页
- **Pass Condition**: 输出宽度=最大宽度；重复组合行为符合提示选项
- **Evidence**: 单元测试 + 真机验证

### AC-12: 整体交互融入度
- **Type**: `rubric`
- **Dimension**: 三项功能与现有菜单/面板/快捷键/主题风格的一致性
- **Scale**: 1-5
- **Anchors**: 1 = 入口隐蔽、风格割裂；3 = 功能可用但交互突兀；5 = 入口位置自然、反馈与现有功能一致
- **Pass Threshold**: >= 4
- **Evidence**: 真机走查三项功能

### AC-13: 工程安全与兼容底线
- **Type**: `rule`
- **Given**: 全部功能投入使用并保存工程
- **When**: 重开工程、执行 RUN、切换页面
- **Then**: 无异常；未新增强制依赖；headless 导入与运行不被新 UI 破坏；全部新文案可翻译
- **Pass Condition**: py_compile/相关测试通过；旧工程往返加载成功；offscreen 启动检查通过
- **Evidence**: CI 等价命令输出 + 测试记录
