# M10 · 源码扫描类断言的四个盲区

> **触发时机**：写或修改"扫描源码找**未登记/未处理**项"的自动化检查时 ——
> i18n 文案登记、TODO 标签、许可头、禁止出现的 API、目录白名单。
> 上级索引：`../INDEX.md` ｜ 相关：`M01`（断言设计纪律）· `M02`（反向验证）·
> `M08`（运行时故障注入）· 项目附录 `A02`（硬规矩与断言纪律）

## 为什么值得单独一篇

这类断言的**失败方式全部是"假绿"**：扫描漏了东西不会报错，只会让该检查
悄无声息地永远通过。于是症状出现在**完全无关的地方** —— 用户看到一个按钮
写着英文、一个禁用 API 混进了代码、一份文件没有许可头。

排查方向也因此全错：会去看那个按钮的代码、去看文件内容，而不会想到
**"检查根本没看到它"**。

以下四条是同一个 bug 的四种形态，都真实发生过（本项目 P9.3 → P10.6 连续
踩了三次才收敛）。

## 盲区 1 · 扫描范围

**症状**：新加的文件里的问题从没被报过；旧文件报得挺勤。

**根因**：范围写死成"一个文件"或"一个目录"。新文件落到范围外就永久失察。

**规矩**：

- 范围宁大勿小，但**别用"扫全仓库"**代替思考 —— 会把历史欠账一次性炸出来，
  然后你会忍不住放宽判据，等于把检查废掉。
- 白名单里的文件**必须要求存在**，不存在就返回一个哨兵错误而不是静默跳过：
  ```dart
  if (!extraFile.existsSync()) return ['<${extraFile.path} not found>'];
  ```
  静默跳过 = 文件一改名，这条检查自动变装饰品。
- 用一条断言**钉住"范围覆盖到了"**（下一条）。

## 盲区 2 · 字面量形态

**症状**：检查全绿，界面却是英文；或者反过来，检查突然把**半页源码**当成
一个 key 报出来。

**根因**：正则只认**一种**写法。真实源码里有四种：

| 形态 | 例子 | 只写 `'…'` 时会怎样 |
|---|---|---|
| 单引号 | `'Add term'.tl` | 正常 |
| **双引号** | `"Add term".tl` | **整页漏扫**（一整个文件 15 条从没被看过） |
| **跨行** | `"很长的文案…"`<br>`    .tl,` | 漏扫 —— `dart format` / `prettier` 对超长串会拆行 |
| 相邻拼接 | `'part A ' 'part B'.tl` | 只扫到后半段，报出一个不存在的 key |

**规矩**：

- 正则要**同时**吃两种引号，并用反向引用保证前后一致：
  ```dart
  RegExp(r"""(['"])((?:[^'"\\]|\\.)*?)\1\s*\.tl(?:Params)?\b""")
  ```
- 🔴 **内容里必须排除两种引号**（`[^'"\\]`），不能只排除起始那一种。
  只排除单引号时，双引号分支会从 `"第一处"` 一路吞到下一处 `"`（中间隔着换行、
  参数名、别的字符串），把源码片段当成 key —— 第一版就是这么炸的。
- **允许 `.tl` 前有空白**（`\s*`），否则跨行写法永远扫不到。
- 相邻字面量拼接**无法用正则可靠解析**：接受它，但把判断留给"扫到的 key
  在不在白名单里"这层兜底（报出来的 key 会是可读的片段，不是垃圾）。

## 盲区 3 · 词边界与锚点

**症状**：带参数的文案（`@a` 占位符）漏扫；条件选择的文案一条都扫不到。

**根因**：

- `\btl\b` **匹配不到** `tlParams` —— `l` 和 `P` 之间没有词边界。于是所有
  参数化文案（恰恰是项目规范强制要求的那种写法）对检查不可见。
- 锚在 `tooltip: '…'` 这样的**参数名**上，只能匹配"字面量直接当参数"的写法；
  `cond ? 'A'.tl : 'B'.tl` 一个都扫不到。

**规矩**：锚在**调用**（`.tl` / `.tlParams`）上，而不是参数名上。

## 盲区 4 · 判据被复制成多份

**症状**：同一条规则在不同检查里结果不一致；修好一处，另一处照旧。

**根因**：正则/判据被复制粘贴。每一次复制都是一次**独立漂移**的机会 ——
本项目那条 i18n 正则被复制成三份，于是盲区 2、3 各踩了一遍，
**修的时候还得记得改三处**。

**规矩**：

- 一条判据**只能有一份实现**，放在公共文件里导出。
- 再加一条断言把这件事钉住（防自己再复制回去）：
  ```dart
  // 绿 = 别的文件里不再出现那条正则；故障 = 对照组（公共实现所在文件）确实有它
  !codeHas(p5Path, r'\.tl(?:Params)') && !codeHas(headlessPath, r'\.tl(?:Params)')
  ```

## 检查清单

写完任何一个扫描类断言，逐条过：

- [ ] **空结果判 FAIL**？"一条都没扫到"不是通过 —— 正则写坏、文件挪走都会让它
      静默变绿。另外用一条断言钉住"确实扫到了 N 条（N ≥ 预期下限）"。
- [ ] **对照组**？故障路径要拿一个**确实含有该特征**的**别的**文件跑同一条判据，
      证明判据不是恒真。"搜一个不存在的字符串"证明不了任何事。
- [ ] **范围**？目录型范围要加"新增文件落进范围"的断言；白名单文件缺失要 FAIL。
- [ ] **形态**？单引号/双引号/跨行/相邻拼接，四种写法都试一遍（至少前三种要有断言）。
- [ ] **锚点**？锚在调用上；确认带参数（`Params`）的写法也在覆盖内。
- [ ] **唯一实现**？正则/判据没有第二份副本。
- [ ] **新文件落在被扫目录里**？把新文件放进扫描覆盖的目录（或显式加进白名单），
      否则它永远不被核对 —— 而"没被核对"不报错，只显示英文。
