## P70+P71 会话收尾 · 坑总表（10 条，教训级）

> 用户已验收：蓝标恢复、翻倍消失。以下为跨轮复用价值最高的坑。

1. **UUID 误读成话号**：`^(\d+)` 宽匹配把 `0fbab379-…` 读成第 0 话，模拟时 69 话错配成 47 个 UUID ⇒ 话号归一前必须先挡 UUID。
2. **只修增量不修存量**：P70 让「以后不再翻倍」，库里 138 格仍在；网格按 `allVersionKeys` 逐格查下载状态 ⇒ 双倍查询+双倍布局=卡顿。改归一口径必须同时想到存量自愈。
3. **`List == const [...]` 是引用比较**，恒假 → 假基线 96/97；恒假断言会让注入「看起来只红目标」，比假绿更隐蔽。
4. **`Iterable` 没有 `containsAll`**（编译期 undefined_method），先 `.toSet()`。
5. **构建产物 mtime 滞后** → headless 跑旧 exe，跑出 93 条假基线；自检前必比 exe 与源码时间戳。
6. **故障注入锚点必须唯一**：同一句 `return keys.toList();` 出现两次，`replace_nth(...,2)` → `INJECT_MISS`；锚点要带上下文拼唯一串。
7. **`headless.dart` 是 CRLF**：`git diff --check` 全判 trailing whitespace，须 `-c core.whitespace=cr-at-eol`。
8. **`INJECT_MISS` 会写台账为 FAIL**；单组重跑按 case 合并，别手改台账洗绿。
9. **headless 不写 `data/logs.txt`**（启动即截断），日志只在 GUI 会话可见 ⇒ 别把「headless 没日志」当「没问题」。
10. **多组同话**：折等口径 = 话号 + 归一翻译组（`默認/默认/default`→空）+ 语种；跨组同话号必须保留，不能一刀切折叠。
