# A06 · 翻译组 / 合集 / 下载语义

> **触发时机**：碰翻译组、章节模型、选章器、下载、缺页表**之前**。
> 上级索引：`../MEMORY.md` ｜ 相关：`A03`（目录命名）· `A07`（comix 源）

---

## 1. 翻译组信息从哪来

- ✅ **组信息已在 `local.db` 里**（`ComicChapters.toJson()` 序列化）→
  UI 显示组标签**不需要文件名标记、也不需要边车文件**。
- ❌ 例外：**本地导入的漫画是「扁平」的**（无组信息）；**`bt_` 卡的组为 `null`**。
- S7U 遗留（并入 S12/S13）：同话多组在阅读器里并列展示的问题；本地导入补组信息只能靠边车 `chapters.json`。

## 2. 🔴 章节标识与目录名

- **`downloadedChapters` 存的是 `chapterKey`**（**不是**话号、**不是**目录名）。
- 已知 bug：**选章器交出的是「索引」** → 选 B 组会被 `ids.elementAt(i)` 翻成 A 组。
- **章节目录名唯一真相 = `chapterDirectoryName(chapters, chapterKey)`**：
  下载 / 读取 / 删除 / 缺页表 / 磁盘反查**必须全部调它**（旧目录用 `migrateChapterDirectories()` 迁移）。
- 🔴 `findValidId` 必须带 `AND id GLOB '[0-9]*'`：
  `CAST(id AS INTEGER)` 会把 `bt_xxx` 变成 `0` → **导入即崩**。

## 3. 🔴 `preferDownloaded` 不能省

- 现象：只下载了**非首选组**时，阅读器取不到目录 → **空白页**。
- 解法：把**已下载的版本提到该话首位**（必须走 `versionedOrdered`）。
- 选章器形态：按组分节 + 折叠 + **默认只展开第一组**。

## 4. 下载语义

- **每章一个任务**（不是每话、不是每图片）。
- `maxParallelDownloads` 默认 **1**（上限 ≤3）。
- 图片层面走**滚动窗口并发**。
- 副标题格式：`来源 · 翻译组 · 章节名`。
- 🔴 `ImagesDownloadTask.==` / `hashCode` **必须把 `chapters` 纳入**（否则不同章节的任务会被判为重复）。

## 5. 多轮渐进超时与失败页

- **4 轮渐进超时**：`[5, 10, 15, 30] s`。
- **仅最后一轮的失败页**写进 `missing_pages.json`。
- 🔴 **失败页每一轮都必须重建新的 wrapper**（复用旧 wrapper 会把上一轮的状态带进去）。
- 阅读器侧的**缺页标识**：章节标签变红（优先级最高，见 `A02 §1`）。

## 6. 版本模型（易混点）

- 代码里已有的 `ComicChapters.versioned` / `versionedOrdered` 是 **S7U 的「同一话多个翻译组」章节模型**。
- 它与 **S13 计划里的「同一话左右对照原版/译文」** **不是一回事** —— 讨论时不要混用。

## 6.1 🔴 章节矩阵三形态：谁在用哪种（P69 · 2026-11-18 实测）

`ComicChapters` 有三个构造函数，对应三种落库形态。**同一本书在不同写入路径下会是不同形态，这不是异常而是常态** —— 任何按「形态相同才合并」写的代码都会在某类源上失效（P67 的真因就是这个）。

| 形态 | JSON 形状 | 谁在用（2026-11-18 抽查 `data/local.db` 13 条记录） |
|---|---|---|
| **grouped** 分组式 | `{"组名": {"章节key": "标题"}}` | **拷贝漫画（App v3 接口与网页端 `comicdetail/<slug>/chapters` 都走这里）**：单组「默認」，组内 key 是**章节 UUID**（`230c97f8-632e-11ee-9733-d3d228a76de6`），话号只在标题「第01话」里 |
| **versioned** 版本化 | `{"话号键": [{group, lang, title, key}, …]}` | **comix.to**（外层键带站标+组名，如 `70 [comix.to]`、`1 [Rokari Comics] [comix.to]`）；**P52 手工重建过的拷贝漫画本地记录**（外层键 `1 [copymanga]`，版本 key 同键） |
| **flat** 扁平 | `{"章节key": "标题"}` | **包子 baozimh**（`0 [baozimh]`）；comix.to 少数早期落库记录（`1 [HiveToons] [comix.to]`）；无组概念的单版本源 |

**推论（踩坑清单）**：

1. 拷贝漫画的书碰 comix.to 的书没有意义，但**拷贝漫画的本地记录可能是 versioned，而源刷新回来是 grouped** —— 这不是配置错，是 P52 重建留下的历史形态。P69 前 `mergedWith` 在这里 `return this`，于是「刷新永远补不到新章节，只有删历史重新识别才正常」。
2. **话号不能只看章节 key**：拷贝漫画的 key 是 UUID，话号在标题里；反过来 P52 重建的矩阵 key 有号码、版本 key 可能是 UUID。判定同一话要按 `章节key → 标题 → 外层桶键` 依次回退（`_cellNumberKey`）。
3. **「默認/默认/default」等一于无组**（`_normalizeChapterGroup`）：拷贝漫画的「默認」与 comix.to 的 null 组必须是同一身份，否则跨源合并整本翻倍。
4. **合并只增不减，且落回本地形态**：分组页签、下载目录名（`[语言] 话号 [组] [站]`）、阅读器下标全部按本地形态算，换成源的形态会连累下游。版本化方向补进来的新格子按**归一话号**落桶，否则 UUID 键会让整本退化成字典序、新话排到最后。
5. 形态互转（`toVersioned()` / `toGrouped()` / `toFlat()`）走的是同一条规范格通路（`_ChapterCell`），需要迁移/调试时直接调，不要另写转换。
6. 断言在 `runP69Checks`（`reader-ux-check` 一部分，6 条），反向验证工装 `tools/_p69_inject.py`，台账 `test-materials/runs/p69_fault_injection.json`。
