## 2. P27：跨页框选崩溃 + 长画布卡顿（用户实测反馈，运行日志实栈定性）

① **跨页框选整页崩溃** —— 实栈落在 `ScrollController.position` 的 `_positions.single`
（`Bad state: Too many elements`）。根因是 P26 的 `build` **条件式改变树形结构**
（`if (!spanMode) return listView;` 否则包一层新建 `Stack`）⇒ `ListView` 被挪位、
旧 `Scrollable` 先失活帧末才 unmount ⇒ **同一帧两个 `ScrollPosition`**。
改：**`Stack` 常驻** + `_hasSolePosition`/`_scrollOffset` 兜底 + 拖框状态改 `ValueNotifier`。

② **长画布滚动卡顿** —— `PageCanvasPainter.shouldRepaint` 按 **identity** 比 `blocks`，
而 `_blocksFor()` 每次 build 都新投影一张表 ⇒ 任何 rebuild 都整页重绘；每块重绘含
`_fitFontSize` 收缩循环 + 描边/正文 `TextPainter`（每块数次排版），`_keepAlive = 7`
⇒ 一次重绘数千次 `layout()`，滚动中解码完成即 `setState` ⇒ 持续触发。
改：`CanvasTextBlock` 逐字段**值相等** + `shouldRepaint` 改 `_sameBlocks`。

⚠️ 两条**都只能 GUI 复测**（崩溃是 widget 生命周期性质、headless 无树可断），
本轮**不标 ✅**。🔴 故意**未改** `_onScroll` 双注册（两次 O(页数) 整数比较，相对数千次排版可忽略）。

门禁（P27 实测，与 P26 持平）：BUILD_OK / block-ops **81** / run-plan 31 / bootstrap 34 / glossary 26 / glossary-ui 30 / edit-check **202**。

## 3. P28：用户判 P27 无效后按四条诉求重做

① **跨页块"只能存在上页"** —— 根因**不是 z-order**：`studio_page._blocksFor(pageKey)` **只返回
"存这一页的块"**，而跨页块只落在**顶页**（`_span.parts` 是真相）⇒ **下页压根没有可画的图元**。
改：`CanvasTextBlock` 加 `ownerPageKey`（投影片段），`_blocksFor` 投影 `_span.parts` 落在本页的段；
片段**只能点选**（拖动/缩放/吸附都排除），点选回指真身（`_StripItem._reportTap`）。

② **卡顿 + 频闪**（三条独立根因）：`_StripItem` 整体包 **`RepaintBoundary`**（消除"滚动重绘全视口 ⇒
每页 `_paintText` 跟着跑"）；`_pageAspect` 由"每次解码都改写"改为**只赋一次**（否则未解码页估高
反复跳 ⇒ `ListView` 重排 = 频闪）；`_keepAlive` 7 → **10**。

③ 非选中框由 `outline@0.55`/0.8px 细线改 **3.0px 白晕 + 1.2px 黑框**。

④ `_blocksFor` **投影 memo**（`_BlockProjectionCache`/`_spanFragmentCache`，随 `_revision` 失效 ⇒
与撤销栈联动）；顺手补批量管线逐页 `setState` 漏掉的 `_revision++`。

⚠️ ①③④ 是 widget 树/绘制性质、② 的投影逻辑在 State 里（抽纯逻辑件属重构）⇒ 本轮**不加断言、不标 ✅**，
只能 GUI 复测。

门禁（P28 实测，与 P27 持平）：BUILD_OK / block-ops **81** / run-plan 31 / bootstrap 34 / glossary 26 / glossary-ui 30 / edit-check **202**。

## 6. P31：长画布缺页根治与缩放修复（P30 核心假设被推翻）

P30「横版首页污染估高」假设**被用户实测推翻**（隐藏后约 15 页仍缺页/卡死、回顶才活）。真因两条：

① 逐页探测**根本不认 webp**（工程 94 张全 webp，探测全 null）⇒ 补 `_probeWebp`
（VP8 签名 `9d012a`+宽高 14 位 / VP8L `0x2f`+打包位 / VP8X 24 位画布，声明长度≫已读可截断、坏签名安全 null），
文件探测先 32 字节魔数再 64KB 漫游；
② 出窗 null 失败页 failures 永不清零（深滚反复回收后凑满 3 次永久闩锁）
⇒ 抽纯逻辑 `strip_decode_planner.dart`（窗口/距中心优先/出窗 evict·cancel·**resetFailures**
三路 + `DecodeBudget` 名额账），五条解码终结路径共同 release；`decodePageFile` catch (e) 留 StripDecode 日志。

另：**B 缩放手柄回归** —— P30 GestureDetector 的 pan slop（触摸 36px）+ ListView 抢赢 ⇒ 8 手柄全失灵；
改 `RawGestureDetector` + `_EagerPanGestureRecognizer`（down 点命中手柄/框选即 resolve accepted、
覆写距离门槛直接放行）；⚠️ 本仓 Flutter 是 `GestureArenaTeam` 且 `DoubleTapGestureRecognizer` **无 team setter**。
**B2 nest 组外框直接缩放**（用户拍板=并集框整体等比变换、一次撤销）：纯函数 `scaleRectsToBounds`
（原点换算，非 r*sx）、`CanvasGroupFrame`+painter 画 8 手柄、groupResize 拖种、
`studio_page._activeGroupFrameFor`（成员全在本页/非 link 才出框）+ `_resizeGroup`
（当前模型重算并集、`captureBlockListEdit` 单快照）；顺带修复 strip 恒传 selectedIndex=-1
导致长画布选中块从不画手柄。
**C 真等比缩放**：P30 只改 effectiveWidth ⇒ 只横滚；改 `_pageHeight` 去 min(1.0) 钳制按原图宽比算、
gap/padding/缝几何全乘 zoom、视口中心锚点 post-frame 双轴 jumpTo、横向独立 controller；
