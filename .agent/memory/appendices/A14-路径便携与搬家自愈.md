# A14 · 路径便携与搬家自愈（PathRoots）

> **触发时机**：碰 `local_path`、`btProjectRoot`、工程 json `directory`、`comic_source`
> 目录解析，或项目目录再次改名/搬家之后。
> 上级索引：`../MEMORY.md` ｜ 相关：`A03`（磁盘布局/工程互读）· `A01`（构建与 junction）

## 1. 为什么会有这套机制（2026-10-13 · P46）

项目从 `D:\Mangrove_Windows` 迁入工作区后，**四处绝对路径**同时失效：

| 位置 | 存什么 | 旧行为（失效后） |
|---|---|---|
| `%APPDATA%/…/local_path` | downloads 库根明文绝对路径 | 静默回落**空的默认目录** → 已下载漫画"全部消失" |
| `appdata.json settings.btProjectRoot` | projects 根（分号多根） | 扫描器 `root.exists()` 为假，整根跳过 |
| 每个工程 json 的 `directory` | 原图根绝对路径 | 回落到 json 父目录，原图全断 |
| `%APPDATA%/…/comic_source/` | 源脚本（本来就在 APPDATA） | 不随项目走 |

`local.db` 的 `comics.directory/cover` 是**相对库根**的（实测 5 行均为
`漫画名`/`cover.jpg`），所以只换根、不用改库。

## 2. 便携根（portable root）

实现：`lib/foundation/path_roots.dart`（纯 Dart + dart:io，可被启动前
headless 自检引用）。从 `Platform.resolvedExecutable` 目录**向上最多 6 级**，
找第一个满足签名的目录 P：

1. `P/mangrove.portable` 标志文件（显式，最强；文件可空）；
2. `P/ComicLibrary/downloads` 目录存在（隐式，项目树自带，零操作）。

深度覆盖：部署态 `builds/mangrove/mangrove.exe` 上溯 2 级；开发态
`build/windows/x64/runner/Debug/mangrove.exe` 上溯 5 级。只走直系祖先、
有界、必须有签名，不会误中 Program Files。找不到 → 全部维持旧行为。

## 3. 四处自愈规则

1. **库根**（`LocalManager.init`）：绝对路径在 → 原样（用户手动选的盘优先）；
   存的是相对形式 → 相对便携根重放；绝对路径失效 →
   `P/ComicLibrary/downloads`（存在才采用），并**回写相对形式**
   `ComicLibrary/downloads`，下次搬家零自愈；都没有 → 平台默认（旧行为）。
   解析出的最终根注册到 `PathRoots.currentDownloadsRoot`（在任何 BT 扫描前）。
2. **btProjectRoot**（`BtProjectManager.roots` 静态 getter，所有消费方自动受益）：
   失效根重定位到 `P/ComicLibrary/projects`；相对条目按便携根重放；
   库在便携布局但设置为空时**自动补全**兄弟 projects 根。
   `persistPortableSelfHeal()` 在 `App.initComponents` 末尾跑一次，回写相对形式；
   🔴 **无法重定位的失效根（移动硬盘没插）原样保留在设置里**，绝不抹掉。
3. **工程 json `directory`**：读侧（`TranslationProject.directory` 与
   legacy `BtProject.parse`，两路同规则）——失效时取路径中最后一个 `downloads`
   段之后的尾段（`<漫画>[/<章节>]`）拼当前库根，**拼出的路径必须真实存在**
   才采用。🔴 **读取绝不回写 json**（零字节 diff 契约，A03 §3.2）。
   workspace 不动：失效时回落到 json 父目录本就正确。
4. **漫画源**：`ComicSourceManager.doInit` 合并扫描两个目录——
   `%APPDATA%/…/comic_source`（读写、更新/登录态，优先）与
   `P/comic_source`（随项目走的只读副本；同名 key appdata 优先）；
   `.data` 读取在 appdata 缺失时回落便携目录，写仍写 appdata。

## 5. 验证与构建坑

- 自检：`mangrove.exe --headless portable-paths-check`（18 条，临时目录造
  "旧根消失+便携根"，含故障反证；报告 `portable_paths_check.json` 已 gitignore）。
  经 `tools/run_headless_task.py` 跑（GUI 子系统 AttachConsole 吞重定向）。
  **2026-10-16 实跑 PASS 18/18**（verdict=success）。
- 🔴 **构建插件链接二次失效（第三次遇到）**：迁移后
  `windows/flutter/ephemeral/.plugin_symlinks/app_links` 是指向 pub cache 的
  **SymbolicLink**，flutter build 重建它时报 `PathNotFoundException errno=2`
  （真符号链接需 SeCreateSymbolicLinkPrivilege，当前非提权会话没有；报错文案
  有误导性）。修法：读 `.flutter-plugins-dependencies`（结构是
  `plugins.<platform>[]`，PS 解析别当成扁平数组），为全部 53 个插件用
  **Junction**（不需特权）预建到 `.plugin_symlinks/<name>`；删旧链用
  `(Get-Item).Delete()`（只删 reparse point，不跟目标）。之后 build 通过。
  长效修法：开 Windows 开发者模式（需用户操作/提权，未擅自改）。
