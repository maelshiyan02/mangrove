## 1. 规则本体

1. **基线**：2026-10-08 `4c5bf8c` VeneraX→Mangrove 改名时承袭上游 Venera 的 `2.3.4`
   （fork 自 Venera 2.3.4；上游自身的 2.3.5 与我们无关），此后 Mangrove **独立计数**。
2. **计数口径（口径 B，用户选定）**：每交付一批**施工/交付/修复**类工作日志
   （= 一次走完 `python tools/run_build_task.py` → `BUILD_OK` 的代码交付）= 1 个小版本。
   **不计版本**：可行性分析、计划/方案、能力对照、验收需求、结论核对、交接/开场白、
   纯诊断（未当场交付修复）、经验汇总。
3. **进位规则（base-10 三段式）**：版本号 = `大版本.小版本A.小版本B`，其中
   - **大版本**（第一小数点前）：**不限位数**，独立计数；
   - **小版本A / 小版本B**（后两段）：均为 **0~9 的十进制**，`小版本B` 满 10 进位到 `小版本A`，
     `小版本A` 满 10 进位到 `大版本`。例：`0.0.9 → 0.1.0 → … → 0.9.9 → 1.0.0`。
   - **一个大版本 = 10×10 = 100 个小版本**（`0.9.9` 的下一版是 `1.0.0`）。
   - 写版本时：把"基线小版本数 + 新增数"按 base-10 拆成 `大版本*100 + 小A*10 + 小B`
     （例：基线 234 + 50 = 284 → 大2·小A8·小B4 → `2.8.4`；**不是** `2.3.54`）。
4. **唯一权威落点**：`Mangrove/pubspec.yaml` 的 `version: x.y.z+build`。
   About 页 `V${App.version}`（`lib/pages/settings/about.dart`，来自 PackageInfo.version）
   自动读取——**改 pubspec 即改显示**，全库无第二处硬编码版本号。
5. **build 号**（`+` 后）不参与显示，随发布 +1 单调递增即可；改名继承值为 247。
