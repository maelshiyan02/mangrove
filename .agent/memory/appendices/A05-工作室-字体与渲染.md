## 1. 🔴 两条渲染路径**不共享代码**

| 路径 | 用途 |
|---|---|
| `page_renderer` | 生成**成品**（`result/`，可导出） |
| `text_block_canvas` | **画布**上所见（编辑时） |

⇒ **改一个字体属性，要数清楚分支数**：
- `_fillStyle` **两个分支**；
- **`_strokeStyle` 还有一个「无格式」分支**。

**漏掉任何一处 → 填充与描边出现两种字面 → 重影，而且不报错。**

## 2. 🔴 `RegionFontStyle`：字体属性的贯通

- 形态：**纯标量、零 Flutter 依赖**，放在 `image_translation/translation_types.dart`；
  是 `TranslatedRegion` 上的**可选字段** `fontStyle`。
- 设计目标：**六个构造点一行不改**就能把字体信息带进 region。

### 三处断链（必须同时看）

1. `toTranslatedRegion()` **只传 5 个字段**（不含 fontStyle）；
2. 🔴 **`result_renderer` 重建 region 时也只抄 5 个字段** —— **这处最关键，工作室保存走的就是它**；
3. `page_renderer` 里写死了 `w500` / `1.2`。

### 单位陷阱（四处）

| 字段 | 陷阱 |
|---|---|
| `font_size` | 是**上限**，不是"替换值" |
| `letter_spacing` | 是**倍率**，写进 CSS 要转成 `(v-1)em` |
| `stroke_width` | 是**绝对 px**，**不再随字号缩放** |
| `vertical` | FT 的该标志**压过**竖排启发式判定 |

- `_scaledFontStyle` 按 `scale` 只缩放**像素类**字段。
- 🔴 **「没传时行为不变」这条也要锁**（不能因为新增字段而改变既有渲染）。

## 3. 🔴 字体（`bundled_fonts.dart` 是**契约**，不是配置表）

- 未注册的字族必须**显式落到打包字体**（不能静默回落到系统字体）。
- 雅黑（= `defaultFontFamily`）**必须被"认识"**（要能被识别并走打包回退）。
- 🔴 **`primaryBundledFamily` 是回退终点，绝不为新增字体搬动它。**
- 新增字体的正确姿势：
  - 加**独立 family**（例：KR 400 / 700）；
  - sfnt 版本是 `OTTO` → 文件**必须**是 `.otf`；
  - 同时加**别名**与 `bundledFamilyFallbacks`；
  - 回退规则：**bundled → bundled 可以；requested → 别的 不行**。
- **证据方式**：**直读 cmap format 12**，以 `covered > 10000` 判"非空覆盖"；
  工具 = `tools/inspect_font.py`（**自带 known-answer 自检**）。
- ⚠️ **P0-1（字体贯通）与 P1-4（字体资产）拆开做会"假绿"**：没有注册字体时，改字体族**没反应**，
  看起来"功能正常"。拆开做就必须声明**字族未验收**。

## 4. 出图腿（`inpainted/` + `result/`）

### 4.1 职责

| 产物 | 角色 |
|---|---|
| `inpainted/` | **去字底图**（把原文笔画抹掉，保留气泡/网纹） |
| `result/` | **成品**（在底图上画译文） |

统一保存契约（P6 §2.8，用户原话）要求两者**保存时同步产出**。

### 4.2 🔴 `inpainted/` 曾长期无人生产（P9.8 发现 1）

- 现象：出图腿**从未工作过，而且不报错**。日志证据：
  `result/ regenerated: artifacts written=0 skipped=1 failed=0 (dirty=1)`。
- 成因：**欠账在三份文档之间掉下去** ——
  P6 §2.8 要求保存时同步产出 → P8.1 把去字推给 S9 → **S9 交付清单里没有这一项**。
  每一份单看都没错，错在**交接处**。
- 修法：新增 `renderInpaintedPage(project, pageKey)`（`result_renderer.dart`）：
  `原图 → _decodeBounded → 按 regions 的 eraseRects 擦除 → 编码 PNG`；
  并把保存改成**两阶段**（先 `inpainted` 后 `result`，顺序不可交换，理由见 `A04 §4`）。

### 4.3 两个刻意的设计选择

1. **底图只从原图取**，不对已有的 `inpainted/` 再擦一遍
   （对已是去字结果的位图再擦 → 背景越擦越糊，**每保存一次更糊一点**）。
2. **只在不需要降采样时产出**。原因：
   `result/` 侧的坐标换算是 `scale = decoded.image.width / decoded.originalWidth`；
   当输入是 `inpainted/` 时这两个值是**同一个文件的宽** → `scale == 1.0` → 页面 regions 被当作**源坐标**直接使用。
   **一旦写出一个被 `_decodeBounded` 缩过的底图，`scale == 1.0` 就变成谎言**：
   框按源坐标落在缩小的图上，**位置全错而不报错**。
   ⇒ 大页（> 12 MP 或 > 8000 px）**宁可不产出 `inpainted/`**（`result/` 会如实记成 skipped），
   也不造一个破坏坐标契约的文件。

### 4.4 `eraseRects` 为什么可以用块外框

- 工程模型里 `eraseRects` 就是块的 `xyxy`（`TextBlock` 不存字形级矩形，FT 也没这个概念）。
- `TextInpainter.erase` 内部的 **Otsu + 笔画判定 + 膨胀**只把传入矩形当**搜索窗口**，
  真正被抹的像素由窗口内的笔画决定 → **用外框是安全的**。

### 4.5 🟠 待办：`mask/`

- `ProjectWriter.save` 会**建出空的 `mask/` 目录**（`artifactDirs` 含它）→ 四件套里有一件"有目录无内容"。
- 诚实路线已具备：`TextInpainter.computeMask(RgbaImage, IntRect)` 是**公开的**，
  逐 region 取**字形级**掩膜再拼成整页 PNG（≈20 行）。
- 🔴 **没有采用矩形近似的理由**：FT 的 mask 是字形级，用外框近似会造出一个**同名但语义不同**的文件
  （属本项目最忌讳的"静默分歧"）。
