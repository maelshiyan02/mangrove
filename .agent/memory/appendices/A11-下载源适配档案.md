## 2. 🔴 comix.to WAF 硬规矩（P39~P45 四轮翻案换来的）

1. **WAF 按出口 IP 封，名单当天漂移**：34 节点实测时 31 个 200，美/印 403、韩 000；次日港 Y01
   （早上还通）和法国也被封。**钉死"直连"或"某节点"任一方向都会失效**（P39 全域直连结论次日即翻案）。
   实测好用：**🇭🇰香港 IEPL / 🇯🇵日本 / 🇸🇬新加坡 / 🇬🇧英国**；避开美/印/法/澳（随时变，以当天实测为准）。
2. **挑战页也是 HTTP 200**，Clash 延迟测试判不了 WAF。指纹（P45 收口）：
   URL `/@waf/challenge?return=` ＋ `<title>Security check</title>`（约 9.4 KB、无 initial-data）；
   旧的 CF `Attention Required`（`status=403 len≈5848`）仍认。
   🔴 **裸 `challenge-platform` 不能当判据** —— CF jsd 探针在真页也注入该串（offset 26834 实测），
   现行识别器用 `challenge-platform/h/` + `@waf/challenge` + `<title>security check` 三特征。
3. 命中挑战页：`_navigate` 咽喉 `_throwIfOnChallenge`（双采样 ~0.7/1.6s）→ 抛 **`COMIX_IP_BLOCKED`**，
   四处 catch + `_route` 直通，**禁止空结果重启重试**（旧路径最坏干等 30~90s，现 ~1s 出**中英双语切节点提示**）。
4. **代理策略已回归"跟随用户代理"**：`kDirectProxyHostSuffixes = []`（机制保留）；
   dio/WebView 都走系统代理 `127.0.0.1:7890`，bypass 只传 `<local>`。
   WebView2 的 `--proxy-bypass-list` 实测**不被采纳**（P40 实证，勿再走这条老路）。
5. **字段名会随站方重新构建漂移**：reader chunk 压缩字段 `bZ`(URL)→`B0`、`q2`(页序)→`ka`、
   数组容器→`hs` 等（chunk 名 `tmq6ux-…`→`tmqy0z-…`，同签名同 61,878 B）。
   `urlOf` 现行策略：已知名优先 → 通用兜底（任一 `http` 开头直字符串属性，排除 `/title/`、`/chapter` 导航链接）。
   章节选择器（`mpage__chapters`/`mchap-item`/`npager` 等）P44 线上实测**未漂移**。
6. 阅读器是 **Swiper slides 虚拟化**（同屏只挂 3 张 `img.rpage-page__img`）⇒ DOM 探针永远只有 3~5 张；
   **整章页数组在 React fiber 内存**，`_pagesByReactJs` 沿 fiber 挖（深度≤7、visited 去重、最长数组胜出）。
7. 🔴 **源仅在 App 启动 `doInit()` 时加载，无文件 watch** ⇒ 改完 js/数据**必须完全重启 App**。
