## 2. 🔴 comix.to WAF 硬规矩（P39~P45 四轮翻案换来的）

1. **WAF 按出口 IP 封，名单当天漂移**：34 节点实测时 31 个 200，美/印 403、韩 000；次日港 Y01
   （早上还通）和法国也被封。**钉死"直连"或"某节点"任一方向都会失效**（P39 全域直连结论次日即翻案）。

2. **挑战页也是 HTTP 200**，Clash 延迟测试判不了 WAF。指纹（P45 收口）：
   URL `/@waf/challenge?return=` ＋ `<title>Security check</title>`（约 9.4 KB、无 initial-data）；
   旧的 CF `Attention Required`（`status=403 len≈5848`）仍认。
   🔴 **裸 `challenge-platform` 不能当判据** —— CF jsd 探针在真页也注入该串（offset 26834 实测），
   现行识别器用 `challenge-platform/h/` + `@waf/challenge` + `<title>security check` 三特征。
3. 命中挑战页：`_navigate` 咽喉 `_throwIfOnChallenge`（双采样 ~0.7/1.6s）→ 抛 **`COMIX_IP_BLOCKED`**，
   四处 catch + `_route` 直通，**禁止空结果重启重试**（旧路径最坏干等 30~90s，现 ~1s 出**中英双语切节点提示**）。
4. **代理策略已回归"跟随用户代理"**：`kDirectProxyHostSuffixes = []`（机制保留）；
   dio/WebView 都走系统代理 `127.0.0.1:7890`，bypass 只传 `<local>`。
   WebView2 的 `--proxy-bypass-list` 实测**不被采纳**（P40 实证，勿再走这条老路）。
5. **字段名会随站方重新构建漂移**：reader chunk 压缩字段 `bZ`(URL)→`B0`、`q2`(页序)→`ka`、

   `urlOf` 现行策略：已知名优先 → 通用兜底（任一 `http` 开头直字符串属性，排除 `/title/`、`/chapter` 导航链接）。
   章节选择器（`mpage__chapters`/`mchap-item`/`npager` 等）P44 线上实测**未漂移**。

## 6. 🔴 P48 包子源修复铁律（2026-10-27，v1.2.6）

> 实证样本：灭门家族重生者 第152章（comicId=`miemenjiazudezhongshengzhe-yangpyungpainkillersaintnine`）。
> 镜像 webmota/kukuc 152 章 = **1 张图、slug=`meishaonianbangjiashijian-aojianyixi2`（错）**；官方 appcn 152 章 = **91 张图、slug 正确、在 s2/s.baozicdn.com**。
> 验证：Node 桩驱动真实 `baozi.js`，残缺 152 章从"只 1 张错图"变为回落官方域拿到完整章（86 去重值），正常 151 章仍 50 张不被误伤，含**故障注入**共 21/21 断言通过（v1.2.7 撤掉 UA/改写挑战两条后条数由 24 → 21）；样本落在 `test-materials/runs/baozi_p48_samples/`（第三方页面，已 gitignore，不入库）。
> 线上复查（同日 10:58，curl）：四镜像仍各 1 图、官方域 200/91 图 ⇒ 判据与回落均仍适用。**但 curl 200 ≠ App 能取**：App 侧 appcn 一律 `CloudflareException`（§6.8/6.9）。

1. **"最新章连不上"≠ 反爬/新防护**：先查"镜像章页 200 但内容残缺 / 引用错 slug"——这是镜像同步滞后，不是墙。**镜像侧**确无新 CF 挑战（四个镜像全 200）时，**不要**去给镜像加 Cloudflare 挑战逻辑，那是 P39/P41 翻过的车。**但官方 app 域不同**：它对 App 的 TLS 指纹发挑战（见第 8、9 条），排查时别用 curl 200 就断言"App 能拿到"。
2. **`collectPages` 首图"串错书"判据（P48 核心修复）**：首图数 `<5` **且** 所有首图都不含 `comicId`（= 图片 URL 里的 `/scomic/<slug>/` 段）→ 抛 `DomainBlock` 触发 `loadEp` 的官方 app 域回落。两者必须**同时**成立，否则会误伤正常章（正常章图多≥50 且 slug 正确，天然互斥）。
3. **图床穷举必须链式、闭包互不相同**：`onImageLoad` 的 `onLoadFailed` 返回"下一个候选 URL + 自带下一个 `onLoadFailed`"；**每个链接都是 `link(k)` 新闭包**，绝不能返回同一个函数引用——引擎会在每次调用后 `free()` 上一个 JSInvokable（`images.dart:424`），复用同一引用 = use-after-free 静默失效。`retryLimit` 设 `alts.length + 1` 保证遍历完所有候选。
4. **`cdn_domains` 候选必须含官方域真实图床**：包子官方 app 域图片在 `s2.baozicdn.com` / `s.baozicdn.com`，镜像图在 `s1/s2.bzcdn.net`。漏掉 s2/s.baozicdn.com 时，官方域回落图的某个候选会 404（已实测 s2.baozicdn.com/s.baozicdn.com 都 200）。
5. **🔴 改完 `comic_source/baozi.js` 必须手动同步到 `<dataPath>\comic_source\`**：本机 dataPath = `%LOCALAPPDATA%\.mangrove_datapath` 指针所指（现为 `Mangrove\data`），**不是** `%APPDATA%\io.github.maelshiyan02\mangrove`。见 §3 顶部纠正框。仓库副本改了 ≠ App 生效。同步动作：先 `baozi.js.bak_YYYYMMDD` 备份，再 cp；`<dataPath>` 与 `%APPDATA%` 两处都同步最保险。本次部署副本备份 `baozi.js.bak_20261027_P48datadir`。
6. **上游 `venera-configs-main/baozi.js` 也要同步改**（已改到 v1.2.7）：那是发布到 jsdelivr 的源。若只改仓库副本、不发布上游，将来 App 点"更新漫画源"会从 jsdelivr 拉回旧版覆盖。保持两副本版本号一致。
7. **验证套路（可复用）**：Node 桩 + 现场抓的真假 HTML。用 `new Function(..., raw + '\n;return Baozi;')` 加载真实 `baozi.js`（stub `ComicSource/Network/HtmlDocument`），驱动 `_cdnAlternativesFor` / `onImageLoad` 链 / `loadEp` 端到端。注意 app 域图片是 `<img>`（非 `<amp-img`），`data-src` 才是真图——桩抽取要覆盖 `<img>`。桩脚本 `test-materials/runs/baozi_p48_check.cjs`，样本目录可用 `--samples <dir>` 覆盖（默认同级 `baozi_p48_samples/`，回退 `/tmp`、`D:/tmp`）。
8. **🔴 appcn 的挑战判据是 TLS 指纹，不是 UA（v1.2.7 修正 v1.2.6 的错误结论）**：curl 用 Chrome/126、131、155 三个 UA 都是 200；但 **App（Dart/BoringSSL）请求 appcn 一律 403 + `Cf-Mitigated: challenge`**。
   - ⇒ **不要**在源里塞 User-Agent：既无效（不是变量），又会把版本号写死随浏览器更新过期；引擎 `js_engine.dart::_http` 缺省注入 `consts.webUA` 已够。
   - ⇒ curl 取证只能证明"内容存在"，**不能**证明"App 能拿到"；判断 App 可达性必须看 `logs.txt` 里的 `CloudflareException`。
9. **🔴 回落到 appcn 时绝不能吞掉 / 改写 `CloudflareException`（v1.2.6 回归事故）**：
   - Dio 层（`lib/network/cloudflare.dart:124`）识别 403+`cf-mitigated:challenge` 后抛 `CloudflareException`；
   - UI 错误页（`lib/components/loading.dart:34-66`）用 `CloudflareException.fromString(message)` 匹配该消息 → **自动跑一次离屏 WebView 验证 → 成功自动 retry**，并缓存 cookie（后续章节不再验证）；
   - 源若把它包成 `DomainChallenge: ...` 或别的字符串，匹配失败 ⇒ 自动验证永不触发 ⇒ 用户只看到一条死报错。**源层对挑战应当"什么都不做"，原样透传**。
   - 首次访问 appcn 必然要验证（`cookie.db` 里若查不到 baozimh 域 cookie 即证），可能需用户点一次"验证"（Turnstile 交互式无法离屏通过）。
   - 图片主机 `s2.baozicdn.com` 无需 cookie：`Referer` 给 appcn 或镜像域都 200（37KB 真 JPEG）。
