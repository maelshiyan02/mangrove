# A23 · 文字块类型（kind）与多边形精确掩膜 · 复合工具栏

> 触发时机：改工作室「新建文字块」工具栏、文字块识别类型、多边形画笔、单块修图/复原/马赛克。
> 上级索引：`MEMORY.md` §1 附表。相关：A04（画布与编辑层）、A05（`inpainted`/`result`/`mask`）、A15（版本号）。

## 1. 复合工具栏（三键合一）
- 三键（开启 `add_comment` / 形状下拉 / 类型下拉）必须用带描边的 `Container` **框成一个整体**，
  否则用户看不出它们是一组。
- 两个下拉都必须有 `Icons.arrow_drop_down` 小三角，明确"可展开"。
- 菜单必须 `position: PopupMenuPosition.under` + `color: scheme.surface`：默认弹出会**盖住按钮**，
  默认底色偏灰、与工具栏不一致。
- 菜单收窄：`constraints: BoxConstraints(minWidth:168,maxWidth:220)` + `PopupMenuItem(height:38)`。

## 2. PopupMenuButton 类型坑
- `itemBuilder` 返回 `List<PopupMenuEntry<String>>`。若抽本地构建函数，返回类型必须写
  **`PopupMenuItem<String>`**；写 `Widget` 会报 `list_element_type_not_assignable` 编译错。

## 3. 多边形精确擦除
- 多边形块擦除 = **字形掩膜 ∩ 多边形栅格掩膜**，再 `erasePageMaskInPlace`；绝不能退回外接矩形
  （会把轮廓外、落在矩形内的线条/网点一并抹掉）。
- 栅格化用 scanline + 奇偶规则（只扫 bbox），见 `lib/foundation/translation_project/polygon_mask.dart`。
- 矩形块继续走原 `TextInpainter.erase(rects)`，保证字节级不变。
- 可空类型提升：`final precise = poly != null && ...; if (precise)` **不会**提升 `poly`；
  必须直接 `if (poly != null && poly.length >= 3)`。

## 4. 水印块语义
- 水印块 **不翻译、不嵌字**：去水印/修图**不要求译文**；`_repairSelectedBlock` 的译文守卫必须是
  `if (!block.isWatermark && translation.isEmpty)`。
- 水印【马赛克】把**区域级**掩膜并进 `mask/`，复原才有效；复原时水印块用区域级掩膜（不是字形级）。
- 拟声词块默认不译：面板隐藏【翻译】。
- 「AI 修复填充」当前是 Dart `TextInpainter`，**未接 ONNX 模型**；文案与日志要如实标注。

## 5. 构建与提交
- `flutter analyze` 的输出被构建 wrapper 吞掉：错误去 **`builds/step_2_analyze.log`** 找，
  不要只看 `builds/build.log`（那里只有 rc）。
- 🔴 编辑 `assets/translation.json`（HEAD 为 CRLF）后，工作区会整体变成 LF，产生 7000+ 行脏 diff。
  提交前必须还原 CRLF：
  `python -c "p='Mangrove/assets/translation.json';d=open(p,'rb').read();d=d.replace(b'\r\n',b'\n').replace(b'\n',b'\r\n');open(p,'wb').write(d)"`
- 版本号权威 = `Mangrove/pubspec.yaml`。2026-10-26 现状 `2.8.19+263`
  （记忆旧值 `2.8.16` 已过时，一律以 pubspec 为准）。

## 四轮（2026-10-26）：水印 = 整体物体，不是"文字笔画"

人工验收定性结论（用户原话归纳）：
- **水印不需要识别文字，也不需要翻译**；对话/拟声词**都需要翻译**（拟声词只是异形字难，留后续）。
- 水印擦了还留紫底 ⇒ 程序对"水印是什么"理解不足。
- 水印块只框水印的**一小块**（怕伤边缘），但程序需要 ~30% 上下文来理解底图。

### 🔴 规则 1：水印走物体级掩膜，`buildMaskPage` 只适用于对话/拟声词
- 水印 = 底盘 + 圆标 + 白字 的**整体图形**。`buildMaskPage` 是 Otsu 字形级掩膜，
  只能分出"字"，底盘必然留下（黑底一条紫杠、裙子两个紫点，都是这么来的）。
- 正确入口 `context_repair.dart::buildWatermarkMask`：残差种子 → k=3 聚类 → 连通生长
  → 闭运算 → 去小块 → **填洞** → 膨胀 2px。种子不足时**退整块块框**（水印必须消失）。

### 🔴 规则 2：背景预测必须从"外圈"取，不能从块框边界取
- 用户贴着水印框，块框边界**还在水印自己身上**。从那里预测 ⇒ 预测出水印底色 ⇒
  残差≈0 ⇒ 检测失败（实测被 headless 断言当场判红）。
- 实现：检测区 `ctx = 块框外扩 max(30%, 24px)`，背景取样区 `outer = ctx 再外扩一圈`。
  **预测洞 = ctx，取样环 = outer 之外的像素**。
- 24px 最小绝对宽度不能省：585×40 的网站条，30% 只有 12px，环带仍在底盘上。

### 🔴 规则 3：颜色聚类 k 必须 ≥3，且掩膜必须"填洞"
- 水印三色（底盘/圆标/白字）。k=2 时第三种颜色在**框外**长不进来 ⇒ 掩膜留竖洞 ⇒
  洞里的原色成为填色源 ⇒ 填出一团原色（"擦了还留紫"的真凶）。
- `_fillHoles`：从窗口边界 flood fill 非掩膜像素，未达的都是内洞，一律并进掩膜。
  水印内部没有"必须保留"的东西，边缘精度由 ctx 边界保证。

### 🔴 规则 4：填色不要用 `TextInpainter.erase` 的最近邻
- `_fillNearest`（chamfer 最近邻）在长条洞/大洞上填出放射性条纹。
- 现有两档（`repairRegionInPlace`）：
  - `structural`：四方向射线插值（权重 1/(d²+1)）+ Jacobi 松弛 ⇒ 纯色/渐变底几乎完美；
  - `texture`：块级 patch 合成（Criminisi 简化版）⇒ 衣物/网点底不糊成一块平色。
- **"AI 修复填充"是本地经典算法，不是神经网络**。面板/日志/汇报都必须这么讲。

### 🔴 规则 5：任何"擦不干净"先怀疑掩膜，不要先怀疑填充算法
- 症状：擦完仍残留原色（不是糊，而是**颜色还在**）。
- 判据：残留区若能被掩膜覆盖 ⇒ 是填充问题；不能 ⇒ 是掩膜问题。
- 本轮两次都是掩膜问题（空洞 + 生长色差门槛）。

### 🔴 规则 6：断言里的"写死计数"必须和落点一起改
- `wiring.result_still_renders_in_a_second_pass` 写死 `calls == 4`，代码早就是 5 处
  （马赛克是后加的第 5 处），于是这条断言**上一轮起就恒红**，被当成环境问题跳过。
- 写 `calls == N` 时，同一 commit 内必须核对落点数；恒红的断言比没有断言更糟
  （它训练大家忽略红色）。

### 🔴 规则 7：新增断言必须"先红后绿"
- 本轮三条水印断言**第一次跑全红**，逐条逼出两个实现缺陷后才绿。这是正常流程，
  不是失败；反过来"写完立刻绿"要怀疑断言恒真。
- 故障路径必须构造**旧实现真会做的事**（只框矩形 / 只抹白字 / blend=0 马赛克），
  不要用"搜一个不存在的字符串"。

## 五轮整改新增铁律（2026-10-26 夜）

### 🔴 规则 8：ONNX 张量必须按声明布局填 —— HWC/NCHW 错位不报错、只出噪声
- LaMa 声明 `image [1,3,512,512]` = **NCHW**。Dart 侧却按 `(y*size+x)*3+c`（HWC）填，
  再按 HWC 读输出 ⇒ 三通道整体错位。
- **症状**：水印原样保留 + 整片噪声块。不崩、不抛，肉眼极易误判成"模型太差/模型不对"，
  这个判断会让整条线走偏两轮。
- **数值判据**：合成条纹图上正确布局 `mean|out-clean|≈0.9`，HWC 布局 `≈7.9`。
- **落实**：`inpaintImageIndex(c,y,x,size) => (c*size+y)*size+x` 是唯一真相，填与读都走它；
  断言 `inpaint.tensor_layout_is_channel_planar` 锁公式 + 用 HWC 公式做故障注入。
- 通用推论：**任何 `OrtInput.float32(flat, shape)` 都要先确认 flat 的填充顺序与 shape 一致**。

### 🔴 规则 9：写入范围 = 画笔轮廓 ∩ 块框（两条诉求会打架，必须同时满足）
- 用户两条原话：①"修图范围限制在画笔不规则框中" ②"修改的范围明显多了一圈，只修框选范围内的部分"。
- 真实数据：`003.webp` 的 196 顶点手绘 lasso 包围盒比水印块框高 22px、向下多 36px，
  下缘压在蓝头发上。**纯按 lasso 涂黑 → 头发被刷黑**（`ViewImage` 实测）。
- 定案：形状听多边形，**边界钉死块框**；交集为空（画笔整个画在框外）才退回纯多边形。
- 实测 `selectionPixels`：9750(矩形) → 18646(纯多边形) → **9394**(交集)。

### 🔴 规则 10：纯色底判定的两个陷阱
- **取样框只认块矩形**，绝不用多边形外接框（lasso 常比块框松，会把头发算进背景 ⇒ 黑底不判平色）。
- **弱多数不算表态**：一条边要投票给主色，必须自己 ≥65%（`edgeBest/edgeTotal >= 0.65`）。
  否则"三条边多数色都是白但两条只有 0.3~0.5"会把整块刷白（用户截图那块白方块）。

### 🔴 规则 11：纹理档窗口 pad 不能和写入范围等大
- `repairRegionInPlace` 若 pad 太小（曾是 3），写入区域=整片选区时窗口里放不下干净的 8×8 patch
  ⇒ `sources` 为空 ⇒ 直接 return ⇒ **与结构档逐字节相同**（静默空操作，用户看到"点了没反应"）。
- 定案：纹理档 `pad = max(24, min(bw,bh)*0.35)`；断言用 `stats.textured` 判定。
