# A02 · 硬规矩与断言纪律

> **触发时机**：写代码、写断言、写文档、写报告**之前**。

## 1. 术语与协作约定

- **BT 工程 → 「FT 工程」**；**group → 「翻译组」**；**翻译工作室 = Translation Studio**。
- **一律中文汇报**（含代码注释与文档）。
- **章节标签配色**：白＝未下载 / 黄＝下载中 / 蓝＝已下载 / 红＝缺页或失败。
  优先级：**红 > 黄 > 蓝 > 选中 > 白**。翻译组 chips **不着色**。
- **两个 agent 目录已统一**（详见 `../kb/methodology/M07`）：
  **目录唯一真相 = `<root>/.agent/`**；`.workbuddy/{memory,documents,skills,specs}`、`.trae/{同}`、`<root>/docs` 都是**指向它的目录联接**。
  ⇒ **不要再手动同步**（过去那套"写完 `.workbuddy` 再拷回 `.trae`"已作废）。
  ⇒ **项目根目录将来会改名** ⇒ 引用一律用**相对路径**，**绝不写 `D:\...` / `C:\...`**。
- 新增文件放进 `.agent/` 对应子目录；**不要**再往 `.workbuddy` / `.trae` 里塞真实文件。

## 2. i18n（Flutter UI 字面量）

- 🔴 `String.tl` 的查找表**以英文原文为 key** → **未登记就原样返回英文**。
  新 UI 字面量**必须登记**进 `assets/translation.json`（只有 `zh_CN` / `zh_TW`）。
- 🔥 **带变量一律用 `'x @a'.tlParams({'a': v})`**。
  `'x $v'.tl` 是**先插值再查表** → 查的 key 变成 `'x 值'`，**永远匹配不到**。

## 3. 缓存与生命周期

- 🔴 **跨帧缓存绝不能挂在「每次 build 都新建的对象」上**（P9.3 血泪）：
  - 要么挂 **state 字段**，要么让消费方按**稳定 key** 复用。
- 🔴 **失效判据用「key 集合变化」，不要只比 `length`**：
  长度相同是巧合 → 会把**偶发 bug 变成永久 bug**（配合"只比 length 的 `didUpdateWidget` → 永久不自愈"）。

## 4. 验证「新代码真的进产物」的方法

- 🔴 **不要用 `grep` 私有标识符**判断代码是否进产物：AOT 会**重命名/内联**私有字段与局部变量
  （`_viewportWidth`、`structureChanged` 这类 grep 不到 ⇒ **假阴性**）。
- 正确做法：
  1. **`app.so` 的 mtime > 源码 mtime**；
  2. `build.log` 里**有链接步骤**，而不是 `Up-to-date`；
  3. 如需字符串证据，grep **字符串字面量**（AOT 保留字面量，如 `"pipeline-check OK"`）。
- ⚠️ **不要在构建运行途中改代码** —— Flutter 按启动瞬间的快照计算依赖图。

## 5. 路径处理

- 🔴 **绝不用 `entity.uri.pathSegments.last` 取目录名**：
  目录 URI **必带结尾斜杠** → 永远得到 `''`；而且段是**百分号编码**的（`6 [DivaScans]` → `6%20%5BDivaScans%5D`）。
  - 对 `File` 安全（`download.dart` / `_pageIndexesIn` 前面都有 `is! File → continue`），**对 `Directory` 致命**。
  - 正确做法：`FileSystemEntityExt.name`（内部是 `p.basename`，`utils/io.dart:41`）。

## 6. 影子类型

- 🔴 **`IntRect` / `RgbaImage` 是本仓库自制的，不是 `dart:ui` 的**（声明在 `image_translation/translation_types.dart`，
  **故意**让翻译模型零 Flutter 依赖、可 headless 测）。
  - 本地 `IntRect` 只有 `IntRect(l,t,r,b)`，**没有 `fromLTWH`，且构造器不是 `const`**。
- 见到"Flutter 里缺失"的标识符，**先 `grep "^class <名字>" lib/` 确认是不是影子类型**，不要急着 `import 'dart:ui'`。
  同名引入会把 `undefined_identifier` 变成更迷惑的 `isn't defined for the type`（P9.3 连踩 4 刀）。

## 7. 🔴 断言纪律（十条）

1. **空结果判 FAIL** —— 扫描返回空集还判 PASS 就是**假绿**。
2. **每条断言都要反向验证**（注入故障 → 该断言必须 FAIL）。见 `A01 §5`。
3. **扫源码的断言必须先剥注释**（否则注释里的字样会喂给它）。
4. **「集合被收窄」类断言：先证明未收窄那一侧非空**，否则"全被过滤"与"过滤生效"给出同一结果。
5. **detail 必须可诊断**（例如 `Rect` 没有分量 `toString()`，要自己拼）。
6. **夹具要落在「正确值」与「故障值」之间，并留余量**
   （`Rect.intersects` 边界相等算 false —— 靠边界相等＝靠运气）。
7. **挑能区分的观测量**（雅黑别名与未知回落会给出同一个 `(family, fallback)` → 只能读 `reason`）。
8. **报告顺序即诊断**：**上游失败必须先于下游无产出报**，否则读者去查错地方。
9. **缺失原因要报到根因那一层**：按"第一个成立"取原因，会把真实错误藏到第二层（读起来像"这些页本来就没文字"）。
10. **能机器读的取证痕迹要落日志**（如 `Studio Pipeline` 的 JSON 行）—— 人只看现象，事后无法复算。
