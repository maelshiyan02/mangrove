## 2026-10-05 三轮：决定性根因 evaluateJavascript 不 await Promise（v0.6.3）
- 🔥 **核心发现（务必记住）**：本环境 `evaluateJavascript`（WebView2 ExecuteScriptAsync）**不等待 Promise**——`(async function(){...return JSON.stringify(x)})()` 的返回值被序列化成 `{}`。此前三处（fetchPageHtml / 图片 Worker _fetchOnce / _inPageFetchJson）**全部静默失败**；章节数据其实一直靠截获钩子+DOM 兜底拿到，所以"能用"掩盖了"页内 fetch 已死"。
- 修复：新增 `evalAsyncResult(controller, asyncBody, {timeout})`（comix_client.dart，顶层函数）——脚本同步返回 1、结果写 `window.__comixAsync[slot]`，Dart 轮询同步读取（250ms/轮）。配套 `unwrapEvalString`、`looksLikeChallengePage`。fetchPageHtml 另改为「导航 + 同步读 outerHTML」（CF 挑战由浏览器自己过完再读，读到挑战页等 2.5s 重试×3）。
- 包子"每章都要重新验证"根因：请求起点 appcn.baozimh.com →302→ www.baozimh.com（gatekeeper，cookie 存 www），**dio cookie 拦截器只在原始请求跑一次，302 跳不重跑** → cookie 永远带不上。修复三层：① 站点簇归一 `_clusterOf`（eTLD+1）+ `_clusterCookies` 缓存；② `CloudflareInterceptor.onRequest._injectClusterCookies` 请求阶段注入票据；③ loading 层 `isClusterVerified` 命中则跳过 headless 直接 retry；④ baozi.js 被挑战域名记 `challenged_domains`（30min 降级），webDomains 改「good → selected → 未挑战 → 被挑战」。
- 构建 BUILD_OK（app.so 14:08）。踩坑：cloudflare.dart 的 `cookies` 变量不在 solved 块作用域 → 移入循环内 `_markClusterVerified`。
- 下一步计划已写入 `docs/P4-下一步优化计划-20261005.md`（P0 验证 → P1 性能 → P2 持久化/跨品牌归一/重定向接管 → P3 下载 → P4 可观测性）。教训 18~21 见 P4 日志 v0.6.3。
