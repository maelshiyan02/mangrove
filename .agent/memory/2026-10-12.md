## ⑩ comix 阅读页「只 3 张」真根因 = **站方构建致页对象字段漂移**（任务 B 落地，P44）

> 承接 ⑨（真因=代理节点被封，已切 🇭🇰香港Y01）。网通后按用户建议**在 agent 里开浏览器细测 comix fiber**。

- **现场取证**：对线上 entry 拆分后的 42 个 chunk 逐块比对，定位本构建 reader chunk = **`tmqy0z-DcHRFp8b2.js`**（61,878 B，`rpage`×252 / `swiper`×6，与 P43 的 `tmq6ux-CARftgsC2.js` 同签名同大小）。逆出当前页组件：**URL = `B0`**、页序 = **`ka`**、高/宽 = `Rh`/`MO`、域数组 = `lk`、备用域 = `NX`、整章页数组容器 = **`hs`**。
- ⇒ **真根因**：P43 的 `_pagesByReactJs::urlOf` **写死 `bZ` + `q2` 守卫**，新构建下恒 `null` ⇒ `harvest` 取不到 URL ⇒ 恢复 **0 图** ⇒ 退回 `<img>` 探针（虚拟化下只有 3 张）⇒ 正是用户所见「阅读页只 3 张」。
- **修复**（`Mangrove/lib/network/comix_client.dart`）：`urlOf` 改为「**已知名 `B0`/`bZ` 优先 → 通用兜底**（页对象里任一**直接字符串属性**以 `http` 开头即认，并**排除** `/title/`、`/chapter` 导航链接，避免把章节/关联漫画数组误当页数组——`harvest` 取最长，撞上就全错）」+ 同步文档注释登记漂移对照。
- **章节选择器未漂移**：`browser_use` 实测**线上 DOM**，`section.mpage__chapters`/`li.mchap-item`/`a.mchap-row__primary`/`a.mchap-row__group`/`span.mchap-row__ch`/`nav.npager`/`button.npager__num`/`.npager__num.is-active` **全部仍在用**（分页「Showing 1 to 20 of 365 items」；阅读页「1 / 100」= 100 页而 DOM 只挂 3 张 `rpage-page__img`，**虚拟化再次证实**）。教训：SSR/CSS 类名**不在 JS chunk 字面量里**，静态搜 JS 得 0 命中**不等于**失效，以线上 DOM 为准。
