### 问题一（下载侧）`My Dragon Girlfriend Has Returned / 6 [DivaScans]`：缺了 150.webp 却不报错，且翻译组分类 UI 消失

三条独立证据链锁定 **两个独立缺陷 + 一个新工具自身 bug**：
- **磁盘**：`6 [DivaScans]` 145 文件 / min0 / max176 → 应有 177，**实缺 32**（33,41,…,142 + 146,150,…,175，含用户看到的 150）；对照 `6 [Asura Scans]` 128 文件 0..127 **0 空洞**。
- **缺页账本**：`missing_pages.json` **当时根本不存在**（`missingBefore=0`）。日志只有 `Repair 22:04:38 Repaired all 1 missing page(s)`，`5.webp` mtime 正是 22:04:38 → 表里**只有 index 5 一条**。目录 mtime 分三批（20:17–20:19 / 20:25 / 20:34–20:37）＝多次独立下载，**每次都在末轮前结束**。
- **`local.db`**：`chapters` 退化成 **6 个版本（全 DivaScans ch1–6，第 7 话消失）**；`downloadedChapters` 7 条**全 Asura**；**交集为空**。而源侧（`details_cache.db`）实况是 **7 话 × 最多 11 组 = 66 个版本**。

🔴 **根因 A**：缺页表**只在末轮（第 4 轮）落盘** → 末轮前取消/崩溃的运行 = "既缺页又不报错、还被判成 downloaded"，且"修复"的目标集来自缺页表 → **永远修不到那 32 页**。
🔴 **根因 B**：`LocalManager.add()` 的 `INSERT OR REPLACE` 整行覆盖 —— `downloadedChapters` 走**并集**（Asura 7 条活下来），`chapters` 走**覆盖**（被那次任务自己的按组过滤矩阵换成 DivaScans 6 条）。组 chips **需要 2+ 组才渲染** → 退化成单组就整行消失。
🔴 **根因 C（工具自身）**：`entity.uri.pathSegments.last` 对**目录**恒为 `''`（目录 URI 必带结尾斜杠）→ 紧接着 `isEmpty → continue` → **每个目录都被跳过、报告恒空**；且段是**百分号编码**的（`6 [DivaScans]`→`6%20%5BDivaScans%5D`）。同一写法在 `reconcileMissingPages` 里也抄了一份（**同一个 bug 两处**）。⚠️ **该写法对文件安全**（`download.dart` / `_pageIndexesIn` 前面都有 `is! **修复**：`missing_pages.dart` 加 `pageIndexGaps()` + `MissingPages.reconcileChapter()`；`local.dart` 加 `reconcileMissingPages()`（**扫磁盘章节目录**，跳过 `ComicType.local` 与正在下载者；`completeTask()` 里下完立刻对账）+ `enrichComicChapters()` + `add()` 的"矩阵只许变多"守卫；`models.dart` 加 `versionCount` / `mergedWith()`（只增不减）；`comic_page.dart` 详情页并集自愈 + `_persistEnrichedChapters()`；`repair_download.dart` 加 `_resolveBlankUrls()`（`url:''` 的空洞现场解析真实 URL）；`headless.dart` 加 🆕 `page-reconcile`。
