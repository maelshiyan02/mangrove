守卫把"残留故障"判据写成"这行有没有 `injected fault` 这几个字"，而
`headless_p1_checks.dart:1037` / `headless_p2_checks.dart:463` 的断言 detail 文案里
写着 `'injected fault$unverified'` ⇒ **每一次 `_rv_drive` 都被自己的守卫挡在门外**
（报"树不干净"，最不该误报的结论）。豁免规则 `line.strip() == "'injected fault',"`

**修法**：判据改成"它是不是一句注释" —— 故障一律是 `// injected fault` / `# injected
fault`，字符串字面量里的不算。双向验过：注入一行真注释 ⇒ 报警；`'injected fault$…'`
⇒ 不报警。

### B · 入队端（新文件 `studio_enqueue.dart`）

`StudioChapterQueue.enqueue()` 五步：本地副本 → `ensureBinding` → 这一章的页
（`studioChapterPageKeys`） → 还缺 `result/` 的页（`studioPagesNeedingWork`）
→ `startStudio`。空则 `upToDate`（**不建任务**，否则列表里出现 0 页幽灵任务）。
`cancelIfRunning()` / `unbind()` 对应关开关：**取消在跑的任务 + 解绑**，
**不删工程、不删产物**。

`registerStudioTaskRunner()` 把执行体注入任务框架（`init.dart` 里在
`resumePendingTasks()` **之前**调用 —— 顺序即契约，反了会让遗留任务报
"翻译失败"，一个由启动顺序制造的无线索失败）。

### C · 任务模型（交付 4，只接展示）

`PreTranslationTask` 加 `studio` / `studioJsonPath` / `studioChapter`；
`startStudio()`（**不查** `isReadyForComic`：工作室读的是磁盘上的工程）；
`_run()` 里**唯一一处**分叉（`if (task.studio)` → `_runStudio`）；
`cancel()` 里 `_studioTokens[id]?.cancel()`（这才叫"可取消"）；
`pause()` 与任务卡按钮对 studio 任务**都不给**（`StudioChapterRunner` 没有暂停，
画一个按下去没反应的键 = UI 在说谎）。

🔴 **框架不认识工作室引擎**：`pre_translation_tasks.dart` 只有注入点
`static StudioTaskRunner? studioRunner`，没有 `StudioChapterRunner` 的 import
与调用（有断言锚着）—— 这就是交付 4 说的"只接展示，不把旧缓存写入口拉进工作室"
